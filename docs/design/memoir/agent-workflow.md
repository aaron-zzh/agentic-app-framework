# 智能体工作流

原则：AI 提效，人工把关。每一层都有不可省略的人工卡点，任何作品都要经过人工确认才能交付。

## 七层流水线

| 层 | 模块 | AI 做什么 | 人工卡点（不可省） | 关键指标 |
|----|------|----------|-----------------|---------|
| L1 | 线索与预评估 | 解析家属预问卷，提示健康状况与话题禁忌，给访谈可行性打分 | 顾问确认能否接单 | 线索到签约转化率 |
| L2 | 访谈辅助 | 生成个性化提纲，建议记忆锚点（老照片、老物件、年代歌曲），实时提示追问 | 访谈师主导对话与共情 | 单次访谈有效素材字数 |
| L3 | 转写与理解 | 方言和口音适配，说话人分离，抽取时间、地名、人名 | 抽审 10% 转写 | 字错率、实体召回率 |
| L4 | 记忆结构化 | 生成时间线、人物关系图、"事件-地点-职业"三元组，标记矛盾点 | 家属确认时间线 | 时间线条目准确率 |
| L5 | 成稿生成 | 生成章节大纲，保持讲述者语言风格，出多版本初稿，去模板化表达 | 编辑重写关键段落 | 初稿可用率（编辑改动比例） |
| L6 | 事实核对 | 逐条溯源到原始录音和转写，可疑陈述标红，提示与外部史料比对 | 逐条人工核实，家属签字 | 每万字事实错误数（目标 0） |
| L7 | 交付与运营 | 排版、原声二维码、电子书、人生短片、机构报告、分享页 | 设计终审、印刷质检 | 交付周期、转介绍率 |

```text
L1 预评估 → L2 访谈 → L3 转写 → L4 结构化 → L5 成稿 → L6 核对 → L7 交付
                ↑                    │                    │
                └──── 补采 ←─────────┴──── 存疑退回 ←─────┘
```

L4 发现时间线空缺、L6 发现事实无法核实时，退回 L2 补采。

## 事实核对报告

行业最大的痛点是品质没有统一标准，以及 AI"添油加醋"。把 L6 的结果做成交付物《事实核对报告》，让家属签字，作品就从"AI 生成"变成"可验证的家族档案"。这是标准档定价的依据。

报告包含事实清单、核对状态、修改对照、编者注和签字页。陈述抽取、风险规则、核对流程、报告模板的详细设计见 [事实核对模块](./fact-check-engine.md)。

## 数据资产

L4 和 L6 的结果不能做成一次性脚本，必须持久沉淀：

- **人生记忆图谱**：人物、事件、地点、时间及其关系，每条带来源和核对状态。追加访谈、出书、做短片、建家族档案都基于同一份图谱。
- **核对记录**：每条事实的核对过程和结论，是评测集和品控标准的来源。
- **年代事件库**：在多个项目中积累的地区年代事件，用于提纲生成和史料比对提示。

这三类数据积累得越多，提纲和核对越准，是同行难以复制的部分。

## 指标体系

| 类型 | 指标 | 目标 |
|------|------|------|
| 北极星 | 单项目编辑有效工时 | 3 万字项目从 60 小时以上压到 15 小时以内 |
| 护栏 | 每万字事实错误数 | 0 |
| 护栏 | 家属返工轮次 | 不超过 2 轮 |
| 护栏 | 单次访谈时长 | 不超过 2.5 小时 |
| 商业 | 机构试点签约数、单机构覆盖人数 | 试点后设定 |
| 商业 | 家属自费升级率 | 试点后设定；这是 B2B2C 能否跑通的关键信号 |

## 技术风险

- **方言与老年语音是转写准确率的主要瓶颈**，也是投诉集中点。必须单独建立方言和老年语音评测集，不用通用演示效果对外承诺。
- **"AI 全自动"的宣传会反噬。** 行业已有对 AI 情感把握不足、擅自加工的公开质疑。对外口径统一为"AI 提效，人工把关"。
- **L4、L6 做成一次性脚本会丢失壁垒。** 见上文数据资产。

## AAF 能力映射

| 层 | AAF 能力 | 说明 |
|----|---------|------|
| L1 | 智能体 + EntityDef 管理后台 | 预问卷解析智能体；线索和项目由实体声明管理 |
| L2 | 多智能体协作 | 提纲智能体、追问智能体，读取人生记忆图谱和年代事件库 |
| L3 | 工具（Tool） | 方言语音识别、说话人分离作为工具接入 |
| L4 | 知识库管理 | 人生记忆图谱存储，矛盾检测；P0 用 PostgreSQL 加 JSON 存时间线与人物关系，后续再评估投影到 Neo4j 图谱 |
| L5 | 工作流 | 大纲、初稿、风格保持的 AI 编排流水线，步骤可重跑 |
| L6 | 工作流 + 领域状态机 | 核对智能体产出清单；人工核实、讲述者确认和家属签字由项目状态机的卡点控制，用领域代码实现，不建 BPMN 审批流 |
| L7 | 数字人 / 视频生成 | 人生短片复用 [数字人设计](../digital-human/Readme.md) 中的视频生成能力 |

具体接口与数据结构在进入迭代后，由 architect 在任务目录的 `design.md` 中定义。
