# 事实核对模块

事实核对是 [智能体工作流](./agent-workflow.md) 的 L6，对应 [后续需求规格](../../prd/memoir/后续需求规格.md) 的 P0-09。它是本项目的护栏，也是标准故事书 9800 到 16800 元定价的依据：把"AI 生成"变成"可验证的家族档案"。

## 目标与非目标

**目标**：

- 成稿中每条可核查陈述都能追溯到证据，或已被明确处置（修正、软化、删除）。
- 高风险项 100% 经人工裁决和家属确认，形成可交付的《事实核对报告》。
- 3 万字项目的核对工时可控，预算见下文"工时预算"。

**非目标**：

- 不做历史真伪鉴定，不承诺地方史、家族源流的学术正确性。
- 不对医疗、法律、政治做权威判定，只判断"有没有依据、要不要软化或删除"。
- 不替代当事人的记忆裁决，冲突时按"裁决优先级"处理并在报告中留痕。

**裁决优先级**：在世且能自主表达的讲述者本人 > 签约委托人 > 其他家属。主文本保留讲述者的叙述，其他人的补充记入报告。

## 数据模型

本模块的四张表是 [P0 数据与接口设计](./p0-data-api.md) 中 `fact_claim` 的扩展，以本文为准。

### 关系

```text
chapter ──1:N── fact_claim ──N:M── evidence（经 claim_evidence 关联）
                    │
                    └──1:N── verification_record（机器、编辑、家属的每次动作）
```

### 表结构

```sql
fact_claim(
  id PK, chapter_id FK, project_id FK,
  claim_text TEXT,              -- 成稿中的陈述原文
  claim_span JSON,              -- 章节内字符偏移 [start, end]
  ref_chapter_ids JSON,         -- 同一事实在多章出现时的其他引用位置
  claim_types JSON,             -- 一个或多个：time/place/person/org/event/number/relation/eval
  risk ENUM('high','mid','low'),
  risk_rule_ids JSON,           -- 命中的风险规则，如 ["R01","R05"]
  status ENUM('pending','machine_checked','editor_review','pending_external',
              'family_pending','family_disputed','closed'),
  disposition ENUM('verified','fixed','softened','removed','rejected') NULL,
  confidence DECIMAL,           -- 机器判定置信度
  required_action TEXT,         -- 给人工的处置建议
  prev_text TEXT,               -- 修改前文本
  reviewer_id FK NULL, reviewed_at,
  family_result ENUM('confirmed','modified','unsure','disputed') NULL,
  family_ack_by FK NULL, family_ack_at, family_note TEXT,
  external_rounds INT DEFAULT 0, -- 外部核实轮次，上限 2
  created_by ENUM('machine','editor','family')
)

evidence(
  id PK, project_id FK,
  kind ENUM('transcript','family_material','photo','timeline','self_card','external_ref','editor_judgement'),
  source_id,                    -- 转写片段、材料、时间线条目或外部条目 ID
  quote TEXT,                   -- 证据原文片段
  locator JSON,                 -- 时间戳、页码、文件名
  strength ENUM('strong','medium','weak'),
  authorized_for_report BOOL,   -- 是否授权在报告中展示原文
  uploaded_by, verified BOOL
)

claim_evidence(
  claim_id FK, evidence_id FK,
  relation ENUM('support','contradict','partial'), note
)

verification_record(
  id PK, claim_id FK, actor_type ENUM('machine','editor','family'), actor_id,
  action ENUM('scan','flag','bind','verify','fix','soften','remove','reject',
              'request_external','confirm','modify','unsure','dispute'),
  before_text, after_text, reason, created_at
)
```

与原稿相比做了两处调整：

- **状态与处置分开。** `status` 表示陈述走到了哪一步，`disposition` 表示编辑怎么处理的。原稿把两者放在同一个枚举里，无法表达"已修正、等家属确认"这种组合。
- **类型改为多值。** 同一证据能同时证明的要素（如年份和单位都来自同一张工作证）放在一条陈述里，`claim_types` 存多个类型；需要不同证据的要素才拆成多条。

### 状态机

```text
pending
  → machine_checked（机器预筛完成，附证据与置信度）
      ├─ 低风险且有强证据 → closed（disposition=verified，进入 10% 抽检池）
      └─ 其他 → editor_review
editor_review
  ├─ 无需家属确认（中低风险，未被抽中）→ closed
  ├─ 需外部资料 → pending_external（最多 2 轮，每轮不超过 5 个工作日）
  │     ├─ 找到依据 → editor_review
  │     └─ 仍无依据 → disposition=softened 或 removed → editor_review
  └─ 高风险、有矛盾证据、或中风险被抽中 → family_pending
family_pending
  ├─ confirmed / modified / unsure → closed
  │    （unsure 时 disposition 改为 softened，加限定词）
  └─ disputed → family_disputed
family_disputed
  ├─ 补采或改写后 → editor_review
  └─ 无证据且家属不认可 → disposition=removed → closed
```

**硬约束**：存在未 `closed` 的高风险陈述时，项目不能进入 `FAMILY_APPROVED`，也就不能进入 `DELIVERED`。

## 陈述抽取

### 什么算可核查陈述

能被证据（转写、家属材料、外部资料）支持或推翻的陈述。

| 类型 | 例子 | 默认风险 |
|------|------|---------|
| time | "1978 年我调任车间主任" | 高（年份常被口述模糊化） |
| place | "从上海十六铺坐船去宁波" | 中 |
| person | "带我入党的老张" | 高（姓名和关系易错） |
| org | "××纺织厂""××中学" | 高（全称易错） |
| event | "参与了某项工程建设" | 高 |
| number | "养了三个孩子""走了八百里" | 中 |
| relation | "他是我表舅""我们是同班同学" | 中 |
| eval | "那几年是最苦的""他为人很正直" | 高（评价，涉及他人） |

### 不抽取的内容

- 纯感受、心情、氛围描写（"心里很踏实""天很冷"）。
- 已明确标注记忆模糊的表述（"记不清是哪年了，大概是春天"）。
- 文学性修辞与比喻。
- 家属在时间线确认环节**人工确认**过的条目，继承确认状态。逾期默认通过的条目（`confirm_mode=timeout`）不继承，照常抽取。

### 抽取规则

1. **句子级为主，短语级为辅。** 一句含多个要素时，需要不同证据的拆为多条，可由同一证据证明的合为一条多类型陈述。
2. **无源即高危。** 无法绑定任何证据的陈述自动定为高风险，处置建议为"无来源，需补证或删除"。
3. **数字与年份强制抽取。** 阿拉伯数字、汉字数字、年代词（"七几年""解放前后"）全部成条，不得遗漏。
4. **人名、机构名规范化。** 识别别名变体（"老张、张师傅、张××"），生成候选统一实体，由编辑合并。
5. **去重。** 同一事实在多章出现时合并为一条，记录所有引用位置，家属只确认一次。

### 抽取提示词（节选）

```text
你是回忆录事实核对助手。任务：从给定章节中抽取"可核查陈述"。
硬性要求：
1) 只抽取可由证据验证真假的陈述；感受、修辞、已标注记忆模糊的内容不要抽取。
2) 每条陈述必须是原文的连续子串，并给出字符偏移。
3) 一句话含多个要素时，需要不同证据的拆成多条。
4) 对每条给出类型（可多个）、初判风险（high/mid/low）及命中的规则 ID。
5) 不得推断原文未出现的信息；不得补全年份、姓名、机构全称。
6) 输出严格 JSON，不输出解释。
输入：章节文本 + 已确认时间线 + 已确认人物表
输出：{"claims":[{"text","span","types":[],"risk","risk_rule_ids":[],"hint"}]}
```

**验收**：抽取召回率不低于 95%（200 条人工标注金标准集）；误报率不超过 25%，过高会拖垮编辑工时。

## 证据模型

### 来源与强度

| 来源 | 说明 | 强度 |
|------|------|------|
| 访谈转写片段 | 讲述者原话，带时间戳 | strong（但口述本身可能不准，高风险项仍需家属确认） |
| 家属补充材料 | 证件、工作证、书信、档案复印件 | strong |
| 老照片和影像 | 有拍摄时间、地点标注的 | medium 到 strong |
| 家属人工确认的时间线 | P0-06 中人工确认的条目 | strong |
| 自助事实卡片 | 自助阶段讲述者本人确认或修改过的卡片（`self_card`），升级人工时带入 | medium：低、中风险项可直接作为依据，高风险项仍需编辑裁决和家属确认 |
| 外部参考库 | 年代事件库、行政区划沿革、单位和学校名录 | medium |
| 编辑判断 | 无外部依据，仅逻辑推断 | weak，不能单独支撑高风险项 |

### 绑定规则

- 处置为 `verified` 或 `fixed` 的陈述，必须绑定至少 1 条 medium 及以上强度的证据。
- 高风险陈述只有 weak 证据时，只能进入 `pending_external`，或被软化、删除。
- 存在矛盾证据时，自动进入 `family_pending`，报告中并列展示双方依据。
- 家属提供的照片和书信需确认授权范围，未授权展示的材料可以作为依据，但报告中不展示原文。

### 外部参考库（P0 最小集）

| 库 | 用途 |
|----|------|
| 年代事件库 | 校验"那年发生了什么"类陈述的时间一致性 |
| 行政区划沿革 | 地名变迁，如"××公社""××乡"；保留原称并括注今名 |
| 单位和学校名录 | 机构全称核对，来源为家属提供或公开可查资料 |

外部库只用于提示矛盾，不直接改写讲述者的表述；改写必须经编辑和家属确认。

## 风险分级

### 分级与处置

| 级别 | 定义 | 处置 |
|------|------|------|
| high | 错误会实质损害可信度或引发纠纷 | 编辑裁决加家属确认，缺一不可 |
| mid | 影响细节准确性但不致争议 | 编辑裁决，抽 20% 送家属确认 |
| low | 有强证据支持，误差影响小 | 机器通过，抽检 10% |

### 高风险规则（命中任一即为 high）

| 规则 | 触发条件 |
|------|---------|
| R01 | 涉及具体年份或日期，且转写中有模糊词（"大概""记不清""七几年"） |
| R02 | 涉及在世第三方的负面评价或责任归属 |
| R03 | 涉及已逝人员的评价、过错或关系判断 |
| R04 | 涉及政治运动、历史争议事件的因果或立场表述 |
| R05 | 涉及职务、职称、荣誉、党籍、军功等身份性事实 |
| R06 | 涉及金额、数量、伤亡、面积等可被外部核验的数字 |
| R07 | 无证据绑定 |
| R08 | 存在矛盾证据 |
| R09 | 涉及医疗、诊断、用药、疗效 |
| R10 | 涉及未成年人信息或他人隐私（住址、病历、纠纷细节） |

### 不可被自动化绕过的规则

命中 R02、R03、R04、R09 时，机器只标不判，必须由编辑裁决。R02、R03、R04 另需家属确认；R04 由资深编辑终审；R09 按"合规边界"一节处理。

规则命中优先于模型判断。模型只对规则未覆盖的陈述补充分级，且不能把规则判定的 high 调低。

## 核对流程

```text
机器预筛（分钟级）
  抽取陈述 → 绑定证据 → 风险分级 → 低风险自动通过 → 生成编辑待办
编辑核对（人工，核心）
  逐条裁决 → 需要时发起补采或外部核实 → 修正、软化或删除
家属确认（人工，授权）
  高风险和争议项逐条确认 → 签字 → 报告定稿
```

### 时限

| 环节 | 时限 | 超时处理 |
|------|------|---------|
| 机器预筛 | 每万字不超过 10 分钟 | 重试 3 次后转人工全量核对 |
| 编辑核对 | 每个 3 万字项目不超过 2 个工作日 | 触发项目预警 |
| 家属确认 | 不超过 7 个工作日 | 第 5 天提醒；逾期后中低风险项默认通过，高风险项不能默认通过 |
| 外部核实 | 每轮不超过 5 个工作日，最多 2 轮 | 仍无依据则软化或删除 |

原稿的编辑时限是"每万字 2 个工作日"，3 万字项目要 6 个工作日，加上家属 7 个工作日，单是核对就超过 14 天交付周期，因此改为按项目计。另外，14 天交付周期不计入等待家属确认的时间，需写入合同。

### 处置动作

| 处置 | 含义 | 场景 | 文本处理 |
|------|------|------|---------|
| verified | 维持原文 | 证据充分 | 不改 |
| fixed | 修正 | 有明确的正确信息 | 替换并保留修改前文本 |
| softened | 软化 | 记忆模糊、无硬证据 | 加"据老人回忆""大约"等限定词 |
| removed | 删除 | 无证据且家属不认可 | 删除并记录原因 |
| rejected | 驳回核对意见 | 机器误报 | 标为误报，回流评测集 |

`pending_external`（待外部核实）是状态，不是处置，暂挂期间不阻塞其他章节。

### 软化模板

统一话术，避免风格漂移：

| 情形 | 模板 |
|------|------|
| 年份模糊 | "那是上世纪七十年代末的事"；"大约 1978 年前后（据老人回忆）" |
| 机构全称不确定 | "××纺织厂（今××）" |
| 他人评价 | "在我印象里，他是个……的人"（加主观视角） |

## 家属确认

### 确认页

- 入口在家庭端，卡片式逐条确认。中低风险项可"全部同意"，高风险项必须逐条确认。
- 每张卡片依次展示：成稿原句、老人原话（可播放音频）、证据摘要、系统疑问（如"任职年份未在材料中出现"），以及三个按钮：`确认无误`、`需要修改`、`我不确定`。
- 选"需要修改"时，提供文本框和建议模板。
- 选"我不确定"时，该条自动按软化模板加限定词，并提示家属。
- 在世讲述者能自主表达时，高风险项先由交付人员朗读给讲述者确认，再交家属确认。

### 沟通话术

供顾问和编辑使用：

| 场景 | 话术 |
|------|------|
| 开场 | "这一部分我们把书里涉及年份、单位、人名的地方逐条整理出来了，每条都附了老人当时的原话。麻烦您花十几分钟帮忙确认一下，主要是避免把年份或单位名称写错，将来家里人翻起来更放心。" |
| 为什么要确认 | "我们用 AI 帮忙整理录音和初稿，速度很快，但涉及具体年份、职务、人名这类事实，必须由人和家属一起确认，我们不希望书里出现任何没有依据的说法。" |
| 家属与老人说法不一致 | "这类情况很常见。回忆录以老人的讲述为主，我们可以在书里保留他的说法，同时在核对报告里注明家属的补充，这样两种记录都留下来了。您看这样处理可以吗？" |
| 质疑"是不是 AI 乱写" | "书里每一句都能追到老人的原话或您提供的材料。这份核对报告就是逐条对照的清单，您可以看到每条的依据来自哪段录音。" |
| 第 5 天催办 | "还剩 6 条待确认，确认后我们就进入排版。如果您这周不方便，我可以约 10 分钟电话，我们逐条过一遍。" |

### 争议处理

| 情形 | 处理 |
|------|------|
| 家属与讲述者说法冲突 | 主文本保留讲述者叙述，报告注明家属补充；编辑撰写中性表述 |
| 家属要求删除涉及他人的内容 | 直接删除，不做说服；报告记录删除原因 |
| 家属之间意见不一 | 讲述者能自主表达时以讲述者为准；否则以签约委托人为准，其他意见记入报告附注 |
| 在世第三方负面评价 | 默认软化为主观视角；家属坚持保留时须书面确认责任归属 |
| 家属长期不确认 | 高风险项不能默认通过；可先交付已闭环章节组成的分册版，或协商暂停 |

家属之间意见不一时以谁为准，签约时向委托人明示。

## 事实核对报告

PDF，随精装书交付。机构版只出统计与摘要，不出逐条明细。

### 结构

| 部分 | 内容 |
|------|------|
| 封面与项目信息 | 项目名、讲述者姓名、成稿版本、核对时间范围、参与人员（访谈师、编辑、确认人） |
| 核对说明 | 固定文案：核对范围、方法、局限性声明（"本报告核查的是文本与所依据材料的一致性，不构成对历史事件的学术考证"） |
| 统计摘要 | 总条数，按类型、风险、处置分布，闭环率，遗留事项数 |

## 与智能体框架的集成

### 上游约束

防幻觉要从生成阶段开始：

1. **引用绑定生成。** 每个段落必须输出来源 ID，无来源段落由校验器拦截（P0-07）。
2. **禁止补全。** 生成规则明确"不得推断年份、姓名、机构全称、数字；不确定时使用模糊表述并标注"。
3. **原话优先。** 涉及具体细节时优先直接引用老人原话（带音频锚点）。
4. **双模型交叉。** 高风险章节用第二个模型只做矛盾检测，不重写，提高召回。需评估增加的算力成本；P1 实现。

### 智能体分工

| 智能体 | 职责 | 输入或工具 |
|--------|------|-----------|
| 陈述抽取 | 抽取与分类 | 章节文本、时间线、人物表 |
| 证据绑定 | 检索并绑定证据 | 转写检索、材料库、外部库 |
| 风险分级 | 规则加模型混合分级 | 规则引擎（R01 到 R10）优先 |
| 矛盾检测 | 找时间线冲突、人物关系冲突 | 时间线、全部陈述 |
| 修改建议 | 给出修正或软化文本 | 软化模板库 |
| 报告生成 | 生成报告和修改对照 | 报告模板 |

前四个智能体串行编排为 AAF 工作流；编辑裁决和家属确认是带人工节点的审批流。见 [智能体工作流 AAF 能力映射](./agent-workflow.md#aaf-能力映射)。

### 接口

在 [P0 数据与接口设计](./p0-data-api.md#接口清单) 的核对接口基础上，以本文为准：

```http
POST /api/v1/projects/{id}/facts/scan
{ "scope": "all", "chapter_ids": [], "cross_model": true }
→ 202 { "task_id": "fcscan_01" }
任务完成后返回 { "claims_found": 214, "high": 37 }

GET  /api/v1/projects/{id}/facts?risk=high&status=family_pending

POST /api/v1/facts/{claimId}/resolve
{ "disposition": "fixed", "after_text": "...", "evidence_ids": ["ev_88"], "reviewer_id": "u_207" }

POST /api/v1/facts/{claimId}/request-external
{ "note": "需查 1979 年单位名录" }

POST /api/v1/facts/{claimId}/family-ack
{ "result": "confirmed", "note": "...", "signature_id": "sig_19" }
-- result 取值：confirmed / modified / unsure / disputed

GET  /api/v1/projects/{id}/facts/report?format=pdf&edition=family
-- edition 取值：family（逐条明细）/ org（仅统计与摘要）
```

服务端校验：

- 高风险陈述在没有家属确认结果时，`resolve` 只能把状态推进到 `family_pending`，不能直接 `closed`。
- `verified` 或 `fixed` 必须附至少 1 条 medium 及以上强度的证据。
- 外部核实超过 2 轮时拒绝再次发起。

## 指标与评测

### 指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 幻觉率 | 家属签字版中每万字事实错误数 | 0 |
| 抽取召回率 | 金标准集中被抽出的比例 | 不低于 95% |
| 误报率 | 抽出项中无需核对的比例 | 不超过 25% |
| 高风险闭环率 | 高风险项达到 closed 的比例 | 100% |
| 核对工时 | 编辑核对小时数 / 万字 | 不超过 1.4 小时 |
| 争议率 | family_disputed ÷ 进入 family_pending 的数量 | 不超过 8% |
| 软化比例 | softened ÷ 总陈述数 | 不超过 12%，过高说明上游生成过度断言 |

### 评测集

P0 必做：

- 标注 200 到 300 条真实脱敏片段，标注陈述边界、类型、风险和正确处置。
- 覆盖至少 3 种方言口音、1950 到 1990 年代至少 4 个年代，包含争议、评价、敏感样本。
- 每次模型或提示词变更都跑回归，指标下降则阻止发布。
- 编辑标为 `rejected` 的误报回流评测集。

### 抽检

- 低风险自动通过项抽检 10%；中风险项抽 20% 送家属确认。
- 每个项目由非本项目质检员做 1 次终审抽检，不少于 30 条，打分计入绩效。

## 工时预算

3 万字项目：

| 环节 | 工时 | 执行人 |
|------|------|-------|
| 机器预筛 | 0.2 小时 | 自动 |
| 编辑核对（高风险约 35 条，中风险约 60 条） | 4 小时 | 编辑 |
| 补采沟通 | 1 小时 | 访谈师 |
| 家属确认引导 | 1 小时 | 顾问或编辑 |
| 报告生成与签署 | 0.5 小时 | 编辑 |
| 合计 | 约 6.7 小时 | — |

原稿目标为"不超过 6 小时"，但明细合计 6.7 小时，此处以明细为准。

在北极星指标"单项目编辑有效工时不超过 15 小时"中，核对占约 6.7 小时，留给转写抽审、结构化和成稿的只有约 8 小时。建议预算分配：

| 层 | 工时 |
|----|------|
| L3 转写抽审 | 1.5 小时 |
| L4 结构化与时间线 | 1.5 小时 |
| L5 成稿 | 5 小时 |
| L6 核对 | 6.7 小时 |
| 合计 | 约 14.7 小时 |

L5 成稿 5 小时要求初稿改动比例控制在 35% 以内，这是预算最紧的一环。

## 自助模式

自助版（见 [产品定位 自助版](../../prd/memoir/产品定位.md#自助版)）没有编辑和家属核对环节，用"本人确认事实卡片"加"受约束润色"替代三级核对。它复用本模块的陈述抽取和风险规则，但不出《事实核对报告》。

### 流程

```text
对话访谈 → 转写 → 抽取事实卡片 → 本人确认或修改 → 风险分级
  ├─ 低、中风险且已确认 → 可用于润色和生成文字
  └─ 命中 R02、R03、R04、R09、R10 → 不润色、不生成旁白，默认不进入成片
→ 生成短片或电子小传 → 本人或子女完整预览 → 生成正式文件
```

### 规则

| 规则 | 说明 |
|------|------|
| 事实卡片 | 按本文"陈述抽取"规则抽取时间、地点、人物、机构、事件、数量；以大字卡片加语音朗读展示，选项为"对""要改""删掉" |
| 可用素材 | 只有本人确认过的卡片和原话可以用于润色；未确认的卡片不进入任何生成文字 |
| 润色范围 | 章节标题、串场字幕、简短旁白、电子小传；语序调整、口语转书面、去重复、方言转普通话字幕；原话对照保留 |
| 禁止 | 新增年份、人名、机构全称、数字、评价；补全老人没说过的经历 |
| 模糊表述 | 命中 R01 时使用软化模板，如"大约 1978 年前后" |
| 高风险 | 命中 R02、R03、R04、R09、R10 时不润色、不生成旁白，默认不进入成片；用户可选择保留原声片段并收到提示 |
| 校验 | 生成后对每句文字做一次反向溯源，找不到对应卡片或原话的句子删除 |
| 标识 | "AI 整理、内容经本人确认、未经人工事实核对" |

### 升级到标准故事书

自助版的事实卡片和素材可直接带入标准流程。本人确认过的卡片在证据模型中按 medium 强度处理：低、中风险项可直接作为依据；高风险项仍需编辑裁决和家属确认。
## 合规边界

以下规则同时写入产品和合同，与 [伦理与合规](../../prd/memoir/伦理合规.md) 一致：

| 方面 | 规则 |
|------|------|
| AI 标识 | 成书和对外材料中显著说明"部分环节由 AI 辅助整理，事实经人工核对" |
| 政治与历史争议 | 保留个人经历视角，不做宏观定性；命中 R04 时由资深编辑终审 |
| 医疗 | 命中 R09 时删除诊断、疗效表述，或改为生活化叙述；回顾服务材料不出现疗效结论 |
| 第三方与逝者 | 在世第三方负面评价默认软化；逝者描述避免未经家属认可的过错性判断 |
| 隐私最小化 | 他人住址、病历、纠纷细节默认删除或概括化（R10） |
| 版权 | 家属提供的照片、书信入库前确认授权范围；报告中不展示未授权材料原文 |

## 排期

对应 [P0 研发任务卡](../../prd/memoir/一期任务.md#epic-05-事实核对) 的 EPIC-05。抽取器和自助规则在一期先上线，服务事实卡片和受约束润色；人工核对链在二期，排期以 [后续需求规格 里程碑](../../prd/memoir/后续需求规格.md#里程碑) 为准：

| W7（二期） | 证据绑定、编辑核对台、家属确认页、争议处理；核对金标准集交付 200 条 | T-502、T-505、T-506、T-507、T-010 |
