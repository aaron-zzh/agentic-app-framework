# 学习反哺功能设计

> Agent 执行结果异步反哺认知基础，形成系统越用越强的闭环。

## 定位

学习反哺是横切通道，连接 Agent 执行层和 Cognition 认知层。从执行结果中提取经验，更新记忆/知识/技能/价值观，使系统从成功和失败中持续学习。

## 核心能力

- **轨迹采集**：记录 Agent 完整执行链路（输入/规划/工具调用/输出/耗时）
- **效果评估**：结果质量评分（自动验证 + 用户反馈 + 对比基线）
- **程序化蒸馏**：从成功模式中提取可复用经验，从失败中提取教训
- **知识生长**：评估通过的结果写入知识库，形成领域知识积累
- **技能生成**：高频成功模式自动生成新 SkillDefinition
- **价值观更新建议**：提出规则调整建议（必须人工审核）

## 学习流程

```text
Agent 执行完成
    ↓
轨迹采集（TrajectoryCollector）
    ↓ 记录完整执行链路
效果评估（EffectEvaluator）
    ↓ 质量评分 + 用户反馈
    ├── 成功 → 程序化蒸馏（ProceduralDistiller）
    │         ↓ 提取成功模式
    │         ├── → 程序化记忆（"如何做"经验）
    │         ├── → 知识生长（KnowledgeGrowthService）
    │         └── → 技能生成（高频模式 → 新 Skill）
    │
    └── 失败 → 失败教训提取
              ↓ 分析失败原因
              ├── → 程序化记忆（"不要做"经验）
              └── → 价值观更新建议（ValueUpdateProposer，需人工审核）
```

## 产出分流

按 assistantId 和全局两个维度分流：

| 产出 | 归属 | 说明 |
|------|------|------|
| 程序化记忆 | 用户私有 | 该用户的操作经验 |
| 知识生长 | 全局共享 | 经评估的领域知识 |
| 技能生成 | 全局共享 | 可被所有 Assistant 使用 |
| 价值观建议 | 全局 + 人工审核 | 不自动生效 |

## 触发时机

- Agent 执行完成后异步触发（不阻塞主链路）
- 用户显式反馈时触发（点赞/点踩/修正）
- 内置"自学习技能"定期触发（批量回顾近期轨迹）

## 与异步审查的关系

- 审查通过 → 结果进入学习管道（成功案例）
- 审查拒绝 → 结果进入学习管道（失败教训）
- 两种结果都有学习价值
