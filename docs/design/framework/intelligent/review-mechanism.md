# AI 产出异步审查

> 助理产出后不阻塞，人类异步审查反馈。高风险项自动提醒。

## 问题背景

AI 助理有两类产出需要人类审查：

| 来源 | 产出类型 | 示例 |
|------|---------|------|
| Auto-Dev 智能开发 | 源码 + 文档 | 生成的 Java 类、API 接口、设计文档 |
| 智能助理任务 | 业务实体变更 + 文档 | 创建/修改记录、生成报告、知识库更新 |

当前问题：
- 产出散落在对话消息、文件系统、数据库中，无统一入口
- 无风险分级，高风险操作（删除、权限变更）和低风险（加日志）混在一起
- 无快速反馈通道，审查结果无法回传给助理学习

## 设计原则

- **异步不阻塞**：助理产出后继续执行下一个任务，不等待审查
- **统一审查队列**：所有 AI 产出汇聚到一个审查收件箱
- **风险分级提醒**：高风险自动标红 + 推送通知，低风险批量审查
- **快速反馈**：一键 approve/reject/comment，结果回传助理学习
- **可追溯**：每个产出关联来源任务、执行实例、事件日志

## 架构总览

```text
AI 产出来源：
  ├── Auto-Dev（代码生成/文档生成）
  ├── 任务执行（业务实体 CRUD）
  └── 助理对话（知识库更新/文件创建）
         ↓ 统一写入
┌─────────────────────────────────────────────────────────────────┐
│  ReviewItem（审查项）                                            │
│  来源 + 类型 + 风险等级 + 内容快照 + diff + 状态                 │
└──────────────────────────────┬──────────────────────────────────┘
         ↓ 前端展示
┌─────────────────────────────────────────────────────────────────┐
│  审查收件箱（前端）                                              │
│  ├── 风险分级标签（🔴高/🟡中/🟢低）                              │
│  ├── 内容预览（代码 diff / 实体变更 / 文档预览）                 │
│  ├── 一键操作（✅ 通过 / ❌ 驳回 / 💬 评论）                    │
│  └── 批量审查（低风险项批量通过）                                │
└──────────────────────────────┬──────────────────────────────────┘
         ↓ 反馈回传
┌─────────────────────────────────────────────────────────────────┐
│  学习反馈                                                        │
│  审查结果 → LearningFeedbackService → 更新 Agent 行为偏好        │
└─────────────────────────────────────────────────────────────────┘
```

## 数据模型

### ai_review_item（审查项）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |
| creator_id | BIGINT | 产出者（助理/Agent）关联的用户 ID |
| reviewer_id | BIGINT | 审查人 ID（可为 NULL，待认领） |
| source_type | VARCHAR(30) | 来源：autodev / task / chat |
| source_id | BIGINT | 来源 ID（任务 ID / 会话 ID） |
| execution_id | BIGINT | 关联执行实例（可选） |
| category | VARCHAR(30) | 类别：code / document / entity_change / config |
| risk_level | VARCHAR(10) | 风险：high / medium / low |
| title | VARCHAR(500) | 标题摘要 |
| description | TEXT | 描述（做了什么、为什么） |
| content_snapshot | JSONB | 内容快照（代码/diff/实体变更前后） |
| status | VARCHAR(20) | pending / approved / rejected / commented |
| feedback | TEXT | 审查反馈（驳回原因/评论） |
| reviewed_at | TIMESTAMP | 审查时间 |

### content_snapshot 结构

```json
// 代码类
{
  "type": "code_diff",
  "files": [
    {"path": "src/UserService.java", "diff": "...", "language": "java"},
    {"path": "src/UserController.java", "diff": "...", "language": "java"}
  ]
}

// 实体变更类
{
  "type": "entity_change",
  "entityType": "user",
  "entityId": 123,
  "operation": "UPDATE",
  "before": {"name": "旧值", "role": "user"},
  "after": {"name": "新值", "role": "admin"}
}

// 文档类
{
  "type": "document",
  "title": "用户模块设计文档",
  "format": "markdown",
  "content": "..."
}
```

## 风险分级规则

| 风险 | 条件 | 处理 |
|------|------|------|
| 🔴 高 | 删除操作 / 权限变更 / 配置修改 / 数据迁移 / ≥5 文件 | 立即推送通知，阻止自动生效 |
| 🟡 中 | 新增接口 / 修改业务逻辑 / 实体字段变更 | 标记待审查，24h 内审查 |
| 🟢 低 | 加日志 / 修 typo / 文档补充 / 只读查询 | 进入队列，可批量通过 |

风险判定时机：
- Auto-Dev：代码生成后，根据变更文件数、是否涉及权限/删除等关键词自动判定
- 任务执行：DurableTaskExecutor 完成后，根据操作类型判定
- 对话产出：工具调用结果中检测实体变更类型

## API 设计

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | /api/reviews | 审查收件箱（分页，支持按 status/risk_level/category 筛选） |
| GET | /api/reviews/{id} | 审查项详情（含完整 content_snapshot） |
| PATCH | /api/reviews/{id}/approve | 通过 |
| PATCH | /api/reviews/{id}/reject | 驳回（含 feedback） |
| PATCH | /api/reviews/{id}/comment | 评论（不改变状态） |
| POST | /api/reviews/batch-approve | 批量通过（低风险项） |
| GET | /api/reviews/stats | 统计（待审查数、各风险级别数） |

## 与现有架构整合

| 组件 | 整合方式 |
|------|---------|
| DurableTaskExecutor | 任务完成后自动创建 ReviewItem |
| Auto-Dev（KiroAgentController） | 代码生成后创建 ReviewItem（code_diff） |
| 工具调用（ToolCallDispatcher） | 实体变更类工具调用后创建 ReviewItem |
| LearningFeedbackService | 审查结果（approve/reject）回传学习 |
| 通知系统（NotificationWebSocket） | 高风险项立即推送 |
| 置信度门控 | <0.7 的决策自动标记为高风险审查项 |

## 与五层架构对齐

- **决策日志**（Cognition 层）：每次 AI 自主推进的决策记录，审查项是决策日志的"需人工确认"子集
- **可撤销渐进提交**：高风险产出先暂存（pending），审查通过后才生效
- **学习反馈**：审查结果反哺 Agent 行为偏好，减少未来同类问题

## 实现优先级

| 优先级 | 内容 |
|--------|------|
| P0 | ReviewItem 数据模型 + CRUD API + 审查收件箱前端页面 |
| P1 | DurableTaskExecutor 完成后自动创建审查项 |
| P1 | 风险自动判定 + 高风险通知推送 |
| P2 | 代码 diff 预览组件 |
| P2 | 审查结果回传学习 |
| P3 | 批量审查 + 审查统计仪表盘 |
