# 五层智能架构设计

> 顶层只放整体架构与横向机制，每层及跨层能力单元的模块设计放对应子目录。

**`bak/` 是 2026-08-23 结构重构前的历史归档，不构成任何合同。** 与本目录现行文档冲突时一律以现行文档为准；AI 与人类均不得据 `bak/` 内容判断当前实现约束。该目录不参与五度空间内容项计数，也不再维护。

## 收录边界

| 位置 | 收录内容 | 判定标准 |
|---|---|---|
| 顶层 | 跨层生效、不归属任何单层的机制 | 删掉任一层后该机制依然存在 → 顶层 |
| 层目录 | 单层的职责、领域模型与契约 | 状态与责任明确归属某一层 → 该层目录 |
| 跨层能力目录 | 定义在一层、被多层消费的能力单元 | 多层消费且有独立版本与授权模型 → 独立目录 |

`architecture.md` 定义**静态结构与责任**——分层职责、主流程有哪几步、功能模块清单；`runtime.md` 定义**动态契约**——一次运行如何进行、每步的模块与输入输出。两者边界不得互相越界。

`CHAT`、`EXECUTION`、`TEAM` 共用同一运行时：**任务式不是另一套运行时，只是受约束的执行策略**。因此不存在按交互模式划分的文档，模式差异统一在 `runtime.md` 的差异表中表达。

## 文档规格

本目录所有设计文档统一使用五段结构，单篇不超过 400 行：

| 段 | 内容 | 要求 |
|---|---|---|
| 定位与边界 | 是什么、不是什么 | 与 Front Matter 的 scope 一致 |
| 领域模型 | 实体、关系、不变量 | 用表格与代码块表达，不用散文 |
| 契约 | 接口签名、事件、状态机、字段 | 每条契约可被代码或测试对照 |
| 实现态 | 已实现 / 部分实现 / 目标态 | 见下方标记法 |
| 验收基线 | 可验证的判定句 | 每条能被一次检查证伪 |

### 实现态标记法

契约条目必须标注实现状态，禁止把目标态写成既有约束：

| 标记 | 含义 | 要求 |
|---|---|---|
| ✅ 已实现 | 代码中已生效 | 必须附 `文件:行号` |
| ⚠️ 部分实现 | 部分生效或存在偏离 | 必须附 `文件:行号` 与缺口说明 |
| 🎯 目标态 | 尚未落地 | 明确写“当前不得声称已执行” |

### 内容硬规则

- 上游已定义的概念只链接引用，不复述
- 原理与取舍论证移入 `docs/explanation/`，设计文档只留结论与契约
- 每个概念最多一个示例
- 章节标题不加数字编号
- 任何目录内容项不超过 5 个（`bak/` 与图片资源不计入）
