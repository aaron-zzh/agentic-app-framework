# Assistant 运行要点历史记录

> **不构成现行设计合同。** 以下保留早期总结的十项运行要点及其原始表述，用于追溯五层智能架构的设计演进；现行流程以[五层智能架构](../../architecture.md#统一智能任务运行流程)和[任务式 Assistant 统一执行路径设计](task-oriented-assistant-execution-design.md)为准。

助理访问入口（任务式+对话式），五层智能架构是一条可循环、可恢复的智能任务流水线，文案生成任务只是指定角色技能的一个具体应用场景：

1. 预处理: 输入参数处理，路由、授权与执行策略，当前支持哪些参数？（推理模型(指定+自动)，处理模式（自动、询问-重点动作执行前询问）） L3
2. 缓冲区，不阻塞输入，控制处理频率 L3
3. 前注意，理解规划，协调者Agent = Coordinator Agent，根据任务选择角色技能、分解任务、编排子智能体（单智能体单任务、单智能体多任务、多多并行串行）、目标澄清、输出 CoordinationPlan  L3
4. 混合检索：知识库+记忆，协调者Agent。 L1
5. 上下文管理（智能体系统提示词+Actor+角色技能工具+用户偏好+知识库+记忆）、提示词压缩，协调者仅读取摘要，子智能体仅可访问自己任务所需的上下文，渐进局部按需加载。 L1
6. 运行时 Harness Agent Loop：协调者智能体 + 执行智能体，两者都有自己的 ReAct Loop 任务管理。协调者负责整体 AgentLoop 大循环的任务及目标，执行者子智能体负责自己的。L2
  - 并行、串行、循环。 支持暂停、取消等过程控制。
  - Assistant 是我们的核心领域模型、Agent 是执行者 （基于 agentscope harness），分为协调者智能体 + 执行智能体，基础功能相同职责不同，都可以管理自己的ReAct任务循环
  - Agent 基础系统提示词，是否作为系统参数。（基本原则、理解澄清目的、查漏补缺（停止让用户输入、或给出选项让用户选择）、明确目标、任务拆分规划、循环执行、审核）
  - 正确调用技能工具、聚合、完成验证、终态或恢复
7. 人工干预 HITL: 重点动作执行前询问，授权，补全未知参数。终止、暂停、继续、重试... L2
8. 自学习：抽取知识、记忆、优化任务及编排（如何支持、应该要支持多版本）
9. 模型推理: 模型调用、工具调用、Prompt/消息处理、流式输出、结构化输出、Token用量统计
10. 事件消息：定义对话与非对话 AI 任务共享的规范事件、协议投影、重放和演进机制
各模块并非独立
