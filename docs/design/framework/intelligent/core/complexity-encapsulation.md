# 复杂性封装策略

> 复杂性默认隐藏，按需展开，不强制暴露。
> 展开深度由用户角色决定，查看权限和操作权限分离——任何角色都可以查看细节，但修改权限严格分级。

## 展开层次

默认态（所有用户）：
- 对话框 + 工作区
- 复杂性完全隐藏，只看到结果

展开态（所有用户可选查看，无需权限）：
- 查看 DSL 定义（只读）
- 查看执行计划和步骤日志（只读）
- 查看工作流 DSL（纯文本 / 可视化切换）
- 查看 AI 推理过程和工具调用记录（只读）
- 查看积分明细和结算记录（只读）

开发态（需要开发者权限）：
- 编辑业务 DSL
- 编写自定义逻辑片段（AI 生成 + 用户确认）
- 配置工作流节点
- 管理自定义工具和插件
- 查看和调试沙箱执行结果

框架维护态（需要框架维护者权限）：
- 修改引擎配置
- 调整路由规则和置信度阈值
- 管理系统级 DSL 规范
- 访问引擎内部状态和性能指标

## 权限分级

| 角色 | 查看 | 操作 |
|---|---|---|
| 普通用户 | 所有细节（只读） | 个人偏好、助理设置、自己的业务数据 |
| 开发者 | 同上 | 编辑业务 DSL、工作流、自定义工具和插件 |
| 框架维护者 | 同上 + 引擎内部状态 | 引擎配置、路由规则、系统级规范 |

核心原则：**查看不需要权限，修改需要权限，两者严格分离。**

普通用户查看 DSL / 工作流 / 推理过程，有助于理解和信任系统，不应设置查看门槛。

## 展开原则

- 对话框是默认态，DSL 查看是展开态，DSL 编辑是开发态
- 复杂性展开是渐进的，不强制一次暴露所有细节
- 每个展开层次独立，用户可以只展开感兴趣的部分

## 五度空间约束

元引擎作为核心模块，自身设计遵守五度空间原则：每个子模块设计及实现复杂度不超过 5，超出则强制递归分解为子模块。

```text
元引擎各模块当前复杂度：
  后端核心（5）：执行调度器 / 状态管理器 / 置信度门控器 / 文档引擎 / 元数据管理器
  前端核心（5）：DSL 解析器 / 组件渲染器 / 内容注入层 / 插件加载器 / 交互控制器
  引擎编排（5）：工作流 / 智能体 / 知识库 / 记忆 / 工具
  DSL 层  （2）：解析 / 校验
  自进化层（3）：采集 / 评估 / 重生成
```

后端引擎核心和引擎编排层均已达上限 5，不允许再添加新模块而不分解。
