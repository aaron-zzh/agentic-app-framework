# 置信度门控器

> 控制的本质不是开局握紧缰绳，而是拥有随时介入修正的能力。

## 二维门控模型

置信度门控采用**置信度 × 可验证性**二维模型，两个维度正交，共同决定执行策略：

```text
每个执行步骤携带两个评分：置信度 + 可验证性

置信度维度：
  > 0.9   → 自动执行，异步通知
  0.7–0.9 → 生成执行计划，等待用户确认
  < 0.7   → 暂停，说明原因，转人工处理

可验证性维度（与置信度正交）：
  可验证 + 高置信   → 自动执行 + 自动验证（系统闭环，最高效率）
  可验证 + 低置信   → 执行 + 自动验证 + 失败自动回滚（安全试错）
  不可验证 + 高置信 → 执行 + 决策日志 + 异步人工审查（信任但留审计）
  不可验证 + 低置信 → 暂停 + 转人工决策（最保守）
```

## 不可逆操作约束

无论置信度和可验证性评分如何，以下操作强制人工确认：

- 删除操作（文档、数据、配置）
- 发布操作（部署、上线、对外开放）
- 提交操作（代码提交、规范变更提交）
- 权限变更（角色分配、数据权限调整）

## 置信度来源

```text
置信度 = 意图理解置信度 × 规范匹配置信度 × 历史成功率
```

- 意图理解置信度：LLM 对输入意图的解析确定性
- 规范匹配置信度：DSL 与现有规范的一致性程度
- 历史成功率：同类任务的历史执行成功率

## 可验证性判定

输出是否有明确的正确性检查手段：

| 可验证 | 示例 |
|---|---|
| ✅ | 编译通过、单测通过、Schema 校验、规则匹配 |
| ❌ | 创意内容生成、架构决策、用户体验判断 |

## 防退化约束

- **人类未响应不自动超时执行**：进入等待态后保持等待，不因超时降级为自动执行
- **不允许静默降低标准**：置信度不足时只能上报，不能自行降低阈值绕过门控
- **主导权切换必须记录日志**：每次切换写入审计日志，支持事后复查

## 异步审查机制

高置信度操作不等待人类确认，先执行并暂存结果，异步通知人类审查。核心思想：**不阻塞 AI 执行效率，但保留人类纠错窗口。**

### 运作机制

```text
置信度 > 0.9 + 可验证   → 自动执行 + 自动验证 + 结果暂存 → 异步通知人类
置信度 > 0.9 + 不可验证 → 执行 + 决策日志 + 异步人工审查
人类审查通过            → 结果从会话状态提升到持久状态（渐进提交）
人类审查拒绝            → 结果回滚，记录到学习反哺通道（失败教训）
审查超时                → 结果保持暂存态，不自动提升（防退化）
```

### 与其他机制的关系

| 机制 | 在异步审查中的角色 |
|------|-------------------|
| 置信度门控 | 决定"是否需要审查" |
| 渐进提交 | 决定"审查通过后结果去哪" |
| 防退化约束 | 保障"审查超时不自动通过" |
| 学习反哺 | 从"审查拒绝"中提取失败教训 |
| 监控引擎 | 记录完整审查链路（谁执行/谁审查/何时/结果） |

### 适用场景

| 场景 | 执行 | 审查 |
|------|------|------|
| Agent 自动生成代码 | 暂存到工作区 | 异步 code review |
| Agent 自动回复用户 | 暂存待发送 | 异步质量抽检 |
| 工作流自动审批 | 暂存审批结果 | 异步合规审查 |
| 知识库自动入库 | 暂存入库内容 | 异步准确性校验 |

## 动态决策权——场景示例

决策权不固定归属某层，而是跟着置信度在人/AI/系统间实时流动：

```text
Agent 执行任务，置信度 0.95
  → Agent 自己决定，直接执行

同一任务遇到模糊情况，置信度降到 0.75
  → 决策权上移到 Assistant，展示计划等用户确认

用户确认后，置信度恢复
  → 决策权回到 Agent 继续执行

置信度跌到 0.5
  → 决策权再上移到人类，完全转人工
```

"动态"的本质：

- 不是预先分配"这类任务归 AI 做、那类归人做"
- 而是同一个任务执行过程中，决策权随置信度实时变化
- 高置信 → AI 自主；低置信 → 自动上报；恢复后 → 自动回收

在组件中的体现：

| 组件 | 职责 |
|------|------|
| 置信度门控器 `core/confidence` | 判断当前置信度，决定执行/确认/转人工 |
| Agent 执行 `agent` | 每步评估置信度，不够就上报 |
| 助手执行 `assistant` | 意图澄清后提升置信度，或转人工 |

区别于传统系统"管理员审批"的固定流程——决策权是动态的、可回收的、跟着置信度走的。

```text
core/gate/
├── ConfidenceGate.java             核心接口
├── ConfidenceScore.java            置信度评分（意图×规范×历史）

    └── DefaultConfidenceGate.java
```
