# 组件粒度确认稿（终版）

> 每个组件 = 一个功能设计文档 + 一个技术方案文档。

**核心特色：**

- 动态决策权：决策权随置信度在人/AI/系统间实时流动，不固定归属
- 防退化保障：系统在无人响应/异常场景下不允许自动降低安全标准
- Agentic RAG：认知层写入/检索时用 LLM 级能力增强
- 异步审查：高置信操作先执行暂存，异步通知人类审查，不阻塞执行链路
- 用户感知横切：画像/记忆/情感跨层协同，被动响应式个性化
- 记忆与知识分离：记忆是用户私有交互经历（自动），知识是全局共享领域知识（人工）
- 渐进决策：置信度×可验证性二维门控，决策权在人/AI/系统间动态流动
- 元引擎编排：DSL 调度 + 四层状态渐进提交 + 26 个专项引擎协同
- 复杂性封装：默认隐藏，四层按需展开，五度空间约束递归分解
- 内置技能：自我认知 / 用户理解 / 自学习 / 技能创建，助手开箱即用
- DSL 驱动：三重身份（规范/生成目标/执行程序），分层分域，贯穿开发时和运行时
- 自进化：行为→评估→规范更新→代码重生成→沙箱验证→热部署，系统越用越强

## 用户感知

用户感知与个性化确实是横切面——它的数据来源跨多层：

- 交互层：用户界面输入、UI 操作行为、设备/端信息
- Assistant 层：会话上下文、情感状态、意图历史
- Cognition 层：用户画像、长期记忆、情感记忆、偏好
- 引擎层：行为日志（监控引擎）、使用统计

而它的消费方也跨多层：

- Assistant：注入 System Prompt、调整回应风格
- Agent：上下文优先级组装（P0-P5）
- 语义组件引擎：界面个性化适配

我的建议：放 Cognition 层，作为独立组件。

理由：

1. 它的核心是"理解用户是谁"——这是认知能力，不是编排能力
2. 数据存储和计算主体在 Cognition（画像存储、记忆检索、偏好提炼）
3. 它是被动的——被 Assistant/Agent 调用时提供用户上下文，不主动触发
4. 与 Cognition 的记忆服务、学习反哺天然协作（学习反哺产出→更新画像）

Assistant 层只是"消费"个性化结果（读取画像→注入 Prompt），不负责"生产"。交互层的 UI 操作行为通过事件驱动写入
Cognition，不需要个性化组件直接感知交互层。

### 动态决策权

动态决策权指的是：谁来做决定不是固定的，而是根据置信度在人/AI/系统之间实时流动。举例：

- Agent 执行一个任务，置信度 0.95 → Agent 自己决定，直接执行
- 同一个 Agent 遇到模糊情况，置信度降到 0.75 → 决策权上移到 Assistant，展示计划等用户确认
- 用户确认后，置信度恢复，决策权回到 Agent 继续执行
- 如果置信度跌到 0.5 → 决策权再上移到人类，完全转人工

"动态"体现在：

- 不是预先分配"这类任务归 AI 做、那类归人做"
- 而是同一个任务执行过程中，决策权随置信度实时变化
- 高置信 → AI 自主；低置信 → 自动上报；恢复后 → 自动回收

在组件中的体现：

- 置信度门控器 meta/confidence：判断当前置信度，决定执行/确认/转人工
- Agent 执行 agent：每步评估置信度，不够就上报
- 助手执行 assistant：意图澄清后提升置信度，或转人工

本质是：决策权不固定归属某层，而是跟着置信度在层间流动。这区别于传统系统"管理员审批"的固定流程。

## 状态与上下文

- 状态（State）：系统运行时的"当前情况"——正在做什么、做到哪了、暂存了什么结果，可变的、会被修改的运行时数据（任务进度、暂存结果、在线用户列表）
- 上下文（Context）：请求级的只读组装物，用完即弃（当前消息 + 从记忆/知识检索到的片段 → 拼成 Prompt 送给 LLM）
  - 记忆：用户的"个人经历"——过去发生了什么、学到了什么、偏好是什么
  - 知识库：全局的"领域知识"——事实、规范、文档

Checkpoint（断点续跑）：

- 是会话状态的快照——Agent 执行到某一步时，把当前工作记忆、已完成步骤、中间结果序列化保存
- 恢复时从快照重建会话状态，继续执行
- 关系：Checkpoint ⊂ 会话状态管理，是状态的"存档点"

审计（Audit）：

- 是决策日志——每次状态变更、决策权切换、工具调用都记录不可删除的日志
- 存储在记忆引擎的"决策审计区"（PostgreSQL，管理员可审计）
- 关系：审计从状态变更事件中产生，但审计日志本身是持久记忆（不是状态）

整体关系：

  Agent 执行中
    ├── 状态变更 → 触发审计日志写入（记忆引擎/决策审计区）
    ├── 到达检查点 → 快照当前状态（Checkpoint，可恢复）
    ├── 执行失败 → 从最近 Checkpoint 恢复状态 → 继续执行
    └── 执行完成 → 状态销毁，审计日志永久保留

状态 = 可变、可恢复、会销毁
审计 = 不可变、不可删、永久保留
Checkpoint = 状态的某个时刻快照，用于错误恢复

简单说：状态是"现在"，Checkpoint 是"存档"，审计是"历史记录"。 三者生命周期完全不同。

## 异步审查

高置信度操作不等待人类确认，先执行并暂存结果，异步通知人类审查。核心思想：**不阻塞 AI 执行效率，但保留人类纠错窗口。**

运作机制：

- 置信度 > 0.9 + 可验证 → 自动执行 + 自动验证 + 结果暂存 → 异步通知人类
- 置信度 > 0.9 + 不可验证 → 执行 + 决策日志 + 异步人工审查
- 人类审查通过 → 结果从会话状态提升到持久状态（渐进提交）
- 人类审查拒绝 → 结果回滚，记录到学习反哺通道（失败教训）
- 审查超时 → 结果保持暂存态，不自动提升（防退化）

与其他机制的关系：

- 置信度门控决定"是否需要审查"
- 渐进提交决定"审查通过后结果去哪"
- 防退化保障"审查超时不自动通过"
- 学习反哺从"审查拒绝"中提取失败教训
- 监控引擎记录完整审查链路（谁执行/谁审查/何时/结果）

适用场景：

- Agent 自动生成代码 → 暂存 → 异步 code review
- Agent 自动回复用户 → 暂存 → 异步质量抽检
- 工作流自动审批 → 暂存 → 异步合规审查
- 知识库自动入库 → 暂存 → 异步准确性校验

## 认知模型映射

> 参考 `intelligent/agent.jpg`（人类认知心理学模型），AAF 五层智能架构的设计灵感来源。

- 刺激输入 → 交互层（安全网关 + 协议适配）
- 短时感觉存储（前注意） → 助手执行 `assistant` 前注意分流（规则+小模型快速判断，<50ms 完成分流决策）
  - 前注意分流（协调者 AI，快速模型 <50ms）：
  - 规则匹配：关键词/正则快速识别已知意图
  - 轻量分类：小模型意图分类 + 情感极性 + 语言检测
  - 缓存命中：语义相似度匹配历史问答，命中直接返回
  - 分流决策：直接响应 / 路径 A 简单 LLM / 完整 Agent 流程
- 感知 → 助手执行 `assistant`（意图理解 + 情感感知）
- 注意力资源 → Assistant 管辖的整体算力资源池（Agent 池并发数 + Token 总预算 + 任务优先级分配）
- 识别 → 混合检索 `cognition/retrieval`（从记忆/知识中匹配相关信息）
- 工作记忆（有限容量 3-7 项） → WorkingMemory + 上下文 P0-P5 优先级（Token 窗口有限）
- 长期记忆（无限容量） → 记忆引擎 `memory` + 知识库引擎 `knowledge`
- 决策与响应选择 → 助手执行 `assistant`（协调者：路径决策 + Agent 选择 + 资源分配），置信度门控为约束条件
- 响应执行 → Agent 执行（工具调用 + LLM 推理）+ 工具引擎 `tool`
- 响应 → AG-UI 协议 `agui`（SSE 流式输出）
- 反馈 → 学习反哺 `cognition/learning`（执行结果反哺更新记忆/知识）
- 眼动（注意力调控） → 助手执行 `assistant`（选择 MemoryStrategy，决定关注哪些记忆/知识来源）
