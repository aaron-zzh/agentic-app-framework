# 安全架构设计（Security Architecture）

> 认证与授权见 [访问控制设计](access-control.md)，本文档聚焦安全横切关注点。

## 安全体系概览

```
认证（access-control.md #认证）     → 你是谁？身份验证
      ↓
授权（access-control.md #授权）     → 你能做什么？权限控制
      ↓
安全（本文档）                      → 如何保护整个系统？加密、脱敏、审计、防护
```

- **认证是授权的前置条件**：必须先确认身份，才能判断权限
- **安全是贯穿全栈的横切关注点**：包含但不限于认证和授权，覆盖传输、存储、AI、部署等全链路

## 1. 安全分层模型

```
┌─────────────────────────────────────────┐
│  传输层安全（TLS）                       │
├─────────────────────────────────────────┤
│  应用层安全（认证 / 授权 / 输入校验）    │  → access-control.md
├─────────────────────────────────────────┤
│  数据层安全（加密 / 脱敏 / 审计）        │  → 本文档
├─────────────────────────────────────────┤
│  AI 安全（Agent / LLM / 沙箱）          │  → 本文档
├─────────────────────────────────────────┤
│  基础设施安全（网络隔离 / 密钥管理）     │
└─────────────────────────────────────────┘
```

## 2. 加密策略

### 2.1 传输层

- 所有接口强制 HTTPS（TLS 1.3）
- 内部服务间通信：服务网格 mTLS（生产环境）

### 2.2 存储层加密

| 数据类型 | 加密方式 | 实现 |
|----------|----------|------|
| 普通业务数据 | 传输加密 | TLS |
| 用户隐私（邮箱、手机） | 列加密 | JPA AttributeConverter |
| 密钥、凭证、Token | KMS 托管 | 云厂商 KMS / Vault |
| 知识库敏感内容 | 列加密 + 二次鉴权 | 同上 |

**选型理由：**

- JPA AttributeConverter：应用层加密，数据库无关，便于迁移
- 云厂商 KMS：密钥托管安全，支持自动轮换，合规性好

### 2.3 密钥管理

| 环境 | 方案 |
|------|------|
| 开发/测试 | 环境变量 / 配置文件 |
| 生产 | 云厂商 KMS（AWS KMS / 阿里云 KMS） |
| 私有化部署 | HashiCorp Vault |

密钥轮换策略：
- 数据密钥：90 天自动轮换
- 主密钥：年度轮换，人工确认

## 3. 数据分级

| 级别 | 数据类型 | 保护措施 |
|------|----------|----------|
| L1 公开 | 公开文档、系统配置 | 传输加密 |
| L2 内部 | 业务数据、用户内容 | 传输加密 + 访问控制 |
| L3 敏感 | 用户隐私（邮箱、手机） | 列加密 + 脱敏展示 |
| L4 机密 | 密钥、凭证、财务数据 | KMS + 二次鉴权 + 审计 |

### 3.1 隐私数据分片存储

> 敏感数据拆分存储到不同位置，单一存储泄露无法还原完整信息。

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 字段分离 | 敏感字段与业务数据分库存储 | 用户隐私（手机、身份证） |
| 密钥分离 | 加密数据与密钥分离存储 | 所有加密数据 |
| 分片存储 | 数据拆分为多片，分布式存储 | L4 机密数据 |
| 关系分离 | 实体存 PostgreSQL，关系存 Neo4j | 权限、社交关系 |
| 本地+云端 | 敏感部分本地存储，非敏感云端 | 企业私有化部署 |

**典型实现——用户隐私分离存储：**

```
PostgreSQL 主库：user_id, name, avatar, created_at
PostgreSQL 隐私库：user_id, phone_encrypted, id_card_encrypted
Neo4j 关系库：(User)-[:BELONGS_TO]->(Org), (User)-[:FRIEND]->(User)
KMS：加密密钥（独立服务）

攻击者获取主库 → 无敏感数据
攻击者获取隐私库 → 加密数据，无密钥
攻击者获取 Neo4j → 只有关系，无实体属性
攻击者获取 KMS → 无数据
```

**结合 Neo4j 的安全优势：**

| 优势 | 说明 |
|------|------|
| 关系与属性分离 | 实体属性存 PostgreSQL，关系拓扑存 Neo4j，两者泄露均不完整 |
| 权限路径不含数据 | Neo4j 只存 `user:123 -[VIEWER]-> doc:456`，不含文档内容 |
| 遍历不暴露全量 | 图查询按需遍历，不像 SQL 全表扫描 |
| 细粒度访问控制 | Neo4j 支持属性级权限，敏感属性可单独加密 |

**分布式分片（L4 机密）：**

```
原始数据
    ↓
Shamir 秘密共享算法
    ↓
拆分为 N 片（如 5 片）
    ↓
分布存储到 N 个节点
    ├─ PostgreSQL 节点 1：片段 A
    ├─ PostgreSQL 节点 2：片段 B
    ├─ Neo4j：片段 C（关系型片段）
    ├─ Redis：片段 D（临时）
    └─ 本地存储：片段 E
    ↓
还原需要 M 片（如 3 片），单节点泄露无意义
```

**存储分工总结：**

| 存储 | 存储内容 | 安全特性 |
|------|----------|----------|
| PostgreSQL 主库 | 业务数据、非敏感属性 | 标准访问控制 |
| PostgreSQL 隐私库 | 加密的敏感字段 | 列加密 + 独立实例 |
| Neo4j | 关系拓扑、权限路径 | 无实体属性，泄露无意义 |
| Redis | 会话、临时权限 | 短 TTL，自动过期 |
| KMS | 加密密钥 | 硬件隔离，审计日志 |

## 4. AI 数据安全

### 4.1 脱敏引擎

发送至云端 LLM 前的脱敏流程：

```
原始数据
    ↓
敏感字段识别（规则 + NER 模型）
    ↓
替换为占位符（保留格式）
    ↓
发送至云端 LLM
    ↓
响应中占位符还原
    ↓
结果数据
```

**脱敏规则：**

| 类型 | 识别方式 | 脱敏方式 |
|------|----------|----------|
| 手机号 | 正则 | `138****1234` |
| 身份证 | 正则 | `110***********1234` |
| 银行卡 | 正则 | `6222***********1234` |
| 姓名 | NER | `张**` |
| 地址 | NER | `[地址已脱敏]` |

### 4.2 本地与云端分流

| 数据敏感度 | 处理方式 |
|------------|----------|
| L1-L2 | 可发送云端 LLM |
| L3 | 脱敏后发送云端 |
| L4 | 仅本地模型处理 |

企业版支持：
- 本地 OCR 预处理
- 本地小模型处理敏感数据
- 私有化 LLM 部署

### 4.3 Prompt 注入防护

| 防护层 | 措施 |
|--------|------|
| 输入层 | 用户输入与系统提示词隔离 |
| 处理层 | 关键词过滤 + 模式检测 |
| 输出层 | 异常响应检测 |
| 执行层 | 敏感操作二次确认 |

### 4.4 多模型分片策略

> 将敏感业务拆分到多个模型处理，防止单一模型还原完整业务上下文。

| 策略 | 说明 |
|------|------|
| 数据分片 | 敏感字段拆分到不同模型处理，结果在本地聚合 |
| 模型轮换 | 同类任务随机分配到不同模型，降低单模型数据积累 |
| 上下文隔离 | 不同业务域使用独立会话，禁止跨域上下文共享 |

**典型场景：**

- 财务数据：金额、账户、交易分别由不同模型处理
- 用户画像：基础信息、行为数据、偏好分析分片处理
- 合同审查：条款提取、风险识别、建议生成分模型执行

**实现要点：**

```
原始任务
    ↓
任务分解（识别敏感字段）
    ↓
分片路由（按敏感度分配模型）
    ├─ 模型 A：处理非敏感上下文
    ├─ 模型 B：处理脱敏后的敏感字段
    └─ 本地模型：处理 L4 机密数据
    ↓
本地聚合（结果合并，还原完整响应）
    ↓
返回用户
```

## 5. Agent 安全

### 5.1 权限约束

详见 [访问控制设计 - Agent 权限](access-control.md#51-权限主体who)。

核心原则：
- Agent 权限 ≤ 触发用户权限
- 工具调用受白名单约束
- 高风险操作受置信度门控

### 5.2 沙箱隔离

Agent 执行不可信代码时的隔离方案：

| 方案 | 适用场景 | 隔离级别 |
|------|----------|----------|
| GraalVM Polyglot Sandbox | JS/Python 脚本 | 进程内隔离 |
| Docker 容器 | 复杂任务 | 进程隔离 |
| 子进程 + 超时 | 简单脚本（降级） | 进程隔离 |

**沙箱约束：**

- 禁止文件系统访问（白名单除外）
- 禁止网络访问（白名单除外）
- 禁止创建线程
- 执行时间限制
- 内存限制

### 5.3 工具安全

| 约束 | 说明 |
|------|------|
| 白名单 | Agent 只能调用配置的工具 |
| 参数校验 | 工具输入必须符合 Schema |
| 结果审计 | 工具调用结果记录日志 |
| 幂等设计 | 重试不产生副作用 |

## 6. 审计

### 6.1 审计范围

| 审计项 | 记录内容 | 保留期限 |
|--------|----------|----------|
| 登录登出 | 时间、IP、设备、结果 | 180 天 |
| 权限变更 | 变更前后、操作人 | 永久 |
| 敏感操作 | 操作类型、对象、结果 | 365 天 |
| 运营操作 | 操作人、目标、详情 | 永久 |
| LLM 调用 | 模型、Token、耗时 | 90 天 |
| Agent 执行 | 任务、工具调用、结果 | 90 天 |

### 6.2 审计日志存储

```sql
-- 通用审计日志表
CREATE TABLE audit_log (
    id BIGSERIAL PRIMARY KEY,
    category VARCHAR(50) NOT NULL,      -- auth/permission/ops/llm/agent
    action VARCHAR(100) NOT NULL,
    subject_type VARCHAR(50),           -- user/agent/system
    subject_id VARCHAR(100),
    target_type VARCHAR(50),
    target_id VARCHAR(100),
    detail JSONB,
    result VARCHAR(20),                 -- success/failure/pending
    ip VARCHAR(50),
    user_agent TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_audit_category ON audit_log(category, created_at);
CREATE INDEX idx_audit_subject ON audit_log(subject_id, created_at);
```

### 6.3 审计查询

支持运营后台查询：
- 按时间范围
- 按操作类型
- 按操作人
- 按目标对象

## 7. 输入防护

### 7.1 常规注入防护

| 类型 | 防护措施 | 实现 |
|------|----------|------|
| SQL 注入 | 参数化查询 | JPA 默认 |
| XSS | 输出编码 + CSP | Spring Security |
| CSRF | Token 校验 | Spring Security |
| 路径遍历 | 路径规范化 | 白名单校验 |

### 7.2 API 安全

| 措施 | 说明 |
|------|------|
| 限流 | 按用户/IP 限制请求频率 |
| 签名 | 外部 API 调用签名校验 |
| 版本控制 | API 版本管理，废弃通知 |

## 8. 部署安全

### 8.1 网络隔离

```
┌─────────────────────────────────────────┐
│  公网                                    │
│  └─ 负载均衡 / WAF                       │
├─────────────────────────────────────────┤
│  DMZ                                     │
│  └─ API Gateway / Web Server            │
├─────────────────────────────────────────┤
│  内网                                    │
│  └─ 应用服务 / 数据库 / 缓存             │
└─────────────────────────────────────────┘
```

### 8.2 密钥管理

- 禁止硬编码密钥
- 生产环境使用 KMS / Vault
- 密钥与代码分离
- 定期轮换

### 8.3 镜像安全

- 使用官方基础镜像
- 定期漏洞扫描
- 最小权限原则
- 镜像签名验证

## 元引擎安全执行链路

元引擎执行链路受三层原则约束，从外到内依次收紧：

```text
用户请求
  ↓ [输入净化 + 注入检测]           ← 系统级原则（不可变）
元引擎 DSL 解析与调度
  ├→ [工具白名单校验] → 沙箱执行    ← 系统级原则
  ├→ [记忆隔离查询]  → 用户私有记忆  ← 系统级原则
  ├→ [知识分级访问]  → 加密知识库    ← 系统级原则
  └→ [模型配额校验]  → LLM 调用     ← 助理级原则（可定制）
  ↓ [输出内容审查 + 溯源标注]        ← 系统级原则
返回对话层
```
