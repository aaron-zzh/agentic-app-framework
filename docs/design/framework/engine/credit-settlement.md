# 积分与结算引擎设计

> 积分引擎管虚拟货币体系（内部流转），结算引擎管真实资金跨界（对接支付）。两者共享账户模型，分工明确。

## 分工边界

```text
积分引擎（内部）                    结算引擎（外部）
─────────────────────────────────────────────────────
虚拟积分的赚与花                    真实资金的进与出
不涉及真实资金                      对接支付接口
规则由 DSL 定义                     流程由工作流引擎驱动
实时记账                            异步结算 + 对账
```

## 积分引擎

### 积分来源与业务开关

每种来源可独立启用/禁用，规则通过 DSL 配置，运行时热生效：

| 来源类型 | 场景 | 规则配置 |
|---------|------|---------|
| 知识/计算/协作贡献 | 知识标注、众包任务、算力贡献 | 贡献类型 + 质量评分权重 |
| 生态贡献 | 上传 Agent / 工具 / 知识库 / 提示词 | 使用次数 + 评分系数 |
| 游戏化 | 打卡签到、每日挑战、排行榜奖励 | 周期 + 上限 + 防刷规则（具体实现待定） |
| 社交裂变 | 邀请新用户、内容被引用/收藏 | 分成比例 + 层级上限 |
| 订单消费返积分 | 商品/服务订单完成后返还 | 返积分比例 + 品类规则 |
| 充值兑换 | 用户付费充值 → 积分额度 | 充值金额 → 积分汇率 |

### 积分消费

| 消费类型 | 场景 |
|---------|------|
| API 调用 | LLM / Agent / 工具调用按量扣减 |
| 功能解锁 | 高级功能、优先队列、更大存储配额 |
| 市场购买 | 购买他人发布的 Agent / 工具 / 知识库 |
| 治理投票 | 社区决策权重（积分质押） |
| 提现申请 | 积分 → 现金，触发结算引擎 |

### 积分质量评估

- AI 自动评估贡献质量（准确性、完整性、一致性）
- 高质量贡献进入知识库，低质量退回重做
- 多人交叉验证，防止刷分
- 异常行为触发风控冻结

### 账户模型

```text
CreditAccount
  ├── userId
  ├── balance          当前可用积分
  ├── frozen           冻结中（提现申请 / 争议中）
  ├── totalEarned      累计获得
  ├── totalSpent       累计消费
  └── transactions[]   流水记录（来源类型 / 金额 / 时间 / 关联业务 ID）
```

### 积分规则

- 规则以 DSL 定义，存储在规则库
- 规则变更需社区投票确认，不允许单方面修改
- 所有积分记录链上存储，不可篡改
- 社区排行榜、等级勋章基于积分账户实时计算

## 结算引擎

### 支付接口

| 场景 | 支付渠道 |
|------|---------|
| 用户充值（国内） | 微信支付 / 支付宝 |
| 用户充值（国际） | Stripe |
| 贡献者提现 | 银行转账 / 微信零钱 |
| 开发者分成 | 周期批量结算 |

### 结算业务场景

| 场景 | 触发条件 | 流程 |
|------|---------|------|
| 用户充值 | 用户发起支付 | 支付回调 → 积分入账 → 通知 |
| 贡献者提现 | 积分余额达到阈值 / 主动申请 | 冻结积分 → 审核 → 打款 → 扣减 |
| 开发者渠道分成 | 项目交付确认 | Token 消耗汇总 → 分成计算 → 批量打款 |
| 商品订单结算 | 用户下单（实物/服务/数字资产） | 支付 → 回调 → 订单确认 → 可触发积分返还 |
| 退款 | 用户申请 / 争议仲裁 | 冻结 → 审核 → 退款 → 积分回滚 |

### 结算流程

不同场景流程不同，结算引擎只负责支付侧，积分侧由业务服务层编排：

**充值 / 订单支付（资金流入）**
```text
用户发起支付
  → 结算引擎调支付接口
  → 支付成功：写结算记录 → 通知业务服务
  → 业务服务调积分引擎.earn()（充值返积分 / 订单返积分）
  → 支付失败：记录原因 + 通知用户
```

**提现 / 开发者分成（资金流出）**
```text
业务服务调积分引擎.freeze()冻结积分
  → 结算引擎审核 → 调支付接口打款
  → 打款成功：积分引擎.spend()扣减冻结积分 + 写结算记录
  → 打款失败：积分引擎.unfreeze()解冻 + 通知用户
```

**退款（资金回退）**
```text
用户申请 / 争议仲裁触发
  → 结算引擎调支付接口退款
  → 退款成功：写结算记录 → 通知业务服务
  → 业务服务调积分引擎回滚已返积分（如有）
  → 争议走社区仲裁工作流
```

### 结算约束

- 智能合约代码开源，规则透明
- 结算记录不可逆，归档后不允许修改
- 争议处理走社区仲裁流程，元引擎提供仲裁工作流
- 定期与支付渠道对账，差异自动告警

## 两引擎隔离边界

积分引擎和结算引擎是两个独立系统，互不直接调用，通过事件/接口解耦：

```text
┌─────────────────────────────┐     ┌─────────────────────────────┐
│       积分引擎               │     │       结算引擎               │
│  虚拟积分账户 · 规则执行      │     │  支付接口 · 流水记录 · 对账   │
│                             │     │                             │
│  对外接口：                  │     │  对外接口：                  │
│  + earn(userId, amount, src)│     │  + charge(userId, amount)   │
│  + spend(userId, amount)    │     │  + withdraw(userId, amount) │
│  + freeze / unfreeze        │     │  + refund(orderId)          │
│  + getBalance(userId)       │     │  + getRecord(userId)        │
└──────────┬──────────────────┘     └──────────┬──────────────────┘
           │ 充值成功 → earn()                  │ 提现申请 → withdraw()
           │ 消费扣减 → spend()                 │ 退款 → refund()
           └──────────────┬─────────────────────┘
                          │ 两引擎通过业务服务层协作，不直接互调
                          ↓
        ┌─────────────────────────────────────────┐
        │  Layer 4 业务服务（调用方）               │
        │  众包协作服务  → 积分引擎.earn()          │
        │  市场服务      → 积分引擎.spend()         │
        │  充值服务      → 结算引擎.charge()        │
        │                  → 回调积分引擎.earn()    │
        │  提现服务      → 积分引擎.freeze()        │
        │                  → 结算引擎.withdraw()   │
        │  订单服务      → 结算引擎.charge/refund() │
        └─────────────────────────────────────────┘
```

**隔离原则**：
- 业务服务只调用引擎对外接口，不直接操作引擎内部数据
- 积分引擎不感知支付渠道，结算引擎不感知积分规则
- 充值/提现等需要两引擎协作的场景，由业务服务层编排，不在引擎内部耦合

## 与其他模块的关系

| 模块 | 关系 |
|------|------|
| Token 计量（`intelligent/core/token/`） | 每次 LLM/Agent 调用后触发积分扣减 |
| 众包协作服务 | 任务完成后触发积分入账 |
| 市场服务 | 购买/销售触发积分流转 |
| 工作流引擎 | 驱动结算审核、退款、仲裁等有状态流程 |
| 元引擎 | 负责贡献事件采集和引擎编排，不实现业务逻辑 |
| 风控 | 异常积分行为检测，触发冻结或人工审核 |
