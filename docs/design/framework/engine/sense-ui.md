# 语义组件引擎设计（Sense-UI）

> 后端输出 DSL，引擎动态组装组件树，前端渲染。同一套组件多端适配，UI 与业务逻辑解耦。

## 核心理念

传统模式：前端写死 UI → 后端提供数据
Sense-UI：后端输出语义 DSL → 引擎组装组件树 → 前端流式渲染

```text
业务意图
  → DSL（描述"展示什么"，不描述"怎么展示"）
    → 语义组件引擎（组件匹配 + 内容注入 + 布局组装）
      → 组件树
        → 多端渲染（Web / 移动 / 微信 / CLI）
```

## 核心组件

| 组件 | 职责 |
|------|------|
| 组件注册表 | 组件元数据注册（名称/类型/输入输出契约/多端实现） |
| DSL 解析器 | 将语义 DSL 解析为组件树描述 |
| 组件匹配器 | 根据内容类型和上下文选择最合适的组件 |
| 内容注入器 | 将业务数据注入组件 props |
| 布局引擎 | 组件树的层级、排列、响应式规则 |
| 插件加载器 | 动态加载第三方组件，热插拔 |
| 流式渲染器 | 支持 SSE 流式输出，组件逐步呈现 |

## 组件类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 展示组件 | 纯展示，无交互 | 文本、图片、表格、图表 |
| 交互组件 | 用户输入/操作 | 表单、按钮、选择器 |
| 容器组件 | 布局和组合 | 卡片、列表、分栏 |
| 智能组件 | 内嵌 AI 能力 | 对话框、推荐列表、摘要卡片 |
| 执行组件 | 触发 Agent/工作流 | 任务卡片、进度追踪、审批流 |

## 多端适配

同一套组件 DSL，不同端渲染不同实现：

| 端 | 渲染方式 | 特点 |
|----|---------|------|
| Web | React 组件 | 完整交互，双栏布局 |
| 移动端 | UniApp 组件 | 触控优先，单栏滚动 |
| 微信 | 消息卡片 | 轻量，受平台限制 |
| CLI | 文本/ANSI | 纯文本，无图形 |

## 与 DSL 引擎的关系

DSL 引擎负责解析和路由，语义组件引擎负责 UI 组装：

```text
DSL 引擎（解析 + 路由）
  → 识别为 UI 渲染指令
    → 语义组件引擎（组件匹配 + 组装）
      → 组件树 → 前端渲染
```
