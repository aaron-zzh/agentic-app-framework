# 编排服务设计

> 编排服务是服务层（aaf-api/module/）的管理入口，负责编排定义的 CRUD、可视化配置和执行记录查看。编排定义的实际执行由元引擎（engine/meta）驱动。

## 定位与职责

```text
服务层：编排服务（本文档）
  → 编排定义的创建/配置/启停/版本管理
  → 编排执行记录查看、调试回放
  → 可视化编排设计器的后端 API

引擎层：元引擎（engine/meta）
  → 接收编排定义（DSL）→ 路由 → 调度专项引擎执行
  → 状态管理、置信度门控、生命周期管理

关系：编排服务定义"做什么"，元引擎执行"怎么跑"
```

## 与元引擎的关系

| 维度 | 编排服务（服务层） | 元引擎（引擎层） |
|------|------------------|-----------------|
| 层级 | Layer 4 服务层 | Layer 2 引擎层 |
| 职责 | 管理入口（CRUD + 配置 + 监控） | 执行引擎（调度 + 状态 + 门控） |
| 面向 | 用户/管理员 | 系统内部 |
| 类比 | Flowable Modeler（流程设计器） | Flowable Engine（流程执行器） |
| 数据 | 编排定义表、执行记录表 | 运行时状态（Redis + PG） |

## 核心功能

### 编排定义管理

- 创建/编辑/删除编排定义
- 版本管理（草稿/已发布/已归档）
- DSL 编辑器支持（文本模式 + 可视化模式）
- 编排模板库（预置常用编排模式）

### 已支持的编排模式

| 编排模式 | 底层实现 | 说明 |
|---------|---------|------|
| Agent 自主规划 | AgentScope ReActAgent | Agent 接收目标后自主拆分子步骤、选择工具、迭代执行 |
| 工作流编排 | Flowable | 固定流程骨架，节点顺序确定，支持审批/暂停/回退 |
| Team 多 Assistant 协作 | TeamOrchestrator + TaskDistributor | Leader 协调或平等协作，任务分发与进度同步 |
| A2A 跨服务通信 | AgentScope A2A starter | Assistant 间异步消息，支持跨框架/跨进程 |
| 混合编排 | 元引擎 DSL 路由 | 工作流节点嵌入 Agent 任务，确定性 + 不确定性混合 |

### 执行监控

- 编排执行记录（触发时间、耗时、状态、结果）
- 执行轨迹回放（每步的输入/输出/耗时）
- 异常记录与告警

### 编排产物的对外服务方式

编排定义发布后，可通过以下方式对外暴露：

| 产物类型 | 对外方式 | 适用场景 |
|---------|---------|---------|
| 含 AI 流式输出的编排 | AG-UI 协议（SSE） | 前端实时展示推理过程 |
| 纯业务逻辑编排 | REST API | 同步调用，返回最终结果 |
| 后台异步编排 | 异步调度 + Webhook 回调 | 长时任务 |
| 跨系统 Agent 团队 | A2A 协议 | 与外部 Agent 系统互联 |
| 技能 | 技能引擎路由 | 由 Assistant 内部调用 |
