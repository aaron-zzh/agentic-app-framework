# 预算控制设计

> 预算控制是元引擎执行调度的一部分，负责在任务执行前预估、执行中监控、超限时介入。
> 统计分析（消耗趋势、成本分布）由监控引擎负责，预算控制只管"能不能继续执行"。

## 预算维度

| 维度 | 说明 | 超限行为 |
|------|------|---------|
| Token 预算 | 单次任务 LLM 调用的 Token 上限 | 暂停，提示用户确认继续 |
| 时间预算 | 任务最大执行时长 | 超时强制中断，保存检查点 |
| 工具调用预算 | 单次任务工具调用次数上限 | 暂停，防止失控循环 |
| 费用预算 | Token + 工具调用折算的积分/费用上限 | 暂停，等待用户确认 |

## 执行前预估

任务执行前基于任务特征给出预算预估，用户确认后再执行：

```text
「本次任务预计消耗：
  Token：约 2000-3000
  时间：约 30-60 秒
  工具调用：约 5-8 次
  费用：约 0.5-1 积分
 是否继续？」
```

预估策略：
- 保守估算（上限 × 1.2），宁可高估不低估
- 基于历史同类任务数据持续校准，越用越准
- 简单任务（置信度 > 0.9）可跳过预估直接执行
- 多 Agent / 多工具复杂任务必须展示预估等待确认

## 执行中监控

实时跟踪各维度消耗，达到阈值时介入：

```text
消耗达到预算 70% → 告警提示（继续执行）
消耗达到预算 90% → 警告，询问是否扩大预算
消耗超出预算     → 暂停执行，保存检查点，等待用户决策
```

用户决策选项：
- 扩大预算继续执行
- 从检查点恢复，调整策略后重试
- 放弃本次任务

## 预算配置

预算可在三个层级配置，下层不能超过上层：

| 层级 | 配置方 | 说明 |
|------|--------|------|
| 系统级 | 管理员 | 全局上限，所有任务不得超过 |
| Assistant 级 | Assistant 配置 | 该 Assistant 下所有任务的默认预算 |
| 任务级 | 用户 / Agent | 单次任务的预算，可低于 Assistant 级 |

## 预算学习

- 记录每次任务的实际消耗 vs 预估偏差
- 自动校准同类任务的预估模型
- 用户反馈「预估偏差大」时触发模型更新

## Token 计量机制

Token 计量是预算控制的数据基础，通过事件驱动实现采集→记录→累计→超限判断的完整链路：

```text
Core/Agent 层                        预算控制引擎                    积分引擎
─────────────────────────────────────────────────────────────────────────────
LLM 调用完成                              │                            │
  → Hook 触发 TokenUsageEvent             │                            │
    (model, inputTokens,                  │                            │
     outputTokens, taskId,                │                            │
     agentId, assistantId)                │                            │
                                          ▼                            │
                                    接收事件                           │
                                    → 写入消耗记录                     │
                                    → 累计到任务/会话/用户维度          │
                                    → 超限判断                         │
                                       ├── 未超限 → 继续               │
                                       └── 超限 → 暂停执行             │
                                              → 通知用户               │
                                                                       │
                                    正常消费（每次调用后）        ──→  扣减积分
                                    或超限确认继续后             ──→  扣减积分
```

### Hook 注册点

| 注册位置 | 触发时机 | 说明 |
|---------|---------|------|
| `LlmClient` 实现层 | 每次 LLM 调用返回后 | 携带 model + token 数 |
| `AgentScopeExecutor` | Agent 单步执行完成后 | 汇总该步所有 LLM 调用 |
| `ToolCallDispatcher` | 付费工具调用完成后 | 工具调用折算为积分消耗 |

### 累计维度

```text
TokenUsageRecord
  ├── taskId        → 任务级累计（对比任务预算）
  ├── sessionId     → 会话级累计（对比 Assistant 预算）
  ├── userId        → 用户级累计（对比账户余额）
  └── model         → 按模型统计（不同模型单价不同）
```

### 与积分引擎的对接

- 预算控制引擎判断"能不能继续"，不负责扣钱
- 每次 Token 消耗确认后，发布 `TokenConsumedEvent` → 积分引擎按模型单价扣减
- 超限暂停期间不扣减，用户确认扩大预算后恢复扣减

## 与监控引擎的分工

```text
预算控制（本文档）          监控引擎
────────────────────────────────────────
判断能否继续执行            采集消耗数据
触发暂停/中断               统计消耗趋势
等待用户决策                成本分析告警
扩大预算/恢复执行           暴露 metrics
```

预算控制消费监控引擎产生的实时消耗数据，两者通过事件解耦。
