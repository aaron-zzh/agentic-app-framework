# 前端交互模式总体设计

> 详细设计：[结构化视图模式](./interaction-mode-structured-view.md) | [生成式交互模式](tmp/interaction-mode-generative.md)
> 目录结构：[directory-structure.md](./directory-structure.md) | 技术选型：[tech-stack.md](./tech-stack.md)

## 一、双模式定位

AAF 前端并存两种交互模式，面向不同用户心智和任务类型：

| 维度 | 结构化视图模式 | 生成式交互模式 |
|------|---------------|---------------|
| 一句话 | 配置驱动的低代码多视图 CRUD | 对话驱动的动态 UI 组装 |
| 用户心智 | "我知道要操作什么" | "我说出想要什么" |
| 导航 | 侧边栏菜单 → 实体 → View 切换 | 对话/命令 → Agent 生成界面 |
| 界面生成 | 实体注册表配置 → 自动派生视图 | 运行时 DSL 动态组装 |
| 数据流 | RSC 初始 + TanStack Query 客户端缓存 | AG-UI 协议流式推送 |
| 路由组 | `app/(workspace)/` | `app/(canvas)/` |
| 新增模块成本 | 注册实体配置（零页面代码） | 注册语义组件 |
| 适用场景 | 数据管理、流程审批、后台运营 | 探索性任务、创作、多 Agent 协作 |

**核心原则**：两种模式共存不互斥，共享底层能力（组件库、API 层、认证、状态管理），用户可随时切换。

**主次关系**：结构化视图是主交互面（高带宽通道：并行信息展示、直接操作、空间布局），生成式交互是辅助通道（意图表达、探索性任务、快速指令）。AI 输出优先"焊"进结构化视图（高亮修改、内联 diff、表单预填充、看板卡片更新），而非在对话中输出长文本。对话中确认的决策应自动"固化"为结构化产出物（文档/配置/实体数据），避免上下文腐烂。

**设计依据**：纯聊天将树状决策压缩为线性对话，导致上下文不可控。结构化视图天然支持并行信息和空间布局，是规划和审查的高效载体。AI 使执行近乎免费后，规划与审查成为新瓶颈——结构化视图正是降低审查成本的关键。

## 二、模式切换策略

### 2.1 切换入口

| 入口 | 方式 |
|------|------|
| 顶栏模式切换器 | 图标按钮，一键切换当前模式 |
| 命令面板 | `⌘K` → 输入"切换模式" |
| URL 直达 | `/workspace/...` vs `/canvas/...` |
| Agent 建议 | 对话中 Agent 推荐切换（如"这个任务用看板视图更合适"） |

### 2.2 上下文保持

切换模式时保持用户上下文：
- 认证状态共享（同一 Session）
- 当前操作的业务对象可跨模式引用
- 浏览器历史栈独立（各模式有自己的路由历史）

### 2.3 默认模式

- 首次登录：根据用户角色推荐（管理员 → 结构化，创作者 → 生成式）
- 后续访问：记住上次使用的模式（localStorage）

## 三、共享层架构

```text
┌─────────────────────────────────────────────────┐
│  结构化视图模式 (workspace)  │  生成式交互模式 (canvas)  │  ← 路由组
├─────────────────────────────────────────────────┤
│                    共享层                         │
│  ┌─────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ UI 组件  │ │ API 层    │ │ 状态管理         │ │
│  │ shadcn   │ │ TanStack  │ │ Zustand(UI)     │ │
│  │ + 自定义 │ │ Query     │ │ nuqs(URL)       │ │
│  └─────────┘ └──────────┘ └──────────────────┘ │
│  ┌─────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ 认证     │ │ 主题     │ │ 国际化           │ │
│  │ JWT      │ │ next-    │ │ next-intl        │ │
│  │ + RBAC   │ │ themes   │ │                  │ │
│  └─────────┘ └──────────┘ └──────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 3.1 共享内容

| 层 | 共享内容 | 位置 |
|----|---------|------|
| UI 组件 | shadcn/ui + 自定义基础组件 | `components/ui/` |
| API 层 | TanStack Query hooks + Server Actions | `lib/queries/` + `lib/actions/` |
| 认证 | JWT 鉴权 + RBAC 权限 | `lib/auth/` |
| 类型 | Zod Schema + TypeScript 类型 | `lib/types/` |
| 主题 | next-themes 暗色/亮色 | `providers/` |
| 工具 | 日期/格式化/验证 | `lib/utils/` |

### 3.2 各模式独有

| 结构化视图独有 | 生成式交互独有 |
|---------------|---------------|
| ViewSwitcher 视图切换 | 语义组件注册表 |
| DataTable / Kanban / Form | 画板引擎（Canvas） |
| 侧边栏菜单导航 | AG-UI 协议适配 |
| nuqs URL 参数管理 | DSL 解析器 |
| @modal 并行路由弹窗 | Agent Session 管理 |

## 四、v0.1.0 实现范围

| 模式 | v0.1.0 范围 | 延后 |
|------|------------|------|
| 结构化视图 | 列表 + 表单 + 基础看板 | 日历/图表/流程图视图 |
| 生成式交互 | 对话界面 + 基础消息流 | 画板/语义组件/DSL 组装 |
| 共享层 | 组件库 + API 层 + 认证 | 国际化、高级主题 |

**v0.1.0 优先级**：结构化视图模式先行（后台管理基础能力），生成式交互仅搭骨架（对话 UI）。

## 六、产品定位与远期愿景

### 6.1 本质定位

AAF 前端不是传统的"管理后台"，而是一个**通用智能工作台（数字座舱）**——对话是入口，画板是空间，Agent 是协作者，文档是载体。

```text
个人知识编辑器 → 通用智能工作台 → 数字座舱 → 元宇宙入口
    ↑ v0.1               ↑ v0.3          ↑ v1.0       ↑ 远期
```

类比：
- **Jarvis**（钢铁侠）— AI 辅助系统界面，理解意图、执行操作、主动建议
- **数字座舱**（飞行器）— 多屏信息聚合、一人掌控全局
- **IDE**（开发者）— 面向知识工作者的统一处理器

### 6.2 同一架构的多层投影

核心架构（文档模型 + Agent + DSL + 知识图谱 + 实时协作）不变，渲染层可演进：

| 渲染层 | 形态 | 对应能力 |
|--------|------|---------|
| **2D 工作台** | 画板 + 对话 + 文档 | 当前实现 |
| **数字座舱** | 空间化多屏布局 + 数据看板 + 消息中心 | 多 Tab → 多空间 |
| **3D 知识空间** | Three.js / R3F 渲染知识地图 | 画板节点 → 3D 对象 |
| **VR/元宇宙** | WebXR + 数字人 + 虚拟空间 | Agent → 数字人助理 |

### 6.3 数字座舱全景

```text
进入数字座舱 →
  ├── 知识地图（可视化知识结构，多层次缩放）
  ├── 记忆宫殿 / 自习室（沉浸式学习空间）
  ├── 数字人助理（Agent 的具象化，对话/引导/陪伴）
  ├── 工作台（画板 + 文档 + 工作流）
  ├── 数据看板（个人数据/学习进度/目标追踪）
  ├── 消息通知（协作/提醒/推荐）
  └── 设置（偏好/权限/插件）
```

### 6.4 当前设计的预留扩展点

| 当前设计 | 远期演进 |
|---------|---------|
| 多 Tab 工作区 | 数字座舱多空间/多屏 |
| 画板节点（CanvasNode） | 3D 空间中的知识对象 |
| Agent 对话 | 数字人助理的交互层 |
| 知识地图（力导向图） | 记忆宫殿的空间化知识 |
| 实时协作（Yjs） | 多人元宇宙同步基础 |
| 语义组件注册表 | 3D 组件/VR 组件扩展 |
| DSL 指令 | 空间操作指令（移动/旋转/缩放） |

### 6.5 北极星

> 与专属助理（数字孪生）一起构建知识地图（数字花园）+ 虚拟世界（数字领土）。
> 不仅是工具升级，更是对人机关系、认知范式和知识载体的重新定义。

最终形态：用户进入自己的数字座舱，AI 助理已准备好一切——知识地图在眼前展开，待办已整理完毕，学习路径已规划，协作者在线等待。用户只需说出意图，世界随之响应。
