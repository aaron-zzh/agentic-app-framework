# AAF Campaign Studio 产品设计

> 一句话定位：以品牌或个人 IP 记忆为基础，由助理把一个简报转化为可编辑、可审核、可复用的图片 + 视频 + 文案内容包。

## 设计结论与产品边界

### 核心判断

产品不应把 Flova、Liblib、Miora、ChatCut 的功能平铺到同一界面，也不应让普通用户先学习无限画布、节点 Flow 或模型参数。更易用的关键是把复杂性分层：

- **助理负责意图与执行**：用户只需说明目标、上传资料并确认关键决策。
- **成果画布负责看见与修改**：图片、视频、文案、故事板和版本都是可选中的业务对象。
- **Flow 负责复用与自动化**：默认隐藏，成功做法可保存为“创作配方”，专家才进入节点视图。
- **系统负责确定性事务**：任务状态、积分、版本、依赖、权限、审核和导出不能只由 LLM 记忆。

因此推荐的产品形态是**有限语义成果画布 + 常驻助理 + 按需 Flow**，而不是自由无限画布 + 常驻节点图。

### 目标用户与共同任务

| 用户 | 高频任务 | 额外约束 |
|---|---|---|
| 企业市场/品牌团队 | 从活动简报生成主视觉、尺寸变体、短视频、文案并送审 | 品牌一致、合规、权限、审批、审计 |
| 中小企业经营者 | 低成本完成产品宣传、投放素材和社媒内容 | 快速出稿、少参数、可持续复用 |
| OPC/个人 IP | 将选题转为封面、图文、口播或剧情短视频 | 风格稳定、多平台适配、单人可运营 |

三类用户共享“简报 → 创意方向 → 多格式产物 → 修改 → 导出 → 沉淀”的骨架。企业能力以治理插件叠加，不为 OPC 单独建设第二套创作系统。

### 产品对象与交付物

最小业务对象如下：

```text
Workspace
  └─ BrandProfile（企业品牌 / OPC 个人 IP）
       └─ Campaign（一次活动、选题或内容系列）
            ├─ Brief（目标、受众、卖点、渠道、限制）
            ├─ CreativeConcept（候选创意方向）
            ├─ DeliverableSet（同一活动的内容包）
            │    ├─ ImageDeliverable（KV、海报、封面、尺寸变体）
            │    ├─ VideoDeliverable（脚本、故事板、镜头、时间线、成片）
            │    └─ CopyDeliverable（标题、正文、CTA、字幕）
            ├─ Recipe（可复用创作配方）
            └─ Review（审核、意见、结论）
```

默认交付单位不是“一张图”或“一段视频”，而是一个**活动内容包**。例如新品发布可一次得到 1 张主视觉、3 个渠道尺寸、1 条 15 秒竖版视频、3 组标题与 CTA，并共享同一品牌和创意方向。

### MVP 与非目标

MVP 必须形成可验证闭环：

- 输入自然语言简报，或从“新品推广、活动预热、个人 IP 口播、爆款改写”模板开始。
- 建立品牌/IP 档案，保存 Logo、标准色、字体、受众、语气、卖点、禁用词和必要声明。
- 生成 2~3 个创意方向，用户选定后生成图片、短视频、文案内容包。
- 支持对象级引用与修改、版本对比、采用/撤销、尺寸与平台变体。
- 视频支持脚本、故事板、逐镜替换、基础字幕/配音/音乐、轻时间线和 MP4 导出。
- 将成功项目保存为配方；长任务有费用预估、进度、取消、重试和失败退还。

首期明确不做：专业 NLE 全功能、真正无限画布、3D/UI 设计、开放模型/Skill 社区、复杂多人实时协同、全渠道自动投放，以及让普通用户从空白节点图编排工作流。

## 参考产品与 AAF 现状

### 参考产品取舍

| 产品 | 已核实优势 | 借鉴 | 不照搬 |
|---|---|---|---|
| Flova | Agent 从意图完成脚本、故事板、媒体生成、时间线；项目记忆；Skill 可封装流程；左侧编辑、右侧指挥 | 项目连续性、可见中间产物、配方化、人工与 Agent 并行 | 完整专业面板默认常驻、长视频作为首期中心 |
| ChatCut | 对话剪辑、文本驱动删改、字幕、动效、图片/视频/音乐补素材 | “说出修改”与对象级编辑结合，优先补齐现有素材缺口 | 首期建设完整专业剪辑器和复杂动效系统 |
| Liblib | 官网本次可核实“一张画布”、Skill、Seedance 2.0 入口 | 单入口创作、能力配方化 | 模型/工作流/社区优势需进一步产品验证，不作为当前范围依据 |
| Miora | 二手公开资料描述 Creative Agent、风格记忆、多模态可编辑画布和 Skill | 品牌风格记忆、完整视觉包、局部可编辑 | 官网本次未成功抓取，相关结论证据较弱；不据此扩张 3D/UI 范围 |

证据等级：Flova 与 ChatCut 为官方公开页面；Liblib 仅采用本次官网可见内容；Miora 为二手公开资料，正式立项前需用可访问产品或官方资料复核。

### AAF 可复用基础

| 能力 | 代码/设计现状 | 本方案用法 |
|---|---|---|
| 图像/视频/音乐/语音生成 | 有统一 AIGC 任务、模型路由、异步执行、积分预检/结算、OSS 回存 | 作为原子生成工具，不新建第二套模型层 |
| 素材与版本 | 有素材分组、标签、变体、引用、生成参数及前端素材区 | 承载内容包素材、引用关系和版本树 |
| 项目结构 | 有项目、内容、故事板、镜头、轨道、时间线领域对象 | 演进为 Campaign 与 DeliverableSet，不另建平行“广告项目” |
| 创作 UI | 有 GenerationPanel、PreviewPanel、CopywritingPanel、故事板和时间线组件 | 重组为成果画布；不按图像/视频多个工具页割裂流程 |
| FlowEditor | 有 React Flow、节点注册、变量、校验和运行状态 | 作为 Recipe 专家视图，默认不暴露 |
| Assistant/Agent | 有助理定义、工具调用、内容创作助理方向和记忆架构 | 作为唯一对话入口，但业务事实落结构化对象 |

“任务文档标记 done”不等于生产可用。源码静态检查仍发现视频故事板含 mock 数据、时间线偏状态列表、部分模型路径未完整支持，以及任务一致性、权限校验、Flow 保存/取消和内容合规仍需验证。实施前必须以真实模型契约测试和端到端测试重新建立基线。

### 差异化

相对参考产品，AAF 的机会不是模型更多，而是：

- **一个简报交付整套内容**，而非在生图、生视频、文案工具间搬运。
- **企业品牌与 OPC 个人 IP 使用同一记忆模型**，从单次生成升级为持续经营。
- **成果可编辑、流程可复用、执行可审计**，兼顾创意自由与企业治理。
- **按对象引用和影响提示**：修改卖点、Logo 或主视觉时，系统提示受影响的尺寸稿和镜头，而不是盲目全部重做。

## 产品与交互设计

### 主界面

```text
┌ 品牌/IP  ·  Campaign 名称     [成果画布] [配方 Flow] [送审/导出] ┐
├──────────────┬──────────────────────────────┬─────────────────┤
│ 项目导航      │                              │ 创作助理          │
│ · 简报        │   有限语义成果画布             │ 当前上下文 chips   │
│ · 创意方向    │   选中对象 / 对比 / 版本 / 预览 │ 计划、任务与进度    │
│ · 内容包      │                              │                 │
│ · 资产        │                              │ 描述目标或修改…     │
│ · 审核        │                              │ [设置] [执行]      │
├──────────────┴──────────────────────────────┴─────────────────┤
│ 最近素材 / 正在执行任务 / 费用与状态                           │
└───────────────────────────────────────────────────────────────┘
```

画布不是任意摆放的白板，而是按 `Brief / Concept / Deliverable / Variant` 自动分组的**有限语义画布**。用户可以缩放、聚焦、比较和拖拽引用，但系统维持对象结构，避免项目变成不可管理的节点海洋。

### 画布、Flow 与助理分工

| 组件 | 回答的问题 | 默认可见性 | 禁止承担的职责 |
|---|---|---|---|
| 成果画布 | 做出了什么、采用哪版、还差什么 | 默认主视图 | 不展示底层模型调用和通用流程节点 |
| 助理 | 我想做什么、下一步怎么做、哪里失败 | 常驻右侧/移动端抽屉 | 不作为素材、任务和版本的唯一存储 |
| Flow/配方 | 这套方法以后如何稳定重复 | 专家视图，按需进入 | 不要求新用户从节点图开始创作 |

Flow 的用户语言叫“配方”。用户点击“保存这套做法”后，系统从执行轨迹生成配方草案，普通用户只看到步骤清单、输入项、确认点和预计成本；切换“专家编辑”才渲染现有 FlowEditor。Recipe 与 AAF `Skill` 需消歧：Recipe 是可执行、版本化的业务流程；Skill 是助理意图路由和执行指引，两者可关联但不能混为同一对象。

### 关键流程

**从简报到活动内容包**

```text
选择品牌/IP → 输入一句目标或选模板 → 助理只追问缺失的关键字段
→ 生成 2~3 个创意方向 → 用户选定 → 展示交付清单与费用
→ 并行生成图片/文案/视频草案 → 成果落画布 → 修改/采用
→ 质量检查 → 导出内容包或送审
```

**基于对象的局部修改**

```text
选中图片、镜头或文案 → 自动加入助理引用 chip → 说“产品更突出，Logo 不变”
→ 助理展示修改范围与受影响对象 → 生成新版本 → 并排比较
→ 采用、撤销或另存分支 → 下游产物提示是否同步更新
```

**把成功项目变成自动化**

```text
点击“保存为配方” → 助理归纳输入、步骤、确认点和输出
→ 试运行小样 → 用户确认 → 版本化保存
→ 下次只替换商品/主题/渠道 → 自动生成 → 异常转人工
```

### 降复杂性规则

- 一个时刻只有一个主工作面；成果画布与 Flow 互斥，助理常驻。
- 一个自然语言入口；图像、视频和文案参数收敛到同一种任务卡。
- 默认只显示比例、时长、数量、预计费用；模型、seed、负向提示词在高级设置。
- 助理最多连续追问一个关键问题，其余使用模板默认值并明确展示假设。
- 所有生成先形成可撤销版本；覆盖、删除、付费超预算、送审和发布必须确认。
- 长任务统一展示阶段、当前步骤、费用、取消、重试和恢复点。
- 移动端支持查看、对话修改、审批和导出；复杂故事板与 Flow 编辑引导到桌面端。

### 企业与 OPC 的渐进差异

核心创作体验不分叉，只按工作区能力开关渐进增强：

| 能力 | OPC 默认 | 企业增强 |
|---|---|---|
| 品牌记忆 | 个人 IP、语气、平台偏好 | 多品牌、多产品线、声明与禁用规则 |
| 协作 | 单人版本与历史 | 角色权限、评论、审批、审计 |
| 质量门禁 | 风格与平台规格检查 | 品牌、法务、敏感词、版权与肖像检查 |
| 配方 | 个人模板、定时复用 | 团队模板、版本发布、预算和停用策略 |
| 导出 | 文件与内容包 | 审批水印、交付清单、归档记录 |

## Agent 与技术设计

### Agent 组织方式

MVP 不建议一开始堆叠多个会被用户感知的 Agent。采用“一个 Campaign Assistant + 受控专业能力 + 确定性流程骨架”更稳妥：

```text
Campaign Assistant（唯一对用户负责）
  ├─ Brief Planner：补齐目标、受众、渠道和交付规格
  ├─ Creative Planner：提出创意方向与内容结构
  ├─ Copy / Image / Video 能力：生成和局部修改
  ├─ Brand Guard：检查品牌规则、声明和平台规格
  └─ Completion Validator：按交付清单判断完成/修复/转人工
```

这些首期可实现为同一助理下的 Skill、Prompt 模块、工具和校验器，不必全部物化为长期运行的独立 Agent。只有并行创意探索或互相质证带来可测收益时，再升级为多 Agent/Team。

### 决策边界

| 决策 | 责任主体 |
|---|---|
| 创意方向、脚本草案、镜头描述、提示词 | Agent 建议，用户选择 |
| 模型路由、任务幂等、积分、文件存储、版本关系 | 系统确定性执行 |
| 品牌事实、产品卖点、禁用词、必要声明 | BrandProfile 唯一真理源 |
| 覆盖、删除、超预算、送审、发布 | 人工确认或企业审批 |
| 完成判断 | Completion Validator 对照 DeliverableSet，不以一轮对话结束为准 |

品牌记忆应由结构化 `BrandProfile` 承载，Cognition 只补充偏好和历史经验。不得把 Logo、法务声明和已核准卖点只保存在向量记忆或聊天摘要中。

### 产品层增量

在现有 AIGC 模块上增加产品层，不复制底层生成服务：

- `BrandProfile`：品牌资产、视觉规则、语气、受众、声明和禁用项。
- `Campaign` / `Brief`：目标与项目上下文，可复用现有 AigcProject 并演进命名。
- `DeliverableSet`：交付清单、规格、依赖和完成状态。
- `AssetDependency`：来源、引用、衍生和变更影响关系。
- `RecipeDefinition`：用户友好步骤与底层 AI FlowDefinition 的版本映射。
- `Review` / `ReviewDecision`：送审、意见、采用、驳回和审计。

运行链路如下：

```text
Studio UI → Campaign Application Service → Assistant / Recipe Runtime
         → 现有 AigcTaskService → 模型适配器 → OSS / MediaAsset
         → Task Event → 画布更新 → BrandGuard / CompletionValidator → 审核或导出
```

### 必须补齐的工程能力

- **媒体工程**：视频合成、字幕/音频对齐、转码、缩略图、失败恢复和导出规格；不能只依赖生成模型返回单段 URL。
- **任务一致性**：幂等键、超时、取消、断线恢复、素材写入与积分结算一致性、供应商回调去重。
- **对象依赖**：版本不可变、采用指针、分支、下游影响计算和部分重跑。
- **企业治理**：租户/工作区隔离、对象 ownership、配方权限、审核、审计和数据保留策略。
- **质量评测**：提示词/配方回归集、品牌符合度、内容安全、模型质量与成本看板。

正式开发前优先验证当前静态审查暴露的问题：故事板 mock、Flow 变更回传与真实取消、部分模型 unsupported 路径、素材 ownership、供应商超时重试，以及 Agent 工具是否全部经过统一任务和积分链路。

## 工作量、可行性与实施路径

### 工作量判断

“主要工作量在交互 + Agent”对**差异化和 PoC**基本成立，但对**生产化总投入**不完全成立：

- 交互决定用户是否感到简单，是最大单一产品工作包。
- Agent 决定能否把模糊简报稳定变为结构化内容包，是第二个核心工作包。
- 企业上线时，媒体合成、异步一致性、权限合规和评测的投入与前两者接近，不能低估。

| 工作包 | 主要内容 | 估算人周 |
|---|---|---:|
| 产品与交互 | 原型、语义画布、对象操作、任务卡、移动适配 | 8~12 |
| Agent 与配方 | Brief/Creative Planner、上下文、工具编排、校验、评测集 | 7~11 |
| 产品后端 | Brand/Campaign/Deliverable/Recipe/Review、依赖图 | 5~8 |
| 媒体与模型 | 合成转码、字幕音频、模型契约、超时重试、成本路由 | 6~10 |
| 企业治理 | 权限、审核、审计、合规、预算 | 3~6 |
| 测试与可观测 | E2E、契约、故障注入、质量/成本看板 | 6~8 |
| **合计** | 可并行，不等于自然周 | **35~55** |

交互 + Agent 约占 15~23 人周，是差异化最大组合，但通常只占生产化总投入约 40%。若只做演示，可借现有能力把该比例提高到 60% 以上；若做企业小流量试点，非功能工作不能省略。

### 分期路线

| 阶段 | 周期 | 范围 | 退出条件 |
|---|---:|---|---|
| PoC | 2~3 周 | 单品牌、简报、2 个创意方向、1 个图像模型、1 个视频模型、内容包画布 | 5 个真实简报端到端跑通，用户可对象级修改 |
| MVP | 累计 8~12 周 | 品牌档案、图文视频内容包、故事板、轻时间线、版本、配方、费用与恢复 | 首次可用稿 ≤10 分钟，关键任务终态率 ≥99% |
| 企业试点 | 累计 12~16 周 | 审核、权限、合规、审计、团队配方、质量与成本看板 | 跨用户访问全部拒绝，品牌检查与审计闭环可用 |

推荐 5~6 人核心团队并行：产品/设计 1、前端 2、后端/媒体 2、Agent/评测 1，测试与安全按阶段投入。若只有 2~3 人，应把 MVP 延长到 16~24 周，并继续缩减企业治理范围。

### 可行性结论

| 维度 | 判断 | 说明 |
|---|---|---|
| 技术可行性 | 高 | AAF 已有主要生成、任务、素材、项目和 Flow 骨架 |
| 产品可行性 | 中高 | “一个简报到内容包”价值清晰，但需真实用户验证画布心智和成片质量 |
| 工程可行性 | 中 | 现有能力广但深度不均，生产稳定性与媒体合成是主要不确定性 |
| 企业可行性 | 中 | 权限、版权、广告声明、数据治理和供应商 SLA 尚需专项建设 |
| 商业可行性 | 中高 | OPC 可按积分/订阅切入；企业可按席位、品牌空间和生成额度收费 |

总体建议：**可做，且应基于现有 User Studio 演进，不另起系统；先验证“一个简报到一套可用内容”的完成率，再扩展无限画布、专业剪辑和社区生态。**

### 验收指标与决策门

- 首次用户从输入简报到产生首组可比较创意不超过 3 个主动步骤。
- 简报到首个可用图片稿 ≤5 分钟，到 15 秒视频草案 ≤10 分钟（不含供应商排队异常）。
- 活动内容包完成率、首稿采用率、平均重做次数和配方复用率可追踪。
- 关键异步任务终态率 ≥99%，重复提交不重复扣费，断线恢复不丢结果。
- 企业工作区跨用户/跨租户访问拒绝率 100%，关键操作有审计记录。
- 若 20 个真实项目中内容包完成率低于 50%，暂停扩展功能，优先修复 Agent 规划与对象编辑。
