# 通用项目管理持久化边界

> 本文是[通用项目管理模型](../general-project-management-model.md)的持久化裁剪结果。默认实现采用 **24 个类型化核心实体表 + 3 个通用项目语义元数据表**；复杂语义交给智能文档，专业对象交给所属模块，进度与健康度由事实派生。本文列出逻辑表及其职责，不等同于最终 SQL DDL。

## 核心结论

通用项目管理不能把每个领域名词都映射为一张表。只有同时需要稳定身份和独立生命周期，或承担事务不变量、权限、追溯、高频结构化查询职责的对象，才进入类型化核心实体模型。

持久化内容分为三层：

| 层次 | 承载方式 | 适用内容 | 核心约束 |
| --- | --- | --- | --- |
| 稳定事实层 | 24 个类型化核心实体表 | 项目、工作、交付、治理、发布、观测等可独立追踪对象 | 类型化代码维护状态机与硬不变量 |
| 领域语义层 | 3 个通用项目语义元数据表 | 方法、阶段、实践域、角色、类型、规则和映射 | 配置语义，不动态创建业务表 |
| 开放内容层 | 智能文档、外部引用、事件、值对象与派生投影 | 复杂叙述、专业对象、动作事实和计算结果 | 一项事实只有一个真理源 |

默认判断顺序如下：

```text
领域概念
→ 能否作为值对象或枚举表达？
→ 能否由智能文档承载复杂语义？
→ 是否已有专业模块拥有该对象？
→ 能否由既有事实派生？
→ 仍需独立身份、生命周期或硬不变量时，才提升为类型化实体
```

## 类型化核心实体表

### 项目与价值

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 项目 `Project` | 项目聚合根，维护项目身份、边界、状态与当前基线 | 所有项目事实的权限、生命周期和关联根 |
| 价值目标 `ValueObjective` | 定义项目期望创造的业务或用户价值 | 需要独立优先级、责任与演进历史 |
| 结果指标 `OutcomeMetric` | 定义验证价值目标的可度量指标 | 需要结构化计算、阈值判断和观测关联 |
| 项目基线版本 `ProjectBaselineVersion` | 冻结某次方法、范围、交付契约和治理配置 | 需要不可覆盖的版本身份和审计能力 |

项目章程、原始意图、问题定义、范围、约束和假设不是上述表的字段集合替代品；它们优先保存在智能文档中，由项目或基线引用。

### 迭代与工作

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 迭代 `Iteration` | 表示项目内一次有目标、有时间边界的演进循环 | 具有独立生命周期、基线和完成条件 |
| 工作项 `WorkItem` | 表示为交付结果而执行的可管理工作 | 需要状态机、优先级、责任和高频查询 |
| 工作依赖 `WorkDependency` | 表示工作项间的前置、阻塞或协同关系 | 关系本身具有约束、状态和追溯价值 |
| 工作分配 `WorkAssignment` | 将工作项分配给参与者或执行能力 | 需要独立接受、转派、开始和完成事实 |

计划说明、估算依据和工作契约说明由智能文档承载；时间范围、估算值、优先级等作为实体上的值对象，不独立建表。

### 交付与证据

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 交付物 `Deliverable` | 表示项目承诺交付且可独立验收的结果 | 需要身份、责任、版本和成熟度事实 |
| 验收标准 `AcceptanceCriterion` | 定义交付物可被接受的结构化判据 | 需要稳定编号、验证状态和证据关联 |
| 制品引用 `ArtifactReference` | 引用文档、知识、代码、媒体等实际制品 | 需要统一关联和追溯，但不复制制品正文 |
| 证据 `Evidence` | 记录支持验收、决策或价值判断的可追溯事实 | 需要来源、完整性、可信度和不可抵赖性 |
| 门禁评估 `GateEvaluation` | 记录某个门禁在指定基线上的评估结果 | 需要可审计结论、评估主体和证据快照 |

`ArtifactReference` 是跨模块引用，不取得专业制品的所有权。验收报告、测试报告和交付说明仍由智能文档承载，表中只保存结构化结论和引用。

### 风险与治理

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 风险 `Risk` | 管理尚未发生的不确定事件及响应 | 需要概率、影响、责任、响应和状态演进 |
| 已发生问题 `Issue` | 管理已经发生并影响项目的障碍或偏差 | 与风险语义不同，具有独立处置生命周期 |
| 决策 `Decision` | 记录具有约束力的治理选择和生效范围 | 需要身份、权限、生效状态和追溯链 |
| 变更请求 `ChangeRequest` | 管理对基线、范围、交付或运行绑定的正式变更 | 需要提交、影响分析、审批和实施闭环 |

风险分析、决策推理和变更影响说明由智能文档承载；风险状态、决策结论和变更审批结果由类型化实体维护。

### 协作与追溯

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 参与者分配 `ParticipantAssignment` | 将人、Agent、团队或系统能力绑定到项目角色 | 需要有效期、权限范围和责任追溯 |
| 执行引用 `ExecutionReference` | 关联 Workflow Run、Agent Run、系统任务等专业执行实例 | 项目需要统一追踪执行，但不拥有内部运行状态 |
| 项目事件 `ProjectEvent` | 保存影响项目语义的不可变事实和审计时间线 | 需要跨对象追溯、回放和派生投影 |

`ProjectEvent` 只保存需要长期审计的项目事实，不等于为每一种领域事件建立一张表，也不取代消息总线、Outbox 或专业运行时日志。

### 能力运行与价值验证

| 逻辑表 | 核心职责 | 独立持久化原因 |
| --- | --- | --- |
| 可运行能力 `RunnableCapability` | 表示由交付制品组装而成的可运行能力 | 需要稳定身份、组成契约和发布资格 |
| 能力发布 `CapabilityRelease` | 表示不可覆盖的能力发布版本 | 需要版本身份、制品快照、批准和回退目标 |
| 运行绑定 `RuntimeBinding` | 将能力发布绑定到环境、入口和运行配置 | 需要独立启停、切换、权限与审计 |
| 结果观测 `OutcomeObservation` | 保存运行后与结果指标相关的观测事实 | 需要时间序列追踪、来源和价值验证关联 |

运行日志、模型调用、Workflow 节点状态和专业监控数据属于运行时模块；项目只保存发布、绑定和价值验证所需的稳定事实与引用。

## 语义、文档与外部资源

### 通用项目语义元数据

项目方法不通过新增业务表扩展，而由以下 3 个通用元数据表表达：

| 逻辑表 | 承载内容 | 不承担的职责 |
| --- | --- | --- |
| 项目语义定义 `ProjectSemanticDefinition` | 阶段、里程碑、实践域、角色、责任、制品、证据、指标、门禁、风险分类、项目类型等稳定语义身份 | 不保存具体项目的运行状态 |
| 项目语义版本 `ProjectSemanticVersion` | 语义定义的版本化内容、规则、模板引用和生效区间 | 不动态生成实体类或数据库表 |
| 项目语义关系 `ProjectSemanticRelation` | 主链、阶段、实践域、角色、模板和规则之间的类型化关系 | 不替代工作依赖或项目对象关系 |

元数据可承载项目阶段、阶段里程碑、项目实践域、项目方法版本、项目模板、项目角色、责任类型、制品类型、证据类型、指标定义、质量门定义、风险分类、项目类型与模式，以及主链—阶段—实践域映射和 UI/智能文档模板。

`EntityDef` 只负责将稳定实体能力投影给 UI 和智能交互，不是核心实体的定义源；Resource Catalog 定义服务端可用能力上限，项目元数据不能绕过它创建任意数据能力。

### 智能文档

以下内容语义复杂、叙述性强、结构会随项目类型变化，默认由 Document 模块的智能文档承载：

| 文档族 | 典型内容 |
| --- | --- |
| 项目定义 | 项目章程、原始意图、问题定义、范围、约束、假设 |
| 需求与方案 | 需求、业务规则、方案、架构、项目规范 |
| 计划与治理 | 计划说明、工作契约说明、风险分析、决策推理、变更影响分析 |
| 验证与报告 | 测试报告、验收报告、项目报告、运行价值分析 |
| 学习与沉淀 | 回顾、经验、方法改进建议、可复用知识 |

文档正文、文档版本和协同编辑状态由 Document 模块拥有。项目实体只保存 `ArtifactReference` 或受约束的文档引用；不得把同一正文再复制到项目表的 JSON、大文本字段或元数据中。

### 外部资源引用

项目模块只引用下列专业对象，不拥有其正文、定义或内部状态：

| 所属模块 | 项目可引用内容 | 项目不得复制的内容 |
| --- | --- | --- |
| Document / Knowledge | 文档版本、知识条目或知识库 | 文档正文、知识正文、索引内部状态 |
| Intelligent / Agent | Agent、AgentTeam、Tool、Skill 及其版本 | 定义正文、提示词、记忆和内部治理状态 |
| Workflow / Runtime | Workflow 定义、版本与运行实例 | 节点状态、变量、重试栈和运行时日志 |
| Chat / Task Infrastructure | 会话、消息、Todo、异步系统任务 | 消息正文、Todo 状态机和队列内部状态 |
| 专业业务模块 | AIGC、软件开发等专业制品与执行对象 | 专业制品正文、专业属性和专业状态机 |

引用必须包含可解析的资源类型、资源身份和必要的版本身份。跨模块删除、权限变化和版本不可用通过领域事件或引用校验处理，不通过复制数据兜底。

## 非实体承载模型

### 领域事件与动作

领域事件是已经发生的事实，动作或命令是改变状态的意图，两者都不应按动词建立实体表。

- 提交、批准、拒绝、暂停、恢复、重试、取消是应用命令；执行后更新对应实体并产生可审计事实。
- 发布、切换、回退是能力发布或运行绑定上的领域动作；结果进入实体状态和项目事件时间线。
- 临时领域事件由消息总线传播；需要跨事务可靠投递时使用基础设施 Outbox，但 Outbox 不是项目领域实体。
- 只有影响项目基线、治理、交付、发布或价值验证且需要长期审计的事实，才归档为 `ProjectEvent`。

### 值对象

以下内容没有独立身份，其相等性由值决定，应作为实体字段、嵌入值对象或受元数据约束的代码使用：

| 值对象族 | 示例 |
| --- | --- |
| 状态与分类值 | 项目状态、阶段代码、优先级、严重程度、置信度 |
| 时间与数量值 | 时间范围、持续时间、阈值、估算值、完成条件 |
| 度量值 | 指标值、单位、目标区间、概率、影响等级 |
| 引用标识值 | 外部资源类型、资源 ID、版本 ID、定位 URI |
| 快照与校验值 | 基线号、内容摘要、校验和、不可变版本标签 |

阶段和类型的语义定义来自项目语义元数据；具体项目当前使用的代码值保存在相应实体上。不能因为值可配置，就为每个状态、优先级或单位建立业务实体表。

### 派生投影

以下信息由核心实体、事件和外部观测计算产生，默认不作为人工维护的真理源实体：

| 投影 | 主要事实来源 |
| --- | --- |
| 工作进度 | 工作项状态、工作依赖、工作分配与执行引用 |
| 交付成熟度 | 交付物、验收标准、证据与门禁评估 |
| 价值实现度 | 价值目标、结果指标、结果观测与能力发布 |
| 治理健康度 | 风险、问题、决策、变更请求和项目事件 |
| 项目报告与组合看板 | 上述投影及指定基线的聚合结果 |

投影可以物化为查询表、搜索索引、缓存或分析视图以满足性能需求，但它们必须可重建、标注计算版本和数据时点，且不得反向成为核心事实的编辑入口。不存在跨项目通用且可手工维护的“统一完成百分比”。

## 真理源与提升规则

### 单一真理源

| 事实类型 | 唯一真理源 | 其他载体的角色 |
| --- | --- | --- |
| 核心状态与硬不变量 | 类型化核心实体 | 文档和 UI 只引用或投影 |
| 方法、角色、类型与规则 | 项目语义元数据 | 代码执行受 Resource Catalog 与硬约束限制 |
| 复杂叙述和报告正文 | Document 模块 | 项目保存引用和结构化结论 |
| 专业对象及运行时细节 | 对应专业模块 | 项目保存外部引用和必要快照 |
| 已发生的项目级审计事实 | `ProjectEvent` | 消息、日志和看板是传输或投影 |
| 进度、健康度和价值趋势 | 可重建派生投影 | 不允许人工双写核心结论 |

一项文档内容提升为核心实体后，实体立即成为该结构化事实的真理源；文档改为引用实体或展示快照，不能继续独立维护同一状态。

### 文档内容提升为实体的条件

复杂内容默认先进入智能文档。出现以下任一硬条件，或多个查询与治理条件持续存在时，才提出实体化设计：

- 需要跨文档保持稳定身份，并被多个对象长期引用；
- 具有独立创建、变更、失效或归档生命周期；
- 必须在单个事务中维护状态机、唯一性或其他硬不变量；
- 需要对象级权限、审批、签名或不可抵赖审计；
- 需要高频过滤、排序、聚合、关联或自动化规则计算；
- 文档结构已稳定，且不同项目类型共享同一核心语义。

实体化前必须同时回答：谁拥有该事实、迁移后如何消除双写、历史文档如何引用新实体、现有投影如何重建。仅因“可能以后查询”或“概念看起来重要”不能建表。

### 暂不建表清单

下列内容不进入首版类型化实体表：

- 项目阶段、实践域、方法版本、角色、责任类型和各类分类字典；
- 项目章程、需求、范围、约束、假设、方案、规范、报告和回顾正文；
- 文档、知识、Agent、Workflow、Chat、Todo、系统任务及专业制品的内部对象；
- 状态代码、优先级、严重程度、置信度、时间范围、阈值和估算值；
- 提交、批准、拒绝、暂停、恢复、重试、取消、发布、切换和回退动作；
- 工作进度、交付成熟度、价值实现度、治理健康度和统一完成百分比。

后续扩展必须由真实业务不变量、性能数据或监管要求驱动。扩展优先增加元数据定义、智能文档模板、外部适配器或派生投影；只有这些方式不能满足稳定身份和事务治理要求时，才增加新的类型化实体表。
