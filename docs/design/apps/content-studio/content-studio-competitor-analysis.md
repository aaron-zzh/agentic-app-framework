# AI视频创作竞品分析

本文面向正在设计或使用 AI 创作工具的产品经理、设计师和开发者。通过对 Flova、LibTV、Miora、ChatCut 与 WorkRally 的定位、流程、对象模型和界面工作面进行对照，识别 AI 创作产品从灵感输入到规模化生产的共同模式与关键分歧，并将观察沉淀为 Content Studio 的设计输入。

它不是功能大全、上手教程或模型效果测评，而是尝试回答一个更基础的问题：不同产品分别想把 AI 视频创作的哪一部分变得更简单？阅读后，你可以快速建立对不同产品范式的初步认知，理解自由画布、节点编排、时间线剪辑和批量生产流程各自适合什么场景，也能为选择工具或设计自己的 AI 创作产品提供一些参考。

## 概述

### 竞品全景

| 产品 | 官网 | 一句话定位 | 核心范式 | 最强能力 | 主要认知成本 | 最适合的任务 | 商业化 |
|---|---|---|---|---|---|---|---|
| Flova | [flova.ai](https://www.flova.ai/) | AI 原生视频创作 Agent 平台，把品味和习惯写进 Skill | Agent 制片 + 媒体空间（列表/画布双视图）+ 时间线 | 创意持续推进到成片 | 对象层级多，媒体空间与时间线双模式 | 短剧、MV、广告片 | 积分 + 订阅 |
| LibTV | [www.liblib.tv](https://www.liblib.tv) | 专业 AI 影视创作平台，人与 Agent 双入口 | 节点画布 + 显式三阶段影视生产流程 | 镜头与资产的显式控制 | 节点 + 表格 + 参数并存 | 漫剧、影视、复杂广告流程 | 点数 + 订阅 |
| Miora | [miora.design](https://miora.design) | 带记忆的 Agentic Creative Studio，一个简报产出多模态资产包 | 对话任务 + 记忆 + 多模态自由画布 | 记忆驱动的跨媒介一致性 | 自由画布膨胀后失控 | 品牌、IP、电商视觉套系 | 积分 + 订阅 |
| ChatCut | [chatcut.io](https://chatcut.io/) | 网页版 AI 视频剪辑 Agent，像助理剪辑师一样工作 | Agent 粗剪 + 7 面板专业编辑器接管 | 自动粗剪后人工精修 | 时间线仍需剪辑知识 | 口播、访谈、创作者后期 | 积分 + 订阅 |
| WorkRally | [workrally.qq.com](https://workrally.qq.com) | 面向漫剧生产的 AI 创作工作台，覆盖小说拆解、资产、分镜、图生视频与后期配音 | 阶段化批量生产 + 无限画布 + 基于 Skill 的智能助手 | 将剧集、场次、分镜与批量生成组织为明确层级 | 入口较多，批量创作、无限画布与主图编辑是不同工作面 | 小说/剧本驱动的漫剧批量生产 | 积分充值 |

### 核心结论

- 自然语言表达目标，结构化对象承载过程，专业编辑器最后接管
- “Skill”已成为行业通用一等公民
- **记忆**从“隐性个性化”变为“可编辑规则”。Miora 明确区分个人记忆与项目记忆并允许查看/修改/删除
- **首页不应同时暴露画布、节点、故事板、时间线和模型参数**。
- **推荐**：Miora 式领域入口与示例 Prompt 降低启动成本，Flova 式项目连续性维持长任务上下文，LibTV 式阶段条与镜头表支撑复杂流程但默认隐藏节点图
- **WorkRally 补充**：对漫剧这类重复结构强、可批量生产的任务，应先固定“剧集 → 场次 → 分镜 → 结果”的业务层级，再让画布和 Agent 作为局部创作与编排工具；不要让用户从通用画布自行发明生产结构。

## Flova

### 产品档案

| 项 | 内容 |
|---|---|
| 定位 | AI 原生视频创作 Agent 平台 |
| 目标用户 | AI 视频新手、独立创作者、品牌与营销创作者、AI 短剧与专业制作团队 |
| 覆盖内容 | 短剧、MV、广告与营销片、社媒竖版、单次媒体探索、为实拍补镜头与合成 |

### 核心概念术语

| 官方术语 | 含义 |
|---|---|
| Agent | 项目内的执行者，读取当前项目状态并决定下一步 |
| Skill | Agent 的操作手册——可复用创作工作流，定义如何拆步骤、调工具、选模型、设计故事板 |
| 故事板（Storyboard） | 由关键元素、分镜、全局音乐/旁白组成的结构化生产载体 |
| 关键元素（Key Element） | 角色、场景、音色等跨镜头复用对象，可挂多版本媒体 |
| 分镜（Shot） | 单个镜头，含运镜描述、时长、引用元素与生成媒体 |
| 媒体空间（Media Files Panel） | 项目主工作面，承载故事板与未归类素材，支持列表与画布两种视图 |
| 项目级记忆 | 持续记录脚本、镜头、媒体与剪辑当前状态，使中间步骤可改而不丢线索 |
| Add to Chat | 把元素、镜头、媒体或选中文本连完整信息带入对话作为修改目标 |
| Brunch in new project / back to this moment | 从任一 AI 回复分支出新项目或回到该时刻 |
| Flova TV | 精选成片展示，可查看创作过程并复用其 Skill |

### 核心流程

```text
一句 Prompt / 模糊灵感 / 剧本镜头表 / 已有素材 / 拉片参考 / 选定 Skill
  → Agent 规划并生成故事板（关键元素 + 分镜 + 全局音频）
    → 逐镜生成媒体，中间步骤产出多版本供比较选择
      → 时间线拼装，预览节奏
        → 对象级修改（Add to Chat / Edit / 评论式生成）与 Agent 任务并行
          → 导出成片、PR 工程文件或全部素材
```

交互原则是"右侧指挥、左侧查看与编辑"：Agent 完成的内容落到左侧对应面板，每个面板也支持手工编辑，且手工编辑可与 Agent 任务并行；同一内容被双向修改时系统弹出冲突面板。流程不强制顺序，可先探索风格图再进正式故事板。

### 界面

媒体空间是主工作面，内部再分列表与画布两种视图（左下角图标切换，共用同一套缩放控件）

![Flova 首页](./tmp/flova-1.png)

首页：左侧竖导航为首页/项目/快速生成/资产库/Skill/FlovaTV/教程；主输入框可附加模型、Skill、资产库三类上下文；下方依次是热门 Skills，最近项目，分类展示的 FlovaTV。

![Flova 媒体空间 · 列表视图](./tmp/flova-2.png)

媒体空间的列表视图：故事板（关键元素 / 分镜）与未归类素材；中栏预览；右栏对话。

![Flova 媒体空间 · 画布视图](./tmp/flova-3.png)

媒体空间的画布视图：卡片悬浮工具条为添加参考 / 保存到资产库 / 删除元素，预览改为浮窗叠加在画布上，左下补充撤销、重做、布局与居中控件。是按对象类型分区的半结构化画布；分镜卡之间的连线表示镜头先后顺序，不是节点数据依赖，关键元素之间不连线。

![Flova 时间线模式](./tmp/flova-4.png)

时间线模式：左侧故事板（关键元素展开后每个元素含音频 + 多版本图片 + 局部调整输入框），右侧是播放器，底部一条视频轨 + 两条音频轨。

### 总结

**优势**：Agent 持续更新故事板、素材和时间线，过程状态可见；角色、镜头、音频都有明确归属，适合一致性要求高的项目

**复杂性**：需同时理解故事板、关键元素、分镜、未归类素材、媒体版本与时间线；媒体空间的列表与画布两种视图加上时间线模式，构成三套操作手感，切换成本不低；三栏叠加预览浮层后空间争夺明显。

## LibTV

### 产品档案

| 项 | 内容 |
|---|---|
| 定位 | 专业 AI 视频创作平台，管理从概念到成片的全流程；人类 UI 与 AI Agent 双入口，另开放 OpenAPI 与遵循 OpenClaw 规范的开源 Skill 包 |
| 目标用户 | 漫剧/短剧团队、影视与商业广告创作者、需要角色一致性和批量资产的工作室 |

### 核心概念术语

| 官方术语 | 含义 |
|---|---|
| 工作区 / 画布 | 项目容器，一个工作区可含多张画布 |
| 节点 | 画布上的生产单元：文本、图片、视频、视频合成、导演台、音频、脚本、素材库 |
| 工作流 / 故事板 | 同一项目的两个视图——工作流看依赖，故事板按节点分组看结果 |
| 关键元素 | 角色、场景、道具三类设定对象，在镜头描述中以高亮引用出现 |
| 镜头表 | 镜号、时长、画面描述、景别、光影氛围、对白旁白、音效、运镜、最终提示词的结构化表格 |
| 三阶段 | 确认镜头 → 准备资产 → 合成提示词，全部完成后可批量生成视频 |
| 全局风格 | 项目级视觉基调描述，约束所有资产 |
| Skill | 领域创作流程包；官方 Skill Hub 提供导演级 Skill 供 Agent 调用 |
| 领域动作 | 对象级专业能力：全景、多角度、打光、九宫格、宫格切分、25 宫格连贯分镜、剧情推演四宫格、画面推演±秒、人像质感调节、电影级光影校正 |

### 核心流程

```text
首页输入灵感或挑选 Skill
  → 进入画布，创作助手先追问关键信息（题材、时长、基调）
    → 脚本/剧本节点产出剧本
      → 阶段① 确认镜头：逐行核对镜头表（景别/光影/对白/音效/运镜）
        → 阶段② 准备资产：按角色/场景/道具生成设定图，缺失项批量补齐
          → 阶段③ 合成提示词：镜头 + 元素 + 全局风格合成最终提示词
            → 批量生成视频，在故事板视图审阅结果
```

### 界面

顶部切换工作流与故事板两个视图，右栏创作助手跨视图常驻。

![LibTV 首页](./tmp/libtv-1.png)

首页：最近项目；输入框写明"输入你的创作灵感，或从下方挑选一个 Skill 开始"，Skill 与 Prompt 并列为两条起点；下方是 Skill 卡与按题材分类的 TV Show 案例区。

![LibTV 工作流视图与创作助手](./tmp/libtv-2.png)

工作流视图：左栏画布/资产双 Tab 与画布元素列表；中央节点工作流，脚本节点内嵌三阶段进度条（确认镜头 / 准备资产 / 合成提示词）；右栏创作助手标题即所加载的 Skill，追问关键信息。

![LibTV 参数面板](./tmp/libtv-3.png)

参数面板；节点顶部另有一排领域动作；底部固定显示模型、参数摘要与本次消耗点数

![LibTV 节点添加菜单](./tmp/libtv-4.png)

节点类型即能力清单——文本、图片、视频、视频合成、导演台、音频、脚本、素材库；

![LibTV 故事板视图](./tmp/libtv-5.png)

故事板视图：同一项目的另一种读法。左侧关键元素网格把角色/场景/道具拉平为可检索卡片，右侧预览并标注模型与分辨率。

![LibTV 领域动作菜单](./tmp/libtv-6.png)

领域动作菜单：分镜叙事组（调度故事板、25 宫格连贯分镜、剧情推演四宫格、画面推演±秒）与质感调节组（人像质感调节、电影级光影校正），把导演经验封装成一次点击；同时支持"从画布选择参考"。

![LibTV 镜头确认表](./tmp/libtv-7.png)

三阶段带精确缺口计数（7 个镜头已就绪 / 资产还差 8 个 / 提示词 1-7 已合成）。表格列含镜号、时长、画面描述、景别、光影氛围、对白旁白、音效、运镜与最终提示词

![LibTV 资产准备与角色编辑](./tmp/libtv-8.png)

资产生成：全局风格约束下按角色、场景、道具三组；右侧编辑角色抽屉除外观外还含服装、特征、构图规范（必须是角色四视图）与光影要求。

### 总结

**优势**：把脚本、镜头、角色、场景、道具与最终提示词全部显式化，生产过程可追溯、可逐项修正；工作流/故事板双视图兼顾依赖与结果阅读；阶段条给出精确缺口计数，用户始终知道下一步做什么

**复杂性**：节点图、资产列表、创作助手、故事板、镜头表和参数面板同时存在，认知负担在四家中最高；大量专业动作与节点类型对新用户不友好

## Miora

### 产品档案

| 项 | 内容 |
|---|---|
| 定位 | 腾讯设计出品的"带记忆的 Agentic Creative Studio"，产出脚本、故事板、视频、UI/UX、插画、3D 与品牌系统的完整资产包 |
| 目标用户 | 品牌与设计团队、IP 运营、电商广告、需要跨项目保持视觉一致性的个人创作者 |

### 核心概念术语

| 官方术语 | 含义 |
|---|---|
| Agent Memory | 自动积累的品牌、风格、规则与禁忌，完全可查看和编辑；分个人记忆（跨项目）与项目记忆（含客户品牌规则，不外溢） |
| 显式记忆 vs 生成历史 | 显式记忆是可开关的强约束，生成历史是会自然衰减的弱上下文；改口味建议"告知规则失效"而非直接删除 |
| Specialist Network | 一个简报自动编排多个 AI 专家分工执行 |
| Canvas | 可编辑无限画布，图像/视频/UI/3D 共存，支持分页（Page）；不做节点硬连线，多种风格可并排试而不干扰 Agent |
| Skill | 把记忆与工作流打包成可复用对象，可自用、分享给同事或发布到市场；创建时需界定范围，避免打包客户专属上下文 |
| Selection Edit / Edit Text | 选中局部后用自然语言描述修改 |
| 记忆 / 技能 / 灵感 | 与创作、项目并列的一级导航入口 |

### 核心流程

```text
挑一个 Skill
  → 画布上得到完整设计好的主体（如一个 IP 角色），每个元素可选中并口述修改
    → Agent 逐项弹出参数卡等待确认（VI 手册 / 社媒素材 / 包装场景 / 四视图）
      → 主体扩展为多模态世界：视频、游戏 UI、3D、皮肤、周边，同一 IP 一致
        → 把本次积累的记忆打包成自己的 Skill，复用或分享
```

### 界面

![Miora 首页](./tmp/miora-1.png)

首页：左侧一级导航为创作、灵感、技能、记忆、项目；顶部按五个领域分流；主输入框带角色库芯片与 Ask 模式切换；下方是 Skill 卡，以及 UI 标为“模板”的示例 Prompt。它们用于启发或预填输入，未见独立的项目模板实体。整页白色轻量，无常驻专业面板。

![Miora 对话任务与自由画布](./tmp/miora-2.png)

项目页：左栏对话流把交付物列成清单并逐项标注"等待确认 / 已完成"；右栏是自由画布（支持分页），工具以悬浮竖栏排列；画布上的"图片生成器"占位框就地弹出生成输入框，支持从画布选图作参考并选模型与比例。

### 总结

**优势**：首页用领域与模板表达能力，不要求用户先理解模型或工作流；记忆作为一级入口且可查看可编辑，把"AI 记住你的风格"从黑盒变成可治理的规则集；对话任务与画布并行，对象旁生成避免远端面板与画布来回定位

**复杂性**：对话、任务、悬浮工具与对象级输入都能触发操作；画布对象增多后视觉杂乱、分组控制不足，且多模态并行渲染会造成视口卡顿；需要像素级控制时要导出到外部编辑器。

## ChatCut

|---|---|

## WorkRally

### 产品档案

| 项 | 内容 |
|---|---|
| 定位 | 面向漫剧批量生产的 AI 创作工作台；从小说/剧本、资产与分镜到图生视频、后期配音的连续入口 |
| 目标用户 | 需要按剧集、场次、分镜组织内容并批量生产漫剧的创作团队 |
| 覆盖内容 | 小说/剧本导入与分析、剧集/场次/分镜管理、人物等资产生成、图生视频、后期配音、主图与图层编辑 |

### 核心概念术语

| 界面术语 | 截图可见含义 |
|---|---|
| 项目 / 剧集 / 场次 / 分镜 | 批量创作的层级容器。项目创建时可指定集数，并从分镜或小说/剧本开始；图生视频页按剧集、场次、分镜筛选结果 |
| 批量创作 | 顶级工作区，菜单含脚本创作、关键帧、图生视频、后期配音，形成面向漫剧的生产链路 |
| 脚本创作 | 显示六个阶段：小说上传、小说分析、改编方案、结构化文字剧本、剧本正文、文字分镜剧本 |
| 无限画布 | Agent 驱动的多模态创作空间；可放置文本、图像/视频生成卡与资产，并支持缩放、页面缩略图和工具栏操作 |
| 智能助手 | 画布右侧常驻对话面板，说明“基于 Skills 组合”；可见脚本创作、拆解剧本提取资产、连镜四宫格、生成人物多视图图、多机位九宫格、提示词润色、批量管理画布素材等快捷 Skill |
| 资产 / 参考主体 | 生成卡与主图编辑均可选择项目资产或本地上传为参考；视频生成页另显示“参考主体”与本集资产区 |

### 核心流程

```text
创建项目（命名、权限、集数、画布尺寸，选择从分镜或小说/剧本开始）
  → 上传小说/剧本，依次完成小说分析、改编方案、结构化剧本、剧本正文与文字分镜
    → 在无限画布用 Skill 拆解资产、生成角色多视图/九宫格并完善提示词
      → 按剧集、场次、分镜组织关键帧与参考主体
        → 批量图生视频（选择模型、比例、分辨率、时长与生成数量）
          → 后期配音与结果管理
```

### 总结

**优势**：以项目、剧集、场次、分镜的业务层级承载漫剧生产，批量制作入口和六步脚本阶段把长流程显式化；资产/参考主体贯穿无限画布、主图编辑和图生视频，利于把一致性控制留在项目内。

**复杂性**：批量制作、无限画布、主体绘图分别是不同工作面，用户需要理解何时切换。

### 共同模式

- **首页意图入口**：首页先让用户选择目标或创作入口，再用 Skill、模板、附件或项目上下文补足信息；WorkRally 将目标收敛为漫剧批量制作、无限画布和 CLI 三类入口。
- **Agentic**：AI 不只返回文本，而是更新镜头、素材、任务、时间线或画布资产；WorkRally 的截图进一步把这些产物嵌入项目、剧集、场次、分镜层级。
- **画布模式**：除 ChatCut 外四家都提供画布，并支持在画布内直接生成；但 WorkRally 把画布作为批量生产链路的局部创作面，而不是唯一的项目组织方式。
- **渐进进入专业面**：从对话、模板或领域入口进入画布、故事板、时间线或批量工作面，而不是一开始展示全部工具。
- **画布连线语义分四派**：LibTV 的连线是真正的数据依赖（上游节点输出作下游输入），因此最像工作流，控制力最强、门槛也最高；Flova 的连线只表达分镜先后顺序，是叙事时间关系而非执行依赖；Miora 不做硬连线，以便多种风格并排试错；WorkRally 的截图未显示连线，其项目层级和分镜列表承担了主要的组织职责。“画布”因此并不等于“节点编排”。
- **双视图同源不是唯一答案**：Flova 与 LibTV 都是同一批对象配两种视图切换（Flova 列表↔画布，LibTV 故事板↔工作流）；WorkRally 则以批量生产、无限画布、主体绘图等不同专业工作面服务同一项目，提醒 Content Studio 要明确工作面间共享对象与跳转上下文，避免用户重复建立资产。
