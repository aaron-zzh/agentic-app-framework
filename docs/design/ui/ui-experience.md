# 界面与交互体验设计

> 传统界面是预先设计的固定结构，所有用户看到同一张脸。
> AI 时代的界面是**为你生成的**——同一个功能，不同的人看到不同的界面，
> 同一个人在不同状态下看到不同的界面。

本文档是 AAF 设计系统 的体验层延伸，聚焦**交互范式**而非视觉 token。
视觉约束（颜色、字体、间距）见设计系统文档，本文聚焦"怎么交互"和"怎么体验"。

## 核心命题：界面不再是设计出来的

传统工作流：设计师设计 → 工程师实现 → 所有用户使用同一套界面。

AAF 的工作流：

```text
用户画像（角色 / 偏好 / 历史行为 / 当前状态）
  +
场景上下文（任务类型 / 设备 / 环境 / 情绪）
  +
语义组件注册表（可用的 UI 原子）
  ↓
元引擎实时组装
  ↓
为这个人、在这个时刻、为这件事生成的界面
```

**同一个"创建任务"功能**：

| 用户                 | 看到的界面                           |
| -------------------- | ------------------------------------ |
| 第一次使用的普通用户 | 一句话对话框："你想做什么？"         |
| 熟练的开发者         | DSL 编辑器 + 字段配置面板            |
| 移动端用户           | 语音输入 + 卡片确认                  |
| 视障用户             | 纯语音交互 + 屏幕阅读器优化结构      |
| 儿童用户             | 毛绒玩具风格图标 + 大按钮 + 语音引导 |

界面个性化不是"换个皮肤"，而是**组件选择、布局密度、交互模式、视觉风格**的全维度适配。

## 一、个性化界面生成

### 1.1 用户画像驱动的界面差异化

元引擎维护每个用户的界面偏好模型，驱动三个维度的差异化：

**交互密度**

```text
探索模式（新用户）    →  对话优先，隐藏配置，引导式
效率模式（熟练用户）  →  快捷键、命令面板、高密度信息
专家模式（开发者）    →  DSL 直接编辑、原始参数暴露
```

**视觉风格**

```text
系统默认    →  专业克制（见 aaf-design-system.md）
温暖活泼    →  圆角更大、配色更暖、图标更可爱
极简专注    →  去除装饰、高对比、无动效
高对比无障碍 →  WCAG AAA 标准、大字号、强对比
```

**信息密度**

```text
摘要视图    →  只看结果，细节折叠
标准视图    →  结果 + 关键参数
详细视图    →  完整信息 + 执行链路 + DSL 原文
```

### 1.2 AIGC 实时生成界面资产

AI 时代的界面资产不再是设计师手工制作的静态文件，而是**按需实时生成**：

**图标生成**

```text
用户偏好"毛绒玩具风格"
  ↓ 图标生成模型
实时生成该用户专属的毛绒质感图标集
  ↓ 缓存到用户资产库
下次加载直接复用，偏好变更时重新生成
```

支持的风格维度：

- 质感：毛玻璃 / 毛绒 / 金属 / 纸质 / 霓虹 / 水彩
- 形态：圆润 / 几何 / 有机 / 像素
- 情绪：专业 / 活泼 / 沉稳 / 可爱

**插画与背景**

- 空状态插画：根据当前模块语义实时生成，不再是通用占位图
- 背景纹理：根据用户情绪状态和时间段动态调整（晨间清爽 / 深夜沉静）
- 引导图：新功能引导图由 AI 根据实际界面截图生成，始终与当前版本一致

**动效生成**

- 过渡动效：AI 根据操作语义生成合适的过渡（删除用消散，创建用生长）
- 反馈动效：操作成功 / 失败 / 等待的动效风格与用户偏好一致
- 约束：动效服务于状态变化感知，不做纯装饰性动画

### 1.3 界面版本与回滚

个性化生成的界面需要版本管理：

```text
界面快照（每次重大生成保存）
  ↓ 用户可查看历史版本
  ↓ 一键回滚到某个版本
  ↓ 对比两个版本的差异
```

用户可以"锁定"某个界面版本，阻止自动更新，直到主动解锁。

## 二、多模态交互

### 2.1 语音交互优先

语音是最自然的人机交互方式，AAF 将语音作为**一等公民**，而非辅助功能。

**语音优先原则**：

- 任何可以用文字表达的操作，都可以用语音完成
- 语音输入与文字输入共享同一套意图理解层，不是两套系统
- 语音响应支持流式朗读，不等待完整生成

**语音交互模式**：

```text
唤醒词模式    →  "Hey AAF，帮我创建一个任务"
持续监听模式  →  开启后全程语音，适合驾驶 / 烹饪等双手占用场景
按键说话模式  →  按住说话松开发送，适合嘈杂环境
```

**语音 + 界面联动**：

```text
用户说："把这个任务的截止日期改到下周五"
  ↓ 语音识别 → 意图理解
界面高亮对应的日期字段
  ↓ 用户确认（语音"确认"或点击）
字段更新，语音播报"已更新为下周五"
```

语音不替代界面，而是与界面**双向联动**——语音操作在界面上有视觉反馈，界面操作可以触发语音播报。

**无障碍语音**：视障用户可以通过语音完成所有操作，界面结构语义化，支持屏幕阅读器完整遍历。

### 2.2 视觉与手势交互

**摄像头实时视觉**：

设备摄像头作为输入通道，支持三类视觉交互：

| 交互类型 | 场景                                      | 实现方式                   |
| -------- | ----------------------------------------- | -------------------------- |
| 手势识别 | 挥手翻页、捏合缩放、指向选择              | MediaPipe 手势模型实时推理 |
| 表情感知 | 检测用户专注度 / 疲劳度，自动调整界面密度 | 面部关键点检测             |
| 眼动追踪 | 视线停留触发预加载，凝视选择替代点击      | WebGazer.js 或设备原生 API |
| 环境感知 | 检测环境光线，自动切换深浅主题            | 摄像头亮度分析             |

**手势设计原则**：

- 手势必须有视觉反馈，不能是"盲操作"
- 关键操作（删除、提交）不能只靠手势，必须有确认步骤
- 手势可以关闭，不强制用户使用
- 手势映射可自定义，不固化

**隐私约束**：

```text
摄像头权限明确授权，不静默开启
视觉数据本地处理，不上传服务器
用户可随时关闭视觉交互，不影响其他功能
```

### 2.3 3D 空间交互

**空间交互的适用场景**：

不是所有场景都需要 3D，空间交互在以下场景有明确价值：

- **知识地图**：知识节点在 3D 空间中按语义距离分布，用户在空间中"漫游"探索
- **工作流可视化**：复杂工作流在 3D 空间展开，层级关系用 Z 轴表达
- **多任务管理**：多个工作区在空间中并排，用手势或视线切换
- **协作空间**：多用户在同一 3D 空间中协作，各自的光标和操作实时可见

**3D 交互原则**：

```text
空间是内容的容器，不是装饰
  → 3D 布局服务于信息理解，不是为了"酷"

2D/3D 无缝切换
  → 同一内容支持 2D 平面视图和 3D 空间视图切换
  → 切换时保持内容连续性，不重新加载

深度即层级
  → Z 轴距离表达信息的重要性或时间顺序
  → 近处是当前焦点，远处是背景上下文

运动即关系
  → 相关内容聚集，无关内容分散
  → 操作触发的空间运动表达语义（合并 = 靠近，删除 = 飞离）
```

**技术实现**：

- Web 端：`react-three-fiber`（Three.js React 封装）
- 物理引擎：`@react-three/rapier`（Rapier 物理引擎）
- 手势映射到 3D：MediaPipe → Three.js 坐标系转换
- 性能降级：检测到低端设备自动切换 2D 视图

## 三、物理引擎与质感设计

### 3.1 物理引擎的交互价值

物理引擎不是游戏专属，在 UI 中引入真实物理模拟，能带来**直觉性**和**沉浸感**：

**弹性与惯性**

```text
卡片拖拽：松手后有弹性回弹，不是瞬间停止
列表滚动：有惯性，手指离开后继续滑动并自然减速
抽屉展开：有重力感，快速滑动时展开更快
```

**碰撞与堆叠**

```text
通知卡片：新通知"落入"通知列表，有轻微碰撞动效
任务拖拽排序：被拖拽的卡片"压住"其他卡片，其他卡片自动让位
文件拖入：文件"落入"目标区域，有轻微弹跳
```

**流体与粒子**

```text
AI 思考中：流体粒子动效表达"正在处理"，比转圈更有生命感
知识检索：相关知识节点像磁铁一样被"吸引"到结果区域
数据流：工作流执行时，数据在节点间"流动"
```

**约束**：物理效果必须可关闭（无障碍 / 性能模式），动效时长不超过 300ms，不影响操作响应速度。

### 3.2 质感设计体系

AIGC 使得高质量质感设计的成本趋近于零，AAF 支持多套质感主题，用户可选择或自定义：

**毛玻璃（Glassmorphism）**

```css
/* 毛玻璃卡片 */
background: oklch(1 0 0 / 0.12);
backdrop-filter: blur(20px) saturate(180%);
border: 1px solid oklch(1 0 0 / 0.2);
box-shadow: 0 8px 32px oklch(0 0 0 / 0.08);
```

适用场景：深色背景上的浮层、对话区消息气泡、通知卡片。
不适用：高密度信息列表（模糊影响可读性）。

**柔软质感（Soft UI / Neumorphism）**

```css
/* 柔软凸起按钮 */
background: oklch(0.94 0.006 250);
box-shadow:
  6px 6px 12px oklch(0.80 0.01 250),
  -6px -6px 12px oklch(1 0 0);
```

适用场景：儿童模式、健康类模块、低压力操作区。
不适用：高对比度需求场景（无障碍不友好）。

**材质纹理**

- 纸质：文档编辑区，降低长时间阅读的视觉疲劳
- 磨砂金属：工具栏、操作面板，传递精密感
- 织物：个人空间、偏好设置，传递温暖感

**护眼模式**

```text
色温调节：根据时间段自动调整色温（白天冷白，傍晚暖黄）
亮度自适应：根据环境光（摄像头感知）自动调整屏幕亮度
对比度柔化：降低纯黑纯白的极端对比，使用 oklch(0.12) 替代纯黑
蓝光过滤：夜间模式自动降低蓝光分量（降低 oklch 色相角中的蓝色权重）
```

### 3.3 动画设计原则

**动效的唯一目的是传递信息**，不是装饰：

| 动效类型                  | 传递的信息          | 时长        |
| ------------------------- | ------------------- | ----------- |
| 生长（scale up）          | 创建、出现          | 200ms       |
| 消散（fade + scale down） | 删除、消失          | 150ms       |
| 滑入（slide in）          | 导航、层级进入      | 250ms       |
| 弹性（spring）            | 确认、成功          | 300ms       |
| 抖动（shake）             | 错误、拒绝          | 200ms       |
| 脉冲（pulse）             | 等待、处理中        | 循环 800ms  |
| 流动（flow）              | AI 生成中、数据传输 | 循环 1200ms |

**缓动函数**：

```css
/* 进入：先快后慢，有落地感 */
--ease-out: cubic-bezier(0.0, 0.0, 0.2, 1);

/* 退出：先慢后快，有离开感 */
--ease-in: cubic-bezier(0.4, 0.0, 1, 1);

/* 强调：弹性，有生命感 */
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
```

**减少动效模式**：尊重系统 `prefers-reduced-motion` 设置，开启时所有动效降级为瞬间切换。

## 四、沉浸式体验

### 4.1 专注模式

深度工作时，界面主动退到背景：

```text
触发：用户连续专注操作 > 5 分钟，或主动开启
效果：
  - 工具栏、导航栏自动隐藏
  - 助理区折叠为最小化气泡
  - 背景色降低对比度，减少视觉干扰
  - 关闭所有非紧急通知
  - 可选：环境音（白噪音 / 自然音）
退出：鼠标移到边缘 / 语音"退出专注" / 快捷键
```

### 4.2 沉浸式阅读与编辑

文档编辑区支持"沉浸模式"：

```text
全屏展开，隐藏所有 UI 框架
字体放大，行距增加，边距加宽
背景切换为护眼纸质纹理
光标变为柔和的竖线，不闪烁
段落间距随内容密度自动调整
```

### 4.3 空间音效

声音是被忽视的交互维度，AAF 支持可选的空间音效：

```text
操作反馈音：轻柔的点击音、滑动音、确认音（非系统默认音）
AI 响应音：流式输出时有轻微的"打字"质感音
通知音：根据紧急程度有不同音调，不使用刺耳的警报音
空间感：3D 视图中，远处的内容音效更小，近处更大
```

所有音效默认关闭，用户主动开启，且可单独控制每类音效的开关和音量。

### 4.4 XR 扩展（未来方向）

当前为概念设计，随硬件普及逐步落地：

**AR 叠加**：将工作区内容叠加到现实环境，在桌面上"放置"虚拟便签和任务卡片。

**VR 工作空间**：在虚拟空间中拥有无限大的工作区，多个工作区在空间中并排，用手势切换。

**空间计算（Apple Vision Pro 等）**：

- 眼动 + 手势替代鼠标
- 窗口在空间中自由摆放
- 与现实物体交互（扫描实体文档导入知识库）

## 六、设计原则

**个性化不等于混乱**：所有个性化变体都在 `aaf-design-system.md` 定义的 token 约束内生成，不允许超出设计系统边界。

**渐进增强**：基础功能在任何设备、任何模态下都可用；高级体验（3D、手势、物理引擎）是增强层，不是必须层。

**用户主权**：所有个性化设置用户可查看、可修改、可重置。AI 推断的偏好只是建议，用户确认后才生效。

**性能优先**：体验增强不能以牺牲响应速度为代价。物理引擎、3D 渲染在低端设备自动降级，核心交互响应始终 < 100ms。

**隐私边界**：摄像头、麦克风数据本地处理，不上传。用户画像存储在用户私有区，不用于广告或第三方分析。
