# 任务管理规范

## 基本原则

- **需求优先**：开发新功能前，必须先有用户故事及需求规格（`docs/prd/`），没有则先明确需求再创建任务
- 每个迭代版本一个任务文件
- 开发新功能前，先确认任务已在对应迭代的任务列表中
- 任务不在列表中时，先添加任务再开发

## 编号体系

| 层级 | 编号格式 | 管理位置 | 说明 |
|------|---------|---------|------|
| 用户故事 | `AAF-{三位序号}` | backlog | 全局递增，不按版本重置 |
| 技术任务 | `#{递增数字}` | 迭代文件 | 全局递增，跨迭代不重置 |
| Bug | `BUG-{三位序号}` | 用户故事目录 | 全局递增，跨用户故事、跨迭代不重置 |

- 新用户故事取 backlog 当前最大编号 +1，添加后同步更新 backlog 顶部最大编号行
- 新技术任务取迭代文件中当前最大 # 编号 +1
- 新 Bug 取全局最大 BUG 编号 +1（查看各用户故事目录下的 bugs.md）
- 提交时在脚注中关联技术任务：`Task: #N`

## 文件命名

```
docs/task/aaf-{version}.md
```

示例：`aaf-v1.0.0.md`、`aaf-v1.1.0.md`

## 任务状态标记

| 标记 | 含义 |
|------|------|
| `[ ]` | 待开始 |
| ⏳ | 进行中 |
| ✅ | 已完成 |
| ❌ | 已取消 |
| 🚫 | 阻塞中 |

## 任务格式

```markdown
1. ✅ 任务描述（已完成） - 负责人
2. ⏳ 任务描述 → `相关文件路径`
3. [ ] 任务描述
```

- 已完成的任务标注负责人
- 有产出文件的任务用 `→` 指向目标路径

## 迭代文件格式

每个迭代任务文件是**版本规划阶段**的产物，说明本迭代的目标和业务需求范围，不包含技术任务（技术任务在启动阶段由 architect 拆分，记录在用户故事的 `docs/task/v{version}/AAF-XXX/tasks.md` 文件中）。

必须包含：

1. **迭代目标**：一句话说明本迭代要达成什么
2. **周期**：开始和结束日期
3. **业务需求列表**：每条业务需求用标题 + 简要描述说明范围和价值
4. **变更记录**：记录迭代范围的调整历史

```markdown
## 业务需求

### {业务需求标题}

{简要描述范围和价值}

## 变更记录

| 日期 | 变更内容 | 原因 |
|------|---------|------|
```

- 业务需求由**协调者**根据版本规划讨论提出草稿，**人类确认**后定稿
- 业务需求不使用 AAF 编号（AAF 编号属于 backlog 中的一级用户故事，由 product 细化后分配）
- 一个迭代建议 **3-7 条**业务需求（受 2-4 周周期约束）
- 模板见 [iteration-template.md](../../.kiro/skills/iteration-management/references/iteration-template.md)
- 拆分规则见 [需求管理规范](../reference/dev/requirement-standard.md#需求拆分)

模板见 [iteration-template.md](../../.kiro/skills/iteration-management/references/iteration-template.md)。

## 工作流程

1. **领取任务**：从当前迭代任务列表中选择 `[ ]` 状态的任务，改为 ⏳
2. **新增任务**：当前列表没有时，在末尾追加，标记 `[ ]`
3. **新建迭代**：当前版本任务全部完成后，按命名规范创建下一个版本文件
4. **完成任务**：将 ⏳ 改为 ✅，补充负责人

## Bug 管理

Bug 在用户故事目录中管理，与产生它的功能绑定，便于追溯和归档。

### 存放位置

```
docs/task/v{version}/AAF-XXX/bugs.md
```

### 工作流程

1. **发现 Bug**：开发自测或测试验收时发现 Bug
2. **登记**：在对应用户故事目录创建或更新 `bugs.md`，填入待修复表格
3. **修复**：developer 修复后移到已修复表格，关联提交
4. **验证**：tester 验证修复，确认关闭

### 与外部问题的区分

| 类型 | 管理位置 | 说明 |
|------|---------|------|
| 项目内部 Bug | `v{version}/AAF-XXX/bugs.md` | 本项目代码缺陷 |
| 外部依赖问题 | `reference/dev/known-issues.md` | 第三方库/工具的已知问题 |

模板见 [_template/bugs.md](_template/bugs.md)。
