# AAF-099 会员订阅 SKU UI 设计

> 本文以 [requirement.md v1.0.1](./requirement.md) 和 [design.md](./design.md) 为锚点。会员交易与生命周期管理的唯一入口是 `/studio/me/membership`；Workspace pricing 只接入同一套餐目录展示并引导至会员页；`/studio/me/pricing` 继续作为模型积分计价页，不在本设计范围内。

## 设计结论

- Plan 作为稳定档位卡片，SKU 作为月、季、年可售规格；页面只展示接口返回的明示价格，不从其他周期价格计算。
- `BillingCycleToggle` 扩为“月付 / 季付 / 年付”；切换只选择付费 Plan 的当前展示 SKU，FREE 始终是一张固定卡片。
- `/studio/me/membership` 增加“当前订阅”管理区，并接通新购、跨 Plan 升级、同 SKU 手动续费、取消、降级及撤销降级。
- `SubscriptionPayDialog` 是唯一支付界面，保留现有渠道选择、支付宝跳转、二维码、订单轮询和支付结果处理；不得复制支付弹窗、渠道列表或轮询逻辑。
- 降级使用 `Dialog` 选择目标 SKU，再使用 `AlertDialog` 确认；取消与撤销降级使用 `AlertDialog` 二次确认。
- Workspace pricing 复用 `BillingCycleToggle`、`PlanCard`、`PlanCompareTable` 和目录数据，仅展示并跳转会员页，不复制订阅管理和支付状态。
- 会员套餐文案只描述会员档位、SKU 周期、权益和订阅动作；积分商品购买入口、充值按钮及充值订单文案不得混入。FAQ 可说明两条商品链路彼此独立。

## 真实现状与调整边界

| 现有实现 | 真实状态 | 本设计要求 |
|----------|----------|------------|
| `/studio/me/membership` | 已查询套餐与当前订阅；`PlanCard.onSubscribe` 为空；无管理区 | 接入唯一支付弹窗和已有生命周期接口，增加当前订阅、pending 与操作状态 |
| Workspace pricing | 已复用套餐卡、切换器、对比表；CTA 打开“联系客服开通”Dialog | 改为 SKU 明示价展示，CTA 前往会员页；移除人工开通中转，不在此页复制交易流程 |
| `PlanCard` | 读取 Plan 月价/年价，计算年度展示、等效月价和积分性价比 | 改为读取选中 SKU；不展示由其他字段计算出的价格、节省比例或性价比标签 |
| `BillingCycleToggle` | 只有按月/按年，并显示“省更多” | 改为月付/季付/年付三段，不携带优惠暗示 |
| `PlanCompareTable` | 桌面展示权益并在移动端隐藏 | Workspace pricing 继续复用；数据来自 Plan 权益，不按 SKU 复制权益列 |
| `SubscriptionPayDialog` | 已有支付渠道、跳转/扫码、轮询、成功与订单关闭处理；入参为 Plan + cycle | 仅将商品入参切为 SKU；保留原支付状态机和查询刷新，不建立第二套流程 |
| Dialog / AlertDialog | `Dialog` 用于表单/选择；`AlertDialog` 用于不可忽略的确认 | 沿用受控 `open/onOpenChange`、焦点锁定、取消/确认按钮和提交 pending 惯例 |
| `Badge` | 已用于当前范围、只读、支付等待等状态 | 用文字 + 语义 variant 表达订阅状态，不只依赖颜色 |

## 信息架构

### 会员页

页面沿用当前 Studio 外壳、`max-w-6xl` 内容宽度和 `SectionHaze`，主体顺序固定如下：

```text
┌──────────────────────────────────────────────────────────────┐
│ 会员套餐                                      [当前档位 Badge]│
├──────────────────────────────────────────────────────────────┤
│ 当前订阅                                                     │
│ [Plan / SKU 周期 / 状态] [开始时间 / 到期时间]               │
│ [取消状态] [pending 降级目标] [续费] [取消] [撤销降级]       │
├──────────────────────────────────────────────────────────────┤
│                         [月付] [季付] [年付]                  │
│ [FREE] [PRO 当前周期 SKU] [TEAM 当前周期 SKU] [ENTERPRISE]   │
├──────────────────────────────────────────────────────────────┤
│ 常见问题                                                     │
├──────────────────────────────────────────────────────────────┤
│ 会员订阅免责声明与联系方式                                  │
└──────────────────────────────────────────────────────────────┘
```

“当前订阅”先于目录出现，让已有会员先确认状态和可用动作；无有效付费订阅时仍显示紧凑 FREE 状态，不用空白替代。目录卡片保持一 Plan 一卡，不按 SKU 展开成十二张卡。

### Workspace pricing

Workspace pricing 保留现有 Hero、信任信息、周期切换、四档套餐卡、桌面权益对比、FAQ 和免责声明。调整边界如下：

- Hero 说明改为“月、季、年均为独立购买规格，价格以页面明示为准”。
- 使用与会员页相同的 Plan/SKU 选择器和显示规则，保证两个页面价格、周期与权益一致。
- Plan CTA 统一为“前往会员中心”，跳转 `/studio/me/membership`；可携带 `cycle=MONTH|QUARTER|YEAR` 和可选 `skuCode` 作为初始展示意图，但会员页必须用最新目录重新校验，不直接发起订单。
- 当前 Plan 只显示 `Badge`“当前档位”，不在 Workspace pricing 提供续费、取消、降级或支付 Dialog。
- `PlanCompareTable` 继续只按 Plan 对比权益；月、季、年 SKU 共享同一 Plan 权益，不新增重复列。
- 移除“联系客服开通”中转 Dialog；联系客服仍可保留在页面底部联系信息中，但不是订阅主路径。

## 数据与本地状态

### 服务端数据来源

| UI 数据 | 来源 | 使用位置 | 规则 |
|---------|------|----------|------|
| Plan、`skus[]`、权益、Plan `sort` | `GET /api/billing/subscription-plans/catalog` | 两个套餐页面、卡片、对比表、降级 SKU 选择 | 只展示 ENABLED 目录数据；FREE 的内部 SKU 不作为购买规格展示 |
| 当前 Plan/SKU、周期、起止时间、状态、`cancelledAt`、pending SKU | `GET /api/billing/subscriptions/me` | 当前订阅区、动作矩阵、卡片状态 | `data=null` 表示没有 ACTIVE 订阅；不得用本地状态伪造订阅变化 |
| FAQ | 既有 `useMemberFaq` / `member.faq` | 两页 FAQ | 以服务端内容为准；不得维护前端权益矩阵副本 |
| 支付订单金额与状态 | 既有 subscribe 返回的 `PayOrderVO` + 支付订单查询 | `SubscriptionPayDialog` | 订单金额是最终支付显示真理；升级补差价不得由前端估算 |
| mutation 后结果 | `/subscribe`、`/me/cancel`、`/me/downgrade`、`/me/pending-downgrade` | 支付、取消、降级、撤销 | 成功后失效目录、当前订阅、权益额度和积分查询；不复制到 Zustand |

### 页面本地状态

| 状态 | 类型 | 初始值与清理 |
|------|------|--------------|
| `selectedCycle` | `MONTH | QUARTER | YEAR` | 默认优先当前付费 SKU 周期；否则默认 `YEAR`；URL 有合法 cycle 时可覆盖；目录变化后重新校验 |
| `selectedPaySku` | `SubscriptionSkuVO | null` | 点击新购、升级或续费时设置；支付 Dialog 关闭后清空 |
| `payDialogOpen` | boolean | 仅由有效 `selectedPaySku` 打开；关闭不修改订阅 |
| `downgradePlan` | `SubscriptionPlanVO | null` | 点击低档 Plan 后设置；Dialog 完全关闭后清空 |
| `selectedDowngradeSkuCode` | string 或 null | 默认选中全局周期对应的可用 SKU；用户可改选目标 Plan 的其他启用周期 |
| `downgradeConfirmOpen` | boolean | 目标 SKU 有效后打开；确认成功或取消后清理 |
| `cancelConfirmOpen` | boolean | 当前为有效付费订阅且尚未取消时可打开 |
| `cancelPendingConfirmOpen` | boolean | 仅 `pendingSku != null` 时可打开 |

Plan 关系由 `currentPlan.sort` 与目标 `plan.sort` 派生；前端不得提交 `NEW / UPGRADE / RENEW` 操作类型。查询失败时不得回退为 FREE 后继续交易，因为无法可靠判定动作。

## 周期与价格展示

### `BillingCycleToggle`

- 三个选项固定为“月付”“季付”“年付”，值分别为 `MONTH`、`QUARTER`、`YEAR`。
- 使用现有 `radiogroup` 结构；移除任何“更省”“优惠”等 badge。
- 切换后每个付费 Plan 从 `plan.skus` 精确匹配 `billingCycle`；找不到时该 Plan 仍保留卡位并显示不可售态，避免网格跳动。
- FREE 不参与周期匹配，不随切换重建、重复或改变价格，始终显示 `¥0` 与“免费套餐”。
- Workspace pricing 和会员页共用相同 cycle 值与映射，不维护大小写不同的第二套周期类型。

### `PlanCard`

卡片仍使用现有主题、推荐标记和权益列表，但价格区与 CTA 改为 SKU 语义：

```text
┌──────────────────────────┐
│ [推荐]          [当前档位]│
│ 专业版                    │
│ 适合个人创作者            │
│                          │
│ ¥82 / 季                  │
│ 参考价 ¥117（如后端提供） │
│ 每月会员积分 3,000        │
│ [升级至专业版]            │
│ ──────────────────────── │
│ ✓ 图像生成                │
│ ✓ 视频生成                │
└──────────────────────────┘
```

- 实付价直接读取选中 SKU `price`；参考价只可直接读取同一 SKU `marketPrice`，标签固定为“参考价”，不计算比例、节省金额、等效月价或性价比。
- 金额单位由分格式化为元，保留接口精度；周期后缀为“/月”“/季”“/年”。
- 每月会员积分是 Plan 权益说明，文案固定为“每月会员积分”，不得把季度/年度 SKU 描述为一次性发放 3/12 个月积分。
- 权益只读取 `plan.entitlements`；BOOLEAN 使用“可用/—”，COUNTABLE 使用后端额度与重置周期。不得硬编码 AIGC 权益矩阵。
- 当前同一 SKU 显示 `Badge`“当前规格”，卡片按钮为“当前套餐”且禁用；手动续费只从当前订阅管理区发起。
- 当前同 Plan 的其他 SKU 显示按钮“本期暂不支持换周期”且禁用，并在可访问描述中说明“可继续使用当前规格或续费当前规格”。
- 选中周期无启用 SKU 时价格显示“该周期暂不可售”，按钮显示“暂不可购买”且禁用。
- FREE 当前用户显示“当前免费套餐”；付费用户的 FREE 卡显示“降级到免费套餐”，走降级确认，不进入支付弹窗。
- `isPending` 只禁用当前正在提交的业务动作；不要用一个全页 pending 永久锁死全部可读内容。

## 当前订阅管理区

### 信息层级

| 字段 | 展示 | 空值规则 |
|------|------|----------|
| 当前 Plan | 名称 + `Badge` | 无 ACTIVE 数据时显示“免费套餐” |
| 当前 SKU | “月付 / 季付 / 年付” + 可选 `skuCode` 次级文本 | FREE 显示“免费规格”，不暴露 `FREE_DEFAULT` 为购买项 |
| 状态 | 文字 Badge | 不只用颜色表达 |
| 生效时间 | `YYYY-MM-DD HH:mm` | 有订阅才显示 |
| 到期时间 | `YYYY-MM-DD HH:mm` | FREE 显示“长期有效”；未知显示“—” |
| 取消状态 | “已取消，权益保留至 {endAt}” | `cancelledAt=null` 不占位 |
| pending | 目标 Plan、周期、价格、生效节点与收费边界 | `pendingSku=null` 不显示 |

状态展示优先级：

1. `status=ACTIVE && cancelledAt!=null`：Badge“已取消·到期生效”，同时保留 ACTIVE 语义说明。
2. `status=ACTIVE && paid SKU`：Badge“生效中”。
3. `status=ACTIVE && FREE`：Badge“免费套餐”。
4. `status=EXPIRED`：Badge“已到期”。
5. `status=CANCELLED`：Badge“已结束”。
6. 未知值：Badge“状态待确认”，禁用交易动作并提供刷新。

`pendingSku` 与当前状态分开显示，不覆盖当前 Plan：

```text
待生效降级
将于当前周期结束后处理：专业版 · 季付（PRO_Q1）
本次预约不收费。到期时不会发起扣款；如需使用该付费规格，请在到期后手动购买，否则将回到免费套餐。
[撤销降级]
```

目标为 FREE 时改为：“到期后切换至免费套餐，不产生费用。”

### 操作区

- “续费当前套餐”：仅 ACTIVE 付费 SKU 可用，即使存在 `cancelledAt` 或 pending 仍可续费；打开支付弹窗并固定当前 `skuCode`，不提供换周期。
- “取消订阅”：仅 ACTIVE 付费且 `cancelledAt=null` 可用；确认后保留当前周期。已取消时隐藏按钮，显示状态说明。
- “撤销降级”：仅 pending 存在时可用；成功只移除 pending 提示，不改变当前卡片和日期。
- FREE、EXPIRED、CANCELLED 或当前查询不可信时不展示续费/取消按钮；购买动作由套餐目录提供。

## 按钮文案与可用动作矩阵

### Plan 卡动作

| 当前状态 | 目标卡 / SKU | 按钮文案 | 可用 | 后续交互 |
|----------|---------------|----------|------|----------|
| 无 ACTIVE 或 FREE | FREE | 当前免费套餐 | 否 | 无 |
| 无 ACTIVE 或 FREE | 任一启用付费 SKU | 购买{月付/季付/年付} | 是 | 打开 `SubscriptionPayDialog`，服务端判定 NEW |
| ACTIVE 付费 | 当前同一 SKU | 当前套餐 | 否 | 续费从管理区发起 |
| ACTIVE 付费 | 同 Plan 其他周期 SKU | 本期暂不支持换周期 | 否 | 不创建订单；提供禁用原因 |
| ACTIVE 付费 | 更高档 Plan 的启用 SKU | 升级至{Plan 名称} | 是 | 打开同一支付 Dialog，服务端判定 UPGRADE |
| ACTIVE 付费 | 更低档付费 Plan | 选择降级规格 | 是 | 打开目标 SKU 选择 Dialog，不打开支付 |
| ACTIVE 付费 | FREE | 降级到免费套餐 | 是 | 直接进入降级确认，不打开支付 |
| 任意 | 选中周期无 SKU | 暂不可购买 | 否 | 显示不可售说明 |
| 当前订阅查询失败 | 任一交易目标 | 刷新后操作 | 否 | 重试当前订阅查询 |
| 任一 mutation 提交中 | 本次动作 | 处理中… | 否 | 防止重复提交 |

### 管理区动作

| 当前状态 | pending | 续费当前套餐 | 取消订阅 | 撤销降级 |
|----------|---------|--------------|----------|----------|
| ACTIVE 付费、未取消 | 无 | 可用 | 可用 | 隐藏 |
| ACTIVE 付费、未取消 | 有 | 可用 | 可用 | 可用 |
| ACTIVE 付费、已取消 | 无 | 可用 | 隐藏 | 隐藏 |
| ACTIVE 付费、已取消 | 有 | 可用 | 隐藏 | 可用 |
| ACTIVE FREE | 任意 | 隐藏 | 隐藏 | 仅数据异常时显示刷新，不提交动作 |
| EXPIRED / CANCELLED / null | 任意 | 隐藏 | 隐藏 | 隐藏 |
| 查询加载或失败 | 未知 | 禁用 | 禁用 | 禁用 |

存在已取消标记时续费成功会由服务端清除该标记；存在 pending 时续费不会清除 pending，页面刷新后必须继续展示新的到期时间和原 pending 目标。

## 交互流程

### 新购

1. 用户切换月付、季付或年付，页面为每个付费 Plan 选出同周期 SKU；FREE 保持不变。
2. 用户点击“购买季付”等 CTA；页面保存唯一 `selectedPaySku`。
3. 打开现有 `SubscriptionPayDialog`，标题为“购买 {Plan 名称} · {周期}”。
4. 用户选择已有支付渠道并继续；请求只发送 `skuCode + channelCode`。
5. 未创建订单前显示 SKU 明示价；订单创建后以 `PayOrderVO.amount` 为最终应付金额。
6. 支付成功后关闭弹窗并刷新目录、当前订阅、权益和积分查询；卡片与管理区从服务端新状态重绘。

### 跨 Plan 升级

1. 当前有效付费用户点击更高档 Plan 的所选 SKU。
2. 支付弹窗标题为“升级至 {Plan 名称} · {周期}”，价格区显示“目标规格价格”，并提示“实际应付金额由系统按当前订阅剩余时间计算，以支付订单为准”。
3. 前端不计算剩余价值，也不提交 UPGRADE 类型；服务端创建订单后显示订单实际金额。
4. 支付成功后目标 Plan/SKU 立即生效；页面刷新当前起止时间、权益和状态。
5. 订单未成功时当前订阅、权益、日期与积分展示不做乐观修改。

### 同 SKU 手动续费

1. 用户在当前订阅区点击“续费当前套餐”。
2. 页面固定传入当前 `skuCode`、Plan 名称、周期和 SKU 明示价；弹窗内没有周期切换。
3. 标题为“续费 {Plan 名称} · {周期}”；说明“支付成功后将从当前到期时间顺延 {cycleMonths} 个自然月”。
4. 支付成功后刷新页面，显示新的 `endAt`；如原来已取消，取消状态消失。
5. 不展示“立即获得未来月份积分”或“重置当前用量”等承诺。

### 取消订阅

点击“取消订阅”打开 `AlertDialog`：

- 标题：“确认取消当前订阅？”
- 描述：“当前权益保留至 {endAt}，本次操作不退款。到期前仍可续费当前规格；到期未续费将回到免费套餐。”
- 次按钮：“暂不取消”
- 主按钮：“确认取消”

提交期间主按钮为“取消中…”，禁用关闭与重复提交。成功后关闭弹窗、刷新当前订阅，并在管理区显示“已取消·到期生效”；失败时保持弹窗与原状态，显示可重试反馈。

### 降级目标 SKU 选择与确认

付费低档 Plan 使用两阶段交互：

1. 点击“选择降级规格”打开 `Dialog`，标题“选择降级目标规格”。
2. Dialog 顶部只读显示当前 Plan/SKU 和到期时间；下方按月付、季付、年付列出目标 Plan 的启用 SKU。
3. 每个选项显示周期、`skuCode` 次级文本和 SKU 明示价，使用单选语义；默认选择全局周期对应 SKU，没有匹配项则选择 sort 最前的启用 SKU。
4. 底部按钮为“取消”和“下一步”；无可售 SKU 时显示“该套餐暂无可用降级规格”，禁用下一步。
5. 点击下一步关闭选择 Dialog 并打开 `AlertDialog` 确认。

确认文案：

- 标题：“确认降级至 {Plan 名称} · {周期}？”
- 描述：“仅记录到期后的目标，不立即切换、不收费。当前权益保留至 {endAt}。目标为付费规格时，到期不会发起扣款；如需继续使用该规格，请在到期后手动购买，否则将回到免费套餐。”
- 次按钮：“返回选择”
- 主按钮：“确认降级”

FREE 没有可支付 SKU 列表，点击 FREE 卡直接确认：

- 标题：“确认降级到免费套餐？”
- 描述：“当前权益保留至 {endAt}，到期后切换至免费套餐，不产生费用。”
- 主按钮：“确认降级”

确认请求只发送目标 `skuCode`；FREE 使用技术契约规定的内部目标编码，但页面不把它呈现为可购买商品。成功后刷新并显示 pending，不改变当前 Plan、SKU、权益和到期时间。

### 撤销降级

点击“撤销降级”打开 `AlertDialog`：

- 标题：“撤销待生效降级？”
- 描述：“将移除降级至 {目标 Plan} · {周期} 的安排，当前套餐与到期时间保持不变。”
- 次按钮：“保留安排”
- 主按钮：“确认撤销”

成功后只移除 pending 面板；失败时保持 pending 和弹窗，不做本地清除。

### 支付结果与关闭

| 事件 | 弹窗反馈 | 页面结果 |
|------|----------|----------|
| 创建订单中 | 主按钮“处理中…”，渠道与关闭外动作禁用 | 不改变订阅 |
| 支付宝跳转 | 沿用“已在新标签页打开支付宝收银台…”与等待 Badge | 继续轮询订单 |
| 二维码支付 | 沿用二维码、金额、订单号和“等待支付…” Badge | 继续轮询订单 |
| 支付成功 | 提示“支付成功，订阅状态已更新”，关闭弹窗 | 失效并刷新四类查询 |
| 请求失败 | 提示“支付请求失败，请重试”，保留渠道和所选 SKU | 当前订阅不变 |
| 订单关闭 | 提示“订单已关闭，请重新发起支付”，回到渠道选择 | 当前订阅不变 |
| 用户关闭弹窗 | 清理弹窗临时二维码/跳转状态，不宣称订单成功或失败 | 不调用取消/降级/积分接口，不做乐观变更 |
| 轮询网络异常 | 保持等待状态，不连续弹出错误；页面重新可见时沿用现有补查 | 当前订阅不变 |

用户关闭已创建订单的弹窗不等于关闭支付订单。若服务端返回“已有待支付订阅订单”，页面展示该明确错误，不创建第二笔订单；本设计不增加订单关闭接口。

## 加载、空态与错误态

### 会员页状态

| 状态 | 表现 | 动作 |

| 当前订阅加载中 | 当前订阅区 Skeleton；套餐可展示，但所有交易 CTA 显示“状态加载中”并禁用 | 防止错误分类 |
| 套餐空 | 保留标题和当前订阅区；目录显示“暂无可用会员套餐” | “重新加载” |

### Workspace pricing 状态

- 套餐加载沿用现有四卡 Skeleton。
- 套餐空显示“暂无可用套餐”和“重新加载”。
- 查询失败显示局部错误与重试；不把失败解释为免费套餐。
- 当前订阅失败不影响目录阅读，但隐藏“当前档位”标识；CTA 仍只前往会员页，不在本页提交交易。
- `PlanCompareTable` 仅在 Plan 至少两项且权益非空时渲染；移动端由 PlanCard 权益列表承担阅读，不出现空表壳。

### 文案边界

- 可说“手动续费”“到期前仍可续费”“到期时不会发起扣款”。
- 可说“目标规格价格”“订单实际应付金额”“参考价”，但不得根据其他周期生成价格、比例、节省额或“更划算”结论。
- 套餐月度积分只作为 Plan 附加权益展示；不得出现“购买积分包即可升级套餐”“充值可增加会员权益额度”等混合承诺。
- FAQ 必须明确会员订阅与积分商品是独立链路，但会员卡 CTA、支付标题和确认按钮不得使用“充值”或“购买积分”措辞。
- 联系客服是支付渠道中的既有选项或底部联系方式，不替代可用的标准支付主路径。

## 响应式设计

| 断点 | 套餐网格 | 当前订阅区 | Dialog / AlertDialog | 对比表 |
|------|----------|------------|----------------------|--------|
| `xl` 及以上 | 四列 | 信息两列，动作右对齐 | 居中，支付约 400px；SKU 选择最大 560px | 显示 |
| `sm` 至 `xl` | 两列 | 信息与动作分两行 | 居中且宽度不超过视口减 32px | `md` 起显示并允许横向滚动 |
| 小于 `sm` | 单列 | 单列堆叠，按钮全宽 | 宽度 `calc(100vw - 24px)`；SKU 选项单列；底部按钮堆叠或等宽 | 隐藏，以卡片权益替代 |

移动端细则：

- 周期切换保持三段同屏；空间不足时缩短为“月付/季付/年付”，不换成下拉框，不横向截断选中态。
- 当前订阅 Plan、状态 Badge 和日期纵向排列；长 `skuCode` 可换行，不能挤出视口。
- PlanCard 不依赖 hover；CTA 与权益始终可见，触控目标至少 `44px`。
- pending 说明完整展示，不因卡片高度省略“到期不扣款”的关键边界。
- 支付弹窗沿用现有移动渠道筛选：移动端支付宝使用手机网站支付；微信内环境按现有可见渠道回退。
- 支付二维码在窄屏不超过内容宽度；订单号允许断行或复制，不造成水平滚动。
- 软键盘、系统安全区和浏览器底栏不得遮挡 Dialog 主按钮。

## 可访问性

- 周期切换使用 `role="radiogroup"` 和可访问名称“订阅周期”；每项使用 `role="radio"`、`aria-checked`，支持 Tab 进入、方向键切换、Enter/Space 选择。
- PlanCard 使用 `article` + 可访问标题；只有 CTA 是按钮，不把整卡同时设为按钮，避免权益文本和按钮嵌套冲突。
- 禁用 CTA 同时提供可感知原因：可见文案、`aria-describedby` 或紧邻说明；不能只降低透明度。
- Badge 必须包含“生效中”“待生效降级”等文字，绿色、黄色、灰色仅作辅助。
- 日期使用 `<time dateTime>`；界面按用户本地时区格式化，并在确认 Dialog 中展示完整日期时间。
- `Dialog` 打开后初始焦点落在首个可选 SKU 或支付渠道；关闭后焦点返回触发按钮。
- `AlertDialog` 初始焦点优先落在取消按钮，危险/重要动作不因按 Enter 被意外触发；Escape 行为沿用组件默认。
- mutation 进行中设置 `aria-busy=true`，动态成功/失败消息通过 `aria-live="polite"` 宣布；订单关闭等错误使用可读文本。
- 支付渠道图标为装饰时 `alt=""`，渠道按钮的可访问名称由文字提供；二维码附近必须有渠道和金额文字说明。
- Skeleton 标记加载语义但不被重复朗读；加载完成后将焦点保持在原位置，不自动跳到套餐卡。
- 所有正文和次级文字满足设计系统对比度；焦点环不可被卡片 overflow 裁切；动效遵循 `prefers-reduced-motion`。

## 验收映射

| 需求验收场景 | UI 设计映射 | 验证要点 |
|--------------|-------------|----------|
| 套餐目录返回月季年独立 SKU | 周期与价格展示、数据来源 | 三段切换精确匹配 `skus[]`；FREE 一张；无 `yearlyPrice` 依赖 |
| 前端不推导周期价格 | PlanCard 价格规则、文案边界 | PRO 三周期显示各自 SKU 价格；无乘法、比例、等效月价或节省额 |
| 新购复用已有支付弹窗 | 新购流程、支付结果 | 只打开 `SubscriptionPayDialog`；发送 `skuCode + channelCode`；成功刷新四类查询 |
| 前端订阅管理区接通既有生命周期接口 | 当前订阅区、动作矩阵 | 续费/取消/降级/撤销分别调用既有四个入口，无本地伪状态 |
| 未支付不得激活 SKU | 支付结果与关闭 | 失败、关闭、用户退出均不改变当前订阅、权益、日期和积分展示 |
| 同 SKU 手动续费从原到期时间顺延 | 续费流程 | 固定当前 SKU；成功后以服务端新 `endAt` 展示，不从前端计算落库值 |
| 续费不触发升级结算或提前发放 | 续费说明 | 不展示升级清算、提前积分或权益重置成功反馈 |
| 支付回调重放不重复续期 | 支付结果 | UI 只按刷新后的单一服务端状态展示，不对成功事件本地累加日期 |
| 跨 Plan 升级继续按剩余时间补差价 | 升级流程 | 不在客户端估算；订单金额作为最终支付金额 |
| 会员等级不按周期总价比较 | 动作派生 | Plan `sort` 决定升降级，价格只用于展示 |
| 降级保存目标 SKU并延迟生效 | 降级选择/确认、pending | 选择唯一 SKU；确认说明不立即收费/切换；成功后当前状态不变并显示 pending |
| 撤销降级只清除 pending 目标 | 撤销流程 | pending 消失，当前 Plan、SKU、endAt 和权益保持 |
| 付费降级目标不得触发渠道扣款 | pending 文案、确认文案 | 明确到期不发起扣款、需到期后手动购买，否则 FREE |
| 取消后权益保留且仍可手动续费 | 取消流程、动作矩阵 | ACTIVE + cancelled 状态可续费；显示权益截止时间；成功续费后刷新取消标记 |
| 到期未续费冻结到 FREE | 当前订阅状态 | 刷新后显示 FREE；旧状态不在前端模拟切换 |
| AIGC 权益复用现有权益模型 | PlanCard、PlanCompareTable | 只显示目录返回权益，不硬编码四档矩阵 |
| AIGC 准入不替代积分结算 | 文案边界 | 权益描述为能力准入，不宣称包含无限模型调用 |
| 积分商品购买不改变会员订阅 | 范围与组件树 | 会员页无积分商品 CTA；不调用积分商品 purchase API |
| 会员订阅不是积分充值订单 | 支付流程、关键文案 | 使用订阅 SKU 和 `SubscriptionPayDialog`；无“充值”主动作 |
| 禁用 SKU 不可购买 | 卡片不可售态 | 目录缺失 SKU 不生成购买按钮；直接状态变化返回错误后刷新 |
| 同 Plan 换周期被明确拒绝 | 动作矩阵 | 同 Plan 其他 SKU 禁用并显示“本期暂不支持换周期”，不打开支付 |
| FAQ 不承诺渠道代扣 | FAQ 与文案边界 | 展示月季年、手动续费、取消到期、FREE 兜底和两条商品链路独立 |

支付幂等、自然月计算、数据库冻结、积分流水与调度器行为属于服务端验收；UI 只验证不做本地重复变更、准确展示后端结果及错误边界。

## 实现约束清单

- [ ] 只改造既有共享组件和页面接线，不新增支付组件或订单轮询 hook。
