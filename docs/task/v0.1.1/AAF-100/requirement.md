# 需求：Studio 首页改版

任务编号：AAF-100  
风险等级：🔴 高  
确认状态：已获人类确认

## 需求分析（六问）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 需求还是方案？ | 用户给出了“四行首页、蓝图建项、快速创作”的界面方案；其真实需求是让 Studio 首页聚焦项目启动与继续创作，减少内容噪声和跳转成本。 |
| 2 | 真正痛点？ | 首页入口分散，蓝图只能浏览而不能直接完成建项，最近生成与项目工作流竞争注意力；用户需要从选择蓝图到进入项目的一条短链路。 |
| 3 | 隐含前提？ | 蓝图具有明确的项目类型、生产模式和发布状态；项目、IP、渠道已有可查询数据与既有创作页面；当前用户只能看到有权访问的数据。数字人完整能力本期尚未就绪。 |
| 4 | 最窄 MVP？ | 首页只保留四个顶层区块；展示已发布蓝图并支持带上下文建项；保留最近项目；快速创作继续复用既有页面，数字人仅进入统一创作容器的占位模式；移除最近生成。 |
| 5 | 完整愿景成本？ | 完整统一创作体验还需重构图像、视频、文案、音频、数字人等创作页及其状态模型、路由与素材链路，属于跨模块高成本改造，不适合并入本任务。 |
| 6 | 推荐？ | 采用 Reduction MVP。先验证“首页发现蓝图 → 创建项目 → 进入项目”的核心价值，同时保留现有创作能力，避免为视觉统一重复实现已有功能。 |

## 背景

Studio 首页应成为用户查看工作概况、从蓝图启动项目、继续最近项目和快速进入创作能力的统一入口。当前首页信息层级需要收敛，尤其应移除“最近生成”，避免生成结果与项目入口重复表达。

用户已确认未来采用统一创作体验，但 AAF-100 仅建立统一入口语义，不重构全部创作页面。已有创作模式继续跳转到现有页面；数字人暂以统一创作入口中的 `digital-human` 模式占位。

## 用户故事

作为 Studio 创作者，我希望在首页按项目类型发现可用蓝图并直接创建项目，以便用最少步骤开始生产。

作为 Studio 创作者，我希望从首页继续最近项目或快速进入各类创作能力，以便在项目工作和即时创作之间快速切换。

## 成功标准

- 首页仅有四个顶层内容区块，顺序固定且不再出现“最近生成”。
- 未发布蓝图不会出现在首页；已发布蓝图可按项目类型切换查看。
- 用户从点击蓝图到创建成功进入项目，无需重复选择项目类型、蓝图或生产模式。
- 图像、视频、文案、配音、音乐继续复用既有创作页面；数字人可进入 `digital-human` 占位模式。

## 范围

### 本期包含

- Studio 首页四行信息架构及其加载、空态、失败态。
- 蓝图 `coverUrl` 可空字段及封面降级规则。
- 按项目类型展示已发布蓝图。
- 蓝图建项 Dialog、字段校验、创建反馈和成功跳转。
- 最近项目展示与项目跳转。
- 快速创作入口及数字人占位模式。
- 删除首页“最近生成”区块及其首页入口。

### 本期不包含

- 重构或合并图像、视频、文案、配音、音乐等既有创作页面。
- 实现数字人生成、编辑、任务提交或结果管理能力。
- 新增或改造蓝图管理、审核、发布、排序流程。
- 改变统计卡的数据口径、权限口径或统计数据源。
- 改造项目详情页、IP 管理页、渠道管理页。
- 将“最近生成”迁移到首页其他位置；它从首页完全移除。

## 信息架构

“行”指首页自上而下的顶层内容区块，不等同于响应式布局中的单行 CSS 网格。区块内部的卡片可随视口换行，但不得因此新增第五个顶层区块。

首页严格按以下顺序呈现四行：

| 行 | 区块 | 目的 | 内容 |
|---|------|------|------|
| 第一行 | 统计卡 | 查看当前工作概况 | 复用现有统计项、数据口径和权限规则 |
| 第二行 | 最近项目 | 继续最近工作 | 当前用户有权访问的最近项目 |
| 第三行 | 蓝图 | 发现生产方案并发起建项 | 项目类型 Tabs、已发布蓝图卡、建项 Dialog |
| 第四行 | 快速创作 | 直接进入创作能力 | 图像、视频、文案、配音、音乐、数字人及既有有效入口 |

首页不得在四行之前、之间或之后展示“最近生成”区块。全局导航、页面标题、通用消息提示不计为首页内容行。

## 数据模型

### 蓝图

“蓝图”指 Studio 用于创建项目的既有项目模板概念。本任务不新建平行的模板体系。

在既有蓝图读模型中新增：

| 字段 | 类型 | 必填 | 规则 |
|------|------|------|------|
| `coverUrl` | String | 否 | 可为 `null`；有效时用于蓝图卡封面，无效或加载失败时触发项目类型渐变降级 |

首页展示蓝图至少依赖以下既有业务属性：蓝图 ID、名称、项目类型、生产模式、发布状态。具体存储字段和接口命名由技术设计确定，但业务语义必须唯一。

### 蓝图建项输入

| 字段 | 来源 | 必填 | 可编辑 | 规则 |
|------|------|------|--------|------|
| 项目类型 | 所点击蓝图 | 是 | 否 | 与蓝图定义一致，用户不得在 Dialog 中改成其他类型 |
| 蓝图 | 所点击蓝图 | 是 | 否 | 展示蓝图名称并提交蓝图 ID |
| 生产模式 | 所点击蓝图 | 是 | 否 | 使用蓝图定义的模式，不要求用户重复选择 |
| 项目名称 | 用户输入 | 是 | 是 | 去除首尾空白后不得为空，并遵循既有项目名称长度与字符规则 |
| IP | 用户选择 | 否 | 是 | 单选；无可用 IP 时仍允许创建项目 |
| 渠道 | 用户选择 | 否 | 是 | 支持选择既有可用渠道；未选择渠道时仍允许创建项目 |
| 补充说明 | 用户输入 | 否 | 是 | 放在“高级设置”内，遵循既有项目描述长度规则 |

不得仅依赖客户端传回的项目类型和生产模式。创建时应以蓝图当前有效定义校验或解析，避免篡改后产生不一致项目。

## 业务规则

### 统计卡

- 第一行复用首页现有统计卡及其数据定义，不在本任务新增、删除或重新解释指标。
- 统计数据只反映当前用户有权查看的数据。
- 加载或查询失败只影响统计卡自身状态，不得阻止其他三行使用。

### 蓝图 Tabs 与卡片

- 第三行以项目类型作为 Tabs 维度，一个 Tab 只展示该项目类型的蓝图。
- 项目类型以系统当前有效的项目类型定义为准，前端不得另建一套含义不同的类型枚举。
- 首页只展示发布状态为 `PUBLISHED` 的蓝图；草稿、审核中、已下线、已删除或其他非发布状态不得展示。
- 蓝图卡至少展示名称、项目类型、生产模式和封面区域。
- `coverUrl` 非空且图片加载成功时，展示该图片。
- `coverUrl` 为 `null`、空白、非法地址或图片加载失败时，封面区域立即改用该项目类型对应的稳定渐变样式，不显示破图图标。
- 同一项目类型始终使用同一渐变语义；不同项目类型应可视觉区分。具体色值由 UI 设计确定。
- 当前 Tab 没有已发布蓝图时，在第三行内部展示空态，不隐藏该行，也不展示其他类型蓝图代替。
- 点击蓝图卡任一主要可点击区域打开建项 Dialog，不先跳转到独立蓝图详情页。

### 蓝图建项 Dialog

- Dialog 打开时必须带入并展示所选蓝图的项目类型、蓝图和生产模式。
- 项目类型、蓝图和生产模式为本次建项上下文，不允许在 Dialog 内修改。
- 项目名称为唯一必填的用户输入字段；IP、渠道和补充说明均为可选。
- IP 选择器只展示当前用户有权使用的 IP；渠道选择器只展示当前用户有权使用且当前有效的渠道。
- 补充说明可折叠放入“高级设置”，折叠状态不得清空用户已输入内容。
- 项目名称校验失败时不得提交，并在字段附近给出可理解的错误提示。
- 用户提交后，在请求完成前禁用重复提交；不得因连点创建多个项目。
- 创建服务必须再次校验蓝图存在且仍为已发布状态。蓝图已下线、删除或不可访问时，创建失败并提示用户刷新或重新选择。
- 创建成功后关闭 Dialog，并使用返回的项目 ID 直接进入新项目，不停留在首页，也不跳到项目列表中转。
- 创建失败时保留 Dialog 和用户已填写内容，不跳转；用户可修改后重试或主动取消。
- 用户关闭 Dialog 后再次点击其他蓝图，应使用新蓝图上下文，不能残留上一次的类型、蓝图或生产模式。

### 最近项目

- 第二行展示当前用户有权访问的最近项目，沿用既有“最近”排序口径和数量上限。
- 点击项目进入对应项目。
- 无最近项目时在第二行内部展示空态，仍保留第二行。
- 单个无权访问、已删除或已失效项目不得出现在列表中。
- 查询失败只影响本行，不得阻止蓝图建项或快速创作。

### 快速创作

- 第四行至少包含：图像、视频、文案、配音、音乐、数字人。
- 除上述入口外，可保留当前有效的既有快速创作入口，但不得拆成新的首页顶层区块。
- 图像、视频、文案、配音、音乐等已有模式继续跳转到各自现有页面，本任务不改变其页面结构、参数模型和生成流程。
- 数字人入口进入统一创作入口，并携带模式 `digital-human`。
- `digital-human` 本期为明确占位模式：可以展示统一创作容器和“能力尚未开放”的状态，但不得伪造可提交的数字人生成任务或成功结果。
- 入口路由失败时应提供可恢复反馈，不能静默无响应。

### 权限与数据一致性

- 项目类型、蓝图、渠道规格、领域扩展、兼容包和执行绑定是平台级全局定义，不按组织复制；获得 AIGC 使用权限的组织可读取已发布定义。
- 全局定义的创建、更新、删除与发布仅允许 `admin`、`super_admin`；`member`、`org_admin` 只读。
- 首页统计、最近项目、可选 IP 和新建项目等业务数据仍按当前登录用户及组织/工作区进行权限过滤。
- 用户不得通过修改客户端参数使用无权访问的 IP，或使用未发布、已删除、不兼容的全局蓝图与渠道。
- 会话失效时按系统统一认证规则处理，不得创建匿名项目。
- 蓝图卡展示的项目类型和生产模式必须与创建后的项目一致。

## 边界与异常

| 场景 | 预期行为 |
|------|----------|
| 某项目类型无已发布蓝图 | 保留对应 Tab，展示该类型空态 |
| `coverUrl` 为空或图片加载失败 | 使用项目类型渐变，不显示破图 |
| 蓝图在 Dialog 打开后被下线 | 提交失败，保留输入并提示重新选择 |
| 用户没有 IP | IP 选择器展示空态，仍可创建 |
| 用户没有可用渠道 | 渠道选择器展示空态，仍可创建 |
| 项目名称全为空白 | 阻止提交并提示名称不能为空 |
| 用户连续点击创建 | 请求期间只能产生一次有效创建 |
| 创建接口失败 | 不跳转、不清空输入，展示错误并允许重试 |
| 最近项目为空或失败 | 仅第二行显示对应空态或失败态 |
| 某一首页数据源失败 | 其他行继续独立加载和交互 |
| 数字人能力未实现 | 进入 `digital-human` 占位模式，不提交生成任务 |
| 响应式下卡片换行 | 仍保持四个顶层区块及固定顺序 |

## 验收标准（Gherkin）

### 首页严格四行

```gherkin
场景: 登录用户打开 Studio 首页
  假如 用户已登录
  当 用户进入 Studio 首页
  那么 首页内容区从上到下依次为“统计卡”“最近项目”“蓝图”“快速创作”
  并且 首页不存在第五个顶层内容区块
  并且 首页不展示“最近生成”
```

### 按项目类型展示已发布蓝图

```gherkin
场景: 用户切换蓝图项目类型
  假如 系统中存在多个项目类型的蓝图
  并且 每种类型同时存在已发布和未发布蓝图
  当 用户切换到某个项目类型 Tab
  那么 只展示该项目类型且状态为 PUBLISHED 的蓝图
  并且 不展示其他项目类型蓝图
  并且 不展示任何未发布蓝图
```

```gherkin
场景: 当前项目类型没有已发布蓝图
  假如 当前项目类型没有状态为 PUBLISHED 的蓝图
  当 用户打开该项目类型 Tab
  那么 蓝图行展示该项目类型的空态
  并且 蓝图行仍位于首页第二行
```

### 蓝图封面及降级

```gherkin
场景大纲: 蓝图卡选择正确的封面表现
  假如 蓝图属于项目类型“<项目类型>”
  并且 蓝图 coverUrl 的状态为“<封面状态>”
  当 蓝图卡完成渲染
  那么 封面区域展示“<预期表现>”
  并且 页面不展示破图图标

  例子:
    | 项目类型 | 封面状态 | 预期表现 |
    | 视频     | 有效且加载成功 | coverUrl 图片 |
    | 视频     | null | 视频类型渐变 |
    | 图像     | 空白字符串 | 图像类型渐变 |
    | 文案     | 图片加载失败 | 文案类型渐变 |
```

### 打开蓝图建项 Dialog

```gherkin
场景: 从蓝图卡发起建项
  假如 用户正在查看一个已发布蓝图
  当 用户点击该蓝图卡
  那么 系统打开建项 Dialog
  并且 Dialog 展示该蓝图的项目类型、蓝图名称和生产模式
  并且 三项上下文不可编辑
  并且 Dialog 提供项目名称、IP、渠道和高级设置中的补充说明
```

### 校验项目名称

```gherkin
场景: 项目名称为空时阻止创建
  假如 用户已打开建项 Dialog
  并且 项目名称仅包含空白字符
  当 用户提交创建
  那么 系统不发送有效创建请求
  并且 项目名称字段附近提示名称不能为空
  并且 Dialog 保持打开
```

### 不配置 IP 和渠道也可创建

```gherkin
场景: 用户没有可选 IP 和渠道
  假如 用户已打开建项 Dialog
  并且 当前用户没有可用 IP
  并且 当前用户没有可用渠道
  当 用户填写有效项目名称并提交
  那么 系统允许创建项目
  并且 新项目保留蓝图的项目类型和生产模式
```

### 创建成功进入项目

```gherkin
场景: 用户通过蓝图成功创建项目
  假如 用户已填写有效项目名称
  并且 可选的 IP、渠道和补充说明均符合规则
  并且 蓝图仍处于 PUBLISHED 状态
  当 用户提交创建
  那么 系统只创建一个项目
  并且 新项目关联所选蓝图
  并且 新项目的项目类型和生产模式与蓝图一致
  并且 系统使用返回的项目 ID 直接进入新项目
```

### 创建失败保留输入

```gherkin
场景: 蓝图在提交前已下线
  假如 用户已在建项 Dialog 填写项目名称、IP、渠道和补充说明
  并且 所选蓝图已被下线
  当 用户提交创建
  那么 系统不创建项目
  并且 用户仍停留在建项 Dialog
  并且 已填写内容保持不变
  并且 页面提示蓝图不可用并建议重新选择
```

```gherkin
场景: 用户重复点击创建按钮
  假如 创建请求仍在处理中
  当 用户再次点击创建按钮
  那么 系统不发起第二次创建请求
  并且 最多创建一个项目
```

### 最近项目

```gherkin
场景: 用户继续最近项目
  假如 当前用户存在有权访问的最近项目
  当 首页第二行加载完成
  那么 系统按既有最近项目排序口径展示项目
  并且 不展示其他用户或无权访问的项目
  当 用户点击一个项目
  那么 系统进入对应项目
```

```gherkin
场景: 用户没有最近项目
  假如 当前用户没有可访问项目
  当 首页加载完成
  那么 第二行展示最近项目空态
  并且 快速创作仍位于第四行且可使用
```

### 快速创作复用既有页面

```gherkin
场景大纲: 既有创作模式从首页继续使用原页面
  假如 首页快速创作行已加载
  当 用户点击“<入口>”
  那么 系统进入“<既有页面>”
  并且 不进入本任务新建的替代创作页面

  例子:
    | 入口 | 既有页面 |
    | 图像 | 现有图像创作页面 |
    | 视频 | 现有视频创作页面 |
    | 文案 | 现有文案创作页面 |
    | 配音 | 现有配音创作页面 |
    | 音乐 | 现有音乐创作页面 |
```

### 数字人占位模式

```gherkin
场景: 用户从快速创作进入数字人
  假如 首页快速创作行已加载
  当 用户点击“数字人”
  那么 系统进入统一创作入口
  并且 当前模式为 digital-human
  并且 页面明确提示数字人能力尚未开放
  并且 页面不允许提交伪造的数字人生成任务
```

## 测试要点

### 单元测试

- 蓝图过滤只保留当前项目类型且状态为 `PUBLISHED` 的记录。
- `coverUrl` 对 `null`、空白、非法值和加载失败均切换到项目类型渐变。
- 项目类型到渐变语义的映射稳定且类型间可区分。
- 建项表单去除项目名称首尾空白并拒绝空名称。
- Dialog 打开、关闭、切换蓝图时上下文正确重置。
- 高级设置折叠与展开不丢失补充说明。
- 创建请求处理中禁用重复提交。
- 数字人入口产生 `digital-human` 模式，其他入口保持既有路由。

### 组件测试

- 首页只有四个顶层内容区块，DOM 顺序与需求一致，不渲染“最近生成”。
- 蓝图 Tabs、空态、封面成功和封面失败状态均可见且可操作。
- Dialog 正确展示只读上下文和可编辑字段。
- 无 IP、无渠道时选择器显示空态且创建按钮仍可用。
- 各行加载、空态、失败态互不阻塞。
- 响应式卡片换行时顶层区块数量和顺序不变。

### 接口与集成测试

- 蓝图查询不能返回非 `PUBLISHED` 蓝图。
- `coverUrl` 缺失时序列化为 `null` 或省略的契约一致，不导致页面异常。
- 创建接口以服务端蓝图定义校验项目类型和生产模式，拒绝篡改参数。
- 蓝图下线、删除、无权访问时创建失败且不产生项目。
- 用户不能选择或提交其他用户无权访问的 IP、渠道。
- 创建成功只产生一个项目并返回可导航的项目 ID。
- 最近项目、统计和选择器数据满足用户数据隔离。
- 未登录或会话失效时不能查询私有数据或创建项目。

### 验收测试

- 按 Gherkin 场景逐条覆盖首页结构、蓝图过滤、封面降级、Dialog 建项、最近项目和快速创作。
- 在至少两种视口下验证“四个顶层区块”语义不因卡片换行改变。
- 人工断开封面图片请求，确认出现类型渐变而非破图。
- 模拟创建中重复点击，确认前后端合计只创建一个项目。
- 验证所有既有创作入口仍到达原页面，未发生隐式重构。
- 验证数字人只进入 `digital-human` 占位模式，不具备生成能力。
