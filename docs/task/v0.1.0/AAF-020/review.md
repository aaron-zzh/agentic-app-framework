# AAF-020 代码审查报告

日期：2026-05-22
审查人：AI/architect

## Blocker（必须修复）

### B1. POST /api/docs 路径穿越漏洞（已修复）

**文件**：`DocumentService.java:78`
**问题**：原始校验仅检查 `filePath.startsWith("docs/")`，攻击者可构造 `docs/../../../etc/passwd` 绕过，写入任意文件。
**修复**：新增 `validateFilePath()` 方法，对路径做 `Path.normalize()` 后二次校验是否仍在 `docs/` 下，并禁止空字节注入。

## Major（建议修复）

### M1. AutodevSession 未继承 BaseEntity（已修复）

**文件**：`AutodevSession.java`、`V4__autodev_session.sql`
**问题**：项目规范要求所有 JPA 实体继承 `BaseEntity`（含 version/org_id/workspace_id/deleted/审计字段）。原实现手动定义 id/createTime/updateTime，缺少乐观锁、软删除、多租户字段。
**修复**：改为 `extends BaseEntity`，补充 `@SQLDelete`，迁移 SQL 补齐标准列。

### M2. SSE 订阅者 onError 回调缺失（已修复）

**文件**：`DocumentService.java:subscribe()`
**问题**：仅注册 `onCompletion` 和 `onTimeout`，未注册 `onError`。连接异常断开时 emitter 残留在列表中，造成内存泄漏和后续广播时的无效 IO。
**修复**：补充 `emitter.onError(e -> remove.run())`，三个回调共用同一 `Runnable remove`。

### M3. KiroAgentController agentRole 前后端不对齐（已修复）

**文件**：`KiroAgentController.java`、`KiroAgentProvider.tsx`
**问题**：前端通过 URL query param `?agentRole=xxx` 传递角色，但后端仅从 `@RequestBody` 读取。AG-UI HttpAgent 发送的 body 遵循 AG-UI 协议格式，不含自定义 `agentRole` 字段，导致角色选择无效。
**修复**：后端 `run()` 方法新增 `@RequestParam(required = false) String agentRole`，优先取 query param。

## Minor（可选优化）

### m1. broadcastChange 中 JSON 手工拼接

**文件**：`DocumentService.java:broadcastChange()`
**问题**：使用 `String.formatted()` 手工拼 JSON，若 title 含特殊字符（换行、反斜杠）可能产生非法 JSON。当前仅做了双引号转义。
**建议**：使用 ObjectMapper 序列化，或至少补充 `\n`、`\\` 的转义。不阻塞发布。

### m2. KiroAgentController 缺少 userMessage 输入校验

**文件**：`KiroAgentController.java:executeKiro()`
**问题**：`userMessage` 直接写入子进程 stdin，虽然 ProcessBuilder 用 List 形式（无命令注入），但超长消息可能导致进程阻塞。
**建议**：对 `userMessage` 长度做上限校验（如 64KB）。

### m3. Flyway 迁移使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 而非 `BIGSERIAL`

**说明**：已在修复 M1 时统一为项目标准写法（`BIGINT GENERATED BY DEFAULT AS IDENTITY`），与 V1 一致。原代码使用 `BIGSERIAL` 不一致但功能等价。已修复。
