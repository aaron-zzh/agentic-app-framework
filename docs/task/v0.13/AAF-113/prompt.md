核查结果：发现 4 处代码与 design.md 不一致

不一致 1：projectSpecification 类型（设计要求类型化，代码是松散 Map）

- design.md 声明：ProjectSpecificationSnapshot projectSpecification（一个具体类型）
- 真实代码：AigcProjectBlueprintSnapshotPayload.projectSpecification 是 Map<String, Object>

影响：松散 Map 意味着编译期无法校验里面该有哪些 key、类型对不对，跟设计"结构化契约负责系统校验"的原则有出入。

不一致 2：CompletionCriteria 结构（设计是双变体密封接口，代码是单一 record）

- design.md 声明：sealed interface CompletionCriteria { SubmissionAccepted, ArtifactSet }——两种完成标准，"只要 Tool
  受理成功"和"必须产出具体资源"是两种不同语义
- 真实代码：ArtifactCompletionContract.CompletionCriteria 只有一个 record（对应 ArtifactSet 语义），没有
  SubmissionAccepted 这个变体

影响：如果有场景只需要"Tool 受理即完成"（不需要等具体资源落盘），现在的代码结构表达不了这种情况。

不一致 3：ProjectArtifactCommandApi 接口偏差最大

  AAF-115 已有的 InvocationContext 类型，语义上没有冲突，只是命名没对齐。
