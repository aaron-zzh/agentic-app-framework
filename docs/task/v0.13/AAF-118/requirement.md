# AAF-118 Role 可见性与归属模型

## 背景

Role 是助理的"能力配置"：一组技能绑定加一个工具授权池，通过 `ai_assistant_role` 挂到助理上。助理在已绑定且启用的角色里，由 `DefaultRoleSelector` 按任务输入路由。联网搜索、医疗工具接入时发现 Role 层存在以下缺口：

- `ai_role` 没有可见性字段，"系统内置"只靠 `system.role.*` 命名约定，没有字段或校验保证。
- `AiRoleService.listRoles` 是 `findAll()`，角色全局可见；`/api/ai/roles` 是管理端 CRUD，创建时不记录所属用户，普通用户没有私有角色能力。
- 用户只能被动拿到创建默认助理时复制的模板绑定，之后既不能自己增删角色，也没有"可绑定角色库"的概念。
- Role 的 `skill_ids` 只存 `skillKey`，保存时不校验技能的可见性与归属。技能有 `PRIVATE / WORKSPACE / PUBLIC / INTERNAL`，角色没有对应约束，公开角色可能带出私有技能，反之亦然。
- `tool_whitelist` 只存工具名，不校验工具是否已登记、已启用、风险等级是否允许由用户配置。
- 助理加载时，绑定的角色只要有一个非 `active`，整个助理解析就抛错，所有对话不可用。

## 目标

建立与技能、工具蓝图一致的 Role 可见性模型，并让用户自维护角色绑定：

- **系统内置**：平台维护，所有用户可在角色库中看到并绑定。
- **公开**：经管理员发布，所有用户可在角色库中看到并绑定，不可被非所有者修改。
- **私有**：用户创建，仅所有者可见和绑定，可引用自己的私有技能。
- 助理的初始角色仍由系统模板在创建时复制；之后用户自己绑定、解绑、排序、切换默认，并受数量上限约束。
- 任何角色保存、绑定和执行时，都按其可见性校验所引用的技能与工具，不允许越权引用。

## 用户故事

### 从角色库绑定内置和公开角色

**作为**普通用户，**我希望**在角色库中浏览平台内置和公开的角色并绑定到自己的助理，**以便**按需扩展助理能力，也能随时解绑不需要的角色。

### 创建自己的私有角色

**作为**普通用户，**我希望**基于平台已登记的工具和我自己可见的技能创建私有角色，**以便**按自己的场景定制助理能力，且他人看不到也用不了。

### 公开角色可被全员复用

**作为**平台运营，**我希望**把审核过的角色发布为公开角色供所有用户绑定，**以便**优质能力配置可复用，同时保证它不依赖任何私有资源。

### 引用越权被拦截

**作为**平台安全负责人，**我希望**角色保存、绑定和运行时都校验所引用技能与工具的可见性，**以便**私有技能不被公开角色带出，用户也不能借私有角色提升权限。

### 失效角色不拖垮助理

**作为**用户，**我希望**某个已绑定的角色被下架或删除时，助理仍能正常使用其余角色，**以便**一个坏角色不会让所有对话失败。

## 验收标准

```gherkin
Feature: Role 可见性、归属与用户自维护绑定

  Scenario: 新用户获得模板初始角色
    Given 系统模板助理绑定了若干角色和一个默认角色
    When 新用户创建默认助理
    Then 复制模板的角色绑定和默认角色
    And 之后绑定关系归该用户维护

  Scenario: 角色库只展示可绑定的角色
    Given 存在 SYSTEM、PUBLIC 角色和用户 A、B 各自的 PRIVATE 角色
    When 用户 A 查询角色库
    Then 返回 SYSTEM、PUBLIC 和用户 A 自己的 PRIVATE 角色
    And 每个角色标明是否已绑定
    And 不包含用户 B 的私有角色

  Scenario: 用户绑定公开角色
    Given 用户 A 的助理已绑定角色数小于上限
    When 用户 A 绑定一个 active 的 PUBLIC 角色
    Then 绑定成功并出现在候选路由中

  Scenario: 绑定数量超过上限
    Given 绑定上限取自系统参数，默认 10
    And 用户 A 的助理已绑定角色数等于上限
    When 用户 A 再绑定一个角色
    Then 绑定被拒绝并提示上限
    And 管理员调大系统参数后，用户 A 可以继续绑定

  Scenario: 新增内置角色随模板到达新用户
    Given 管理员将新增的 SYSTEM 角色挂到系统用户模板助理上
    When 新用户创建默认助理
    Then 新用户的助理自动带有该角色的绑定

  Scenario: 不能绑定不可见的角色
    Given 角色 R 是用户 B 的私有角色
    When 用户 A 通过角色 ID 尝试绑定 R
    Then 返回不存在，不泄露其存在性

  Scenario: 默认角色受保护
    Given 角色 D 是助理当前的默认角色
    When 用户尝试解绑 D
    Then 被拒绝，提示先切换默认角色
    And 助理始终有且仅有一个默认角色

  Scenario: 系统受管助理不开放用户绑定
    Given 系统客服助理属于系统受管助理
    When 任何普通用户调用角色绑定接口修改它
    Then 被拒绝
    And 它的角色只能由管理员维护

  Scenario: 用户创建私有角色
    Given 用户 A 已登录
    When 用户 A 创建角色，引用已启用的目录工具和自己的私有技能
    Then 角色保存为 visibility=PRIVATE，owner 为用户 A
    And 用户 B 无法通过角色 ID 或 code 读取、修改、删除或绑定它

  Scenario: 私有角色引用他人私有技能被拒绝
    Given 技能 S 属于用户 B 且为私有
    When 用户 A 创建角色引用技能 S
    Then 保存被拒绝并返回明确的引用越权错误

  Scenario: 公开或内置角色引用私有技能被拒绝
    Given 技能 S 为私有
    When 管理员保存或发布 SYSTEM 或 PUBLIC 角色，其 skill_ids 含 S
    Then 保存被拒绝，不允许降级为默认放行

  Scenario: 角色不得引用工作区可见的技能
    Given 技能 W 的可见性为 WORKSPACE
    When 任何人保存引用 W 的角色
    Then 保存被拒绝，提示本轮角色不支持引用工作区技能

  Scenario: 工具引用校验
    Given 工具 T 未登记或已停用
    When 任何人保存引用 T 的角色
    Then 保存被拒绝

  Scenario: 私有角色引用高风险工具
    Given 工具 T 的风险等级为 HIGH 且在目录中已启用
    When 普通用户创建引用 T 的私有角色
    Then 保存成功，不按风险等级限制
    And 调用 T 时仍按目录声明的权限码、确认要求和策略门控执行

  Scenario: 失效的非默认绑定被跳过
    Given 用户助理绑定了角色 X，之后 X 被下架或删除
    When 用户发起对话
    Then 助理跳过 X 并记录决策，其余角色正常路由
    And 不因单个角色失效而整体失败

  Scenario: 默认角色失效明确失败
    Given 默认角色被下架或删除
    When 用户发起对话
    Then 明确失败并提示切换默认角色，不静默换角色

  Scenario: 运行时再次校验技能可见性
    Given 私有角色引用的技能在保存后被所有者改为不可用或删除
    When 用户使用该角色发起对话
    Then 该技能不激活并记录决策，不得静默使用已失效或越权的技能

  Scenario: 被引用的技能无法删除
    Given 技能 S 被若干角色引用，其中包含 PUBLIC 角色和用户自己的私有角色
    When 技能所有者删除或下线 S
    Then 操作被拒绝，提示需先解除关联
    And 列出引用 S 的 SYSTEM / PUBLIC 角色和所有者自己的私有角色
    And 他人私有角色只返回数量，不泄露其身份

  Scenario: 被引用的技能不能被收窄可见性
    Given 技能 S 为 PUBLIC，被 PUBLIC 角色或他人的私有角色引用
    When 所有者将 S 改为私有
    Then 操作被拒绝，提示需先解除关联
```

## 范围

- `ai_role` 增加可见性与归属约束，存量系统角色回填为 SYSTEM。
- 角色查询、创建、更新、删除按可见性与所有者授权，管理端与用户端接口分离。
- 角色库查询、用户绑定 / 解绑 / 排序 / 切换默认，绑定数量上限与默认角色保护。
- 保存与绑定时校验技能与工具引用，运行时再次校验。
- 助理加载容错：跳过失效的非默认绑定。
- 技能可见性变更或删除前做反向引用检查：被任何角色引用的技能无法删除或下线，需先解除关联。
- 前端角色库与"我的角色"管理入口。

## 不在范围

- 新增内置角色回填给已有用户（项目未部署，已有用户通过重建库获得；新增内置角色只需挂到系统用户模板，新用户创建助理时自动带上）。
- 角色市场、评分、付费或分成。
- 角色版本化与审批流（沿用现有技能版本机制，本故事不为角色新增版本表）。
- 跨组织 / 工作区共享与限制：角色、工具不按工作区限制，`WORKSPACE` 可见性不启用（字段预留），任何角色不得引用 `WORKSPACE` 技能。
- 工具与技能本身的权限模型调整。
- 助理路由算法本身（`DefaultRoleSelector` 逻辑不变）。

## 约束

- 项目未发布：直接替换，不保留旧路径，不加兼容层。
- 涉及权限与数据模型，设计经人工审核通过后才能编码；助理解析链路只做容错改动，不重写。
- 已确认：SQL 直接修改现有 `v2__ai_schema.sql` 与 `v12__init_seed_data.sql`，不新增迁移文件（项目未部署）。绑定上限通过系统参数配置，私有角色数量不限，私有角色可引用的工具风险等级不限。
- 不新增非必要单元测试；权限与引用校验属于安全边界，必要时仅补最小用例。
