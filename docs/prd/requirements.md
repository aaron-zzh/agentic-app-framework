## 需求详情

### 单据识别入库工作流（2026-05-06）

**背景**：分销企业用户，有 3-10 月积压的大量送货单、对账单需要处理，数据安全要求高。

**核心诉求**：

| 能力 | 描述 |
|------|------|
| 私有化部署 | 本地部署（5090 D 显卡），完全断网运行，账目数据严禁上传云端 |
| 多模态单据识别 | OCR 识别复杂单据（手写涂改、反光、褶皱），提取品名、单价、数量、金额 |
| 自动化审计工作流 | ① OCR 提取 → ② AI 逻辑校验（单价×数量=总额）→ ③ API/DB 写入进销存 |
| 领域微调 | 支持 Llama 3 / DeepSeek 本地 LoRA 微调，识别行业简写（如"雀2"→"雀巢200g"） |
| 可维护性 | Docker 镜像交付，开源可自维护 |

**用户关注点**：

- 是否有类似案例和演示？
- 交付物是否包含 Docker 镜像？
- 针对 5090 D 硬件的调优程度？

**评估意见**（对照 [产品概述 #需求评估原则](../explanation/product-overview.md#需求评估原则)）：

| 评估维度 | 分析 |
|---------|------|
| **产品定位** | ✅ 符合。多模态识别（OCR）+ 工作流编排 + 外部系统集成，是 AI 原生应用的典型场景 |
| **框架层 vs 业务层** | 框架层：OCR 能力（通过在线 API）、工作流引擎、API 集成接口；业务层：具体单据模板、领域术语映射、进销存对接 |
| **核心能力依赖** | 多模态识别（v0.2 工具系统）、工作流引擎（v2.0）、外部系统集成（v0.2） |
| **部署模式** | 引导用户采用在线部署，通过数据安全措施解决顾虑 |
| **数据安全** | 通过脱敏、分片调用、审计日志等措施保障，详见下方安全方案 |

**核心流程识别**：

```
拍照/上传单据
    ↓
[OCR 识别] — 框架核心能力，调用在线多模态 API（GPT-4o Vision / Claude 3.5）
    ↓
结构化提取（品名、单价、数量、金额）
    ↓
[AI 逻辑校验] — 框架工作流节点，规则引擎校验（单价×数量=总额）
    ↓
[领域术语映射] — 知识库能力，"雀2"→"雀巢200g"（可通过 RAG 或微调）
    ↓
人工确认（可选，置信度低时触发）
    ↓
[API/DB 写入] — 框架集成能力，对接进销存系统
```

**框架实现方案**：

| 环节 | 框架能力 | 实现方式 |
|------|---------|---------|
| OCR 识别 | 多模态工具 | Spring AI 调用 GPT-4o Vision / Claude 3.5 Sonnet，提取结构化数据 |
| 逻辑校验 | 工作流节点 | Flowable 规则任务，配置校验表达式 |
| 术语映射 | 知识库 | 向量检索行业术语表，或 Few-shot Prompt 注入领域知识 |
| 置信度门控 | Agent 协作 | 识别置信度 < 阈值时，自动转人工确认 |
| 系统集成 | MCP/API 工具 | 标准化接口对接进销存，支持 REST/数据库直连 |

**场景示例规划**：

作为 v2.0 工作流引擎的示例应用，展示：

1. **多模态输入**：图片上传 → OCR 结构化
2. **工作流编排**：识别 → 校验 → 映射 → 确认 → 入库
3. **人机协作**：低置信度自动转人工
4. **外部集成**：对接示例进销存系统

**数据安全方案**（针对用户"账目数据严禁上云"顾虑）：

| 措施 | 说明 |
|------|------|
| **敏感字段脱敏** | 金额、客户名等字段在调用 LLM 前替换为占位符，返回后还原 |
| **多 LLM 分片** | 单据图片发送给 OCR 模型，提取的文字分片发送给不同 LLM 校验，单个模型无法还原完整业务 |
| **企业版 API** | 使用 OpenAI/Anthropic 企业版，明确数据不用于训练 |
| **本地预处理** | 图片压缩、格式转换在本地完成，减少上传数据量 |
| **完整审计** | 记录每次 LLM 调用的输入输出，支持合规审查 |
| **可选本地 OCR** | 对于极敏感场景，支持切换到本地 PaddleOCR（能力降级但数据不出域） |

**引导话术**：

> 我们理解您对数据安全的顾虑。AAF 采用"数据脱敏 + 多模型分片"机制，确保单个云端模型无法还原您的完整业务数据。同时提供完整审计日志，满足合规要求。
>
> 相比完全离线部署（需要 5090 级显卡、本地模型能力有限、运维成本高），在线部署 + 安全措施是更经济高效的选择。如果您的行业有强制离线要求，我们也支持本地部署模式。

**建议状态**：采纳

- 优先级：P2（v2.0 工作流引擎就绪后作为示例场景）
- 框架能力：OCR 多模态识别纳入 v0.2 工具系统规划
- 示例应用：v2.0 开发"单据识别入库"示例


### 个人智能助理用户画像（2026-05-12）

**背景**：当前 AI 助理每次对话都是"白纸"状态，用户需要反复说明自己的背景、偏好和习惯，交互效率低。

**核心诉求**：

| 能力 | 描述 |
|------|------|
| 助理人设定义 | 用户可为助理设定性格、语气、称呼等人设属性，形成专属交互风格 |
| 用户画像建模 | 系统持续学习并记录用户的兴趣爱好、专业领域、工作习惯、偏好等 |
| 上下文自动注入 | 对话时自动检索相关用户画像信息，注入 Agent 上下文，减少用户重复说明 |
| 渐进式学习 | 通过日常交互自动提取和更新用户画像，支持用户手动修正 |

**场景示例**：

- 用户说"帮我写个周报"→ 助理已知用户的岗位、项目、汇报风格，直接生成符合习惯的周报框架
- 用户说"推荐本书"→ 助理基于已知的阅读偏好和近期兴趣推荐，无需追问"你喜欢什么类型"
- 用户说"整理下会议纪要"→ 助理按用户惯用的格式和关注点组织内容

**框架能力依赖**：

| 环节 | 框架能力 | 实现方式 |
|------|---------|---------|
| 人设存储 | 记忆系统 | 长期记忆存储助理人设配置 |
| 画像建模 | 知识库 + 记忆系统 | 结构化用户画像（向量 + 图谱），支持语义检索 |
| 画像提取 | Agent 智能层 | 对话后自动提取用户偏好、习惯等信息 |
| 上下文注入 | Agent 上下文管理 | 对话前根据意图检索相关画像片段，注入 System Prompt |
| 隐私管控 | 权限系统 | 用户可查看、编辑、删除自己的画像数据 |

**与现有能力的关系**：

- 依赖记忆系统（短期/长期/情景记忆）
- 依赖知识库（向量存储 + 语义检索）
- 依赖 Agent 上下文管理器
- 是"个人助理"类应用的基础能力，可复用于多种场景

### 专家知识萃取工作流（2026-05-12）

**背景**：领域专家拥有大量隐性知识（决策逻辑、经验判断、流程诀窍），但难以直接转化为可执行的自动化流程。现有工作流搭建工具要求用户具备编程或流程设计能力，门槛高。

**核心诉求**：

| 能力 | 描述 |
|------|------|
| 对话式知识萃取 | 通过结构化对话引导专家表达隐性知识：目标、步骤、判断条件、异常处理等 |
| 自动工作流生成 | 将萃取的知识自动编排为多智能体工作流，包含角色分工、提示词、技能、工具调用、流程节点 |
| 可视化展示 | 生成的工作流以可视化图形展示，专家可直观理解和确认 |
| 交互式调试 | 支持单步执行、断点、变量查看，专家可逐步验证工作流是否符合预期 |
| 迭代优化 | 调试发现问题后，通过对话修正知识，自动更新工作流 |

**场景示例**：

- 资深销售经理描述"如何判断客户意向等级"→ 系统萃取为一个包含信息收集 Agent、意向评估 Agent、跟进策略 Agent 的协作工作流
- 运维专家描述"服务器故障排查流程"→ 生成诊断 Agent → 定位 Agent → 修复 Agent 的级联工作流，含条件分支和回退逻辑
- 教师描述"作文批改思路"→ 转化为结构分析、内容评价、语言润色、综合评分的多步骤工作流

**核心流程**：

```
专家发起萃取会话
    ↓
[萃取 Agent] — 结构化提问：目标、输入输出、步骤、判断条件、异常分支
    ↓
知识结构化（意图图谱 + 决策树 + 流程骨架）
    ↓
[编排 Agent] — 自动映射为多智能体工作流（角色、提示词、技能、工具、流程）
    ↓
可视化渲染（流程图 + 节点详情）
    ↓
[调试 Agent] — 支持模拟执行、单步调试、结果对比
    ↓
专家确认/修正 → 迭代优化 → 发布为可复用工作流
```

**框架能力依赖**：

| 环节 | 框架能力 | 实现方式 |
|------|---------|---------|
| 知识萃取 | Agent 智能层 + 对话管理 | 专用萃取 Agent，多轮结构化引导对话 |
| 知识建模 | 知识库 + 知识图谱 | Neo4j 存储决策逻辑和流程关系 |
| 工作流生成 | DSL + 工作流引擎 | 将结构化知识转译为 Flowable 工作流定义 |
| 提示词/技能组装 | Agent 编排 | 自动生成各节点 Agent 的 System Prompt 和技能配置 |
| 可视化 | 前端组件 | 工作流画布渲染，节点可点击查看/编辑详情 |
| 调试执行 | 工作流引擎 + 沙箱 | 沙箱环境单步执行，记录中间状态 |
| 迭代修正 | Agent 协作 | 对话修正 → 差量更新工作流定义 |
