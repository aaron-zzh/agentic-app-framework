# 一图一事产品方案

本文是一期的产品方案。[一期需求规格](../一期需求规格.md) 已按本文重写，业务规则、状态机、验收线等规格细则以一期需求规格为准。

形态：一个微信小程序，按登录身份进入子女、老人、家人三种视图，与主方案"一个移动端、多种模式"的思路一致，见 [产品定位 产品形态](../产品定位.md#产品形态)。

## 主流程

```text
子女：选档位付款 → 填爸妈称呼、录一句话 → 生成邀请卡片 → 微信发给爸妈
                                                          ↓
老人：点开卡片 → 听子女那句话和语音说明 → 本人授权 → 看本周话题
      → 选 1 到 9 张照片或翻拍老照片 → 按住说话 1 到 3 分钟 → 等约 1 分钟
      → 预览短片 → 点"发给家人"或"重讲"
                                                          ↓
家人：在家庭群或通知里点开 → 看短片 → 加入家族档案 → 留言、补照片、续费
                                                          ↓
老人：收到家人留言的语音播报 → 下周话题提醒 → 讲下一段
```

## 功能清单

"首发"指一期上线必须具备；"后置"指 [验证计划](验证计划.md) 期间按需加入。

### 子女端

| 功能 | 说明 | 范围 |
|------|------|------|
| 购买与支付 | 尝鲜包、月度包、年度故事包；首段不满意可退款 | 首发 |
| 邀请爸妈 | 填称呼，录一句 10 秒以内的话，生成邀请卡片；一个子女可邀请多位老人（两边父母） | 首发 |
| 出题 | 从话题库选，或自己写一句，例如"爸，讲讲你当兵那几年" | 首发 |
| 新故事通知 | 老人确认发布后推送服务通知 | 首发 |
| 档案查看 | 按时间看全部故事；查看剩余段数和到期时间 | 首发 |
| 兄弟姐妹共同续费 | 家人加入后可为同一位老人续费 | 后置 |

### 老人端

| 功能 | 说明 | 范围 |
|------|------|------|
| 本人授权 | 语音朗读加大字号，一项一句话说明。内容采集、声音和照片用于短片为必选，否则无法出片；案例展示默认不勾选 | 首发 |
| 本周话题 | 首页只有一个大卡片：话题文字加语音朗读 | 首发 |
| 选照片 | 从相册选，或用相机翻拍老照片；每段 1 到 9 张，按选择顺序排列，可删除和调整顺序；不选照片时用话题卡片作为画面 | 首发 |
| 按住说话 | 最长 3 分钟，松开可继续，可重录；显示已讲时长，不显示文字 | 首发 |
| 预览与确认 | 完整播放短片；"发给家人"和"重讲"两个大按钮；不确认则只有自己可见 | 首发 |
| 我的故事 | 按时间排列的短片列表 | 首发 |
| 家人留言播报 | 家人的文字留言用语音读给老人听，语音留言直接播放 | 首发 |
| 不讲这个话题 | 跳过本周话题，换一个或自由讲 | 首发 |

老人端不出现价格、余额、套餐和积分。额度用完时，老人仍可完成当前这段讲述，系统提醒子女续费。

### 家人端

| 功能 | 说明 | 范围 |
|------|------|------|
| 观看短片 | 未加入档案的家人可以看被分享的单条短片 | 首发 |
| 加入家族档案 | 由老人或已加入的家人邀请；加入后可看全部已发布故事 | 首发 |
| 留言 | 文字或语音，推送给老人 | 首发 |
| 补照片 | 为某段故事补充照片，标注来源人 | 后置 |
| 给自家长辈也开一个 | 片尾和档案页入口，跳转购买页 | 首发 |

### 短片生成

| 项 | 规则 |
|----|------|
| 画面 | 竖屏 9:16；每张照片缓慢推拉，按讲述时长平均分配，照片之间淡入淡出；一张照片时全程推拉；照片修复为验证期按需加入的付费增值项 |
| 声音 | 老人原声，只做降噪和音量均衡；配乐默认开启、音量压低，可关 |
| 字幕 | 逐句显示转写原文，只去掉"嗯、那个"等口头语，不改写、不补字；方言讲述也只显示识别结果 |
| 标题 | 从原话中摘取一句作为标题，不概括、不新增人名、年份、地点和评价；摘不出时用话题名 |
| 片尾 | 讲述者称呼和讲述日期；标识"AI 整理，内容经本人确认，未经人工事实核对" |
| 时长 | 等于讲述时长，1 到 3 分钟 |
| 出片时间 | 目标 1 分钟内 |

这套规则不做润色，所以不需要事实卡片。命中高风险规则（在世他人负面评价、逝者评价、政治与历史争议、医疗、他人隐私）时，与 [产品定位 内容规则](../产品定位.md#内容规则先确认事实再润色) 第 3 条保持一致：标题改用话题名；这段默认只有老人自己可见，预览页提示老人"这段提到了别人"，由老人决定是否发给家人；不能用于案例展示。规则细节见 [事实核对模块 自助模式](../../../design/memoir/fact-check-engine.md#自助模式)。

照片和讲述内容的对应（讲到哪张切到哪张）一期不做，后置为验证期迭代项。

### 话题库

- 首发 52 个话题，一年每周一个，按童年、求学、工作、成家、子女、老家、节日排序。
- 节日和老人生日前后推对应话题，例如春节前推"小时候怎么过年"。
- 子女出的题优先于话题库。

### 运营后台

订单与退款、话题库维护、内容审核记录、投诉处理。管理后台按 AAF 约定用 EntityDef 声明，不手写页面。

## 故事卡片

每段讲述存成一张故事卡片，这是一图一事和主方案之间的数据接口。

| 字段 | 说明 |
|------|------|
| 讲述者 | 对应一位老人，归属一份家族档案 |
| 照片 | 1 到 9 张，保存顺序；原图保留，修复版另存，不覆盖原图 |
| 原声 | 原始录音永久保留；重讲时保留最后一版，删除需老人确认 |
| 转写 | 逐字转写，带时间戳 |
| 标题 | 摘取的原话或话题名 |
| 话题 | 来自话题库、子女出题或自由讲 |
| 讲述时间 | 录音完成时间 |
| 确认状态 | 未确认、已发布、已撤回 |
| 可见范围 | 仅自己、家人；与 [产品功能 MEM-802](../产品功能.md#家庭端) 一致，不提供公开链接 |
| 案例展示授权 | 老人单独授权后，官方账号才能把这段用于对外内容 |
| 家人补充 | 留言和补充照片，标注来源人 |

与主方案 [产品功能 核心数据对象](../产品功能.md#核心数据对象) 的对应：

| 故事卡片部分 | 主方案对象 |
|------------|----------|
| 照片 | 素材 |
| 原声、转写 | 访谈记录 |
| 讲述者、家人、可见范围 | 回忆录项目、成员 |
| 授权项 | 授权记录 |
| 转写中的人物、地点、时间 | 人生记忆图谱，接入主方案事件抽取后补齐 |

## 合规要点

以下是产品层面的要求，不构成法律意见，上线前由法务逐条确认。

- **本人授权**：子女是发起者，不能代替老人授权，规则同 [伦理与合规 授权原则](../伦理合规.md#授权原则)。
- **AI 生成内容标识**：短片带显式文字标识，文件写入隐式标识，按《人工智能生成合成内容标识办法》执行。
- **模型与备案**：语音识别和大模型使用阿里云百炼已上线的模型；小程序服务类目、是否需要另行算法备案，上线前确认。
- **支付**：iOS 小程序内的虚拟商品支付有限制。上线前确认可行方案，备选是子女在安卓端、公众号 H5 或企业微信内付款。
- **他人隐私**：照片和讲述涉及他人时提示，默认仅家人可见。
- **内容安全**：照片和转写在发布前过内容安全审核。
- **数据归属**：故事归讲述者所有，可导出、可删除，规则同 [伦理与合规 数据归属与长期保管](../伦理合规.md#数据归属与长期保管)。

## 研发估算

估计 2 名全栈 3 到 4 周，复用 AAF 后端、一期规划中的 UniApp 小程序和语音识别接入。最费时的部分预计是短片模板合成、微信支付与退款、授权流程。估算需在技术设计后由 architect 校准，设计文档放 [回忆录平台设计](../../../design/memoir/Readme.md)。
