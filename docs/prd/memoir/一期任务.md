# P0 研发任务卡

本文的范围、规则和验收线以 [P0 需求规格](./一期需求规格.md) 为准。

## 估点口径

| 字段 | 含义 |
|------|------|
| SP | 从零实现的规模，斐波那契数（1、2、3、5、8）。原卡沿用 0.1.0 的 SP，新增卡按同一口径给出 |
| 人日 | 扣除 AAF 已有能力后的研发投入，含自测、代码评审和 `pnpm check:affected`，不含产品验收等待。0.1.0 的"1 SP 约等于 1 人日"不再成立，SP 与人日的差值就是复用收益 |
| 计划 | 实际排入排期的人日。可降级卡按降级口径计；分两段排的卡按段计 |
| 期与周 | W1 到 W4 为一期，W5 到 W8 为二期，W9 到 W12 为三期（与机构试点前 4 周并行） |

T-008、T-010 是数据标注，不是研发工作，人日单独列出，不计入研发容量。

## 团队与容量

| 项 | 值 |
|----|----|
| 人力 | 1 名人类开发者 + 2 个 AI agent，按 3 名全栈计 |
| 每周容量 | 3 人 × 5 天 = 15 人日 |
| 每期容量 | 3 人 × 20 天 = 60 人日 |
| 利用率上限 | 80%，每期计划不超过 48 人日 |
| 留白用途 | 每期 12 人日，用于联调、内测、缺陷修复、人类评审 AI 产出、小程序提审 |

人类开发者还要承担评审、模型与小程序账号、标注组织等对外事项，实际编码时间少于 1 人。80% 上限已经把这部分算进去，不建议再提高。

### 容量结论

| 口径 | 人日 |
|------|------|
| 全部任务卡人日合计（按复用下调，不降级） | 165 |
| P0 计划需求（应用需求规格允许的人工线降级，不含试点支持） | 139 |
| 两期计划上限（2 × 48） | 96 |
| 一期计划 / 二期计划 | 48 / 48 |
| **超出两期** | **43**，排在三期 W9 到 W12；加上 T-802 试点支持 3 人日，三期计划 46 人日，利用率 77% |
| 未排期 | 23：移到 P1 的 5 人日，人工线降级回补 18 人日（W13 起排） |
| 数据标注（不计研发） | 11：T-008 8 人日、T-010 3 人日 |

按原两期里程碑排（一期同时承担自助线和最小人工链路），一期需要 106 人日，是一期上限 48 人日的 2.2 倍；二期只有 33 人日。两期总量 139 人日超出上限 43 人日，即使按 100% 利用率（120 人日）也超出 19 人日，因此改为三期。

本文排期采用方案 A，已于 2026-11-10 经人类确认：一期只做自助闭环，人工链路（降级版）放到二期，顾问、机构、运营能力放到三期。需求规格的 [里程碑](./一期需求规格.md#里程碑) 已按此更新。

## 使用规则

任务卡编号 T-xxx 只在本文内使用；评审通过后，按 [协作规范](../../../.kiro/steering/collaboration.md) 转为 backlog 中的用户故事 `AAF-XXX` 和 `docs/task/` 下的技术任务 `#XXXNN`。

### 开工标准

- 验收线可测。
- 依赖卡已完成，或同周内可先用 mock 推进。
- 设计和接口契约已评审。
- 涉及 AI 的卡已明确评测集和指标线。

### 完工标准

- 代码合并，单测覆盖核心分支，`pnpm check:affected` 全绿。
- AI agent 提交的代码经人类开发者评审后合并。
- 测试命名符合 [测试规范](../../reference/dev/test/unit-test-standard.md)：单测 `*Test.java`、`*.test.ts`；验收测试由 tester 负责。
- 验收线逐条打勾，埋点上报验证通过。
- 接口和数据结构文档同步更新。
- AI 相关卡已跑回归，指标未下降。

### 估点复核

T-903、T-606、T-904、T-203、T-505 是高不确定性卡。T-903、T-606 在 W1 前 2 天做技术验证，T-203 在 W5 第 1 天做；结论推翻估点时立即重排后续周，不带着错误估点继续。
