# 老人回忆录平台产品需求（PRD）

## 产品概述

定位与商业模式见 [产品定位](./产品定位.md)，主流程见 [用户旅程](用户体验地图.md)，七层流水线见 [智能体工作流](../../design/memoir/agent-workflow.md)。本文只定义功能。

### 产品端

| 端 | 形态 | 用户 | 做什么 |
|----|------|------|-------|
| 移动端 | 一套 UniApp 代码，打包为微信小程序和独立 App | 老人、家属、交付人员、机构护理员和社工 | 自助对话访谈、人工访谈录音、拍照上传、事实确认、授权与签字、预览分享、家族档案、排期、照护档案查看 |
| 工作台 Web | 浏览器 | 交付人员、编辑、OPC | 转写校对、时间线、成稿编辑、事实核对台、排版 |
| 管理 Web | 浏览器，按 EntityDef 声明 | 机构管理者、平台运营、顾问 | 机构看板、老人名单导入、订单与 SKU、OPC 派单、工时、模板与年代事件库、投诉处理 |

移动端按登录身份进入四种模式：

| 模式 | 登录者 | 首页 | 设计要点 |
|------|-------|------|---------|
| 老人模式 | 讲述者本人 | "开始讲故事"、本周提问、我的短片 | 大字、语音为主、一屏一件事，不出现任何专业功能 |
| 家属模式 | 子女、家人 | 父母的档案与项目进度、待确认事项、作品、订阅 | 陪同访谈、补照片和记忆、分享、确认时间线、签核对报告、付款、升级人工 |
| 交付模式 | 自营交付人员、OPC | 今日访谈、待上传录音、项目列表 | 长时间稳定录音、离线缓存、断点续传、时长提醒；默认引导使用 App 版本 |
| 机构模式 | 护理员、社工 | 本楼层老人、今日排期、照护档案 | 只看授权范围内的内容，不能看原始录音和完整文稿 |

合在一个移动端的理由见 [产品定位 产品形态](./产品定位.md#产品形态)。

打包成两种形态：小程序免安装、微信登录、分享方便，适合老人、子女和护理员；交付人员要连续录音 1 到 2 小时、上传大文件，小程序的后台录音和文件大小受限，交付模式默认引导使用 App 版本。AAF 技术栈已规划 UniApp（`apps/uniapp/`），一套代码可同时输出两种形态。

| 风险 | 应对 |
|------|------|
| 老人模式被专业功能弄复杂 | 按模式整体切换界面，不在同一界面里藏菜单；老人模式单独做可用性测试 |
| 交付和机构人员能接触家庭数据 | 按项目授权；敏感数据访问记审计日志；机构模式沿用导出限制 |
| 小程序录音不稳定 | 自助对话按 10 到 15 分钟一段录制；交付模式默认使用 App 版本 |
| 小程序类目审核与录音权限 | 上线前确认类目和隐私协议，提前准备审核材料 |

本文中的"家庭端"指移动端的老人模式和家属模式，"交付工作台"指移动端交付模式加工作台 Web，"机构端"指移动端机构模式加管理 Web 的机构部分，"运营后台"指管理 Web 的运营部分。

### 核心数据对象

| 对象 | 说明 |
|------|------|
| 家族档案 | 对应一位讲述者的长期档案，汇集多次讲述、照片、家人补充和人物关系；自助作品和人工项目都挂在其下 |
| 事实卡片 | 从自助对话中抽取的时间、地点、人物、事件，带本人确认状态；升级人工时按中等强度证据带入 |
| 线索与预问卷 | 讲述者基本信息、健康状况、话题禁忌、方言 |
| 订单 | SKU、增值项、付款节点 |
| 回忆录项目 | 对应一位讲述者，含成员、授权、进度；机构项目下挂一批讲述者 |
| 授权记录 | 分项授权、监护人代授权、撤回历史 |
| 访谈记录 | 录音、转写、说话人、访谈者备注 |
| 素材 | 照片、信件、证件扫描件及修复版本 |
| 人生记忆图谱 | 人物、事件、地点、时间及关系，每条带来源和核对状态 |
| 作品 | 故事书、人生短片、照护档案等，每个段落关联图谱来源 |
| 事实核对报告 | 事实清单、核对状态、改写说明、编者注、签字记录 |
| 工时记录 | 每个项目按流水线层级记录的人工工时 |

## 优先级定义

| 优先级 | 含义 |
|--------|------|
| P0 | MVP 必须，分三期研发、各 1 个月：标"一期"的是基础引擎与自助闭环，标"二期"的是最小人工链路，标"三期"的是全用户类型支持 |
| P1 | 第 3 到 6 个月：订阅、自助付费、按需印刷、提升毛利与 B 端适配 |
| P2 | 第 6 个月以后：规模化与对外输出 |

## MVP 范围

2026 年 11 月起，MVP 按**自助优先**分三期研发，各 1 个月，按 3 名全栈、基于 AAF 已有的初始框架构建，依据见 [产品定位](./产品定位.md)。各期的规格、状态机、验收线和 12 周里程碑见 [P0 需求规格](一期需求规格.md)，任务卡与估点见 [P0 研发任务卡](一期任务.md)。

**一期：基础引擎，自助闭环（第 1 个月）。** 会用手机的老人在小程序里完成"开通授权 → 对话讲述 → 确认事实卡片 → AI 整理润色 → 预览生成短片 → 分享给家人 → 家人加入档案、补充记忆"，一期发布后启动 2 到 4 周原型验证。档案页提供升级入口，记录升级请求。

**二期：最小人工链路（第 2 个月）。** 交付人员用交付模式和工作台 Web 承接自助升级订单，走完"录音上传 → 转写 → 时间线 → 初稿 → 事实核对 → 讲述者确认 → 家属签署核对报告"；时间线和初稿半手动，事实核对门禁完整。

**三期：全用户类型（第 3 个月）。** 补齐顾问、机构人员和平台运营的能力，以及排版交付和电子小传，支撑家庭标准交付的完整链路和一个 20 位老人的机构付费试点；试点在三期第 1 周签约。

- **一期包含**：统一账号与身份切换、老人模式、家属模式、分项授权、自助对话访谈与转写、事实确认卡片、自助润色与原声短片、家族档案库、家人邀请与家族内分享、家人补充记忆、资料上传、AI 内容标识、方言与抽取回归评测。
- **二期包含**：交付模式、项目与成员、升级人工、访谈录音、说话人分离、转写校对、事件抽取与时间线、矛盾检测、家属确认时间线、章节大纲与初稿、原文对照、编者注、事实核对清单与报告、家属签字、讲述者确认、家属确认通知。
- **三期包含**：预问卷与接单评估、订单与分段付款、进度看板、提纲生成、访谈时长提醒、监护人代为授权、精装排版与原声二维码、完整导出、电子小传、照护档案、机构最小控制台（老人档案、排期、回顾记录）、订单与项目管理、工时记录。
- **不包含**：数字人、声音克隆、AI 方言电话访谈、有声书、分镜视频与纪录片、多租户与 OPC 派单、逝者相关功能；记忆托管订阅、自助付费解锁、按需印刷、纪念日提醒、拼单在第 3 到 6 个月作为 P1 上线。

| MEM-809 | 自助对话访谈 | 老人自己或子女陪同在小程序里和 AI 语音对话，每次 10 到 15 分钟，按人生阶段和老照片提问并追问；每次讲完生成小短片；子女可设置每周提问 | P0（一期） |

| MEM-811 | 事实确认卡片 | 从对话和家人补充中抽取时间、地点、人物、机构、事件、数量，以大字卡片加语音朗读请本人确认、修改或删除 | P0（一期） |
| MEM-812 | 自助润色与原声短片 | 只用本人确认的卡片和原话生成标题、字幕、旁白和电子小传；高风险内容不润色；预览后生成；标注 AI 整理、未经人工核对 | P0（一期） |

## 核心用户故事与验收标准

### MEM-001 统一账号与多身份 与 MEM-002 身份切换

作为同时是子女和社区社工的用户，我想用一个账号在不同身份之间切换，并且只看到当前身份有权看的内容。

```gherkin
Given 用户同时拥有"家属"和"交付人员"两个身份
When 用户以家属身份登录
Then 首页显示父母的项目进度和待确认事项
And 不显示其他家庭的项目

Given 用户切换到交付人员身份
When 打开项目列表
Then 只显示分配给自己的项目
And 本次切换和之后访问的敏感数据都写入审计日志

Given 用户以机构模式登录
When 打开某位老人的档案
Then 只能看到照护档案和进度
And 没有原始录音和完整文稿的入口
```
### MEM-201 分项授权 与 MEM-204 监护人代为授权

作为讲述者，我想清楚知道每项授权会让我的声音和照片用在哪里，以便只同意我愿意的部分。

```gherkin
Given 项目已创建且讲述者能自主表达
When 交付人员打开授权页并播放语音说明
Then 每项授权以大字号展示，默认只勾选"内容采集"

Given 讲述者未授权"声音使用"
When 交付人员尝试生成使用原声的短片
Then 系统阻止生成并提示需要声音授权

Given 讲述者无法自主表达
When 监护人上传监护证明并提交代授权
Then 授权在顾问审核通过前不生效，作品中标注"监护人代为授权"
```

### MEM-303 时长提醒

作为交付人员，我想在访谈时长接近上限时得到提醒，以便保护老人的身体状况。

```gherkin
Given 访谈录音进行中
When 录音时长达到 60 分钟
Then 交付工作台提示"建议休息或结束本次访谈"

Given 录音时长达到 2.5 小时
When 交付人员未结束访谈
Then 系统持续强提醒，并在工时记录中标记超时
```

### MEM-401 方言增强转写

作为交付人员，我想把老人的方言口述转成文字，同时保留原声，以便核对原意。

```gherkin
Given 讲述者使用预问卷中填写的方言完成一段录音
When 转写完成
Then 每个句子可点击播放对应的原始录音片段
And 识别置信度低的句子被高亮标记为"待校对"
```

### MEM-404 事件抽取 与 MEM-406 矛盾检测

作为交付人员，我想自动得到口述中的事件，并知道每条信息出自哪句话、哪里前后矛盾。

```gherkin
Given 一次访谈的转写已校对完成
When 系统完成事件抽取
Then 每个事件都关联至少一句来源转写
And 没有来源转写的事件不会进入时间线

Given 两次访谈中同一事件的年份不同
When 事件合并到时间线
Then 该事件标记为"存疑"并同时展示两处来源
And 存在"存疑"关键事件时，项目不能进入成稿阶段
```

### MEM-502 初稿生成 与 MEM-503 原文对照

作为家属，我想读到通顺的回忆录，同时确认里面还是父母自己的话。

```gherkin
Given 交付人员基于家属已确认的时间线生成初稿
When 初稿生成完成
Then 保留原话的段落和 AI 改写的段落有可区分的标记
And 正文中不出现没有来源事件的经历描述

Given 交付人员查看一个 AI 改写的段落
When 点击"原文对照"
Then 展示来源转写文字和原始录音片段，并可一键恢复为原话
```

### MEM-602 事实核对报告 与 MEM-603 家属签字确认

作为家属，我想看到书中每条事实的出处，并签字确认后再印刷。

```gherkin
Given 交付人员已完成事实核对清单中的逐条核实
When 生成事实核对报告
Then 报告列出每条事实的来源录音时间点、转写片段和核对状态
And 改写段落和编者注单独列出

Given 报告中仍有状态为"存疑"的事实
When 交付人员尝试提交家属签字
Then 系统阻止提交并列出存疑条目

Given 家属在家庭端审阅报告
When 家属电子签字
Then 作品状态变为"可印刷"，签字记录写入报告
```

### MEM-703 人生短片

作为家属，我想得到一部可以发到家族群的父母人生短片。

```gherkin
Given 讲述者已授权声音使用和肖像使用，且时间线已确认
When 交付人员选择短片模板并生成
Then 生成 3 到 5 分钟的短片，包含照片、原声片段和字幕
And 短片中的每段原声都来自已核实的事实
And 短片带有 AI 生成标识
```

### MEM-704 讲述者确认

作为讲述者，我想在作品交付前听一遍，以便改掉说错或不想公开的内容。

```gherkin
Given 交付人员已提交作品
When 讲述者在交付人员协助下打开确认页
Then 系统逐章朗读作品，讲述者可随时口头提出修改
And 修改意见自动定位到当前朗读的段落

Given 讲述者尚未确认
When 家属尝试签字确认
Then 系统提示需要讲述者先确认
```

### MEM-705 完整导出

作为家属，我想随时把所有资料带走，以便不依赖平台长期保存。

```gherkin
Given 项目中存在录音、照片、转写、作品和事实核对报告
When 家属申请完整导出
Then 系统生成包含全部原始文件、作品和报告的压缩包
And 文件均为通用格式（如 MP3/WAV、JPG/PNG、DOCX/PDF、MP4）
```

### MEM-902 工时记录

作为平台运营，我想知道每个项目在每一层花了多少人工工时，以便判断能否达到 15 小时的目标。

```gherkin
Given 交付人员在交付工作台中处理项目
When 交付人员开始和结束一项任务
Then 工时按流水线层级（L1 到 L7）自动记录

Given 项目已交付
When 运营查看项目工时
Then 展示各层工时、总编辑有效工时及与 15 小时目标的差距
```

### MEM-812 自助润色与原声短片

作为会用手机的老人，我想自己讲完故事后得到一部像样的短片，同时确定里面没有我没说过的话。

```gherkin
Given 老人完成一次对话，系统抽取出 12 张事实卡片
And 老人确认了 9 张、修改了 2 张、删除了 1 张
When 系统生成短片的字幕和旁白
Then 字幕和旁白只使用已确认和已修改的 11 张卡片及原话
And 每句文字都能回溯到对应的卡片或原话片段

Given 某段讲述命中"在世他人负面评价"规则
When 系统生成短片
Then 该段不生成旁白、不改写，默认不进入成片
And 预览页提示用户可以选择保留这段原声

Given 短片已生成
When 老人或子女未完成完整预览
Then 无法生成正式文件和分享链接
And 正式文件标注"AI 整理、内容经本人确认、未经人工事实核对"
```

### MEM-809 自助对话访谈

作为会用手机的老人，我想每次花十几分钟和 AI 聊聊过去，不想谈的事情不会被问到，随时可以停下。

```gherkin
Given 老人开通时填写了不想谈的话题"前一段婚姻"
And 已授权"内容采集"
When 老人点"开始讲故事"并完成一次 15 分钟对话
Then AI 的提问中不出现与"前一段婚姻"相关的问题
And 录音按段保存并完成转写
And 对话结束后 5 分钟内生成本次的事实卡片

Given 老人未授权"内容采集"
When 老人点"开始讲故事"
Then 系统先展示语音朗读的授权说明，授权前不开始录音

Given 对话进行中
When 老人说"不想说了"或点"停下"
Then 对话立即结束，已讲内容正常保存
And 不再追问当前话题

Given 对话进行到 15 分钟
When 老人仍在讲述
Then 系统温和提示"今天先讲到这里，下次接着讲"，并在当前段落结束后收尾

Given 语音服务暂时不可用
When 老人完成一次对话
Then 录音完整保存，界面提示"稍后为您整理"
And 服务恢复后自动补生成卡片和短片
```

### MEM-811 事实确认卡片

作为老人，我想一张张听系统念出它记下的事，说对、要改还是删掉，只有我认可的内容才会写进短片。

```gherkin
Given 一次对话抽取出时间、地点、人物、机构、事件、数量 6 类共 12 张卡片
When 老人打开确认页
Then 每张卡片以大字展示并自动语音朗读
And 选项只有"对""要改""删掉"

Given 老人对一张卡片选"要改"并用语音说出正确的内容
When 老人确认修改
Then 卡片状态变为 EDITED，润色使用修改后的内容

Given 一段讲述的转写置信度低于 0.75
When 生成卡片
Then 这一段不出卡片，下次对话时请老人复述确认

Given 当前账号以家属身份登录
When 尝试确认老人的卡片
Then 系统拒绝并提示"需要由讲述者本人确认"

Given 一张已确认的卡片被短片引用，短片已发布
When 老人删除这张卡片
Then 卡片状态变为 DELETED
And 引用它的短片自动下架，分享链接失效，提示重新生成
```

### MEM-813 家人邀请与 MEM-802 家族分享页

作为老人，我想把短片发到家族群，只有我邀请的家人能看到，别人拿到链接也打不开。

```gherkin
Given 老人在短片页点"分享给家人"
When 生成邀请
Then 邀请有效期 7 天、最多使用 10 次
And 家人扫码后直接加入档案并能看到短片

Given 已加入的女儿向舅舅发出邀请
When 舅舅扫码
Then 舅舅进入"等待老人同意"状态，暂时看不到档案内容
And 老人在老人模式首页看到"舅舅想加入，同意吗"

Given 邀请已过期或已用满 10 次
When 有人扫码
Then 提示邀请已失效，不能加入

Given 一位未受邀的用户拿到了分享链接
When 打开链接
Then 页面不显示任何档案或作品内容，只提示"请联系家人邀请"

Given 老人在老人模式中指定女儿为代管家属
When 女儿把某部短片的分享范围改为"指定成员"
Then 只有被指定的成员能看到这部短片
And 修改记录写入审计日志
```

### MEM-805 家族档案库与 MEM-804 家人补充记忆

作为子女，我想往父母的档案里补照片和我记得的事，这些内容标明是我补的，涉及父母的事实还要父母自己点头。

```gherkin
Given 儿子已加入父亲的档案
When 儿子上传一张老照片并补充"1978 年全家在厂门口合影"
Then 照片和文字进入档案，标注来源人为儿子
And 系统从补充中抽取"1978 年""厂门口"等卡片，状态为 EXTRACTED
And 父亲确认前，这些卡片不用于任何润色

Given 父亲讲过 3 次，家人补充过 5 条
When 任一成员打开档案
Then 按人生阶段看到全部讲述、照片和补充，每条可以查看来源

Given 父亲的档案已有一个待处理的升级请求
When 儿子再次点"升级人工成书"
Then 系统提示已有升级请求在处理中，不重复提交
```
其余 P0 功能的验收标准在进入 backlog 拆分用户故事时补充。

## 非功能需求

| 类别 | 要求 |
|------|------|
| 适老化 | 人工访谈时讲述者不需要操作设备；自助版以语音对话为主，每次 10 到 15 分钟；家庭端正文字号不小于 20pt，单屏一项任务，支持语音输入；所有文字可语音播报 |
| 访谈安全 | 日常单次 45 到 60 分钟，上限 2.5 小时，见 [伦理与合规 访谈健康与安全](伦理合规.md#访谈健康与安全) |
| 方言 | 首个方言在试点城市确定后建立评测集，给出关键实体召回率基线，不以通用演示效果对外承诺 |
| 真实性 | 每万字事实错误数为 0；作品段落到转写到录音的链路完整可追溯 |
| 隐私 | 录音、照片、健康信息加密存储；声纹、人脸、健康信息按敏感个人信息处理；默认不公开 |
| 数据保留 | 原始录音和转写在档案存续期间不可被覆盖或自动清理 |
| 部署 | 机构有要求时支持数据不出院的私有化部署（P2） |
| 合规 | AI 生成内容标识、授权留痕满足 [伦理与合规 相关法规](伦理合规.md#相关法规) |
| 可用性 | 访谈录音支持弱网和断点续传；家庭端兼容中低端安卓机 |
