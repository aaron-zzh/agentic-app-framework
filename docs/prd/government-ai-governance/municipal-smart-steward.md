# 市政“智慧管家”完整解决方案

> **一句话定位**：以市政设施“一物一码一档”为基础，通过边缘物联与AI视觉持续发现问题，以规则和人工研判驱动工单闭环，将市政运维从被动报修转为主动预防。

## 1. 方案摘要与设计结论

| 议题 | 设计结论 |
|---|---|
| 建设主线 | 围绕“感知—识别—融合—研判—派单—处置—复检—评价—学习”建设，不建设仅展示告警的大屏 |
| AI定位 | AI负责识别、归并、分级和辅助决策；安全事故、跨部门事件、行政执法和设备控制必须由有权人员确认 |
| 数据底座 | GIS设施资产台账是设施事实源，事件中心是问题状态事实源，工单系统是处置过程事实源 |
| 前端感知 | 优先复用已有摄像头、液位计、压力计和巡检终端；新增设备须通过点位价值评估 |
| 部署方式 | 政务云/城市云中心节点 + 区县边缘节点 + 设备端推理，视频默认就近分析、按事件取证 |
| 建设策略 | 先选高频、标准明确、闭环责任清晰的“小切口”，验证成效后按设施类型和区域扩展 |

## 2. 建设背景、目标与原则

### 2.1 现状痛点

1. 市政问题主要依赖人工巡查和群众报修，发现晚、覆盖不均、夜间空窗明显。
2. 摄像头、传感器、资产台账和工单系统彼此割裂，同一问题重复告警、重复派单。
3. 事件描述不统一、权责边界不清，跨部门流转和退单耗时。
4. 处置完成重“回单”轻“复检”，设施反复故障无法沉淀预防性养护依据。
5. 传统视频平台存储大量原始数据，但未形成可量化、可评价的治理闭环。

### 2.2 建设目标

- **主动发现**：对重点道路、易涝点、关键井盖和管网节点提供7×24小时监测。
- **秒级识别**：在网络和设备正常条件下，边缘AI对目标事件完成秒级初检。
- **闭环处置**：事件自动关联设施、责任网格和处置标准，减少人工录入与转派。
- **预防养护**：基于历史故障、环境和处置效果形成风险画像和养护建议。
- **可管可控**：每个AI结论保留模型版本、输入证据、置信度、人工修正和操作审计。

### 2.3 建设原则

复用优先、标准先行；边缘处理、最小采集；一事一档、全程留痕；分级处置、人在回路；算法可评估、模型可回退；平急结合、韧性运行。

## 3. Epic、范围与用户故事

### 3.1 Epic

**目标**：建设城市级市政设施智能运维能力，使重点问题可及时发现、准确研判、快速处置、自动复检和持续改进。

**范围**：首期建议选择道路病害、井盖异常、道路积水、路灯故障四类事件；桥隧结构异常和供排水管网风险先做数据接入与辅助预警，达到专业验证条件后再扩展。

### 3.2 用户角色

| 角色 | 主要职责 | 关键权限 |
|---|---|---|
| 城运值班员 | 查看告警、复核事件、启动联动 | 复核、升级、合并、驳回 |
| 市政平台主管 | 配置责任网格、规则和SLA，监督绩效 | 规则发布、跨部门协调、统计 |
| 养护单位调度员 | 接单、分派班组、反馈进度 | 工单调度、申请协同/延期 |
| 现场处置人员 | 导航到场、处置取证、申请完工 | 更新工单、上传材料 |
| 专业技术人员 | 研判桥隧、管网等专业风险 | 专业会诊、风险签署 |
| 算法运营员 | 标注误报漏报、评测和发布模型 | 数据集管理、灰度、回滚 |
| 审计与安全员 | 检查访问、数据使用和模型行为 | 只读审计、告警处置 |

### 3.3 用户故事

1. **作为城运值班员**，我希望同一问题的多路告警被自动归并并展示证据，以便快速确认真实事件。
2. **作为市政平台主管**，我希望事件按设施、位置、等级和责任网格生成派单建议，以便压缩流转时间。
3. **作为现场处置人员**，我希望在移动端获得位置、照片、规范和安全提示，以便一次到场完成处置。
4. **作为专业技术人员**，我希望高风险告警自动升级并保留原始测量值，以便进行专业判断。
5. **作为算法运营员**，我希望将复核结论和复检结果形成标注样本，以便持续降低误报和漏报。

**完成条件**：试点区域内目标设施建档、四类首期事件形成闭环、关键接口连通、AI与人工操作可追溯，并达到双方核定的验收阈值。

## 4. 业务场景与闭环流程

### 4.1 重点场景

| 场景 | 感知方式 | AI/规则能力 | 处置边界 |
|---|---|---|---|
| 道路病害 | 车载/固定视频、巡检APP | 坑槽、裂缝、抛洒物识别，面积估计 | 评分仅用于巡检排序，不替代工程检测 |
| 井盖异常 | 井盖传感器、视频 | 位移、倾斜、缺失、周边积水识别 | 丢失或大位移直接升级人工值守 |
| 道路积水 | 液位计、视频、降雨 | 水位融合、趋势预测、影响范围估计 | 泵闸控制和道路封闭由授权人员决定 |
| 路灯故障 | 控制器电参量、夜间视频 | 不亮、频闪、异常耗电、群体断电识别 | 自动生成维修建议，不直接带电操作 |
| 桥隧风险 | 振动/位移/应变、巡检 | 异常检测、趋势变化、阈值告警 | 不替代法定检测和结构安全鉴定 |
| 管网风险 | 压力、流量、声学、液位 | 爆管/渗漏/堵塞疑似点和趋势 | 开挖和阀门操作必须专业审批 |

### 4.2 闭环流程

```text
设备/视频/人工上报
  → 边缘预处理与AI初检
  → 多源时空融合、去重和设施关联
  → 风险分级与责任匹配
  → 低风险按已批准规则自动派单 / 中高风险人工复核
  → 工单接收、到场、处置、过程反馈
  → 设备复测 + AI复检 + 必要的人工验收
  → 销项、绩效评价、复发分析
  → 误报/漏报/处置结果回流模型与养护计划
```

### 4.3 状态机与时限

`待融合 → 待研判 → 已确认 → 已派单 → 已接单 → 处置中 → 待复检 → 已销项`；旁路状态包括 `已合并`、`误报`、`挂起`、`升级应急`、`退回重办`。

- 原始告警不得因事件合并而删除，只建立归属关系。
- 高风险事件进入“升级应急”后，不受普通工单SLA替代。
- 完工回单不等于销项；必须满足复检规则。
- 超时、退单、反复故障自动升级，规则版本必须留痕。

## 5. 总体架构

```text
感知层：摄像头｜液位/压力/流量/电参量｜车载巡检｜移动上报
  ↓ 国标/行业协议、设备身份与安全接入
边缘层：流媒体解码｜质量检查｜AI推理｜隐私遮蔽｜断网缓存
  ↓ 结构化事件、取证片段、设备遥测
平台层：物联接入｜事件中心｜规则引擎｜GIS资产｜工单编排｜AI平台
  ↓
能力层：识别融合｜风险分级｜派单建议｜复检比对｜预测养护｜智能问答
  ↓
应用层：值守工作台｜领导看板｜移动处置｜算法运营｜设备运维
  ↔ GIS/城运/12345/既有工单/视频平台/统一身份/短信消息
```

- **边缘侧**保留即时推理能力，中心失联时继续检测并按优先级缓存补传。
- **平台侧**采用事件驱动架构；业务事件、设备遥测和视频证据分级存储。
- **AI平台**管理数据集、模型注册、评测、灰度、漂移监测和回滚，不与业务状态混为一体。

## 6. AI与数据方案

### 6.1 AI能力链

| 环节 | 推荐方法 | 输出 | 人机协同 |
|---|---|---|---|
| 图像质量检查 | 清晰度、遮挡、夜间可见性模型 | 可用性和失败原因 | 低质量输入不输出确定结论 |
| 目标识别/分割 | 检测、分割、时序跟踪模型 | 类别、位置、范围、置信度 | 中低置信进入复核池 |
| 传感异常检测 | 阈值、统计模型、时序模型组合 | 异常分、趋势、贡献变量 | 保留原始值与规则命中项 |
| 事件融合 | 时空聚类、设施拓扑和规则 | 唯一候选事件、关联告警 | 值班员可拆分或合并 |
| 风险分级 | 可解释规则 + 校准模型 | 等级、理由、SLA建议 | 中高风险必须人工确认 |
| 派单推荐 | 责任矩阵、网格、负载和技能匹配 | 责任单位和班组建议 | 越权和跨部门派单须确认 |
| 复检 | 前后图像比对、传感恢复判断 | 通过/疑似未完成 | 争议或高风险由人工验收 |
| 预测养护 | 生存分析/时序预测 | 风险区间和建议窗口 | 仅作为计划编制依据 |

### 6.2 置信度策略

每类模型独立校准阈值，不使用统一分数。建议初始策略：高置信且低风险事件可按已审批规则自动建单；中置信进入人工复核；低置信仅进入观察或采样池；任何红线规则命中均升级人工。阈值须在试点标注集上按“漏报成本优先级”核定，不得直接沿用实验室指标。

### 6.3 模型生命周期

`样本授权 → 脱敏标注 → 数据集版本 → 离线评测 → 安全/偏差评审 → 影子运行 → 小流量灰度 → 发布 → 漂移监测 → 复评/回滚`。

每次推理记录 `modelVersion`、`inputDigest`、`confidence`、`ruleVersion`、`output` 和最终人工结论；不保存模型隐含推理过程。出现分区域准确率下降、设备场景变化或连续误报时自动降级为规则/人工模式。

### 6.4 数据来源与质量

| 数据 | 权威来源 | 关键质量规则 |
|---|---|---|
| 设施资产与拓扑 | GIS/市政资产系统 | 唯一编码、坐标、管理单位和状态完整 |
| 视频与图像 | 视频平台/巡检终端 | 时间同步、点位映射、可用率和遮挡检测 |
| 设备遥测 | 物联网平台 | 单位统一、采样频率、校准时间、异常值标记 |
| 工单与处置 | 既有工单平台 | 状态映射、责任单位、时限和证据完整 |
| 气象水文 | 权威气象/水务数据源 | 来源、时效、空间粒度和缺测标识 |
| 道路施工计划 | 住建/交通相关系统 | 有效期、影响范围和审批状态 |

数据进入平台执行身份校验、格式校验、时钟校准、主数据匹配、质量评分和血缘登记。质量不达标的数据可展示，但不得驱动自动派单。

## 7. 功能规格

### 7.1 功能清单

| 优先级 | 模块 | 核心能力 |
|---|---|---|
| P0 | 设施一张图 | 设施档案、空间查询、责任网格、设备绑定、历史事件 |
| P0 | 感知接入 | 视频/物联接入、在线状态、校准、断网缓存、质量诊断 |
| P0 | AI事件中心 | 检测、去重、融合、证据、置信度、风险分级、人工复核 |
| P0 | 工单闭环 | 责任匹配、派单、接单、处置、延期、转派、复检、销项 |
| P0 | 值守与预警 | 地图态势、事件队列、声光提醒、重大事件升级 |
| P0 | 权限审计 | 统一身份、分级授权、操作审计、数据访问审计 |
| P1 | 移动处置 | 路线导航、离线工单、到场签到、前后照片和材料记录 |
| P1 | 绩效分析 | 发现时长、处置时长、一次修复率、复发率、单位履约 |
| P1 | 算法运营 | 标注、评测、灰度、阈值配置、漂移监测、回滚 |
| P1 | 预测养护 | 设施健康度、故障风险、养护优先级和预算模拟 |
| P2 | 数字孪生联动 | 地上地下拓扑和事件影响仿真，不直接替代专业控制系统 |

### 7.2 关键业务规则

1. 事件唯一性由设施、空间网格、类型和时间窗联合判定；人工拆并结果优先于算法。
2. 责任匹配依据已发布的责任矩阵版本，不能由大模型自由生成责任单位。
3. 生成式AI可摘要告警和编写工单描述，但所有事实只能来自结构化字段和证据引用。
4. 高风险事件不得因模型低置信而被静默丢弃，应交由规则兜底或人工查看。
5. 视频默认边缘分析；中心仅接收结构化结果和必要取证片段，保留期按事件等级配置。
6. 系统不得基于人脸身份、车牌身份进行无关追踪；非业务目标区域应遮蔽。

## 8. 数据模型

### 8.1 概念登记表

| 产品概念 | 数据实体 | 主表 | 说明 |
|---|---|---|---|
| 市政设施 | `MunicipalAsset` | `municipal_asset` | 具有唯一编码、位置和责任主体的设施 |
| 感知设备 | `SensingDevice` | `sensing_device` | 摄像头或物联传感终端档案 |
| 设备观测 | `DeviceObservation` | `device_observation` | 一次结构化遥测或设备状态记录 |
| 原始告警 | `DetectionAlert` | `detection_alert` | 单设备、单模型产生且不可覆盖的检测结果 |
| 市政事件 | `MunicipalIncident` | `municipal_incident` | 多告警融合后进入治理闭环的问题 |
| 事件证据 | `IncidentEvidence` | `incident_evidence` | 与事件关联的图片、片段、测量值或文档引用 |
| 研判记录 | `IncidentReview` | `incident_review` | 人工确认、驳回、合并、升级及理由 |
| 处置工单 | `MaintenanceWorkOrder` | `maintenance_work_order` | 事件的责任、SLA和处置状态 |
| 处置记录 | `WorkOrderAction` | `work_order_action` | 工单流转、到场、施工和反馈动作 |
| 复检记录 | `RectificationInspection` | `rectification_inspection` | 完工后的设备、AI或人工验收结论 |
| 责任规则 | `DispatchPolicy` | `dispatch_policy` | 版本化责任矩阵、分级和SLA规则 |
| 模型发布 | `DetectionModelRelease` | `detection_model_release` | 模型、数据集、指标、阈值和发布状态 |
| 设施健康评估 | `AssetHealthAssessment` | `asset_health_assessment` | 指定时点的健康度、风险区间和依据 |

对象存储只保存证据文件，`IncidentEvidence` 是其业务元数据真理源；时序库可作为 `DeviceObservation` 的物理存储优化，但不得另建冲突业务概念。

## 9. 接口与集成

| 接口 | 方向 | 主要内容 | 要求 |
|---|---|---|---|
| `/api/v1/devices/observations` | 设备/物联平台→本系统 | 遥测、时间、质量码 | mTLS、设备签名、幂等键 |
| `/api/v1/detection-alerts` | 边缘节点→本系统 | 模型结果、置信度、证据引用 | 模型版本必填、断点续传 |
| `/api/v1/incidents` | 双向 | 查询、复核、升级、合并 | RBAC/ABAC、乐观锁 |
| `/api/v1/work-orders` | 双向 | 建单、流转、回单、销项 | 全局业务ID、状态映射 |
| `/api/v1/assets/{id}` | GIS/资产系统→本系统 | 设施档案、位置、责任关系 | 增量同步和冲突报告 |
| `/api/v1/model-feedback` | 业务系统→AI平台 | 人工结论、漏报、复检结果 | 脱敏、用途标记 |
| 事件总线 `incident.*` | 本系统→城运平台 | 确认、升级、超时、销项事件 | 至少一次投递、消费幂等 |

视频接入遵循现有平台和适用行业协议；接口字段、错误码及签名规范在技术设计阶段固化。外部系统不可直接更新事件终态，必须通过授权命令并校验状态机。

## 10. 安全、隐私与算法治理

- 按数据分类分级实施专网/政务外网分区、传输加密、密钥托管、最小权限和双人高权审批。
- 原始视频遵循“必要点位、必要时段、必要留存”；事件外画面、行人面部和非必要车牌在边缘侧遮蔽。
- 数据导出必须申请、审批、水印、目的绑定和到期回收；训练集不可直接复制生产全量数据。
- 规则、模型和提示词均版本化；模型发布需业务、算法、安全联合评审。
- 不以生成式AI输出作为设施安全鉴定、行政处罚或重大应急决策依据。
- 建立误报、漏报、区域/昼夜/天气分组表现、模型漂移和自动化越权监控。
- 供应商不得将政务数据用于未授权训练；合同终止时执行数据返还、删除证明和模型残留评估。

## 11. 非功能需求

以下均为**建议目标**，最终以试点基线和基础设施容量核定：

| 类别 | 建议目标 |
|---|---|
| 时延 | 边缘识别P95≤3秒；中心形成候选事件P95≤10秒；重大告警推送P95≤15秒 |
| 可用性 | 中心核心服务月可用性≥99.9%；边缘断网可连续缓存不少于24小时关键事件 |
| 容量 | 支持按区县水平扩展，单租户设备量、视频路数和事件峰值在详细设计中压测定级 |
| 可靠性 | 消息不丢失、重复可幂等；RPO≤5分钟、RTO≤2小时（建议） |
| 安全 | 高危漏洞上线前清零；高权操作、模型发布、规则发布100%审计 |
| 可解释 | 每个事件可查看来源、模型/规则版本、置信度、分级理由和人工修正 |
| 易用性 | 值班员完成复核与派单的关键路径不超过3个主要操作步骤 |

## 12. 部署与运维

- **部署拓扑**：中心双可用区部署业务与数据服务；区县边缘节点部署视频分析和缓存；设备通过安全网关接入。
- **环境隔离**：开发、测试、验收、生产分离，生产数据进入非生产环境须脱敏审批。
- **监控对象**：设备在线率、视频质量、消息积压、接口成功率、事件时延、误报漏报、模型漂移、GPU/存储容量。
- **降级策略**：模型不可用时切换规则/人工巡查；中心不可用时边缘本地告警；GIS不可用时保留设施编码并待补关联。
- **灾备演练**：至少每半年开展断网补传、模型回滚、消息堆积、中心切换和重大事件人工接管演练。
- **运营机制**：建立市政业务、城运、数据、安全、算法和养护单位联合运营组，月度复盘指标和问题清单。

## 13. 实施路线与投入边界

| 阶段 | 建议周期 | 建设内容 | 决策门 |
|---|---|---|---|
| 0. 诊断设计 | 4—6周 | 资产和设备盘点、责任/SLA梳理、点位价值评估、基线测量 | 数据和责任边界可落地 |
| 1. 小切口试点 | 8—12周 | 1—2个区域、四类事件、最小闭环、影子运行 | 准确率、闭环率和用户接受度达标 |
| 2. 区域推广 | 3—6个月 | 扩点扩类、移动处置、绩效分析、模型运营 | 单位事件成本和处置时效改善 |
| 3. 城市级运营 | 6—12个月 | 跨区协同、预测养护、灾备和标准体系 | 形成持续运营预算与责任机制 |

投入应拆分为设备利旧/新增、边缘算力、平台软件、集成实施、数据治理、标注评测、网络安全和持续运营，不能只核算一次性模型采购费。

## 14. 指标体系

指标目标均为**建议值**，试点首月核定基线后由建设方与使用方共同确认：

| 维度 | 指标 | 建议目标/计算方式 |
|---|---|---|
| 覆盖 | 重点设施有效监测覆盖率 | ≥90%，以可用观测而非设备安装数计算 |
| 发现 | 事件发现时长 | 较人工巡查基线下降≥60% |
| AI质量 | 分场景精确率/召回率 | 高风险场景优先保证召回；具体阈值按事件类核定 |
| 闭环 | 有效事件闭环率 | ≥95% |
| 时效 | 平均派单时长 | 较基线下降≥50% |
| 质量 | 一次复检通过率 | ≥90% |
| 治理 | 重复派单率 | ≤3% |
| 运营 | 设备有效在线率 | ≥98%（计划维护除外） |
| 模型 | 人工复核一致率与漂移告警闭环率 | 月度评估，漂移告警100%处置 |
| 效益 | 单位有效事件综合成本 | 试点后形成可比口径并持续下降 |

## 15. 验收标准（Gherkin）

### AC-01 多源告警融合

```gherkin
Given 同一井盖在配置时间窗内产生传感位移告警和视频异常告警
When 平台完成时空与设施关联
Then 生成一个市政事件并保留两条不可变原始告警和各自证据
And 值班员可以查看、拆分或确认融合结果
```

### AC-02 分级派单与人工门

```gherkin
Given 事件已关联设施、责任网格、风险等级和有效责任规则
When 低风险高置信事件满足已审批自动派单策略
Then 系统生成工单并记录策略版本
But 当事件为中高风险、跨部门或规则冲突时
Then 系统必须等待有权人员确认且不得自动越权派单
```

### AC-03 重大积水告警

```gherkin
Given 液位超过红线或模型预测短时内达到红线
When 系统形成重大积水候选事件
Then 在建议时限内通知值班员并展示原始水位、趋势、视频证据和影响区域
And 不直接控制泵闸或自动发布道路封闭指令
```

### AC-04 处置复检

```gherkin
Given 现场人员提交完工材料
When 设备恢复、AI前后比对和人工规则满足该事件的复检策略
Then 事件进入已销项并记录复检证据
But 任一强制项不满足时
Then 工单退回重办或进入人工验收
```

### AC-05 断网续传

```gherkin
Given 边缘节点与中心网络中断
When 本地继续产生告警
Then 节点按优先级持久化关键事件并执行本地重大告警策略
And 网络恢复后按幂等键补传且不生成重复事件
```

### AC-06 模型回退

```gherkin
Given 生产模型出现连续误报、漂移超阈值或服务不可用
When 算法运营员触发回滚或自动保护策略生效
Then 新流量切换至上一稳定模型或人工规则模式
And 已有事件、模型版本和回滚操作完整保留
```

### AC-07 隐私与审计

```gherkin
Given 用户无原始视频查看权限
When 用户打开事件详情
Then 仅展示授权的脱敏证据
And 对查看、导出、规则变更和模型发布形成不可抵赖审计记录
```

## 16. 测试要点

- **验收测试**：按AC编号建立 `*AcceptanceTest`，覆盖正常、边界、异常和权限路径。
- **AI评测**：按道路、区域、昼夜、天气、设备型号分层，分别报告精确率、召回率、校准误差和失败样本。
- **集成测试**：验证GIS主数据、视频/物联、工单状态、消息总线的幂等、重试和补偿。
- **性能测试**：模拟上下班、暴雨和集中设备重连峰值，检查告警时延、积压与自动降级。
- **安全测试**：设备伪造、越权查看、批量导出、接口重放、恶意文件、模型供应链和日志泄露。
- **灾备测试**：边缘断网、中心故障、模型回滚、对象存储不可用及人工接管。

## 17. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 资产台账不准 | 无法关联和派单 | 试点前完成一物一码抽检，建立变更责任人 |
| 摄像头角度/环境变化 | 模型性能衰减 | 点位质量评分、场景化评测、漂移监测和重标定 |
| 告警风暴 | 值班员过载 | 边缘过滤、事件融合、限流和重大事件优先队列 |
| 权责规则争议 | 反复退单 | 先治理责任矩阵，版本发布并建立争议仲裁流程 |
| 过度自动化 | 安全与行政风险 | 分级人工门、最小权限、默认不可执行设备控制 |
| 重建设轻运营 | 模型和设备快速失效 | 将设备维护、数据标注和模型复评纳入年度预算 |
| 隐私与数据滥用 | 合规和公众信任受损 | 最小采集、边缘遮蔽、用途控制、导出审批和审计 |
| 供应商锁定 | 成本和迁移困难 | 开放接口、数据可迁移、模型可替换、退出条款 |
