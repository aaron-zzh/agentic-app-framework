# 城市运行“智能报告”完整解决方案

> **一句话定位**：以统一指标语义和时空数据快照为事实基础，融合GIS与实时城市运行数据，通过AI发现异常、组织证据和辅助成文，经人工审核签发后形成“监测—处置—评估”闭环的可视化决策产品。

## 1. 方案摘要与设计结论

| 议题 | 设计结论 |
|---|---|
| 产品核心 | “指标语义层 + 证据快照 + 报告工作流”优先于大模型写作，所有数字和结论必须可回溯 |
| AI定位 | AI负责异常发现、摘要、图表建议、相似案例检索和有引用的文字草拟，不负责最终事实认定和签发 |
| 报告与预警 | 报告服务周期研判；重大异常走独立实时预警通道，不得等待报告生成或审批 |
| 数据原则 | 源系统是业务事实源，指标平台保存口径和不可变计算快照，报告只引用而不复制修改源事实 |
| 展示方式 | 报告、驾驶舱和GIS专题图共享同一指标与证据，避免数字不一致 |
| 决策闭环 | 每个重点问题可关联事件、处置动作、责任单位、时限和效果评估，下一期报告持续跟踪 |

## 2. 背景、目标与建设原则

### 2.1 现状痛点

1. 城运数据散落在物联、交通、气象、热线、工单和部门系统，统计口径与更新时间不一致。
2. 日报、周报大量依赖手工复制、制表和截图，时效性差且容易出现数字错位。
3. 传统大屏重展示轻解释，难说明异常发生在哪里、持续多久、影响什么以及是否已处置。
4. 报告结论常与证据、工单和责任动作脱节，后续效果难持续跟踪。
5. 生成式AI若直接读取杂乱数据自由成文，可能产生数字幻觉、遗漏重大异常或夸大因果。

### 2.2 建设目标

- **统一事实**：建立城市运行指标目录、语义口径、时空基准和数据质量规则。
- **实时监测**：融合GIS与实时数据，发现异常、聚集和趋势并及时预警。
- **智能成文**：自动生成有数据快照、有图表、有来源引用的报告初稿。
- **闭环跟踪**：关联问题、工单、处置和效果，形成跨期追踪清单。
- **安全可信**：落实人工审核、数字校验、敏感信息控制、版本签发和全过程审计。

### 2.3 原则

事实先于表达；实时预警与周期报告分离；统一口径、一次计算、多端复用；异常结论与数据质量并列展示；生成内容有引用、无证据不成文；分级审核、责任到人；可降级、可纠错、可重现。

## 3. Epic、用户与用户故事

### 3.1 Epic

**目标**：建设覆盖城市运行态势监测、问题处置跟踪和成效评估的智能报告能力，为领导决策、部门协同和值班研判提供及时、准确、可视化、可追溯的信息支持。

**范围**：首期建议接入城市生命线、交通运行、市政事件、12345热点、气象灾害和重点工单六类数据，交付日报、周报和专题报告；月报、预测专题和跨区域对标在口径稳定后扩展。

### 3.2 用户角色

| 角色 | 主要任务 | 关键权限 |
|---|---|---|
| 城运值班员 | 查看实时态势、核实异常、启动预警和跟踪处置 | 异常确认、预警升级、事件关联 |
| 报告编制员 | 选择模板、补充研判、校对数字和图表 | 创建、编辑、送审 |
| 部门数据专员 | 维护指标口径、解释异常和确认部门数据 | 指标会签、数据更正申请 |
| 处置责任人 | 更新行动、时限、进度和结果 | 处置反馈、申请销项 |
| 报告审核人 | 审查事实、表达、涉敏信息和建议 | 退回、会签、批准 |
| 签发领导/授权人 | 对正式发布版本承担签发责任 | 签发、撤回、勘误 |
| 数据管理员 | 管理目录、质量、血缘、权限和保留期限 | 数据规则和授权 |
| 算法运营员 | 管理异常模型、生成模型、评测与回滚 | 模型发布、阈值、灰度 |
| 安全审计员 | 监督访问、导出、发布和模型调用 | 审计、阻断、调查 |

### 3.3 用户故事

1. **作为值班员**，我希望重大异常实时弹出并展示地图位置、指标变化和关联事件，以便立即核实处置。
2. **作为报告编制员**，我希望系统按模板自动汇总指标、图表、异常和处置进展，以便减少重复汇数。
3. **作为部门数据专员**，我希望每个数字可查看口径、来源、更新时间和质量，以便确认事实。
4. **作为审核人**，我希望系统标记未引用结论、数字冲突和敏感内容，以便安全审核。
5. **作为签发人**，我希望正式版本不可静默修改且可发布勘误，以便落实责任和审计。
6. **作为处置责任人**，我希望报告中的重点问题形成跨期跟踪项，以便反馈行动和效果。

**完成条件**：试点报告可以从已授权数据自动生成，经事实校验和人工签发后发布；报告内数字、图表、异常和处置均可回溯，重大异常能够独立实时预警。

## 4. 产品形态与业务闭环

### 4.1 产品形态

| 产品形态 | 主要受众 | 更新频率 | 内容重点 |
|---|---|---|---|
| 实时驾驶舱 | 值班员、指挥人员 | 秒/分钟级 | 指标、异常、事件、地图、处置状态 |
| 城运日报 | 值班和管理层 | 每日 | 总体态势、昨日事件、今日风险和待办 |
| 城运周报/月报 | 管理层、部门 | 周/月 | 趋势、区域对比、反复问题、履约和成效 |
| 专题报告 | 专项工作组 | 按需 | 极端天气、交通拥堵、积水、热线热点等 |
| 领导简报 | 决策层 | 按需 | 关键事实、风险、处置、备选行动和限制 |
| 开放摘要 | 经授权公众 | 按发布计划 | 脱敏、聚合且已审核的公共信息 |

### 4.2 监测—处置—评估闭环

```text
多源数据接入
  → 口径统一、质量校验和指标快照
  → GIS态势与异常检测
  → 重大异常实时预警 / 一般异常进入报告候选
  → 人工核实并关联城市运行事件
  → 责任单位制定和执行处置动作
  → AI按模板组织指标、证据、图表和处置进展
  → 事实校验、部门会签、人工签发
  → 报告发布和阅读反馈
  → 下一周期评估处置效果、复发风险和未完成事项
```

### 4.3 报告状态

`待生成 → 生成中 → 待事实校验 → 编辑中 → 待会签 → 待签发 → 已发布 → 已归档`；旁路包括 `生成失败`、`退回修改`、`已撤回`、`已勘误`。

- 报告任务必须绑定模板版本、统计时点和数据截止时间。
- 已发布版本不可覆盖；更正采用新勘误版本并明确差异、原因和审批人。
- 报告中的待办事项跨期存在，直至完成、取消或由有权人员确认不再跟踪。
- 实时预警状态独立于报告状态，报告失败不得阻断预警。

## 5. 总体架构

```text
数据源层：GIS｜IoT｜视频结构化｜事件/工单｜气象水文｜交通｜12345｜部门业务
  ↓ API、消息总线、CDC、文件交换
数据治理层：目录｜主数据｜时空基准｜质量｜血缘｜分类分级｜授权
  ↓
指标语义层：指标定义｜维度｜口径版本｜计算任务｜指标快照｜质量状态
  ↓
态势智能层：GIS融合｜异常检测｜趋势预测｜影响分析｜相似事件检索｜处置评估
  ↓
报告智能层：模板编排｜证据检索｜图表生成｜受约束文本生成｜事实校验｜敏感检查
  ↓
应用层：驾驶舱｜报告工作台｜移动审阅｜处置跟踪｜算法运营｜审计中心
  ↔ 统一身份、协同办公、消息平台、电子签章、档案和应急指挥系统
```

- 流式链路服务实时态势和预警；批处理链路生成稳定统计快照，两者通过指标定义关联。
- 报告生成使用冻结快照，避免审核期间数字随实时数据变化。
- 地图图层、图表和正文引用相同快照ID，保证多端一致。

## 6. 指标与数据方案

### 6.1 数据域与质量

| 数据域 | 典型数据 | 时效要求 | 质量控制 |
|---|---|---|---|
| GIS基础 | 行政区、道路、河道、设施、网格 | 变更驱动 | 坐标系、拓扑、唯一编码、有效期 |
| 物联感知 | 液位、压力、流量、环境、设备状态 | 秒/分钟 | 时钟、单位、校准、缺测、异常值 |
| 城市事件 | 类型、位置、等级、来源、状态 | 实时 | 分类映射、去重、状态机、证据 |
| 工单处置 | 责任、时限、动作、结果 | 分钟/小时 | 事件关联、状态一致、超时和退单 |
| 气象水文 | 降雨、预警、风力、水位 | 分钟/小时 | 权威来源、发布时点、空间范围 |
| 交通运行 | 速度、拥堵、流量、事件 | 分钟 | 路段匹配、覆盖率、采样偏差 |
| 群众诉求 | 聚合主题、区域、时段 | 日/小时 | 去标识、口径、渠道覆盖、小样本保护 |
| 部门业务 | 专项指标和处置数据 | 按协议 | 责任人、数据截止时间、会签状态 |

### 6.2 指标语义层

每个指标必须定义：业务名称、含义、公式、分子分母、单位、统计周期、维度、空间粒度、来源、责任部门、更新时间、质量阈值、适用范围、版本和废止规则。

- 同名不同口径必须建立不同指标ID，不得在报告中混用。
- 指标口径变更需评估历史可比性；无法重算时在图表和正文中明确断点。
- 指标快照不可变，包含计算输入批次、执行时间、结果、质量状态和校验摘要。
- 数据迟到可触发重算，但已发布报告仅通过勘误流程更新。

### 6.3 时空融合

统一城市设施编码、事件编码、行政区划、网格和坐标系。点、线、面事件根据业务容差匹配空间对象；匹配不确定时保留候选关系和置信度，不强行落区。跨区域对比默认采用标准化指标，避免规模差异造成误导。

## 7. AI方案

### 7.1 AI能力链

| 能力 | 推荐方法 | 输出 | 约束 |
|---|---|---|---|
| 异常检测 | 规则、季节模型、时序异常检测组合 | 异常类型、幅度、持续时长、置信度 | 数据质量差时降级，不静默告警 |
| 趋势预测 | 统计/时序模型、天气等外生变量 | 预测区间、风险概率 | 必须展示区间和适用期限 |
| 影响关联 | GIS关系、事件图谱、时间相关分析 | 可能受影响区域和关联事件 | 只称“候选关联”，不自动认定因果 |
| 相似案例 | 向量检索 + 结构化过滤 | 历史事件、处置动作、效果 | 显示差异，不直接复制方案 |
| 图表建议 | 规则 + 统计特征 | 合适图形、排序和注释 | 禁止截断坐标轴误导，保留原值 |
| 报告生成 | 模板、RAG、工具调用和受约束大模型 | 有引用的段落和摘要 | 只能使用批准快照和证据，不得自由计算数字 |
| 事实校验 | 确定性计算、引用校验、NLI辅助 | 数字冲突、无依据陈述、时间错误 | 确定性规则优先，疑点交人工 |
| 敏感检查 | 规则和分类模型 | 涉密、个人信息、不当表述 | 命中红线阻断签发 |

### 7.2 证据约束生成

报告生成流程采用“先结构、后取证、再成文”：

1. 根据模板生成章节与所需指标清单。
2. 冻结指标快照、地图图层和事件清单。
3. 计算异常、同比环比、排名和变化贡献，结果由确定性工具输出。
4. 检索政策、历史报告和处置记录，形成可引用证据包。
5. 大模型只能基于证据包填充模板，不可调用互联网或未授权知识。
6. 事实校验器逐句匹配数字、时间、主体和引用；不通过内容标红并阻断送审。
7. 人工补充研判、修正表述、会签和签发。

不保存或展示模型隐含推理链；保存输入证据摘要、提示词/模板版本、模型版本、工具结果、输出和人工修改差异。

### 7.3 置信度与降级

异常置信度由模型分数、数据质量、跨源一致性和持续时长组成并分别展示。报告不得以一个综合分代替证据。模型不可用时，系统使用已冻结指标和规则模板生成基础报告；知识检索不可用时取消解释性段落；事实校验不可用时禁止自动送审。

### 7.4 模型治理

异常模型按区域、时段、季节和事件类型评测；生成模型评测数字一致性、引用覆盖、遗漏率、幻觉率、敏感信息泄露和人工修改率。模型先离线评测，再影子运行、灰度发布；任一红线指标超限立即回滚，并评估已生成但未签发报告。

### 8.1 标准报告结构

1. 数据截止时间、覆盖范围和质量摘要。
2. 总体态势与风险等级。
3. 核心指标、同比/环比及异常解释。
4. GIS热点和区域差异。
5. 重点事件与处置进度。
6. 上期重点问题成效评估。
7. 未来短期风险、预测区间与触发条件。
8. 待决策事项、备选行动、依据和限制。
9. 数据来源、指标口径、模型和人工审核声明。

### 8.2 关键规则

- 重大预警由实时规则触发并多通道送达，不能依赖大模型是否生成摘要。
- 数字计算由指标引擎或受控分析工具执行，大模型不得心算、改写或补齐缺失数字。
- 原因、责任和成效结论必须标注“已确认”“候选关联”或“尚待验证”。
- 报告发布范围由密级、数据分类和用户属性共同决定；转发、下载和打印均受控。
- 驾驶舱实时值与报告冻结值不同是允许的，但必须显示各自统计时点。
- 对外报告须使用单独模板和脱敏数据，不得直接复用内部版本。

## 9. 数据模型

### 9.1 概念登记表

| 产品概念 | 数据实体 | 主表 | 说明 |

## 11. 安全与治理

- 按数据分类分级控制驾驶舱、报告章节、地图图层、下载、打印和分享；涉敏报告可启用截屏水印和终端限制。
- 所有模型调用采用最小上下文，不向未授权外部模型发送城市运行明细或内部报告。
- 报告发布实行编制、审核、签发职责分离；紧急简报也需最少双人复核或事后补审机制。
- 指标定义、模板、提示词、模型、知识和权限变更全部版本化并审计。
- 防范提示注入、知识库污染和恶意附件；外部文本只能作为不可信证据，不能覆盖系统规则。
- 建立勘误、撤回、影响通知、模型停用和人工接管流程。
- 对外披露遵循最小必要和聚合原则，个人信息、关键基础设施敏感细节和未确认事件不得发布。

## 12. 非功能需求

以下均为**建议目标**，以试点基线和基础设施容量核定：

| 类别 | 建议目标 |
|---|---|
| 实时性 | 关键流数据入库P95≤10秒；重大异常从触发到发出通知P95≤30秒 |
| 报告效率 | 标准日报数据冻结后5分钟内形成初稿；复杂专题报告异步显示进度 |
| 可用性 | 实时预警月可用性≥99.95%；报告服务≥99.9% |
| 准确性 | 正式报告数字与冻结快照一致率100%；无引用事实陈述为0 |
| 可追溯 | 正式报告段落、图表和数字证据关联率100% |
| 可靠性 | 消息至少一次投递且消费幂等；建议RPO≤5分钟、RTO≤2小时 |
| 并发 | 满足重大事件期间授权用户集中访问，容量在试点压测后定级 |
| 易用性 | 编制员可在同一工作台完成生成、校验、编辑、送审和差异查看 |
| 可访问性 | 核心图表提供文本摘要，颜色不作为唯一状态表达 |

## 13. 部署与运维

- 部署于政务云/城市云，流式计算、指标计算、GIS、报告服务和模型服务可独立扩缩容。
- 实时预警链路与报告生成链路资源隔离，报告高峰不得挤占预警能力。
- 建立开发、测试、验收、生产环境；生产报告模板和模型发布采用审批流水线。
- 监控数据新鲜度、质量失败、指标冲突、流处理积压、异常命中率、预警送达、报告时长、引用覆盖、幻觉和人工修改率。
- 降级顺序：关闭非核心预测和问答 → 使用规则模板生成基础报告 → 仅保留指标与人工编制；实时预警始终优先。
- 每季度开展预警链路、模型回滚、报告勘误、跨区故障和人工编制接管演练。

## 16. 验收标准（Gherkin）

### AC-01 指标可追溯

```gherkin
Given 编制员查看报告中的任一数字或图表
When 打开证据详情
Then 系统展示指标定义版本、公式、数据源、统计时点、计算批次和质量状态
And 展示值与报告签发版本保持一致
```

### AC-02 重大异常独立预警

```gherkin
Given 实时指标命中已发布的重大异常规则
When 报告服务正在维护或报告尚未生成
Then 预警链路仍在建议时限内向授权人员发送通知并跟踪回执
And 不等待大模型生成文字或报告审批
```

### AC-03 证据约束生成

```gherkin
Given 报告任务已冻结有效指标快照和事件证据
When AI生成报告初稿
Then 所有数字由确定性工具提供且每个事实陈述绑定证据
And 对缺失证据的章节标记待补充而不是虚构内容
```

### AC-04 事实校验阻断

```gherkin
Given 初稿存在与快照不一致的数字、过期时间或无来源的原因判断
When 编制员提交会签
Then 系统阻断提交并定位冲突内容和证据
And 只有修正或由有权人员记录例外后才能继续
```

### AC-05 人工签发

```gherkin
Given 报告已完成事实校验、必要部门会签和敏感信息检查
When 授权签发人确认发布
Then 系统生成不可变签发版本、数字签名和发布记录
And 未获签发权限的用户不能发布正式报告
```

### AC-06 勘误与版本

```gherkin
Given 已发布报告发现源数据迟到或事实错误
When 审核通过勘误申请
Then 系统创建新勘误版本并展示与原版本的差异、原因和审批人
And 原版本保留且订阅者收到影响通知
```

### AC-07 跨期处置跟踪

```gherkin
Given 上期报告存在未完成重点问题
When 生成本期报告
Then 系统自动引用最新责任行动、时限、状态和效果指标
And 未取得新进展时明确标记而不自动销项
```

### AC-08 模型降级

```gherkin
Given 生成模型不可用、幻觉指标超阈值或事实校验服务故障
When 用户发起标准日报任务
Then 系统使用指标快照和规则模板生成基础报告或转人工编制
And 在事实校验恢复前不得自动送审
```

## 17. 测试要点

- **验收测试**：按AC编号覆盖实时预警、报告生成、校验、会签、签发、勘误和降级。
- **数据测试**：检查口径、时区、迟到数据、重复事件、GIS坐标、单位转换、历史重算和血缘。
- **AI测试**：构造数字诱导、无证据原因、冲突来源、超长上下文、提示注入和遗漏重大事件样本。
- **统计/可视化测试**：验证同比环比、分母、排序、坐标轴、空间聚合、预测区间和断点说明。
- **性能测试**：模拟流量峰值、报告集中生成和领导集中访问，验证资源隔离。
- **安全测试**：越权图层、报告转发、下载打印、批量接口、知识污染、密钥与日志泄露。
- **灾备演练**：流平台中断、指标任务失败、模型回滚、签章不可用、对象存储故障和人工接管。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 指标口径不一致 | 报告互相矛盾 | 语义层、口径会签、版本化和历史可比性说明 |
| 数据迟到或质量差 | 错误态势判断 | 新鲜度/质量并列展示、冻结快照、勘误机制 |
| 大模型数字幻觉 | 决策误导 | 确定性计算、证据约束、逐句校验和人工签发 |
| 报告替代实时预警 | 重大事件响应延误 | 独立高可用预警链路和资源隔离 |
| 相关性被当作因果 | 错误追责或政策判断 | 候选关联标识、专业研判、保守表述 |
| 过度汇报增加基层负担 | 数据填报反弹 | 优先系统自动采集，不新增无价值报表字段 |
| 涉敏信息扩散 | 安全和合规风险 | 分级权限、脱敏模板、发布审批、水印和审计 |
| 只看大屏不闭环 | 问题持续复发 | 重点问题必须关联行动、时限和效果评价 |
| 供应商锁定 | 数据和模板难迁移 | 开放接口、模板/指标/报告标准导出和退出条款 |
