# “开店宝”商业决策工具完整解决方案

> **一句话定位**：面向小微商业主体和创业者，在合规聚合多维城市数据的基础上，通过可解释模型提供商圈洞察、候选点比较、经营区间预测和政策证照提示，同时以全生命周期治理探索公共数据产品的合规市场化运营。

## 1. 方案摘要与设计结论

| 议题 | 设计结论 |
|---|---|
| 用户价值 | 降低小微主体获得商圈研究和选址分析的成本，不替代经营者判断、实地考察和专业尽调 |
| 产品主线 | “经营需求建模—候选搜索—多维评估—情景预测—风险核验—报告留档—开店后校准” |
| AI定位 | AI负责特征提取、相似业态分析、排序、预测和报告解释；经营投资、签约和行政申请由用户决定 |
| 结果表达 | 使用区间、情景、置信度、数据新鲜度和主要影响因素，禁止将模型分数包装成成功率或收益承诺 |
| 数据边界 | 只交付聚合、去标识和用途受控的数据产品；不提供个人轨迹、设备标识或敏感小样本 |
| 运营模式 | 先作为惠企公共服务验证价值，再探索基础版普惠、专业版付费和API授权；商业化不突破公共数据授权边界 |
| 政府责任 | 政府/运营方保障数据来源、产品质量、合规和公平访问，不为经营结果背书，不利用行政权力强制购买 |

## 2. 背景、目标与原则

### 2.1 现状痛点

1. 小微创业者选址主要依赖中介经验和短时蹲点，缺乏对客流时段、业态竞争、交通可达性和消费能力的系统判断。
2. 商业数据来源复杂、口径不一，价格高且存在个人信息、商业秘密和授权链不清等风险。
3. 通用选址评分通常只给总分，无法说明业态适配、租金压力、数据时效和不确定性。
4. 开店涉及规划用途、证照、消防、环保等条件，经营者容易将信息提示误解为审批承诺。
5. 公共数据开发利用若只重交易、不重授权、质量、用途和退出，可能造成隐私、垄断和公共利益风险。

### 2.2 建设目标

- **普惠服务**：让小微主体以较低门槛获得标准化商圈和选址分析。
- **智能决策**：为不同业态、面积、客单价、时段和经营目标生成可解释的候选点排序。
- **风险前置**：提示数据局限、成本敏感性、竞争风险和证照核验事项。
- **动态校准**：在用户自愿授权下使用开店后聚合经营结果校准模型，不上传无关业务明细。
- **合规运营**：建立数据授权、加工、产品登记、交付、计量、审计、投诉和退出闭环。
- **激活价值**：以可评价的惠企效果和可持续运营成本验证数据要素价值。

### 2.3 原则

公共利益优先、普惠可及；合法正当、最小必要；只给辅助、不作承诺；数据与算法透明可解释；不因付费等级降低隐私和安全标准；一数一源、产品版本化；用途可控、全程审计；先试点再规模化。

## 3. Epic、用户与用户故事

### 3.1 Epic

**目标**：建设覆盖开店需求采集、商圈洞察、候选点评估、经营模拟、政策提示和合规数据运营的一体化商业决策工具，降低小微主体决策信息差。

**范围**：首期建议选择餐饮、便利零售、生活服务三类标准化程度较高的业态，在2—3个商圈试点；不适用于医疗、金融、危化、教育培训等强监管或模型样本不足业态，除非另行完成专业规则和风险评审。

### 3.2 用户角色

| 角色 | 主要任务 | 关键权限 |
|---|---|---|
| 创业者/经营者 | 输入经营计划、比较点位、模拟成本和下载报告 | 管理本人项目和授权数据 |
| 企业服务专员 | 指导使用、解释政策入口、收集问题 | 查看经用户授权的项目摘要 |
| 园区/商圈运营者 | 查看聚合供需、招商结构和公共服务需求 | 仅查看授权区域聚合结果 |
| 数据产品经理 | 设计产品、版本、质量SLA和定价 | 产品登记、发布和下架申请 |
| 数据授权责任人 | 审查数据来源、加工用途和交付边界 | 授权、续期、撤销 |
| 算法运营员 | 训练评测、监测漂移、解释和回滚 | 模型发布和阈值管理 |
| 运营结算人员 | 套餐、计量、账单、退款和对账 | 计费配置与结算，不看敏感明细 |
| 合规/安全审计员 | 开展影响评估、访问审计和事件处置 | 审计、暂停产品和调查 |
| 监管/评审人员 | 检查公平竞争、公共利益和产品合规 | 只读检查和整改要求 |

### 3.3 用户故事

1. **作为创业者**，我希望输入业态、预算、面积、客单价和营业时段后获得匹配商圈，以便缩小实地考察范围。
2. **作为经营者**，我希望比较多个候选点的人流、消费、竞争、成本、可达性和风险，以便理解总分差异。
3. **作为创业者**，我希望看到保守、基准、乐观三种经营情景和盈亏敏感因素，以便评估可承受风险。
4. **作为企业服务专员**，我希望政策和证照提示链接到权威来源，以便引导企业办理而不构成审批承诺。
5. **作为数据产品经理**，我希望每个产品绑定授权、字段、算法、阈值、价格、SLA和有效期，以便合规运营。
6. **作为审计员**，我希望追踪某次查询使用了什么数据和模型、向谁交付、是否超出用途，以便调查风险。

**完成条件**：试点用户可完成一次从需求输入到候选比较和报告导出的闭环；结果具备来源、时效、区间和免责声明；数据产品具备完整授权、交付和审计记录。

## 4. 用户旅程与业务闭环

### 4.1 开店决策旅程

```text
选择业态与城市区域
  → 输入预算、面积、客单价、营业时段、目标客群和经营偏好
  → 系统校验适用范围并提示缺失信息
  → 推荐商圈和候选点 / 用户添加自有候选点
  → 查看人车流、消费、竞争、租金、交通、人口和政策环境
  → 生成业态适配分、主要贡献因素和风险项
  → 调整租金、转化率、客单价、成本等假设做情景模拟
  → 实地核验清单与证照事项核验
  → 人工决定是否考察、签约或放弃
  → 导出带版本与免责声明的决策报告
  → 用户自愿回传开店结果和聚合经营指标用于复盘
```

### 4.2 决策项目状态

`草稿 → 信息待完善 → 分析中 → 可比较 → 待实地核验 → 已形成报告 → 用户已决策 → 已开店/已放弃/暂缓 → 已归档`。

系统不把“评分最高”自动标记为“应签约”。用户决策仅用于本人项目和模型评测；不得向房东、中介、金融机构或其他商户披露。

### 4.3 数据产品运营闭环

```text
数据资源盘点与权利核验
  → 合法性/必要性/公共利益/竞争影响评估
  → 安全加工和最小聚合设计
  → 数据产品登记、模型评测、定价与SLA评审
  → 沙箱测试和灰度发布
  → 用户实名/企业认证、合同与用途承诺
  → API/报告/应用交付、计量和账单
  → 用途审计、质量监测、投诉和纠错
  → 续期、变更、暂停、下架或退出删除
```

商业化前必须确认数据权利链、授权范围、收益分配和公共利益安排；无法证明来源或用途合法的数据不得进入产品。

## 5. 选址评估与经营预测方法

### 5.1 评估维度

| 维度 | 典型指标 | 解释边界 |
|---|---|---|
| 需求潜力 | 分时人流、消费热度、常住/工作人口、搜索或诉求聚合 | 热度不等于真实购买 |
| 业态适配 | 相似业态表现、时段匹配、客单带、商圈生命周期 | 只在样本和定义可比时使用 |
| 竞争供给 | 同类门店数、密度、距离、开闭店变化、品牌结构 | 门店存在不等于有效竞争能力 |
| 成本压力 | 租金、物业、人工、装修、能耗和平台费用假设 | 用户需核验合同和实际报价 |
| 交通可达 | 步行、公交、停车、骑行和道路阻隔 | 受施工、天气和时间变化影响 |
| 空间条件 | 面积、楼层、临街、展示面、用途和周边设施 | 需现场测量和产权/规划核验 |
| 政策环境 | 禁限要求、证照清单、扶持政策、办理入口 | 仅为信息提示，不代表可获批 |
| 经营韧性 | 平峰差异、季节性、单一客群依赖、成本敏感性 | 属风险提示，不是失败判定 |

总分由版本化权重和模型共同产生，必须同时展示维度分、主要正负贡献、缺失数据、相似样本数量和稳定性。用户可调整经营偏好权重，但不能关闭合规和硬风险提示。

### 5.2 经营模型

基础计算关系示例：

```text
到店量区间 = 有效人流区间 × 可见/触达率 × 进店转化率区间
营业收入区间 = 到店量区间 × 成交率区间 × 客单价区间
经营贡献区间 = 营业收入区间 - 商品/原料 - 租金 - 人工 - 能耗 - 平台等成本
```

人流不是营业额，所有转化参数均需注明来自用户假设、行业聚合基线或模型估计。系统输出保守、基准、乐观情景以及租金、转化率、客单价和毛利率敏感性；不得只输出一个确定收益数字。

### 5.3 必做线下核验

报告应生成现场核验清单：真实租金和递增条款、产权及用途、上下水/排烟/电力、消防、招牌、噪声、垃圾处理、停车、周边施工、竞品客流、昼夜差异和目标客群访谈。高风险或数据不足点位应明确建议咨询专业机构。

## 6. 总体架构

```text
数据源层：聚合人车流｜聚合消费热力｜商户POI｜租金/物业｜人口统计｜交通GIS｜政策证照
  + 用户主动输入的经营计划与候选点
  ↓ 授权登记、交换接口、安全计算
治理层：去标识｜空间网格｜时间口径｜主数据｜质量｜血缘｜小样本抑制｜用途标签
  ↓
特征与模型层：商圈识别｜人流校准｜业态图谱｜供需特征｜选址排序｜区间预测｜情景模拟
  ↓
智能服务层：候选推荐｜可解释评分｜风险提示｜政策RAG｜报告生成｜模型监测
  ↓
产品应用层：用户工作台｜商圈地图｜点位比较｜经营模拟｜实地清单｜报告｜运营门户
  ↓
运营治理层：产品目录｜合同授权｜API网关｜计量计费｜结算｜质量SLA｜审计｜投诉退出
```

- 原始轨迹和交易明细原则上不进入应用域；特征在受控环境计算后只输出达到阈值的聚合结果。
- 多租户数据、项目、报告、账单和API密钥严格隔离；运营人员不能默认查看用户商业计划。
- 用户界面、API和离线报告使用同一产品版本、特征快照和模型解释服务。

## 7. 数据方案

### 7.1 数据来源与质量

| 数据域 | 典型来源 | 用途 | 质量与合规要求 |
|---|---|---|---|
| 聚合人车流 | 合法授权的运营商、交通、摄像结构化或传感数据 | 分时热度、趋势、停留分布 | 不含设备标识和轨迹；覆盖率、推算方法和误差必填 |
| 聚合消费 | 合法授权的支付/商业统计产品 | 消费层级、品类和时段热力 | 不含个人交易；商户保密和最小样本保护 |
| 商户POI | 政务登记、地图和公开授权数据 | 竞争、供给和开闭店变化 | 去重、经营状态、分类、更新时间 |
| 人口与就业 | 权威聚合统计 | 商圈结构和标准化分母 | 只使用批准粒度，不推断敏感属性 |
| 交通GIS | 公交、地铁、路网、停车、步行网络 | 可达性和阻隔 | 坐标、时刻、施工和服务状态 |
| 空间成本 | 合法房源、园区或用户提供信息 | 租金和物业成本 | 来源可追溯，区分报价与成交，过期提示 |
| 政策证照 | 权威政策库、办事指南 | 许可清单、限制和扶持提示 | 版本、效力区域、有效期和原文链接 |
| 用户输入 | 预算、业态、面积、成本和目标 | 个性化分析与模拟 | 明示目的、用户可更正删除，不用于未授权营销 |
| 经营反馈 | 用户自愿提供的聚合经营指标 | 复盘和模型校准 | 单独同意、字段最小化、可撤回、不得向第三方披露 |

### 7.2 聚合与隐私规则

1. 不接收或交付手机号、设备ID、支付账号、精确个人轨迹和个人交易序列。
2. 时间与空间网格采用满足业务必要性的最低精度；敏感场所周边采用更粗粒度或不展示。
3. 查询结果必须达到配置的最小样本阈值；连续查询、空间差分和时间差分需防重识别控制。
4. 所有数据附带来源、授权ID、产品版本、统计时间、覆盖率、估算方法、质量分和到期时间。
5. 数据源质量下降、授权撤回或样本不足时，相应特征自动降权、抑制或下线，不能使用旧值伪装最新结果。
6. 不通过消费、位置或商圈数据推断民族、宗教、健康、政治等敏感个人/群体属性。

### 7.3 数据权利与产品登记

每个对外数据产品登记：产品名称与版本、提供方、数据来源和权利依据、加工规则、输出字段与粒度、目标用户、允许/禁止用途、保留期、质量SLA、安全等级、模型版本、价格、计量单位、责任人、投诉渠道、有效期和退出处理。

## 8. AI方案与算法治理

### 8.1 AI能力

| 能力 | 推荐方法 | 输出 | 主要约束 |
|---|---|---|---|
| 商圈识别 | 路网可达性、空间聚类、POI和人流 | 商圈边界及类型 | 边界是分析模型，不替代行政或规划边界 |
| 客流校准 | 多源融合、覆盖率校正、时序模型 | 分时客流区间和误差 | 必须展示估算和新鲜度 |
| 业态适配 | 梯度提升/广义模型、相似样本、规则 | 维度分、贡献因素、稳定性 | 不能只返回黑箱总分 |
| 候选排序 | 多目标排序、约束优化 | 候选点及排序理由 | 用户可调偏好，硬风险不能被覆盖 |
| 经营预测 | 分位数预测、贝叶斯/蒙特卡洛模拟 | 收入/成本区间和情景 | 不输出保证值，校验分布外输入 |
| 风险识别 | 规则、异常检测、变化点检测 | 竞争、成本、季节和数据风险 | 风险需分事实、模型估计和待核验 |
| 政策助手 | 版本化RAG | 证照清单、政策条款和办理入口 | 强制权威引用，不解释为审批结论 |
| 报告生成 | 模板 + 工具 + 受约束大模型 | 可读报告和核验清单 | 数字由工具提供，事实均有引用 |

### 8.2 置信度与适用性

每次分析先执行适用性检测：城市/区域是否覆盖、业态是否在模型范围、样本是否充分、数据是否过期、用户参数是否超出训练分布。任一关键条件不满足时，系统降低结论等级或拒绝给出预测，只提供数据事实和线下核验建议。

结果必须展示：预测区间及覆盖概率、主要假设、特征贡献、相似样本数量、数据截止时间、缺失项、模型版本、历史回测误差和不适用声明。总分不命名为“成功率”。

### 8.3 人在回路

| 环节 | AI可完成 | 用户/人员必须完成 |
|---|---|---|
| 需求建模 | 补全建议、参数范围校验 | 确认经营计划和风险承受能力 |
| 候选推荐 | 搜索和排序 | 选择考察点，不自动签约 |
| 经营预测 | 计算情景和敏感性 | 核实租金、成本、合同和现场条件 |
| 政策提示 | 检索条款和入口 | 向主管部门正式申请和确认 |
| 数据产品发布 | 生成质量与风险报告 | 授权、合规、安全和价格联合审批 |
| 模型更新 | 离线评测和影子对比 | 算法责任人批准灰度/回滚 |

### 8.4 模型评测

- 排序模型：NDCG/Top-K命中、稳定性、解释一致性和用户实地核验反馈。
- 预测模型：MAE/MAPE仅作辅助，重点报告分位数覆盖率、校准误差和分业态/商圈/季节表现。
- 公平与竞争：检查不同规模、区域和价格套餐用户的基础分析质量，不得通过付费差异制造虚假数据质量。
- 生成模型：数字一致性、引用完整率、收益承诺违规率、政策幻觉率和敏感泄露率。
- 生产模型经过离线、影子、灰度后发布；漂移、重大误导或投诉触发暂停、回滚和影响分析。

### 9.1 产品套餐建议

| 层级 | 服务 | 边界 |
|---|---|---|
| 普惠基础版 | 基础商圈、候选比较、政策入口、标准报告 | 保证基本信息可及，不以低价降低安全质量 |
| 专业分析版 | 更多候选、情景参数、专题数据和协作 | 对数据与模型版本透明，避免诱导消费 |
| 企业/API版 | 批量查询、API、SLA和组织权限 | 需加强用途审核、速率限制和禁止转售 |
| 政府/园区版 | 聚合产业与服务洞察 | 不得查看创业者私有项目或商业计划 |

定价可采用按报告、订阅或API调用量，需公示计量单位、免费额度、失败不计费、退款规则和价格变更周期。基础公共信息和依法应公开的政务信息不得借产品重复收费。

### 9.2 关键业务规则

1. 用户必须先确认免责声明和数据截止时间，才能导出正式分析报告。
2. 租金、装修和成本等用户输入与外部估计必须采用不同标识，报告不得混淆。
3. 证照助手只给“可能需要核验”的事项和权威入口，不显示“保证通过”。
4. 任何面向第三方的批量查询都需用途审批、速率限制和禁止再识别/转售条款。
5. 报告过期后仍可查看历史版本，但打开时必须提示数据陈旧并建议重算。
6. 运营人员调整模型权重、价格或产品字段均需版本化、审批和影响评估。
7. 数据源授权撤回时立即停止新交付，评估存量报告、缓存、模型和衍生产品的处置。

## 12. 安全、隐私、合规与公平竞争

### 12.1 安全与隐私

- 数据源接入前开展合法性、必要性、权利链、重识别和安全风险评估；高风险处理需专项评审。
- 应用域只使用聚合特征；原始受控区、特征区、服务区和运营区网络与权限隔离。
- 实施RBAC + ABAC、租户行级隔离、字段脱敏、查询预算、动态水印、导出审批、密钥轮换和异常检测。
- 用户商业计划、候选点和报告属于其私有业务数据，未经授权不得用于园区招商、营销获客或向第三方提供。
- 用户可查询、更正、导出和删除本人输入；经营反馈同意可撤回，撤回后停止新训练并按策略处理已形成模型影响。
- 合同期满或产品下架执行密钥吊销、缓存清理、数据返还/删除、审计封存和删除证明。

### 12.2 合规市场化运营

1. 明确公共数据、企业数据、第三方商业数据和用户数据的权属与授权链，不混同授权。
2. 产品上线前完成数据产品、算法、安全、价格、公共利益和公平竞争联合评审。
3. 合同明确允许用途、禁止再识别、禁止转售、禁止歧视、保留期限、SLA、责任和退出。
4. 计费明细可核对，失败调用不收费，算法或数据重大变更提前通知并提供退出选项。
5. 建立投诉、纠错、退款、争议处理和重大事件报告流程。
6. 定期评估是否形成排他性数据优势、差别待遇或对小微主体不公平门槛；必要时提供普惠配额和可替代接口。
7. 具体运营须结合项目所在地适用法律、公共数据授权制度和主管部门要求，由法务及数据管理责任人正式确认。

### 12.3 算法与表达红线

- 不宣传“稳赚”“必火”“成功率”等无法验证的承诺。
- 不因区域消费水平、商圈标签推断店主或消费者个人敏感属性。
- 不向金融授信、保险、房东筛客等场景复用评分，除非重新开展合法性和算法影响评估。
- 不利用平台掌握的候选点数据抢先招商、抬价或向中介泄露。
- 付费推荐位必须与模型自然排序清晰分离并显著标识。

## 14. 部署、运维与服务支持

- 部署于经批准的政务云/可信数据空间或等效受控环境；计算、应用、API运营和计费审计分区部署。
- 开发、测试、验收和生产隔离；非生产使用合成或脱敏数据，生产访问采用临时授权和全程审计。
- 监控数据新鲜度、样本阈值、接口质量、特征分布、预测校准、用户修正、投诉、跨租户风险、计量和账单。
- 数据源异常时隐藏或降权相关特征并提示；模型异常时降级为事实型商圈报告和手工情景计算。
- 设立用户客服、数据质量、政策内容、算法、安全和结算六类工单，明确SLA和升级责任。
- 每季度复评数据授权、模型质量、定价公平和公共价值；每半年开展授权撤销、模型回滚、租户隔离和结算灾备演练。

## 15. 实施路线与运营模式

| 阶段 | 建议周期 | 主要产出 | 决策门 |
|---|---|---|---|
| 0. 合规与场景设计 | 6—8周 | 数据权利清单、三类业态、指标、模型目标、运营和价格原则 | 权利链清楚、数据可用、风险可接受 |
| 1. 惠企试点 | 10—12周 | 2—3个商圈、需求向导、比较、模拟、报告和人工咨询 | 用户理解度、数据质量和建议有效性达标 |
| 2. 模型校准 | 3—6个月 | 实地核验、用户反馈、开店结果、模型与区间校准 | 分业态预测稳定且无红线事件 |
| 3. 合规运营试点 | 3—6个月 | 产品登记、合同、API沙箱、计量计费、投诉退出 | 审计、计费、SLA和公共利益评估通过 |
| 4. 区域扩展 | 持续 | 新商圈/业态、园区版、开放生态 | 每个新区域/业态重新评估适用性 |

建议先由政府提供普惠基础服务并通过服务采购或运营预算支持；专业增值服务在完成定价和公平评审后收费。收入不是唯一目标，应同时考核创业决策质量、惠企覆盖、数据安全和可持续运营成本。

## 16. 指标体系

所有目标为**建议值**，试点首期核定基线：

| 维度 | 指标 | 建议目标/口径 |
|---|---|---|
| 覆盖 | 目标商圈核心数据有效覆盖率 | ≥90%，按可用特征而非数据源数量计算 |
| 使用 | 完成候选比较的项目比例 | ≥70% |
| 效率 | 用户形成首轮候选清单时间 | 较传统调研基线下降≥50% |
| 理解 | 用户正确理解区间与非承诺边界比例 | 验收调研≥90% |
| 核验 | 报告高风险项线下核验完成率 | ≥80% |
| 模型 | 预测区间覆盖率/校准误差 | 按业态在试点中核定并持续披露 |
| 解释 | 评估主要因素和来源展示率 | 100% |
| 惠企 | 小微主体和首次创业者有效使用占比 | 建立基线并持续提升 |
| 数据 | 产品授权有效率和按时更新率 | 100% / ≥95% |
| 运营 | SLA达成率、计量准确率、投诉按期办结率 | ≥99% / 100% / ≥95% |
| 安全 | 重识别、跨租户、未授权用途和个人轨迹交付 | 0起 |
| 公共价值 | 用户避免明显不适配点位或完善尽调的比例 | 通过回访建立可信口径 |
| 可持续 | 单位有效分析成本和运营收支 | 建立基线，不以增收牺牲普惠性 |

## 17. 验收标准（Gherkin）

### AC-01 候选点可解释比较

```gherkin
Given 用户已输入餐饮业态、预算、面积、客单价和营业时段
When 用户比较三个候选点
Then 系统展示需求、竞争、成本、交通、空间、政策和韧性维度分
And 展示主要正负因素、数据截止时间、来源、缺失项和模型版本
And 不以总分宣称任何点位必然成功
```

### AC-02 区间预测与情景模拟

```gherkin
Given 用户提供租金、毛利率和客单价假设且模型适用性通过
When 系统生成经营预测
Then 返回保守、基准和乐观情景的区间、覆盖概率及敏感因素
And 清楚区分用户输入、行业聚合基线和模型估计
And 显示预测不构成收益承诺
```

### AC-03 样本不足拒绝

```gherkin
Given 某新兴业态在目标商圈样本低于最小阈值或输入超出模型分布
When 用户请求经营预测
Then 系统拒绝输出确定性评分或收入区间
And 仅展示可用事实、缺失原因和实地调研建议
```

### AC-04 禁止个人轨迹

```gherkin
Given API客户请求设备级轨迹、个人消费记录或可重识别的细粒度组合
When 平台执行授权和隐私策略检查
Then 请求被拒绝且不返回可推断结果
And 记录用途、请求参数、拒绝原因和风险告警
```

### AC-05 政策证照边界

```gherkin
Given 用户查询某点位开设餐饮门店所需证照
When 政策助手返回结果
Then 每项提示包含权威来源、适用区域、有效期和办理入口
And 明确要求向主管部门核验且不得显示“保证通过”
```

### AC-06 数据授权撤回

```gherkin
Given 某人流数据产品授权被撤销或到期未续
When 平台收到高优先级治理事件
Then 停止新查询和新报告使用该数据并隐藏相关特征
And 评估缓存、存量报告、衍生特征和模型影响并按批准策略处置
```

### AC-07 数据产品发布

```gherkin
Given 数据产品已完成来源权利、输出粒度、用途、质量、安全、价格和公平竞争评审
When 授权责任人批准发布
Then 产品目录展示版本、SLA、价格、允许/禁止用途、有效期和投诉渠道
And 任一强制评审缺失时系统阻断发布
```

### AC-08 计量计费

```gherkin
Given API订阅按成功调用计费
When 同一幂等键重复请求或平台处理失败
Then 使用量最多记录一次且失败请求不生成费用
And 用户可核对调用时间、产品版本、数量、单价、优惠和退款
```

### AC-09 租户与商业计划隔离

```gherkin
Given 园区运营人员未获得创业者授权
When 其查询区域招商洞察
Then 只能看到满足聚合阈值的商圈结果
And 无法查看创业者项目、候选点、预算、报告或经营反馈
```

### AC-10 模型漂移回滚

```gherkin
Given 某业态预测区间覆盖率连续低于发布阈值或出现重大误导投诉
When 模型监控触发保护策略
Then 暂停该业态的新预测并切换至稳定版本或事实型报告
And 通知受影响用户、保留处置记录并完成复评后方可恢复
```

## 18. 测试要点

- **验收测试**：按AC编号覆盖用户决策、数据产品发布、隐私、计费、授权撤回和模型降级。
- **数据测试**：检查来源授权、空间边界、时间口径、覆盖率、最小样本、差分查询、迟到和撤销联动。
- **模型测试**：按业态、商圈类型、季节、成本带和新老区域分层，报告区间校准、分布外检测和解释稳定性。
- **生成式AI测试**：收益承诺、政策幻觉、数字篡改、引用缺失、提示注入和竞品恶意文本。
- **安全测试**：跨租户访问、API密钥泄露、批量爬取、重放、越权导出、账单篡改和供应链漏洞。
- **商业规则测试**：免费额度、重复调用、失败计费、退款、套餐变更、价格生效和合同到期。
- **用户测试**：验证创业者能否理解分数、区间、假设、风险和线下核验要求，防止自动化偏误。
- **退出演练**：数据源撤销、产品下架、用户注销、模型停用和运营方退出时的数据处置。

## 19. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 人流/消费数据覆盖偏差 | 预测误导 | 披露覆盖率、多源校准、区间输出和定期实测 |
| 评分被当作成功率 | 过度依赖和投资损失 | 禁止性命名、维度解释、理解确认和实地清单 |
| 概念漂移和新业态样本少 | 模型失效 | 适用性检测、拒绝预测、分业态监测和回滚 |
| 个人或商业信息泄露 | 合规与信任风险 | 聚合阈值、租户隔离、用途控制和异常查询检测 |
| 政策提示过期 | 办理受阻 | 权威来源、有效期、定期同步、过期拒答 |
| 公共数据授权不清 | 产品无法合法运营 | 权利链审查、产品登记、合同限制和撤销联动 |
| 数据产品形成排他优势 | 损害公平竞争 | 普惠基础版、标准接口、价格评审和竞争影响复评 |
| 运营方滥用候选点 | 抢租、抬价或招商歧视 | 商业计划隔离、利益冲突制度、审计和严厉问责 |
| 计费争议 | 用户流失 | 可核验计量、失败不收费、退款和争议流程 |
| 政府被理解为经营背书 | 公信力风险 | 明确辅助定位、第三方数据标识、免责声明和宣传审查 |
| 供应商锁定 | 成本和连续性风险 | 开放接口、模型替换、数据/报告可导出和退出演练 |
