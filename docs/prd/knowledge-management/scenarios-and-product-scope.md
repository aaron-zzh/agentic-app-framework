# 知识管理产品：场景与产品范围

> 本文只定义“为谁解决什么问题、先做到什么程度”。统一对象、生命周期、权限隐私和构建决策分别由后续 PRD 定义，本文不提前锁定接口或存储实现。

## 产品定位与成功标准

### 产品定位

产品面向高校教师、行政人员、辅导员、学生和课程团队，把分散在文件、网页、问答、业务过程和项目成果中的内容转化为**有来源、有权限、有责任人、有有效期、可检索、可协作、可归档**的知识资产；在高校场景验证通用模型后，再以模板方式迁移到企业知识管理。

产品不是新增一组互不相通的“档案、网盘、Wiki、词典、社区、地图、问答”菜单。上述形态应共享空间、资产身份、来源、版本、权限和生命周期，只是同一知识的组织视图或使用方式。

AAF 当前已经具备可信入库代际、来源与证据、向量/关键词/图混合检索、引用、知识图谱、基础上传与分块管理。首期产品工作的重点是补齐空间化组织、元数据、版本有效期、评审发布、协作、归档、权限隐私和场景模板，不重复建设第二套知识引擎。

### 用户优先级

| 优先级 | 用户 | 首要任务 | 产品责任 |
|--------|------|----------|----------|
| P0 | 教师、行政人员 | 找到当前有效制度、表单和办事依据并完成事务 | 降低查找与版本判断成本，保留办理依据 |
| P0 | 辅导员、学工队伍、学生 | 在授权范围内获取学生管理规定与个体服务信息 | 严格隔离隐私，避免搜索和回答侧漏 |
| P0 | 课程负责人、任课教师、学生团队 | 持续沉淀项目化课程素材、过程记录和可复用成果 | 按课程、班级、项目隔离，支持跨届复用 |
| P1 | 知识管理员、档案责任人、平台管理员 | 分类、复核、发布、归档、审计和处理异常 | 建立知识责任制和治理闭环 |
| P2 | 企业部门、项目团队、专家 | 迁移高校验证过的通用知识闭环 | 通过模板配置适配，不产生企业专属平行模型 |

### 北极星指标

**授权知识任务一次完成率 `M1`**：用户在一个授权会话内，使用平台知识完成预先登记的查制度、办学生事项或提交课程项目成果任务，且无需转到未登记的外部知识渠道重新寻找依据的比例。

```text
M1 = 一次会话内完成且结果被用户确认的有效任务数
     ÷ 已启动并满足前置条件的有效任务数
```

同一用户、同一任务模板在 30 分钟内重复启动只计一次；主动取消、系统故障和缺少必需业务数据的任务不进入分母，但必须单独记录排除原因。MVP 目标为 `M1 ≥ 80%`，真实数据试点目标为 `M1 ≥ 85%`。

### 指标口径

所有指标先采集连续两周的现行工作方式基线，再进入不少于四周的试点观察。最小样本不足时只标记“证据不足”，不得用少量成功案例判定达标。

| 指标 | 计算与去重规则 | 目标 | 数据源 | 最小有效样本 |
|------|----------------|------|--------|--------------|
| `M1` 授权知识任务一次完成率 | 按上述公式；用户+任务模板+30 分钟去重 | MVP ≥80%；试点 ≥85% | 任务事件、结果确认、排除原因日志 | ≥30 名用户、≥120 个有效任务，三类高校场景各≥30 个 |
| `M2` 任务时间降幅 | `(基线中位时长-试点中位时长)÷基线中位时长`；按同类任务比较 | ≥40% | 任务起止事件、基线观察记录 | 基线与试点各≥100 个任务，每类核心场景各≥25 个 |
| `M3` 可信回答通过率 | 正确且所有关键结论均有调用者可访问、业务时间有效来源的抽检回答数÷可回答的抽检回答数 | ≥90%；制度有效期错误为 0 | 检索/问答日志、引用检查、双人抽检 | ≥200 次查询，三类场景各≥50 次，时间边界问题≥30 次 |
| `M4` 跨人复用率 | 30 天内被至少 2 名授权用户使用或被另一授权项目引用的已发布可复用资产数÷同期已发布可复用资产数 | ≥30% | 资产发布、查看、引用和复用事件 | ≥50 项资产、≥3 个课程/部门空间、≥20 名用户 |
| `M5` 变更可用时延 | 从责任人发布变更到新版本可检索且旧版本不再作为默认依据的 P95 时长 | ≤30 分钟 | 发布、索引、检索验证事件 | ≥30 次有效变更，其中制度类≥10 次 |
| `M6` 未授权暴露率 | 返回正文、摘要、数量、关系线索或可推断元数据的未授权请求数÷全部未授权测试请求数 | 0；确认的真实事件为 0 | 安全测试、拒绝审计、事件报告 | ≥300 次负向请求，覆盖浏览/搜索/问答/导出/关系视图和三类隔离边界 |

## 高校核心场景

### 教师行政办公

| 维度 | 场景定义 |
|------|----------|
| 典型知识内容 | 人事、财务、报销、采购制度；教学运行文件；资产设备流程；审批表单与办事指南 |
| 主要用户 | 全院教师、行政人员；制度责任人和部门知识管理员 |
| 文档形态 | PDF、Word、Excel、扫描件、网页通知及其附件 |
| 更新频率 | 中频，以月度变化为主；政策切换和临时通知可即时发生 |
| 权限要求 | 按角色分级，默认全文可检索；敏感附件和办理记录按责任范围收紧 |

**核心任务**：教师用自然语言或关键词找到当前日期适用的制度条款、表单、所需材料、责任部门和办理路径，并能从答案回到原文定位；行政人员发布新版本后，系统按生效时间切换默认依据并保留历史版本。

**闭环**：办事需求触发 → 搜索或提问 → 比对有效制度与表单 → 获取带来源的办理清单 → 完成事务并反馈缺漏 → 责任人修订、评审和发布 → 旧版本归档并在后续复核中可追溯。

**失败边界**：没有当前有效制度、来源不可访问或版本有效期冲突时，不得拼接旧版本给出确定性办理结论；系统应说明缺口并提交责任人复核。

### 学生管理

| 维度 | 场景定义 |
|------|----------|
| 典型知识内容 | 学籍、奖惩、资助、宿舍管理规定；实习与毕业要求；心理与就业指导；辅导员工作手册；常见问题；必要的个体服务材料 |
| 主要用户 | 辅导员、学工队伍、全体学生；受委托的学院管理人员 |
| 文档形态 | Word、PDF、历史问答记录、表格名单及受控附件 |
| 更新频率 | 中频，以学期变化为主；个体服务记录按事件更新 |
| 权限要求 | 含学生隐私，必须按组织、角色、班级、学生本人和具体事项严格分级授权 |

**核心任务**：学生查看对自己公开或明确授权的规定和服务信息；辅导员在所负责班级与事项范围内查询办理依据和个体材料；学工管理者更新学期规则，并确保调班、转岗、离校或授权撤销后立即停止访问。

**闭环**：学生事项或咨询触发 → 识别当前用户与事项范围 → 在授权内容中检索 → 返回公共规则或最小必要的个体信息 → 辅导员处理并记录结果 → 高频问题经脱敏审核后沉淀 → 学期复核、到期归档或按保留策略删除。

**失败边界**：授权结论缺失、超时或依赖服务不可用时必须失败关闭；不得通过命中数量、标题、摘要、关系图或回答措辞泄露学生是否存在某类记录。

### 项目化教学知识沉淀

| 维度 | 场景定义 |
|------|----------|
| 典型知识内容 | 项目化课程大纲与教案；UG NX、AutoCAD 项目案例；岗课赛证资料；竞赛指导书；学生作品与企业真实项目归档 |
| 主要用户 | 课程负责人、任课教师、学生团队；按约定参与的企业导师 |
| 文档形态 | PPT、图纸、视频、代码、多模态素材和过程性文档 |
| 更新频率 | 高频，按周或项目里程碑更新 |
| 权限要求 | 按课程、学期、班级、项目团队与外部导师范围隔离；公开样例需单独审核 |

**核心任务**：课程负责人从模板创建课程空间；教师组织案例、任务书和评价标准；学生团队持续提交过程材料与版本；团队在本项目范围内搜索和复用知识；结项时形成冻结成果包，并选择经授权、脱敏和审核的内容供下一届复用。

**闭环**：课程或项目立项 → 套用空间模板与权限 → 导入教学材料 → 团队协作和阶段提交 → 检索案例并解决问题 → 教师评审与成果确认 → 结项冻结、归档 → 审核可复用样例并迁移到下一教学周期。

**失败边界**：跨课程、跨班级、跨项目组或未授权外部导师不得获知内容、摘要和关系；归档成果不得被后续编辑覆盖，修订必须形成新的受控版本或派生资产。

## 相邻管理场景

### 统一承载原则

相邻场景不是新的产品烟囱，而是对同一知识资产主线施加不同元数据、生命周期、权限和视图策略。

| 场景 | 在统一产品中的定位 | 首期承载范围 | 不另建的内容 |
|------|--------------------|--------------|----------------|
| 文件管理 | 知识资产的内容载体与日常组织方式 | 文件夹/集合、标签、批量导入、预览、版本、分享、回收与恢复 | 不建设与知识资产脱节的独立网盘真理源 |
| 传统档案管理 | 资产进入受控归档状态后的治理策略 | 分类号、责任人、形成时间、保管期限、移交、借阅、冻结、到期复核和销毁记录 | 不在首期替代专业档案系统、电子签章或法定长期保存平台 |
| Wiki、词典、社区问答、知识地图 | 同一资产与语义对象的编排、讨论和可视化视图 | Wiki 导航、术语释义、问答沉淀、评论讨论、实体关系浏览，均回链来源 | 不为每种视图复制正文、权限、版本或图谱真理 |
| 企业知识管理 | 高校通用模型的第二验证域 | 部门制度、岗位手册、项目复盘、专家经验、客户/产品知识模板 | 不在高校首期建设 HR、CRM、ERP 或企业门户深度集成 |
| 智能检索与助手 | 受治理知识进入工作的统一消费方式 | 当前空间内搜索、问答、推荐、引用、反馈和任务上下文继承 | 不允许助手绕过权限或把生成内容直接当作已发布知识 |

### 档案与知识的边界

普通内容只有在完成责任确认、元数据校验和归档动作后才成为归档资产。归档不是“移动到归档文件夹”，而是状态与约束变化：归档版本冻结、修改留痕、借阅受控、保管期限可执行、到期需复核。知识视图可引用归档资产，但不得覆盖归档原件。

### 企业迁移边界

企业采用与高校相同的场景模板结构：上下文范围、参与角色、知识类型、必填元数据、生命周期、默认权限、责任人和有效期策略。学院可映射为部门，课程/班级/项目可映射为岗位/客户/企业项目；迁移通过显式字段映射完成，不复制一套企业专属资产模型。

## 版本边界与场景模板

### MVP：受控数据闭环

目标是在脱敏、合成或公开数据上跑通三类高校场景，证明统一产品主线可用。

**范围内**：

- 提供行政制度、学生服务、课程项目三类空间模板及统一知识入口。
- 支持文件/在线内容的组织、元数据、版本、生效失效、责任人、评审发布、归档和来源回溯。
- 支持当前权限范围内的搜索、问答、引用、反馈和基础知识地图；默认使用已有 NexusKB 可信检索能力。
- 支持 PDF、Word、Excel、文本和网页等首期办公载体；扫描件提供受控 OCR，视频、图纸和代码首期至少作为带元数据的原始载体保存并明确解析状态。
- 收口旧 Segment/Problem 入口并接入统一授权，完成跨组织、工作区、课程、班级、项目和知识库的负向测试。

MVP 不使用真实学生隐私数据，不因演示需要放宽授权或跳过失败关闭。

### 受控真实数据试点

入口条件是 P0 授权问题关闭、安全设计经人类审核、隐私告知与保留删除策略已生效，并完成备份恢复演练。

**范围内**：选择至少一个学院行政团队、一个学工团队、三门课程及六个学生项目组；导入经批准的真实数据；验证角色/班级/本人/事项权限、撤权时效、扫描件与表格质量、制度时间边界、项目结项归档和跨届复用；连续观察不少于四周并按 `M1-M6` 出具证据。

任何确认的未授权暴露事件都使试点安全指标直接失败；处理完成并重新审核前暂停扩大数据范围。

### 增强阶段

在试点达标后按证据排序进入增强：实时多人共编与在线感知、更多业务系统连接器、音视频/图纸/代码深度解析、Wiki 自动生成、专家网络与社区运营、企业模板库、运营分析和可配置档案规则。

增强能力仍必须复用统一资产身份、权限和生命周期，不以“快速上线”为由增加双写或独立知识库。

### 场景模板

| 模板 | 默认上下文与角色 | 必填治理信息 | 默认闭环 |
|------|------------------|--------------|----------|
| 行政制度与办事 | 学院/部门；教师、行政人员、制度责任人 | 制度类别、责任部门、生效/失效时间、适用范围、表单版本 | 起草→评审→发布→办理反馈→修订→归档 |
| 学生服务与管理 | 学院/年级/班级/学生本人/事项；学生、辅导员、学工管理员 | 数据分级、授权依据、学生范围、保留期限、责任人 | 采集→授权使用→事项处理→脱敏沉淀→学期复核→删除/归档 |
| 课程项目 | 课程/学期/班级/项目组；负责人、教师、学生、企业导师 | 课程与项目归属、素材许可、里程碑、成果公开级别 | 立项→协作→阶段提交→评审→结项冻结→跨届复用审核 |
| 企业部门与项目 | 企业/部门/岗位/客户/项目；员工、负责人、专家、外部伙伴 | 责任人、业务范围、保密级别、有效期、来源系统 | 采集→加工→评审发布→业务复用→复核→归档/退役 |

### 首期非目标

- 不替代教务、学工、OA、财务、人事、资产、LMS、CRM 或 ERP 的业务交易与主数据系统。
- 不在 MVP 提供 CRDT 实时多人共编；首期协作限定为编辑、评论、任务、评审、发布、活动记录和版本恢复。
- 不建设满足全部法定档案门类、电子签章、长期格式保存和移交标准的完整档案系统。
- 不开放任意图谱 CRUD、任意 Cypher 或由普通用户直接修改知识真理；地图是授权后的可重建视图。
- 不在高校试点前投入企业深度连接器、积分商城或大规模社区运营。

## 需求追踪与验收

### 场景追踪矩阵

| 场景 ID | 场景 | 主要角色 | 核心对象与能力 | 阶段 | 指标 | 关键 AC |
|---------|------|----------|----------------|------|------|---------|
| `SCN-H01` | 教师行政办公 | 教师、行政人员、制度责任人 | 制度/表单资产、有效期、评审发布、搜索问答、引用归档 | MVP→试点 | M1、M2、M3、M5 | AC-H01、AC-H02 |
| `SCN-H02` | 学生管理 | 学生、辅导员、学工管理员 | 空间与记录授权、隐私分级、最小披露、撤权、保留删除 | MVP 合成数据→安全审核→试点 | M1、M3、M6 | AC-H03、AC-H04 |

### 验收标准

**AC-H01：制度业务时间边界**

```gherkin
Given 报销制度 V1 的有效区间为 [2026-01-01, 2026-09-01)
And 报销制度 V2 的有效区间为 [2026-09-01, 2027-01-01)
And V3 的生效时间晚于当前查询时间
When 授权教师分别以 2026-08-31 23:59:59、2026-09-01 00:00:00 和 V2 失效后的业务时间查询办理依据
Then 第一次查询默认只使用 V1
And 第二次查询默认只使用 V2
And V3 在生效前不得作为默认办理依据
And V2 失效后没有其他有效版本时不得回退到 V1 或 V2
And 系统应阻断确定性办理建议并通知制度责任人复核
```

**AC-H02：制度变更进入可用状态**

```gherkin
Given 制度责任人已发布通过评审的新版本
When 新版本进入其有效区间
Then 新版本应在 M5 规定时限内可被搜索和问答引用
And 旧版本不得再作为当前默认依据
And 用户仍可在有权访问历史时查看旧版本、失效原因和版本关系
```

**AC-H03：学生隐私失败关闭**

```gherkin
Given 调用者没有访问目标学生个体材料的明确授权，或授权决策服务超时、不可用或返回不确定
When 调用者通过浏览、搜索、问答、导出或知识关系视图请求相关内容
Then 系统不得返回正文、标题、摘要、命中数量或可推断关系
And 不得将相关内容发送给模型或外部解析服务
And 系统应记录不含敏感正文的拒绝审计事件
```

**AC-H04：授权撤销与保留策略**

```gherkin
Given 辅导员因班级调整不再负责目标学生
When 授权撤销生效
Then 该辅导员后续所有读取渠道应立即按失败关闭处理
And 搜索索引、缓存、问答上下文和关系视图不得继续暴露目标内容
And 已形成的业务审计按保留策略保存但不得通过普通知识入口读取
```

**AC-H05：课程、班级和项目隔离**

```gherkin
Given 同一课程包含不同班级和不同项目组
And 企业导师只被授权访问指定项目组
When 其他项目组成员、其他班级成员、其他课程成员或未授权企业导师尝试访问目标项目
Then 浏览、搜索、问答、导出和关系视图均不得返回目标内容、摘要或关系线索
And 每次拒绝均应记录调用者、目标范围、渠道和拒绝原因
```

**AC-H06：项目结项归档与跨届复用**

```gherkin
Given 学生项目成果已通过结项评审并归档
When 原贡献者尝试修改或覆盖归档版本
Then 系统应拒绝覆盖或要求创建新的受控修订
And 归档版本的内容摘要、责任人、评审记录和时间信息保持不变
When 下一届课程申请复用该成果
Then 只有经授权、脱敏和公开级别审核通过的派生样例可进入新课程空间
```

**AC-A01：归档版本不可被普通操作覆盖**

```gherkin
Given 知识资产已有一个冻结归档版本
When 普通编辑、同步任务或重新解析产生新内容
Then 新内容只能形成草稿、修订或新代际
And 不得覆盖归档原件及其元数据
And 归档原件的借阅、恢复、到期复核和销毁动作均应形成活动记录
```

**AC-A02：企业模板迁移不产生平行模型**

```gherkin
Given 高校场景模板包含上下文、角色、字段、流程、权限、责任人、有效期和历史状态
And 企业管理员已提供部门、岗位、项目或客户上下文的显式映射
When 系统将该模板迁移为企业部门或项目模板
Then 所有兼容配置应迁移并继续使用统一资产标识、权限和生命周期主线
And 不得创建企业专属正文副本或平行资产模型
And 不兼容字段应明确报错或进入人工映射
And 系统不得静默丢失字段、权限、责任人、有效期或历史状态
```

### 验收判定

MVP 通过要求：全部 P0 AC 通过，`M6=0`，三类核心场景在受控数据中均有完整闭环，且 `M1-M5` 全部达到 MVP 目标。真实数据试点通过要求：连续四周满足试点目标、无确认的未授权暴露、制度时间边界错误为零、项目归档不可覆盖，并由业务责任人与安全审核人共同签字确认。

任何指标低于最小样本量时标记“证据不足”；任何 P0 AC 失败、未授权暴露或归档原件被覆盖时，本阶段直接不通过，不以平均指标抵消。
