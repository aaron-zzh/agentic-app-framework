# 知识管理产品 PRD 文档大纲规划

> 本轮只确定文档体系与大纲。后续按本文顺序逐篇细化，每篇进入开发前再补齐 Story、Gherkin AC、数据概念登记和相关设计链接。

## 规划目标

### 产品定位

构建一套以高校教师、学生和教学团队为首要用户，同时可迁移到企业知识管理场景的知识资产平台。平台不是“上传文件后问答”的 RAG 工具，也不是把档案、网盘、Wiki、社区和图谱做成彼此割裂的菜单集合，而是用统一对象、统一生命周期、统一权限和多种视图承载不同业务。

产品价值链统一为：

```text
知识从工作中产生
  → 采集与整理
  → 治理与可信发布
  → 检索、问答、协作与复用
  → 复核、归档或退役
  → 知识回到工作中
```

### 设计原则

| 原则 | 规划约束 |
|------|----------|
| 高校优先、企业可迁移 | 先验证教师行政、学生管理、项目化教学三类高校闭环；企业能力通过同一对象模型和策略模板承载，不另建平行产品 |
| 极简对象、多种视图 | 文件、Wiki、地图、词典、问答和社区优先定义为同一知识资产的视图或交互方式，不默认成为独立数据孤岛 |
| 可信来源优先 | 所有搜索、回答、词条和图关系均可回到来源、版本、证据、责任人和有效期 |
| 权限先于智能 | 采集、解析、索引、检索、生成、导出均受同一授权范围约束；隐私不依赖回答阶段补过滤 |
| 管理与智能一体 | 生命周期、权限、质量和审计是基础；问答、推荐、摘要、图谱是基于受治理资产的消费能力 |

### 统一概念假设

后续第二篇 PRD 将验证以下五类核心对象，当前不作为最终数据模型：

| 对象 | 统一含义 | 承载示例 |
|------|----------|----------|
| 空间 `Space` | 组织、课程、项目或个人的协作与安全边界 | 学院、学工部门、课程、竞赛项目、企业部门 |
| 知识资产 `KnowledgeAsset` | 可治理、可授权、可复用的知识逻辑对象 | 制度、办事指南、课程案例、学生作品、FAQ、词条 |
| 内容载体 `ContentItem` | 资产的原始或编辑载体及版本 | 文件、在线文档、网页、表格、图片、音视频、代码包 |
| 语义对象 `SemanticObject` | 概念、实体、关系、同义词及本体约束 | 课程、设备、奖项、岗位、制度条款、前置关系 |
| 活动记录 `ActivityRecord` | 围绕资产发生的协作、审批、复核和审计事实 | 评论、评审、发布、借阅、分享、撤权、归档 |

传统文件、档案和企业知识的映射原则为：文件是内容载体；档案是满足归档元数据、保管策略和不可变要求的知识资产状态；企业知识是带责任人、有效期和复核机制的知识资产。三者共享资产主线，不建立三套重复真理源。

## 现状与决策基线

### AAF 已有能力

| 能力域 | 当前基础 | 规划判断 |
|--------|----------|----------|
| 知识入库 | PDF、DOCX、Markdown、HTML、TXT 基础解析，批量上传，分块策略，异步处理与失败重试 | 复用；补目录、连接器、解析配置、多模态和质量反馈 |
| 可信知识 | 入库代际、来源链、事实与证据、双时态、PgVector 投影、Neo4j 可重建投影 | 作为唯一知识真理主链，不另建 WeKnora 真理库 |
| 检索消费 | 向量、关键词、图三路检索，weighted RRF，来源引用，图谱展示，Agent 知识上下文 | 复用；补统一搜索、问答治理、反馈评测和场景化入口 |
| 文档能力 | Markdown CRUD、发布、树、全文搜索、文档关系图、SSE 变更通知 | 部分复用；实时共编、快照版本和 DAG 归档仍是设计目标，不标为已实现 |
| 运维治理 | 知识库普通 CRUD、租户范围、后台统计、失败任务重试、图投影状态和重建 | 复用；补空间成员、细粒度共享、审计、保留删除和质量运营 |

### 关键产品缺口

当前缺口不应通过新增大量菜单解决，应补齐统一管理层：

- **组织缺口**：文件夹、标签、分类法、元数据模板、专题集合和批量操作尚未形成统一资产组织能力。
- **生命周期缺口**：草稿、评审、发布、复核、归档、保管与销毁等业务状态尚未闭环。
- **场景缺口**：教师办事、学生隐私、课程项目空间、Wiki、词典、社区问答尚未产品化。
- **多模态缺口**：扫描件 OCR、Excel/PPT、图纸、公式、图片、音视频、代码包及结构保真需要明确支持矩阵。
- **协作治理缺口**：评论、任务、评审、版本、分享、借阅、外部协作者、隐私分级和审计仍需统一合同。

### 高校试点前阻断项

现有旧接口 `KnowledgeSegmentController/Service` 与 `ProblemController/Service` 只校验登录，更新、删除和关联操作未统一验证路径中的 `kbId`、`documentId` 与当前授权范围。学生管理包含隐私数据，因此后续权限 PRD 必须把该问题列为 **P0**：完成统一 PDP 接入、旧入口收口及跨组织/工作区/知识库负向测试前，不得进入高校真实数据试点。

### WeKnora 预决策

采用 **AAF 主链自研，能力级择优复用，不整体嵌入 WeKnora**：

| 选项 | 结论 | 原因 |
|------|------|------|
| 整体部署并嵌入 WeKnora UI/API | 不采用 | 会形成知识库、ACL、任务、模型配置、向量与图谱的双真理源，并增加 Go/Vue 与 Java/Next.js 双栈运维 |
| Fork WeKnora 后深度改造 | 不采用 | 长期跟随成本高，且会绕开 AAF 的 BaseCrud、权限、计费、Agent、工作流与 NexusKB 可信链 |
| 参考其产品和架构模式 | 采用 | 借鉴文件夹树、分块版本、解析时间线、数据源同步、RBAC、Wiki、评测和 Worker 治理 |
| 复用无状态解析能力 | 条件采用 | 仅对 OCR、版面、表格、PPT、音视频等解析器做固定版本与安全基准，胜出后通过 Adapter/隔离服务接入 |
| 复用其存储与检索主链 | 不采用 | PostgreSQL 真理源、PgVector/Neo4j 投影和授权检索已由 NexusKB 建立，不允许双写或回写覆盖 |

外部解析器只能返回带页码、版面坐标、时间戳和资源引用的规范化解析包；不得直接写 AAF 数据库、向量库或 Neo4j。最终入库、代际切换、授权、计费、证据与索引均由 AAF 控制。详细决策在第五篇 PRD 中以固定版本、许可证、供应链、安全基准、退出策略闭环。

## 文档集合

未来核心 PRD 严格控制为五篇；目录中不同时创建额外的“助手、Wiki、社区、档案、文件”等平行 PRD，相关需求归入下列唯一真理源。每篇正文最多五个一级章节。

### 场景与产品范围

**拟定文件**：`scenarios-and-product-scope.md`

**目的**：先回答为谁解决什么问题、优先做到何种程度，防止以功能列表代替产品闭环。

| 一级章节 | 细化内容 |
|----------|----------|
| 产品定位与成功标准 | 核心价值、角色优先级、北极星指标、首期范围与非目标 |
| 高校核心场景 | 原样覆盖“教师行政办公”“学生管理”“项目化教学知识沉淀”，逐一描述用户、内容、频率、权限、任务闭环 |
| 相邻管理场景 | 传统档案、文件管理、Wiki/词典/社区问答以及企业知识管理如何映射到通用能力 |
| 版本边界与场景模板 | MVP、试点、增强阶段；学院/课程/项目模板；企业场景后置但可验证 |
| 需求追踪与验收 | 场景—角色—对象—能力—阶段矩阵，每类场景至少一条 Gherkin AC 和量化业务指标 |

**重点问题**：学生隐私如何失败关闭；项目素材如何按课程/项目隔离；制度类知识如何管理有效期；企业需求如何复用而不稀释高校首发定位。

### 统一对象与极简信息架构

**拟定文件**：`object-model-and-information-architecture.md`

**目的**：用少量对象和一致交互承载文件、档案、知识库、Wiki、词典、问答、社区与地图，避免菜单和数据模型同时膨胀。

| 一级章节 | 细化内容 |
|----------|----------|
| 极简信息架构 | 单一知识入口、Space 上下文、统一创建与搜索、渐进披露、移动端/桌面端一致边界 |
| 核心对象模型 | Space、KnowledgeAsset、ContentItem、SemanticObject、ActivityRecord 的身份、关系和责任边界 |
| 最小语义本体 | 概念层级、类型、关系方向与基数、同义词、来源、置信度、有效期、版本、冲突与复核规则 |
| 视图与通用动作 | 文件树、列表、Wiki、地图、词典、问答、社区作为投影视图；收藏、订阅、分享、引用、导出等通用动作 |
| 演进约束与验收 | 禁止平行真理源、视图一致性、跨视图身份稳定、导航深度、任务完成步数和可用性 AC |

**重点问题**：知识库是容器还是资产集合；在线文档与上传文件是否共享版本身份；语义本体如何保持可用而不变成专家建模工具；搜索与助手如何继承当前空间和对象上下文。

### 知识资产生命周期与多模态

**拟定文件**：`knowledge-lifecycle-and-multimodal.md`

**目的**：统一“从工作中来、到工作中去”的采集、加工、治理、消费和退役闭环。

| 一级章节 | 细化内容 |
|----------|----------|
| 来源与资产边界 | 上传、本地同步、网页、业务系统、在线创建、问答沉淀、作品归档；来源与派生资产关系 |
| 采集解析与多模态 | 文本、PDF、扫描件、Word、Excel、PPT、图片、公式、图纸、音视频、代码包的支持/降级矩阵 |
| 治理发布与档案化 | 目录、标签、分类号、元数据模板、去重、版本、评审、发布、复核、归档、保管与销毁 |
| 检索生成与知识应用 | 全局搜索、混合检索、智能问答、Wiki 生成、词条、知识地图、推荐、引用与反馈闭环 |
| 质量运营与验收 | 结构保真、引用定位、解析 P95、失败恢复、检索质量、回答忠实度、资源成本及可观测性门槛 |

**重点问题**：原始载体与解析结果谁是权威；修改分块后如何产生新代际并保留证据；档案记录何时不可变；低质量 OCR 或无法解析内容如何明确降级而非静默入库。

### 协作、权限与隐私治理

**拟定文件**：`governance-and-integration/collaboration-permission-and-privacy.md`

**目的**：定义高校敏感数据和跨角色协作的统一安全合同，而不是仅提供“公开/私有”开关。

| 一级章节 | 细化内容 |
|----------|----------|
| 主体、空间与责任 | 教师、学生、辅导员、行政人员、课程团队、访客、Agent；Owner/管理员/贡献者/查看者与知识责任人 |
| 在线协同与工作流 | 首期限定为编辑、评论、任务、评审、发布、活动流和版本恢复；实时多人共编作为后续独立门槛 |
| 授权、共享与隔离 | 组织/课程/项目空间，继承与例外，记录/字段/附件权限，链接分享、借阅、外部协作者、撤权即时生效 |
| 隐私、保留与删除 | 学生隐私分级、最小化、脱敏、模型与解析器数据边界、留存、导出、删除及外部残留清除 |
| 审计、风险与验收 | 全链路审计、异常访问、越权负向 AC、P0 遗留接口治理、备份恢复与合规证据 |

**重点问题**：Agent 与人工用户使用同一授权主体；缓存、向量、图谱、临时附件和外部解析不得残留已撤权内容；首期不把 SSE 通知误标为实时共编。

### 构建与集成决策

**拟定文件**：`governance-and-integration/build-and-integration-decision.md`

**目的**：基于已有 NexusKB 和文档模块，明确自研、复用与外部集成边界，并给出可逆的实施门槛。

| 一级章节 | 细化内容 |
|----------|----------|
| AAF 现状与目标差距 | 已有业务、引擎、存储、前端和运维能力；需补产品管理层与多模态解析层 |
| 方案比较与真理边界 | 整体集成、Fork、自研、Adapter 四类方案；PostgreSQL/对象存储/PgVector/Neo4j 职责不变量 |
| WeKnora 证据与基准 | 固定 release/commit、MIT 许可证核验、功能映射、统一样本集、解析质量/性能/成本对比 |
| Adapter 安全与运维 | 无状态合同、网络隔离、凭据、SSRF/恶意文件、超时重试、任务观测、数据清理、供应链锁定 |
| 决策门槛与退出策略 | 采用阈值、P0 前置项、阶段里程碑、替换成本、失败回退和不允许的双写/兼容层 |

**预期结论**：知识主链、权限、产品 UI 和治理能力基于 AAF 自研；WeKnora 作为产品与工程参考，不整套运行在 AAF 用户请求链中；仅当独立解析能力在高校样本、安全和成本基准中明显胜出时，才以可替换 Adapter 接入。

## 细化顺序

按业务真理先于技术方案的原则逐篇推进：

| 顺序 | 文档 | 进入条件 | 完成判断 |
|------|------|----------|----------|
| 首篇 | 场景与产品范围 | 本规划经人类确认 | 三类高校场景和相邻场景均有优先级、闭环、边界和 AC |
| 第二篇 | 统一对象与极简信息架构 | 场景边界稳定 | 五类对象假设完成验证，视图不产生重复真理源，本体最小合同明确 |
| 第三篇 | 知识资产生命周期与多模态 | 对象身份稳定 | 生命周期、格式矩阵、降级和质量门槛可验收 |
| 第四篇 | 协作、权限与隐私治理 | 空间与资产边界稳定 | 隐私合同、共享撤权、负向 AC 和 P0 治理方案通过人类安全审核 |
| 末篇 | 构建与集成决策 | 前四篇明确业务需求 | 固定版本、基准、许可证、Adapter 合同和退出策略形成可执行决策 |

完成五篇 PRD 后，才按批准范围创建 `docs/design/` 产品/架构设计和对应 AAF Story；接口、表结构、UI 组件与技术任务不在 PRD 大纲阶段提前锁死。

## 验收门槛

### 单篇文档门槛

- 一级章节不超过五个，标题不使用数字编号。
- 明确 `includes`、`excludes`、角色、业务规则、异常与降级。
- 每个 P0/P1 需求至少有一条可自动化或可重复执行的 Gherkin AC。
- 新概念进入概念登记表，并说明与 NexusKB、Document、File、Authorization 的关系。
- 引用既有设计，不复制 NexusKB 的代际、证据、检索和投影真理。

### 整体规划门槛

- 三类高校场景使用用户原始名称，且均映射到对象、生命周期、权限、指标和阶段。
- 档案、文件、企业知识管理有明确承载方式；Wiki、地图、词典、社区和问答不形成默认数据孤岛。
- 在线协同首期边界明确，多模态有支持/降级矩阵及量化质量门槛。
- 学生隐私、跨租户授权、撤权、删除、模型/外部解析数据边界均有负向 AC。
- WeKnora 决策包含固定版本、许可证、基准证据、唯一真理边界和退出策略；不得以产品截图或功能数量作为集成依据。

### 本轮参考范围

本规划已核对：AAF NexusKB 产品与技术设计、知识模块实现、当前 WebUI 知识管理页、Document 模块与文档引擎设计；WeKnora `v0.7.2` README；`E:\zzh\new\kms\` 下 KMPR、源启、致远、蓝凌、采知连等九张架构图。参考产品只用于发现能力模式，不作为 AAF 需求真理源。
