# 知识管理产品：知识资产生命周期与多模态

> 本文定义知识“从工作中来、到工作中去”的产品合同。它延续 [统一对象与极简信息架构](./object-model-and-information-architecture.md)：KnowledgeItem 是唯一用户可见知识身份，ResourceRef 指向内容修订，KnowledgeBase 只管理处理与索引策略；本文不新增平行业务根。

## 来源与资产边界

### 当前基础与目标差距

本篇同时描述现状和产品目标；“规划目标”只有通过本篇验收后才能对用户承诺。

| 能力 | 成熟度 | 已有基础或缺口 |
|------|--------|----------------|
| NexusKB 可信入库 | 已实现 | PostgreSQL 保存 entity、fact、evidence、source、run 真理；代际隔离、READY 原子发布、来源证据和混合检索已有实现，PgVector/Neo4j 是可重建投影 |
| 基础文件保存 | 部分实现 | `FileRecord` 与 `FileUploadService` 已记录 SHA-256、MIME、大小、存储状态并管理引用生命周期；尚未形成知识原件冻结、安全扫描和完整修订合同 |
| 文本类知识管道 | 部分实现 | 当前 `KnowledgePipelineService` 具有 IMPORT、CHUNK、STORE、EMBED、EXTRACT_FACTS、PUBLISH 阶段，直接支持 PDF、DOCX、MD、Markdown、HTML、HTM、TXT；进度仅在内存保存 |
| OCR 与 ASR | 可复用基础 | 通用 `OcrService`、`OcrResult`、`SpeechService`、`AsrResult` 已存在，但尚未接入知识管道、ResourceRef、locator、质量门禁和代际发布 |
| Excel、PPT、扫描件、图片、音视频、代码和 CAD | 规划目标 | 尚无统一知识摄取合同；首期按本文支持级别显式降级，不得把保存原件描述成深度理解 |
| 安全预检、持久检查点、DEGRADED/BLOCKED、计费去重 | 规划目标 | 当前管道未提供完整能力，必须在真实数据试点前按风险分阶段落地 |
| 统一资源授权 | P0 缺口 | 旧 Segment/Problem 路径只校验登录，未绑定完整资源授权；真实学生数据试点前必须收口并通过跨 Organization、Space、KnowledgeBase 和业务范围负向测试 |

### 内容分层与权威

同一个 KnowledgeItem 可以经历多次修订和多次处理，但每层只承担一种责任：

```text
KnowledgeItem（稳定业务身份、责任人、权限和生命周期）
  ├─ ResourceRef → 原始载体修订（不可变字节、hash、来源元数据）
  ├─ ResourceRef → 规范化内容修订（结构、文本、纠错和 locator）
  ├─ NexusKB PostgreSQL 真理（run、source、evidence、entity、fact）
  └─ PgVector / Neo4j / 搜索缓存（按代际可重建投影）
```

- **原始载体**证明“收到过什么”，保存不可变字节、内容 hash、MIME、大小、采集时间和来源；物理去重不能合并业务身份、权限或来源。
- **规范化内容**证明“平台如何解释它”，保存结构单元、转写文本、表格、说明、纠错和定位锚点；解析器或配置变化产生新修订，不覆盖原件。
- **可信知识真理**证明“当前采信了什么”，由 NexusKB PostgreSQL 保存来源、证据、双时态事实和处理 run；同一处理指纹可复用，不复活旧代际。
- **索引与图**只为检索和浏览加速，可以落后、重建或删除；不得持有独立 ACL、生命周期或反向覆盖真理。
- **发布与归档**是 KnowledgeItem 及指定修订的治理状态，不是新的内容副本或存储系统。

### 来源权威合同

| 来源 | 正文或主数据权威 | AAF 的责任 | 更新规则 |
|------|------------------|------------|----------|
| 用户上传文件 | AAF 保存的不可变原始修订 | 建立 KnowledgeItem、原件、规范化修订、治理和索引 | 再次上传形成新修订；相同 hash 可复用 blob，但不自动合并 KnowledgeItem |
| AAF 在线文档 | Document 的指定修订 | KnowledgeItem 管身份、责任、权限和生命周期，ResourceRef 固定或跟随 Document 修订 | 正文编辑走 Document 版本；发布时固定具体修订 |
| 网页或 URL | 外部页面是来源，AAF 抓取快照是证据 | 保存规范 URL、抓取时间、响应元数据、原始快照和内容 hash | 新抓取生成新快照；不得静默覆盖人工修订或把 URL 当身份 |
| 外部连接器、网盘和业务系统 | 外部系统是内容或主数据权威 | 保存授权快照、外部版本、同步游标和治理映射 | 首期只读；外部更新形成同一 KnowledgeItem 的新修订，不回写源系统 |
| 业务对象 | 教务、学工、OA、ERP 等源系统主数据 | 只采集授权字段的快照或稳定引用，标明截至时间 | 不复制业务交易真理；源记录撤销后按来源状态立即阻断使用 |
| 讨论、问答和社区内容 | ActivityRecord 是原始活动 | 保留作者、上下文和活动引用 | 被采纳前不是已发布知识；晋升后创建或更新 KnowledgeItem 并记录 `promotedFrom` |
| AI 生成内容 | 生成 run、提示上下文和来源是派生证据 | 标识模型/规则版本、输入来源、生成时间和责任人 | 默认是草稿；只有人工确认并发布后才能成为当前知识 |

来源不得反向争夺正文所有权。外部源更新不会覆盖 AAF 人工派生内容；系统应提示比较并由责任人决定创建新派生修订、保持现状或重新基于来源生成。

### 同步方式与幂等身份

产品支持三种接入方式：一次导入、定时镜像和事件同步。首期外部连接器均为单向读取；回写属于后续独立需求。

源映射唯一键为：

```text
sourceIdentity = organizationId + sourceType + connectionId + sourceKey
```

`connectionId` 对上传和 AAF 在线内容可使用系统定义的稳定值。每次同步还必须记录外部版本、内容 hash、采集游标、处理配置指纹和请求幂等键。

- 同一 sourceIdentity 的重复事件不得新建 KnowledgeItem；内容或外部版本变化时为原 KnowledgeItem 创建新修订。
- 内容、外部版本和处理配置均未变化时直接返回已有结果，不再次调用收费解析、OCR、ASR、Embedding 或抽取服务。
- 同一幂等键携带不同请求摘要时拒绝处理并进入人工排查，不选择任一请求静默覆盖。
- 来源需要跨 Space 使用时遵循受控复制；不得通过修改 sourceIdentity 所属范围把原 KnowledgeItem 无损移动并继承权限。
- 事件同步按 sourceIdentity 串行发布；乱序事件保存证据但不得把较旧外部版本重新设为当前版本。

### 四组正交状态

一个状态不能替代另一组状态，解析成功尤其不等于业务已发布。

| 状态维度 | 状态 | 含义与主要迁移 |
|----------|------|----------------|
| Source | `ACTIVE / PAUSED / REVOKED` | 可同步、暂停同步、来源授权或记录已撤销；REVOKED 后先在真理层立即不可检索，再异步清理投影 |
| Processing | `QUEUED / PROCESSING / READY / DEGRADED / FAILED / BLOCKED` | 等待、处理中、质量合格、可有限使用、处理失败、因安全或政策禁止处理 |
| Governance | `DRAFT / IN_REVIEW / PUBLISHED / RETIRED` | 草稿、评审中、已发布、已退休；只有责任人和授权评审流程可改变 |
| Preservation | `WORKING / FROZEN / ARCHIVED / DISPOSAL_DUE / DESTROYED` | 工作修订、冻结修订、已归档、保管到期待复核、已完成审批销毁 |

`READY + DRAFT` 是合法组合；`DEGRADED + PUBLISHED` 只有显式风险接受、使用范围和警告时才允许；`ARCHIVED` 针对不可变修订，KnowledgeItem 仍可继续创建新修订。`DESTROYED` 不得与任何可读取正文组合。

## 采集解析与多模态

### 支持级别与非静默降级

每个原始修订必须给出一个确定的支持级别，不允许用“上传成功”替代解析能力说明。

| 级别 | 用户可获得的能力 | 默认检索与问答行为 |
|------|------------------|--------------------|
| `FULL` | 正文、结构、关键对象和精确 locator 均保真，可在产品内校对 | 质量门禁通过后可进入可信检索与问答 |
| `STRUCTURED` | 主要结构和 locator 保留，少数复杂元素可能以预览或附件呈现 | 标明未保真元素；合格片段可用于问答 |
| `TEXT` | 只保证可搜索文本和基本段落顺序，版式或对象关系不保证 | 仅在文本足以支持结论时参与问答，引用必须回到原件位置 |
| `METADATA` | 只保存原件、预览和元数据，正文未被可靠理解 | 不进入正文问答，可按标题、标签和人工元数据查找 |
| `UNSUPPORTED` | 因格式、加密、安全或政策原因不接受处理 | Processing=`BLOCKED`，不解析、不索引正文、不外发 |

当解析结果低于该格式承诺或低于质量阈值时，系统必须降低支持级别并展示原因、影响、可重试动作和人工处理入口；不得静默生成看似完整的正文。

### 多模态支持矩阵

“当前”描述 2026-09-02 已核实的直接知识管道能力；“目标”是本篇待验收能力。

| 内容形态 | 当前 | 分阶段目标 | 最小 locator | 关键降级规则 |
|----------|------|------------|--------------|--------------|
| TXT、Markdown | `TEXT` | MVP `FULL` | 行范围、标题路径、字符范围 | 未知编码无法可靠解码时 `BLOCKED`，不猜测编码入库 |
| HTML、网页 | `TEXT` | MVP `STRUCTURED` | 规范 URL、快照 ID、DOM 路径、字符范围 | 动态内容缺失时标记快照范围；抓取失败不沿用旧快照冒充当前 |
| 数字 PDF | `TEXT` | MVP `STRUCTURED` | 原件修订、页码、bbox、字符范围 | 缺页、字体映射异常或阅读顺序不可信时 `DEGRADED` |
| DOCX | `TEXT` | MVP `STRUCTURED` | 原件修订、标题/段落、页或对象标识 | 批注、修订、嵌入对象未保真时明确列出 |
| Excel、CSV | 未接入 | MVP `STRUCTURED` | workbook、sheet、cell range、表头版本 | 公式只保留结果而缺公式时不得宣称完整保真；超大表按范围分批 |
| PPT | 未接入 | 增强 `STRUCTURED` | slide、shape、notes | 动画和图层关系不可信时降为 `TEXT` 或 `METADATA` |
| 扫描 PDF、图片 | 通用 OCR 未接入 | MVP 受控 OCR `STRUCTURED` | 页码/图片、bbox、OCR 置信度 | 清晰度或 OCR 质量不达门禁时 `DEGRADED`；恶意内容仍为 `BLOCKED` |
| 公式、图表 | 未接入 | 增强 `STRUCTURED` | 页/slide、bbox、对象 ID、说明来源 | 无法可靠转换时保留原图和人工说明，不生成确定性公式或数值 |
| 音频 | 通用 ASR 未接入 | MVP `METADATA`，增强 `TEXT` | 原件修订、timecode、speaker 可选 | 无音轨或语种不支持时保持 `METADATA`；低置信度转写为 `DEGRADED` |
| 视频 | 未接入 | MVP `METADATA`，增强 `STRUCTURED` | timecode、keyframe、画面 bbox 可选 | 首期不承诺场景理解；仅有 ASR 时不得描述为视频语义解析 |
| 代码、压缩包 | 未接入 | MVP `METADATA`，增强 `STRUCTURED` | repo/commit 或包 hash、file、line range | 绝不执行不可信代码；加密包、压缩炸弹和路径穿越样本 `BLOCKED` |
| CAD、NX、AutoCAD 图纸 | 未接入 | MVP `METADATA` | 原件修订、预览、文件级 locator | 首期不承诺几何、装配或工艺语义；深层理解后置 |

支持矩阵按格式、版本、语言和租户策略版本化。连接器或解析 Adapter 必须固定版本，并通过安全、质量、性能和成本基准后接入；外部工具不是 AAF 真理源，且不得持久化超出处理合同的数据。

### 处理流水线

每次处理 run 按以下阶段执行并持久记录开始/结束时间、输入/输出摘要、配置指纹、供应商、成本、状态和错误码：

1. **授权与安全预检**：在读取正文和外发前复核调用者、来源和处理目的；执行 MIME sniff、扩展名一致性、恶意文件、压缩炸弹、路径穿越、配额、加密/DRM 与政策检查。
2. **原件固定**：保存不可变原始载体、SHA-256、来源身份、采集时间和外部版本；失败时不得进入解析。
3. **基础解析**：生成规范化内容和结构单元，保留解析器版本与原始到规范内容映射。
4. **多模态增强**：按需执行 OCR、ASR、表格、公式、图表、VLM 或代码结构提取；只调用当前 Organization 已批准的能力和处理区域。
5. **质量门禁**：计算完整性、字符/结构质量、locator 覆盖率和异常，唯一决定 `READY / DEGRADED / FAILED / BLOCKED`。
6. **可信入库**：以内容、解析、分块、抽取、模型和本体配置指纹创建或复用 NexusKB run；写入 PostgreSQL 真理并构建可重建投影。
7. **原子发布**：只有 run 标记 READY 后才切换检索代际；Processing READY 不改变 Governance 状态。
8. **运营反馈**：展示时间线、质量报告、成本、取消、从安全检查点重试和重新解析入口。

取消只停止尚未提交的阶段。持久检查点必须绑定 sourceIdentity、原始 hash、配置指纹和阶段输出 hash；重试只能复用全部匹配的安全检查点。部分匹配或供应商结果不可验证时重新执行，不得为节省成本牺牲正确性。

### 定位锚点合同

每个可引用片段必须具有可由用户打开和核验的 locator：

```text
locator = resourceRevisionId + modality + structuralPath + position + checksum
```

`structuralPath` 可以是标题、DOM、sheet、slide、文件路径或媒体轨道；`position` 可以是页码+bbox、cell range、timecode、line range 或字符范围。locator 还应记录提取方式、置信度和规范化片段 hash。

- 无 locator 的片段可以帮助离线质量分析，但不得成为用户可见回答的引用。
- locator 必须固定原件或规范化修订；浮动到“最新版本”的链接不能作为历史回答证据。
- 打开引用时先重新鉴权，再展示规范化片段、原始位置和必要的纠错说明；无权查看时不泄漏标题、摘要、命中数量或关系。
- 原件内容与 locator 校验和不一致时将引用标记失效并创建治理任务，不自动寻找相似片段替代。

### 纠错与质量门禁

用户编辑分块、OCR、转写或表格结果时，修改的是版本化规范化修订或纠错层，不是原始文件。保存纠错后创建新处理指纹和新 NexusKB 代际；旧原件、旧规范修订、旧引用和处理证据保持可追溯。

| Processing 结果 | 使用合同 |
|-----------------|----------|
| `READY` | 满足该格式质量阈值和 locator 合同，可按治理与权限进入默认检索和问答 |
| `DEGRADED` | 可浏览、人工校对和关键词检索；默认不参与高可信事实回答，显式启用时必须显示警告和具体缺陷 |
| `FAILED` | 处理失败，不发布新代际；保留失败阶段、错误码和可重试信息 |
| `BLOCKED` | 加密、恶意、压缩炸弹、政策禁止或不支持；不解析、不索引、不外发，可按政策隔离或销毁原件 |

对学生隐私材料，授权不确定、策略服务超时或处理目的不匹配同样失败关闭；系统不得先提取正文再决定是否允许。

## 治理发布与档案化

### 从草稿到退休

KnowledgeItem 的治理主线是：

```text
DRAFT → IN_REVIEW → PUBLISHED → DRAFT（新修订）→ IN_REVIEW → PUBLISHED
                                  └────────旧发布修订 superseded / archived
PUBLISHED → RETIRED
```

- DRAFT 可持续编辑；进入评审时固定候选修订、责任人、评审人、适用范围、有效区间和来源清单。
- PUBLISHED 只指向通过评审的具体修订，不得“发布最新内容”而不固定版本。
- 已发布修订不可原地改正文、locator、来源或有效期证据；修改产生新修订并重新评审。
- 新版本发布后，旧版本标记 `supersededBy`，但历史业务时间查询仍可在授权范围内定位旧依据。
- RETIRED 表示不再作为当前知识使用，不等于销毁；退休原因、替代项和历史引用必须保留。
- Processing READY 仅表明技术处理完成；不得自动触发 PUBLISHED。

制度、FAQ、课程样例和档案成果可使用不同评审模板，但都复用同一状态和修订合同。AI 可以提出元数据、分类和摘要建议，不能替责任人发布。

### 有效期、冲突与替代

当前知识必须同时满足：来源未撤销、Governance=PUBLISHED、Processing=READY、业务时间有效、系统当前采信、调用者有权访问。

- 有效区间采用左闭右开 `[validFrom, validTo)`；未知业务时间保持未知，不以创建时间伪造。
- 同一适用范围内出现重叠制度或互相矛盾事实时保留双方证据并进入复核；在冲突解决前不得给出确定性办理结论。
- 未来生效版本可提前发布，但只在其有效区间开始后成为默认依据。
- 当前版本失效且无替代项时明确“没有当前有效依据”，不得回退到历史版本。
- 权威版本切换首先在 PostgreSQL 真理层生效；投影尚未收敛时回源复核，不得继续引用旧索引结果。

### 冻结归档与借阅

归档不是把文件移动到一个目录，而是冻结一组可验证证据。归档清单至少包含：

- KnowledgeItem ID、归档修订 ID、原始和规范化内容 hash；
- 来源身份、ResourceRef、locator 清单和 NexusKB run/代际；
- 责任人、贡献者、评审结论、发布人和归档人；
- 创建、有效、发布、冻结和归档时间；
- 元数据模板及版本、权限快照引用、保留策略和到期时间；
- 替代关系、关联活动和完整性校验结果。

`FROZEN` 后普通编辑、覆盖和重算不得改变归档修订；重新解析或补充说明创建新工作修订。`ARCHIVED` 的修订可以只读查看和受控借阅，KnowledgeItem 可继续产生新版本。

借阅是有目的、范围和期限的临时授权，不复制所有权。到期后立即撤销借阅访问；下载副本、导出和离线责任由权限与隐私 PRD 进一步约束。归档清单不是法定电子档案合规证明，首期不承诺电子签章、长期格式迁移和法定移交。

### 保管复核、legal hold 与销毁

保管到期先进入 `DISPOSAL_DUE`，由责任人判断延长、转长期保存或申请销毁。存在 legal hold、未结事项、审计调查、法定保留或有效引用冻结时，系统禁止销毁并记录阻断依据。

销毁必须经过授权申请和审批，且区分以下动作：

| 动作 | 产品含义 | 结果 |
|------|----------|------|
| 撤源 `revoke` | 来源授权或记录失效 | 真理层立即排除检索和问答，投影异步清除；不自动销毁依法需保留的证据 |
| 逻辑删除 `logical delete` | 从普通业务入口移除 | 不再浏览和检索，但仍受保留、调查和恢复策略约束 |
| 销毁 `destroy` | 审批后清除可恢复正文 | 删除原件、规范化内容、活动附件和直接缓存，并触发索引、向量、图和外部临时副本清理 |
| 物理回收 `physical GC` | 存储层在无引用且到期后释放 blob | 只有引用计数为零、宽限期结束且无 hold 才可执行；失败必须重试和告警 |

销毁完成后仅保留最小 tombstone：不可逆业务标识摘要、销毁依据、审批人、执行时间、结果和审计链；不得保留可恢复正文、标题或敏感摘要。备份按独立保留周期到期清除，销毁结果必须显示在线副本、投影、外部临时副本和备份各自状态，不能用一个“已删除”掩盖残留。

### 来源撤销与异常恢复

来源进入 REVOKED 的事务提交点是安全边界：提交后的下一次浏览、搜索、问答、导出、图查询、历史引用和 Agent 工具调用必须失败关闭。PgVector、Neo4j、搜索缓存或会话尚未清理时，读取仍回 PostgreSQL 复核；投影任务随后按可观测检查点清除。

管道或治理动作失败时不得覆盖当前已发布版本：

- 新 run 未 READY 时继续使用上一有效代际，但若来源已撤销或业务已失效则不得使用旧代际兜底。
- 失败任务保留输入摘要、最后成功检查点、错误码、重试次数和责任人，不记录不必要的敏感正文。
- 人工修复后创建新的 run 或修订；同一失败记录不伪装成成功。
- 达到重试上限后转人工治理任务，禁止无界重试和重复收费。

## 检索生成与知识应用

### 授权先于检索

所有知识应用遵循同一顺序：确定调用者与委托人、解析 Organization/Space/业务范围、执行权限决策、筛选有效知识、检索、生成或展示、再次校验引用。

- 默认范围是当前 Space 与有权访问的组织共享知识；跨 Space 搜索必须由用户显式选择。
- 权限决策超时、异常、无结论或依赖不可用时默认拒绝；在允许前不得把正文、标题、向量、摘要或关系发送给模型、解析器或外部服务。
- Agent 的有效权限不超过委托人，并携带同一范围、目的和有效期；后台任务不能以系统身份绕过业务授权。
- KnowledgeBase 的处理或管理权限不授予正文读取权限；索引命中必须回到 KnowledgeItem/ResourceRef 实时复核。
- 当前旧 Segment/Problem 入口及跨组织、Space、KnowledgeBase 的授权缺口为真实学生数据试点 P0；修复和负向测试未完成前只允许公开、合成或脱敏数据。

### 当前有效且可信的候选集

普通搜索与高可信回答默认只使用同时满足以下条件的修订：

```text
Source=ACTIVE
AND Processing=READY
AND Governance=PUBLISHED
AND Preservation!=DESTROYED
AND 业务时间有效
AND 系统当前采信
AND 调用者有权访问
```

DEGRADED 内容可出现在带警告的浏览和关键词搜索中，默认不进入高可信事实回答。历史、退休、被替代或未来生效内容只有用户显式选择相应时间或范围时才作为候选，并继续重新鉴权。

混合检索沿用 NexusKB 的 vector、keyword、graph weighted RRF 能力；排序信号不能突破授权、有效期、质量和采信门禁。无有效来源时回答“现有授权知识不足以回答”，不得用互联网常识、模型记忆、旧版本或低质量来源伪装确定答案。

### 动态生成与保存为知识

搜索摘要、智能回答、推荐、自动 Wiki、词条释义和知识地图说明都是派生输出，不因被展示或收藏而成为已发布知识。

保存派生输出时必须：

1. 创建或更新一个 DRAFT KnowledgeItem 修订；
2. 固定全部来源 ResourceRef、locator、生成 run、模型/规则版本和时间；
3. 标记机器生成范围、未验证结论和责任人；
4. 经过人工校对、权限复核和适用评审；
5. 只有发布后才进入默认可信候选集。

Wiki、词典、地图、FAQ 和社区采纳结果统一回链 KnowledgeItem/ResourceRef，不复制正文。来源变化时生成内容标记“可能过期”并创建复核任务，不自动改写已发布页面。

### 业务嵌入与反馈闭环

知识能力可以通过 Agent、助手、审批流和 AI 工作流嵌入办事、学生服务和课程项目，但只提供依据、建议、材料准备与知识沉淀，不替代教务、学工、OA、ERP 等主系统执行交易或修改主数据。

每个结果提供结构化反馈：`错误答案 / 来源过期 / 缺少答案 / 解析质量差 / 引用定位错误 / 权限问题 / 其他`。反馈必须绑定查询、KnowledgeItem、修订、引用、处理 run 和调用者可见范围，并按类型生成治理任务：

| 反馈 | 默认责任人 | 闭环 |
|------|------------|------|
| 错误答案、引用定位错误 | 知识责任人 + 质量运营 | 复核来源与 locator，修订或标记不可回答，回归测试 |
| 来源过期、缺少答案 | 内容责任人 | 补充/替代来源，评审发布，通知反馈者 |
| 解析质量差 | 摄取运营 | 重新解析、人工纠错或降级，形成新代际 |
| 权限问题 | Space 管理员 + 安全责任人 | 立即阻断疑似泄漏，检查策略与访问日志，完成负向回归 |

治理任务关闭必须记录处理结论、影响范围、修订或配置版本和验证证据。反馈正文按原知识权限保护，不能通过工单标题泄漏敏感内容。

## 质量运营与验收

### 测量与放行规则

以下指标是产品目标，不代表当前实现已达标。每次基准测试固定语料集版本、解析器/模型/配置版本和运行环境；先采集基线，再观察不少于四周。样本不足时只标记“证据不足”，不得判定达标。

指标数据由处理 run、质量报告、同步游标、成本账单、检索/问答日志和双人抽检产生。内容与平台责任人共同确认样本；质量运营每周汇总，安全门禁实时阻断。任一 P0 泄漏、恶意文件逃逸、来源撤销后仍可读取或销毁绕过 legal hold，均直接判定阶段失败，不能由平均指标抵消。

### 真实数据试点 P0 门禁

使用真实学生数据前，必须由人类安全审核确认以下证据全部存在：

- 旧 KnowledgeSegment、Problem 及所有浏览、搜索、问答、导出、图、历史引用、Agent 工具入口已统一绑定资源授权或关闭；
- 按主体×Organization×Space×课程×班级×项目×学生本人×事项×渠道生成负向覆盖矩阵，所有越权用例失败关闭；
- 权限超时、异常、无结论、撤权后的第一笔请求及旧会话均不返回标题、正文、摘要、数量和关系线索；
- 外部 OCR/ASR/解析的数据范围、区域、保留、删除和供应商版本已审批，未批准能力不可自动回退；
- 来源撤销、legal hold、审批销毁、投影清理和备份到期均有可重复演练证据；
- 任一 P0 未关闭时，产品只使用公开、合成或脱敏数据，不以演示需要放宽门禁。

### 验收标准

**AC-L01：同一来源同步更新不重复知识身份**

```gherkin
Feature: 来源同步幂等
Scenario: 同一 sourceIdentity 的新外部版本形成原知识的新修订
  Given Organization 100 的连接器 20 已将 sourceKey "policy-7" 映射到 KnowledgeItem 700
  And 当前外部版本为 "v1" 且内容 hash 为 "hash-v1"
  When 连接器以幂等键 "event-v2" 同步版本 "v2" 和内容 hash "hash-v2"
  Then 系统应继续返回 KnowledgeItem 700
  And 系统应只创建一个指向版本 "v2" 的新修订
  And 系统不得创建第二个 KnowledgeItem
  And 审计事件应记录 sourceIdentity、旧版本、新版本和幂等键
```

**AC-L02：外部权威源与本地派生内容互不覆盖**

```gherkin
Feature: 来源权威隔离
Scenario: 外部源更新不会覆盖本地人工派生修订
  Given KnowledgeItem 701 同时保存外部快照修订 11 和基于该快照创建的本地修订 12
  And 修订 12 已由责任人编辑但尚未发布
  When 外部源产生版本 "v3" 并完成同步
  Then 系统应创建新的外部快照修订
  And 系统应保持本地修订 12 的正文和状态不变
  And 系统应向责任人创建来源变化比较任务
  And 系统不得自动把外部快照设为本地派生正文
```

**AC-L03：纠错不改写原始文件**

```gherkin
Feature: 原件与规范化修订分离
Scenario: OCR 纠错创建新规范化修订和新代际
  Given 扫描件原始修订 30 的 SHA-256 为 "raw-hash-30"
  And 当前规范化修订 31 包含一处 OCR 错误
  When 授权用户修正该错误并提交
  Then 原始修订 30 的字节和 SHA-256 应保持不变
  And 系统应创建新的规范化修订
  And 系统应创建带新配置指纹的 NexusKB run
  And 旧规范化修订、旧 locator 和旧 run 应保持可追溯
```

**AC-L04：表格和扫描件按确定规则降级**

```gherkin
Feature: 多模态透明降级
Scenario: OCR 质量低于门禁时唯一进入 DEGRADED
  Given 扫描 PDF 修订 40 已通过恶意文件和加密检查
  And 固定金标抽检计算出的中文 CER 为 0.09
  And 当前清晰扫描件门禁 CER 上限为 0.03
  When 质量门禁完成判定
  Then Processing 状态应为 DEGRADED
  And 支持级别不得标记为 FULL
  And 默认高可信问答候选集不得包含该修订
  And 用户应看到 OCR 质量、受影响页和人工纠错入口
```

**AC-L05：安全预检阻断危险载体**


**AC-L07：已发布版本不可原地覆盖**

```gherkin

Scenario: 修改已发布制度时创建新修订并保留替代关系
  Given 制度 KnowledgeItem 703 的修订 60 已发布且有效至 2026-10-01T00:00:00
  When 责任人修改制度正文并提交新评审
```
