# 框架特性

AAF 不是"在传统应用上加 AI 功能"，而是"AI 是架构的一等公民"。把 AI 拿掉，系统无法正常运转——这是 AI 原生与 AI 增强的本质区别。

## 核心差异化

### AI 是一等公民，不是附加物

- Agent 和 Human 共享统一 Actor 抽象（同一套权限、审计、协作接口）
- 五层智能架构（Core → Cognition → Agent → Assistant → Team），不是"加个聊天窗口"
- 置信度门控贯穿所有执行路径：>0.9 自动执行 / 0.7-0.9 等待确认 / <0.7 转人工

### 规范驱动开发（SDD）

- 先写规范再写代码，规范是人类和 AI 的共同真理来源
- 文档即程序：DSL 同时是规范文档、AI 生成目标、系统执行程序
- 自进化闭环：行为采集 → 效果评估 → 规范更新 → 代码重生成 → 热部署

### 元引擎：开发即运行

- 统一执行环境，开发时和运行时共享同一套 DSL + 引擎
- 无代码为主（~80%）：实体运行时动态建表 + 工作流运行时 DSL 驱动 + 权限运行时动态鉴权
- 复杂逻辑由 AI 生成代码热加载挂载扩展点

### 对话式交互：界面是对话的投影

- 用户意图 → DSL → 语义组件动态组装，界面不是预先设计的固定结构
- 同一功能根据用户角色自适应呈现（普通用户看对话框，开发者看配置面板）
- 多端统一：同一套语义组件适配 Web / 移动端 / 微信 / CLI

### 人机协作：动态主导权

- 系统优先 → AI 主动 → 人类按需介入
- 主导权根据任务确定性和置信度实时切换，不固定归属
- AI 主动感知上下文、发现重复模式、推荐系统化方案（不等指令）

### 人类计算与集体智慧

- 众包协作：知识拆解、规范评审、专家技能贡献
- 积分与智能合约结算：贡献行为量化，生态激励可持续
- 单用户看起来在做自己的事，宏观上在解决高价值问题

## 技术特性

| 能力 | 实现 |
|------|------|
| 多智能体协作 | Spring AI + AgentScope，五层智能架构 |
| 工作流引擎 | Flowable 封装 + DSL 驱动 |
| 知识库 | PostgreSQL/PgVector + Neo4j 知识图谱 |
| 记忆系统 | 短期/长期/情景/情感记忆，时序+语义双索引 |
| 沙箱执行 | GraalVM Polyglot Sandbox |
| 实时协同 | Yjs（CRDT）+ SSE 流式输出 |
| 外部生态 | 微信/钉钉/飞书统一接入 |
