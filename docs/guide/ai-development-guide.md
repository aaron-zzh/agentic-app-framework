# AI 协作开发指南

本项目使用 Kiro CLI 多智能体协作开发。本文档面向人类开发者，说明如何与 AI 智能体协作完成开发任务。

> AI 运行时规范见 [协作规则](../../.kiro/steering/collaboration.md)，完整过程规范见 [过程规范](../reference/team/process-standard.md)。

## 整体架构

```
人类开发者
  ↓ 描述想法
kiro_default（协调者）
  ↓ subagent 自动派发
  │
  ├── product       → 需求分析、用户故事、验收标准
  ├── architect     → 技术设计、接口定义、架构决策
  ├── designer      → UI/交互设计（涉及前端时）
  │
  ├── 【开发群组】（可并行）
  │   ├── developer-service   → 后端 Java/Spring Boot
  │   ├── developer-webui   → 前端 Next.js/React
  │   └── developer-uniapp   → UniApp 小程序/APP
  │
  ├── tester        → 验收测试、需求覆盖验证
  └── qa            → 过程审计、规范合规检查
```

**协调者是 `kiro_default`**，即你直接对话的 AI。它自动加载 AGENTS.md 和所有 steering 规范，拥有项目全局视图。

## 任务流水线

**人类只需描述目标，协调者自动走完全流程：**

```text
product+architect（需求细化+技术设计）
  → designer（UI/交互设计）           ← 涉及前端时
    → developer（编码+单元测试）      ← 验证
      → architect（代码审查）
        → tester（验收测试）          ← 确认
          → qa（过程审计）
            → 质量门控
```

质量门控通过条件：**blocker=0 且 major≤2**。不通过则自动回退对应环节。

## 迭代全景

```text
准备（版本规划+需求调研+用户故事+技术预研+选取范围）
  → 启动（任务拆分+验收标准确认+依赖识别+规范对齐）
    → 执行（任务流水线）
      → 发布（部署+迁移+验收+发布说明）
        → 总结（回顾+度量+改进+归档）
```

## 文档驱动

智能体间通过文档沟通。每个任务产出到 `docs/task/{版本}/{AAF-XXX}/`：

```
docs/task/v0.1.0/AAF-001/
├── requirement.md    ← product 输出
├── design.md         ← architect 输出
├── dev-log.md        ← developer 输出
├── test-report.md    ← tester 输出
└── review.md         ← qa 输出
```

模板在 `docs/task/_template/` 下。

## 人类的职责

协调者会主动推进，人类聚焦以下几件事：

- **定义目标**：描述想做什么，不需要说怎么做
- **审核高风险设计**：架构调整、接口删除、权限变更等 🔴 高风险项必须人工确认
- **质量判断**：最终验收，决定是否发布
- **价值判断**：优先级权衡、方向决策

**可以放手给 AI 的**：需求细化、技术设计、编码、测试、文档、提交。

## 日常使用

### 开始一个任务

直接描述目标即可：

```
"实现用户登录功能，支持账号密码和微信扫码两种方式"
```

协调者会自动拆解、派发、执行、验证。

### 查看/更新任务进度

```
"当前迭代进度怎么样"
"AAF-003 完成了"
"把 #12 标记为进行中"
```

### 会话结束前

提示协调者收尾：

```
"记录一下今天的工作，准备结束会话"
```

协调者会更新 backlog 状态、写工作日志、提交代码。

### 切换到专属 agent

如果想直接和某个 agent 对话：

```
/agent swap developer-service
```

## AI 自主开发演进路径

| 阶段 | 人类职责 | AI 职责 | 当前状态 |
|------|----------|---------|----------|
| 阶段 1 | 定义规范 | 按规范实现 → 人 Review | ← 当前 |
| 阶段 2 | 定义需求 | 设计 + 实现 → 人 Review | |
| 阶段 3 | 定义目标 | 规划 + 设计 + 实现 + 测试 → 人验收 | |
| 阶段 4 | 批准方案 | 发现问题 → 提出方案 → 人批准 → 实现 | |

推进关键：**规范文档的完善度**。规范越精确，AI 自主开发质量越高，人类参与越少。
