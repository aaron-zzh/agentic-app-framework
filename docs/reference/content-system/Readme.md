# 内容体系 Content System

> 让 AI 和人类都能快速定位、理解、编写内容的结构化文档管理系统。

## 概述

通过知识框架理论 + 五度空间模型，让每篇文档在内容体系中有清晰的位置和作用。

## 为什么需要内容体系

- **找不到**：文档散落各处，搜索靠记忆
- **看不懂**：缺乏上下文和术语共识，每人理解不同
- **写不好**：没有标准，风格各异，质量参差不齐
- **传不动**：知识留在个人脑中，口头沟通信息丢失，人走知识散
- **协作低效**：缺乏可引用的文档基线，讨论无锚点，同一件事反复解释
- **AI 不友好**：缺乏结构化元数据，AI 无法精准检索和生成

## 原则

### 组织原则

> 内容体系如何运作。

- **元数据优先**：结构化 YAML Front Matter 是文档的"身份证"，AI 靠它定位
- **五度空间**：任何目录 = 1 个 README（索引） + ≤ 5 个内容项，超过则拆分子目录
- **类型驱动**：目录按文档类型（Tutorial/Guide/Reference/Explanation）划分
- **命名即语义**：文件名反映内容类型，无需打开即可判断用途

### 编写原则

> 每篇文档如何写好。

- **单一职责**：一篇文档只解决一个问题，混合内容必须拆分
- **读者优先**：先确定读者是谁、要解决什么问题，再动笔
- **渐进披露**：先给结论/用法，再给原理/细节，急用者 30 秒内找到答案
- **准确 > 完整 > 简洁**：宁可少写不可写错；错误信息比没有信息更有害
- **示例即文档**：抽象规则必须配具体示例，示例是最好的解释
- **可验证**：gains 必须可检验——读者读完能做到什么
- **自包含**：文档提供足够上下文，外部依赖用 dependencies 声明
- **消除歧义**：术语首次出现时给出定义或链接术语表
- **DRY**：同一知识只在一处定义，其他地方用链接引用
- **可演化**：文档随代码迭代，过时内容标记 deprecated 而非删除

### 结构原则

> 文档内部如何组织。

- **标题即摘要**：标题应能独立传达核心信息，无需阅读正文
- **扁平优于嵌套**：标题层级不超过 3 级（H1-H3），超过则拆文档
- **表格优于段落**：对比、枚举、规则类信息优先用表格呈现
- **代码优于描述**：能用代码/配置示例说明的，不用文字描述
- **链接优于重复**：已有文档覆盖的内容，给链接而非复制粘贴

## 理论基础

### 知识框架理论

提供文档的认知定位——每篇文档处于什么认知维度（level）和抽象层级（layer），详见 知识框架理论：

```text
level（认知维度）  × layer（抽象层级）
Reality/Thought/    Principle/Paradigm/
Theory/Practice/    Pattern/Model/
Meaning             Product
```

### 五度空间模型

提供文档的物理组织约束——目录结构和信息密度控制，详见 五度空间模型：

```text
任何目录 = 1 个 README（索引） + ≤ 5 个内容项
```

### 文档类型

提供文档的形态分类——决定文档怎么写、放哪里：

```text
Tutorial / Explanation / Guide / Reference / Map
```

三者协同：知识框架定位"是什么层次"，文档类型决定"怎么呈现"，五度空间约束"怎么组织"。

详见 [文档元数据规范](./doc-meta-standard.md)。

## AI 使用指南

### 查找文档

1. 根据需求确定 type（要教程？指南？还是速查？）
2. 根据 level 和 layer 缩小范围（知识框架定位）
3. 通过文件名模式快速识别（如 `how-to-*` = 指南，`*-standard` = 规范）

### 编写文档

1. 确定知识框架坐标（level × layer）+ type → 查 [文档路由规范](./doc-route-standard.md) 决定放哪
2. 按 [文件命名规范](./file-name-standard.md) 创建文件
3. 填写元数据 Front Matter → 查 [文档元数据规范](./doc-meta-standard.md)
4. 按 [写作规范](./content-standard/) 中对应类型的标准撰写内容

## 与项目文档体系的关系

```text
docs/
├── reference/content-system/  ← 你在这里（定义规则）
├── tutorial/                  ← 按规则写的教程
├── guide/                     ← 按规则写的指南
├── explanation/               ← 按规则写的原理
├── design/                    ← 设计文档
└── README.md                  ← 文档中心入口
```

本目录是"规则的规则"——定义其他所有文档应该如何组织、命名和编写。
