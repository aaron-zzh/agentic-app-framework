# Guide 写作规范

## 定义

Guide 是**任务导向**的文档，指导读者完成特定任务，回答"怎么做"的问题。

### 核心特征

| 特征 | 说明 |
| --- | --- |
| **目的** | 解决具体问题 |
| **阅读方式** | 按需查找，快速执行 |
| **内容组织** | 步骤化、任务化 |
| **语言风格** | 简洁指令，直达要点 |
| **前置条件** | 明确列出 |

### 适用场景

- ✅ 解决特定问题的步骤、故障排除、配置设置
- ❌ 概念原理 → Explanation
- ❌ 系统学习 → Tutorial
- ❌ 参数说明 → Reference

## 结构规范

```markdown
# 如何 [具体任务]

## 目标
[一句话说明要完成什么]

## 前置条件
- 条件1
- 条件2

## 步骤

### 1. 第一步标题
[具体操作说明]

### 2. 第二步标题
[具体操作说明]

## 验证
[如何确认任务完成]

## 故障排除
[常见问题和解决方法]
```

## 写作要求

| 要求 | 示例 |
| --- | --- |
| **使用祈使句** | ✅ "打开终端" ❌ "你需要打开终端" |
| **动作具体** | ✅ "点击保存按钮" ❌ "保存并关闭" |
| **避免解释** | ✅ "运行 npm install" ❌ "运行 npm install（这会安装依赖）" |
| **结果明确** | ✅ "终端显示 'Done'" ❌ "应该成功" |

### 步骤编写

1. **单一任务** — 每个步骤只完成一个动作
2. **顺序执行** — 步骤必须按顺序进行
3. **独立完整** — 每步都能独立理解
4. **可选标记** — 明确标出可选步骤

## 质量标准

- [ ] 标题以"如何"开头或明确表达任务
- [ ] 前置条件完整明确
- [ ] 步骤编号且顺序正确
- [ ] 每步都有明确的动作
- [ ] 提供验证方法
- [ ] 语言简洁直接

## 检查清单

1. 读者能立即知道要做什么吗？
2. 前置条件都列出了吗？
3. 按步骤能完成任务吗？
4. 能确认任务完成了吗？

## 文件命名

- `how-to-[任务].md` — 推荐格式
- `troubleshooting-[问题].md` — 故障排除
