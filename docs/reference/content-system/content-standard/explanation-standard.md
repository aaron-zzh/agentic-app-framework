# Explanation 写作规范

## 定义

Explanation 是**理解导向**的文档，帮助读者理解概念、原理和背景，回答"为什么"的问题。

### 核心特征

| 特征 | 说明 |
| --- | --- |
| **目的** | 建立理解和认知 |
| **阅读方式** | 顺序阅读，逐步深入 |
| **内容组织** | 自然叙述，逻辑递进 |
| **语言风格** | 通俗易懂，可以口语化 |
| **前置知识** | 假设读者不了解 |

### 适用场景

- ✅ 概念原理、设计理念、架构决策、历史演进
- ❌ 具体操作步骤 → Guide
- ❌ 参数配置说明 → Reference
- ❌ 学习练习教程 → Tutorial

## 必要元素

| 元素 | 必需性 |
| --- | --- |
| **主题定义** — 一句话说清是什么 | 必需 |
| **背景动机** — 为什么需要关心 | 必需 |
| **核心概念** — 关键概念和原理 | 必需 |
| **具体示例** — 用例子加深理解 | 必需 |
| **价值意义** — 对读者的实际价值 | 必需 |

## 文风要求

### 语言原则

1. **通俗化** — 用日常语言替代专业术语
2. **具象化** — 用类比和例子替代抽象概念
3. **自然化** — 用流畅叙述替代条目罗列
4. **个性化** — 保持作者声音，避免千篇一律

### 避免 AI 味

- 不使用机械的章节标记（【开篇】【动机】等）
- 不过度使用 bullet points
- 段落之间自然过渡，不要机械分割

### 写作技巧

| 技巧 | 示例 |
| --- | --- |
| **类比法** | 文档体系像四层楼房子 |
| **对比法** | 以前...现在... |
| **问答法** | "你可能会问..." |
| **故事法** | "想象这样一个场景..." |

### 关于例子

- ✅ **虚拟**（可以）：想象的场景，但合理真实
- ❌ **虚假**（避免）：假装发生过的事实

## 层级特殊要求

| layer | 重点 |
| --- | --- |
| Principle | 必须包含核心思想或设计哲学 |
| Paradigm | 重点解释思维框架的价值 |
| Pattern | 重点解释方案选择的理由 |
| Model | 重点解释规范设计的考虑 |
| Product | 重点解释实现决策的权衡 |

## 质量标准

- [ ] 开篇 100 字内说清主题
- [ ] 至少包含一个具体例子
- [ ] 明确说明实际价值
- [ ] 语言通俗无学术腔
- [ ] 文风自然流畅

## 检查清单

1. 新手 3 分钟能理解核心概念吗？
2. 读者知道为什么要关心吗？
3. 大声朗读是否自然？
4. 读者知道下一步做什么吗？
