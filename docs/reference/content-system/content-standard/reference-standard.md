# Reference 写作规范

## 定义

Reference 是**查询导向**的文档，提供准确、完整、易查找的技术信息。

### 核心特征

| 特征 | 说明 |
| --- | --- |
| **目的** | 快速查找具体信息 |
| **阅读方式** | 跳跃式、搜索式 |
| **语言风格** | 精确、技术性 |
| **结构要求** | 高度规范、可预测 |
| **内容深度** | 完整但简洁 |

### 适用场景

- ✅ API 接口文档、配置参数说明、命令行手册
- ✅ 数据字典、错误代码表、规范标准
- ❌ 概念解释 → Explanation
- ❌ 操作步骤 → Guide
- ❌ 学习教程 → Tutorial

## 结构规范

```markdown
# [文档标题]

## 概述
[一句话说明这是什么]

## [主体内容]
[根据类型组织：表格、列表、代码块]

## 参考
[交叉引用、延伸阅读]
```

### 组织原则

1. **可预测的结构** — 同类文档结构一致
2. **清晰的层级** — 最多 4 级标题，不跳级
3. **有效的索引** — 提供多种查找方式

## 格式要求

### 表格（Reference 核心格式）

```markdown
| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| name | string | 是 | - | 用户名称 |
```

### 特殊标记

- `必需` `可选` — 用标签标识
- **默认值** — 加粗显示
- *废弃* — 斜体标识
- ⚠️ 警告 — 用图标强调

## 语言规范

- 使用专业术语（首次出现简单解释）
- 保持中性语气，不用"你"、"我们"
- 精确表达："必须"不是"应该"，"默认"不是"通常"

## 质量标准

- [ ] **可查找性**：能通过多种方式快速定位
- [ ] **完整性**：包含所有必要信息
- [ ] **准确性**：信息正确，示例可运行
- [ ] **一致性**：格式统一、术语一致
- [ ] **简洁性**：描述不超过 2 句话，不解释原理

## 检查清单

1. 用关键词能否快速找到？
2. 新手能否找到所有必需信息？
3. 示例代码能否运行？
4. 与同类文档格式是否一致？
