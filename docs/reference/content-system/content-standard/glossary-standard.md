# 术语表写作规范

## 定义

术语表是 Reference 类型文档，为特定主题提供术语的精确定义和快速查询。

## 识别标准

### 需要定义的

| 类型 | 示例 |
| --- | --- |
| **专有概念** — 我们创造或特殊使用的 | 五度空间原则、知识框架定位 |
| **容易混淆** — 需要明确区分的 | 维度 vs 层级 vs 类型 |
| **核心概念** — 理解体系的关键 | level、layer、type |
| **特定含义** — 通用词在特定语境的含义 | "路由"（特指文档定位） |

### 不需要定义的

- 业界共识（API、REST、HTTP）
- 通用编程概念（函数、变量、类）
- 日常用语
- 只出现一次的概念

## 条目结构

### 必需元素

```markdown
### 术语名称
**定义**：一句话精确定义
**作用**：为什么需要这个概念
```

### 可选元素

```markdown
**包含**：组成部分
**对比**：相似概念区分
**示例**：具体使用案例
**参见**：深入了解链接
**英文**：中英对照
```

## 组织方式

1. **核心术语** — 最重要的概念，必须理解
2. **相关术语** — 扩展概念，深入了解用
3. 组内按重要性排序，不按字母序

## 撰写原则

| 原则 | 要求 |
| --- | --- |
| **精确性** | 本质特征，不是表象 |
| **简洁性** | 一句话说清本质 |
| **独立性** | 用更基础的概念解释，不循环定义 |
| **实用性** | 说明作用和价值 |

## 质量标准

- [ ] 每个术语都有定义和作用
- [ ] 相似概念有对比说明
- [ ] 无循环定义
- [ ] 专有概念标注来源

## 文件位置

术语表放在最相关的主题目录下（就近原则）。
