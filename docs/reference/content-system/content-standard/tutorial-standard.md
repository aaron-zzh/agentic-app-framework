# Tutorial 写作规范

## 定义

Tutorial 是**学习导向**的文档，通过引导式练习帮助新手获得基础技能和初步体验。

### 核心特征

| 特征 | 说明 |
| --- | --- |
| **目的** | 建立初始技能和信心 |
| **阅读方式** | 跟随练习，边学边做 |
| **内容组织** | 精心设计的学习路径 |
| **语言风格** | 友好鼓励，耐心引导 |
| **前置条件** | 零基础，最小化假设 |

### 适用场景

- ✅ 新手入门、快速上手、功能初体验、Hello World
- ❌ 高级技巧 → Guide
- ❌ 完整功能说明 → Reference
- ❌ 理论原理 → Explanation

## 结构规范

```markdown
# [技术/工具] 快速入门

## 学习目标
完成本教程后，你将能够：
- 目标1
- 目标2

## 准备工作
- 需要安装...（5分钟）
- 基础知识：无需编程经验

## 第一步：[建立直观认识]
让我们先看看最终效果...

## 第二步：[动手尝试简单任务]
现在轮到你了...

## 第三步：[稍微增加复杂度]
让我们尝试更多...

## 总结
恭喜！你已经学会了：
✅ 技能点1
✅ 技能点2

## 下一步
- 深入学习：[链接]
- 实践项目：[链接]
```

### 设计原则

1. **循序渐进** — 难度逐步提升，不跳跃
2. **即时反馈** — 每步都要看到结果
3. **容错设计** — 预见并处理可能的错误
4. **保持专注** — 不引入无关内容

## 写作要求

| 要求 | 示例 |
| --- | --- |
| **鼓励性语言** | ✅ "很好！现在让我们..." ❌ "你必须..." |
| **清晰指令** | ✅ "点击右上角的蓝色按钮" ❌ "点击按钮" |
| **预期管理** | ✅ "稍等3秒，会看到..." ❌ "等待加载" |
| **错误友好** | ✅ "如果出现错误，说明..." ❌ "不要出错" |

## 质量标准

- [ ] 30 分钟内可完成
- [ ] 零基础可跟随
- [ ] 每步都有明确结果
- [ ] 不超过 5 个主要步骤
- [ ] 包含成功截图或输出
- [ ] 语言友好鼓励

## 检查清单

1. 找一个新手，能独立完成吗？
2. 30 分钟内能完成吗？
3. 完成后有成就感吗？
4. 出错时有引导吗？

## 文件命名

- `[技术]-quickstart.md` — 快速入门
- `[技术]-tutorial.md` — 基础教程
