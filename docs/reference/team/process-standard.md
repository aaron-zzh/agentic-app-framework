# 迭代过程规范

> 本文档定义开发过程的**流程和原则**。各环节人+AI+系统如何协作见 [协作规范](collaboration-standard.md)。

## 核心原则

- **一句话开发**：人类给出目标 → AI 全流程执行 → 系统自动化保障 → 人类异步审核
- **规范驱动**：先写规范再写代码，规范是人类和 AI 的共同真理来源
- **质量内建**：验证与确认分离，系统自动化门控，问题按类型回退修复

### 规范驱动

> 先写规范，再写代码。规范是人类和 AI 的共同真理来源。

**规范不是描述性文档，而是可验证的技术合同**——明确规定系统应该做什么、不应该做什么，以及如何验证。代码是规范的实现结果，当代码与规范不一致时，以规范为准并修正代码。

**规范的特征要求**：

| 特征 | 说明 |
|------|------|
| 明确性 | 对系统行为、约束、边界条件有明确描述，避免歧义 |
| 结构化 | 可被工具或 AI 稳定解析（Markdown / DSL / Schema） |
| 可验证 | 能映射到测试、校验规则或自动化验证 |
| 可演进 | 支持版本化、Diff、回滚，随系统一起成长 |
| 面向实现 | 能直接指导代码生成或人工实现 |

**AAF 采用 Spec-Anchored（规范锚定）模式**：规范长期保留，与代码持续同步维护。人和 AI 都可以修改代码，但必须与规范保持对齐。

**规范流转与验证闭环**：

```text
需求规格 → 设计规格 → 代码实现 → 测试验证 → 过程审计
   ↓          ↓          ↓          ↓          ↓
 product   architect   developer   tester      qa
   ↑          ↑          ↑          ↑          ↑
   └──────────┴──────────┴──────────┴──────────┘
              发现偏离 → 向上游反馈修正
```

**一致性规则**：
- 下游发现与上游规范矛盾时，必须向上游反馈修正，不得自行偏离
- 发现源码与规范不一致时，必须提出并记录，由协调者评估是修正代码还是更新规范
- 规范变更时，同步触发下游重新验证（规范→代码→测试的联动）

**三方角色**：

| 角色 | 在规范驱动中的作用 |
|------|-------------------|
| 人类 | 定义业务规范和验收标准，审核高风险规范变更，判断规范演进方向 |
| AI | 生成和维护规范文档，检查规范一致性，发现偏离时主动提出，辅助规范演进 |
| 系统 | 存储规范版本（Git），自动检查规范合规（lint、静态分析、合约测试），阻断不合规提交，规范变更时触发下游验证 |

> 详见 [规范驱动开发](../../design/auto-dev/blog/规范驱动开发.md)

## 迭代全景

```text
准备 → 启动 → 执行 → 发布 → 总结
                ↑        |
                └── 回退 ←┘（质量门控不通过）
```

周期 2-4 周。融合敏捷开发 + CMMI5 过程域 + 人机协作。

## 1. 准备

**目标**：明确迭代范围，确保可行性。

### 1.1 版本规划

- 确定版本目标和交付范围
- 评估资源和时间约束
- 输出版本计划

### 1.2 需求调研

- 收集业务需求和用户反馈
- 分析可行性和投入产出比
- 输出业务需求列表

### 1.3 用户故事细化

- 将业务需求拆分为用户故事
- 标注优先级（P0/P1/P2）
- 定义初步验收标准

### 1.4 技术预研

- 评估技术方案可行性
- 识别技术风险和依赖
- 输出技术方案和风险清单

### 1.5 选取迭代范围

- 根据优先级和容量从 backlog 选取任务
- 确认迭代目标
- 输出迭代需求列表

---

## 2. 启动

**目标**：对齐目标，分解任务，明确验收标准。

### 2.1 启动会议

- 对齐迭代目标和范围
- 确认团队分工
- 输出会议记录

### 2.2 任务拆分

- 将用户故事拆分为技术任务
- 评估工作量
- 标注任务间依赖关系
- 关联 backlog 编号

### 2.3 验收标准确认

- 逐条细化每个故事的验收标准（AC）
- 确保 AC 可测试、可验证
- 人类确认 AC 完整性

### 2.4 依赖与风险识别

- 识别模块间依赖、跨端依赖
- 制定风险应对措施
- 接口先行，mock 实现解耦

### 2.5 规范对齐

- 确认本迭代适用的编码规范、设计规范、测试规范
- 如有新规范需求，排入规范制定任务

---

## 3. 执行

**目标**：按任务流水线交付。

### 任务流水线

```text
product(需求规格)
  → architect(技术设计)
    → designer(UI/交互设计)           ← 涉及前端时
      → developer(编码 + 单元测试)    ← 验证
        → architect(代码审查)
          → tester(验收测试)          ← 确认
            → qa(过程审计)
              → 质量门控
```

### 3.1 需求细化

- 结构化用户故事（功能点、约束、AC）
- 标注非功能需求（性能、安全、兼容性）
- 输出需求规格

### 3.2 技术设计

- 接口定义（完整签名）
- 类结构和模块交互设计
- 数据模型设计
- 设计决策记录（ADR）
- 输出技术设计文档

### 3.3 UI/交互设计
>
> 涉及前端界面的任务触发，纯后端任务跳过。

- 界面布局和交互流程设计
- 组件规范和设计 token 定义
- 响应式和多端适配方案
- 输出设计稿和交互说明

### 3.4 编码实现

- 按技术设计和 UI 设计编码
- 遵循编码规范和项目约定
- 输出源码和开发日志

### 3.5 验证（单元测试/自测）

- 编写单元测试（覆盖核心逻辑）
- 自测冒烟（主流程跑通）
- 静态分析通过
- 输出测试代码和自测报告

### 3.6 代码审查

- 规范合规检查（命名、结构、异常处理）
- 设计符合性检查（是否按设计实现）
- 安全审查（注入、权限、敏感数据）
- 输出审查意见

### 3.7 代码重构
>
> 审查发现结构性问题时触发，非每次必须。

- 消除重复代码和坏味道
- 优化模块结构和依赖关系
- 确保重构后测试全部通过

### 3.8 确认（验收测试）

- 对照 AC 逐条编写验收测试
- 集成测试（模块间交互）
- 边界场景和异常路径测试
- 需求覆盖验证（每条需求有对应测试）
- 输出测试报告

### 3.9 过程审计

- 检查流程合规（是否按流水线执行）
- 检查规范遵守（编码、设计、测试规范）
- 检查文档完整性（每个环节产出是否齐全）
- 输出审计记录

### 3.10 质量门控

- 统计 blocker/major/minor 数量
- 判定通过或回退
- 通过条件：blocker = 0 且 major ≤ 2
- 不通过则按问题类型回退对应环节

### 3.11 进度跟踪（贯穿执行全程）

- 监控各任务流水线进度
- 识别阻塞和延期风险
- 协调资源和优先级调整

### 3.12 集成验证

- 多任务/多模块集成后的整体验证
- 确认模块间接口对接正确
- 回归测试（已有功能未被破坏）

---

## 4. 发布

**目标**：部署验证，收集反馈。

### 4.1 测试环境部署

- 构建部署包
- 部署到测试环境
- 验证部署成功（冒烟测试）

### 4.2 数据库迁移
>
> 有 schema 变更时触发。

- 编写迁移脚本
- 测试环境验证迁移
- 回滚方案准备

### 4.3 用户验收

- 演示已完成功能
- 收集用户反馈
- 记录遗留问题和改进建议

### 4.4 发布说明

- 汇总本版本变更内容
- 标注破坏性变更和升级指引
- 输出 Release Note

### 4.5 正式发布

- 部署到生产环境
- 生产冒烟验证
- 打 Git Tag

---

## 5. 总结

**目标**：回顾改进，沉淀知识。

### 5.1 迭代回顾

- 做得好的（继续保持）
- 待改进的（分析根因）
- 行动项（落实到下个迭代）

### 5.2 度量分析

- 需求完成率（计划 vs 实际）
- 缺陷密度（blocker/major/minor 分布）
- 周期时间（从需求到交付）
- 回退次数和原因分布
- 输出度量报告

### 5.3 过程改进

- 基于度量数据和回顾结论，识别改进点
- 更新规范和流程
- 输出规范变更记录

### 5.4 规范制定/更新
>
> 迭代中发现规范缺失或不合理时触发。

- 编写或修订编码规范、设计规范、测试规范
- 团队评审规范变更
- 发布新版规范

### 5.5 知识沉淀

- 记录设计决策和理由
- 记录踩坑经验和解决方案
- 更新知识库

### 5.6 backlog 归档

- 已完成和已取消的任务移入归档
- 整理待排期任务
- 更新 backlog 状态

- [ ] 数据库迁移脚本就绪（如有）

- [ ] 发布说明已编写
- [ ] backlog 已归档
