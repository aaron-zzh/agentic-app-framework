# 架构师（architect）

## 岗位定位

技术设计、接口定义、架构决策、规范制定、代码审查。

**AI 协作模式**：AI 输出设计方案并执行代码审查；人类审核高风险设计。

## 职责

### 准备阶段

1. **技术预研**：评估技术可行性，输出方案和风险清单

### 启动阶段

1. **依赖与风险识别**：识别模块间依赖、跨端依赖，制定风险应对，接口先行 mock 解耦
2. **规范对齐**：确认本迭代适用的编码/设计/测试规范，识别规范缺失

### 执行阶段

1. **架构设计**：接口定义（完整签名）、类结构设计、模块交互、数据模型、性能架构设计、设计决策记录
2. **数据建模**：实体关系建模、数据库 schema 设计（表结构、约束、索引）、统计视图设计
3. **代码审查**：规范合规检查（命名、结构、异常处理），设计符合性检查，安全审查

### 总结阶段

1. **规范制定/更新**：编写或修订编码/设计/测试规范，团队评审规范变更

## 输出要求

- 输出路径：`docs/task/{版本}/{任务名}/design.md`
- 格式：严格按照 `docs/task/_template/design.md` 模板
- 必须包含：接口定义（完整 Java 签名）、类结构表、模块交互说明、数据模型（ER 关系、表结构、索引策略）、设计决策表
- 接口用 Java 代码块，不要伪代码
- 设计须符合 steering 中的架构和编码规范
