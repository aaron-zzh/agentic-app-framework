# 状态、上下文、Checkpoint、审计

> 四个容易混淆的核心概念，生命周期完全不同。

## 概念定义

### 状态（State）

系统运行时的"当前情况"——正在做什么、做到哪了、暂存了什么结果。

- 可变的、会被修改的运行时数据
- 示例：任务进度、暂存结果、在线用户列表
- 生命周期：会话级或任务级，执行完成后销毁

### 上下文（Context）

请求级的只读组装物，用完即弃。

- 当前消息 + 从记忆/知识检索到的片段 → 拼成 Prompt 送给 LLM
- 生命周期：单次请求，LLM 调用完成后丢弃
- 组成：
  - **记忆**：用户的"个人经历"——过去发生了什么、学到了什么、偏好是什么
  - **知识库**：全局的"领域知识"——事实、规范、文档

### Checkpoint（断点续跑）

会话状态的快照——Agent 执行到某一步时，把当前工作记忆、已完成步骤、中间结果序列化保存。

- 恢复时从快照重建会话状态，继续执行
- 关系：Checkpoint ⊂ 会话状态管理，是状态的"存档点"
- 生命周期：任务完成后可清理，失败时用于恢复

### 审计（Audit）

决策日志——每次状态变更、决策权切换、工具调用都记录不可删除的日志。

- 存储在记忆引擎的"决策审计区"（PostgreSQL，管理员可审计）
- 关系：审计从状态变更事件中产生，但审计日志本身是持久记忆（不是状态）
- 生命周期：永久保留，不可删除

## 生命周期对比

| 概念 | 可变性 | 生命周期 | 用途 |
|------|--------|---------|------|
| 状态 | 可变、可恢复、会销毁 | 会话/任务级 | 跟踪"现在" |
| 上下文 | 只读、组装后不变 | 单次请求 | LLM 输入 |
| Checkpoint | 不可变（快照） | 任务完成后可清理 | "存档"，错误恢复 |
| 审计 | 不可变、不可删 | 永久 | "历史记录"，事后追溯 |

简单说：**状态是"现在"，上下文是"这一次的输入"，Checkpoint 是"存档"，审计是"历史记录"。**

## 整体关系

```text
Agent 执行中
  ├── 状态变更 → 触发审计日志写入（记忆引擎/决策审计区）
  ├── 到达检查点 → 快照当前状态（Checkpoint，可恢复）
  ├── 执行失败 → 从最近 Checkpoint 恢复状态 → 继续执行
  └── 执行完成 → 状态销毁，审计日志永久保留

每次 LLM 调用：
  ├── 从记忆/知识检索 → 组装上下文（只读）
  ├── 上下文 + 当前消息 → 送入 LLM
  └── LLM 返回后上下文丢弃，结果写入状态
```

## 设计原则

- **状态不等于记忆**：状态是临时的运行时数据，记忆是持久的认知基础
- **上下文不持久化**：上下文是每次请求临时组装的，不存储；存储的是记忆和知识
- **Checkpoint 服务于状态**：Checkpoint 是状态的快照，不是独立的数据层
- **审计独立于状态生命周期**：状态销毁后审计日志仍在，支持事后追溯
