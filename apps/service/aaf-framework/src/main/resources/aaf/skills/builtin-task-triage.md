# 任务前注意判断

先对请求做初步判断，再决定下一步动作。本技能输出的是判断，不是动作；动作由判断结果指向的工具或技能完成。

## 判断项

- 意图类型：用户要的是问答、内容生成、操作执行还是任务管理
- 关键输入是否缺失：缺失会让结果方向性错误时，调用 `request_clarification` 一次问清阻塞项（该工具不可用时直接在回复中提问）；能依据上下文合理假设的不要追问
- 所需技能与知识：只判断需要哪类能力，不在此展开执行
- 是否涉及需要用户授权的动作：写入、发布、外发等有外部副作用的动作
- 复杂度：见下文四种动作

## 四种动作

只能选一种，不要同时拆步骤又派生执行者：

- 直答：当前角色能胜任且任务是单一、连贯的工作，直接给出最终答案，不调用计划、切换或委派工具
- 切换角色：对话态下当前角色不适合、角色目录中另有更合适的角色时，调用 `activate_role` 切换，由新角色回答。必须在输出任何正文之前调用，调用后不要再输出内容
- 升级拆步骤：同一份工作需要多个有序步骤。任务态下使用 `builtin-step-planning` 的 `plan_steps` 与 `report_step`；对话态下先调用 `promote_to_task`，`shape=STEPS`
- 升级拆多角色：不同领域分工、可并行拆为独立子任务。任务态下使用 `builtin-agent-delegation` 的 `delegate_agents`；对话态下先调用 `promote_to_task`，`shape=DELEGATE`

对应工具不在可用工具列表中，说明本次请求不允许该方式（例如调用方锁定角色或要求单段直答），此时不得切换或拆分，按直答或按步骤推进完成。

## 判断依据

不要仅凭任务描述长短判断复杂度，只看语义上是否真的存在多个有序步骤或需要不同角色分工。用户明确要求"直接
回答""不要拆解"时优先遵从用户意图；用户明确要求多角色协作时优先遵从，对话态下调用 `promote_to_task` 并带
`shape=DELEGATE`。

## 对话态升级

没有任务的对话态下，遇到以下情况，在任何外部副作用和面向用户的正文之前调用 `promote_to_task` 升级为任务：

- 语义上需要多个有序步骤
- 需要不同角色分工
- 用户明确要求多角色协作
- 结构化人工交互或多步骤持久执行

需要用户授权的工具（Skill 工具清单中标为"需要用户审批"）不要先调用 `promote_to_task`：用户要执行时直接调用该工具，
系统会自动转为任务并弹出审批卡，调用后本轮结束。

升级时可用 `roleKey` 指定任务协调者角色（取自角色目录），用 `shape` 说明形态。普通问答、自然澄清和本回合可完成的
目标不要升级。调用 `promote_to_task` 后本轮立即结束，不要再输出内容。
